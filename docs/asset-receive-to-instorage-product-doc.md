# 资产接收到入库产品文档

## 1. 文档目的

本文从产品视角描述 MMP 系统中“资产采购接收”到“资产入库”的完整业务过程，帮助产品、研发、测试、运维和业务用户统一理解：

- 谁在什么场景下操作资产接收和入库
- 系统页面如何流转
- 接收单、入库单、资产台账之间是什么关系
- 哪些状态会变化
- 哪些业务规则会阻断流程
- 哪些数据会回写或推送到外部系统

本文不描述具体代码实现细节，只保留必要的系统对象和业务规则。

## 2. 业务背景

采购订单进入 MMP 后，资产管理员需要根据 PO 对采购到货资产进行接收。接收完成后，系统要求维护资产标签号、SN号、责任人、地点、服务、成本中心等信息。待信息完整后，资产管理员再创建入库单并执行入库。

执行入库后，系统正式生成资产台账，同时记录资产入库事务，并将入库结果回写采购系统。

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 资产到货可接收 | 支持按 PO 行选择本次接收数量 |
| 接收过程可追踪 | 生成接收单和接收明细，保留接收人、接收时间、接收数量 |
| 资产信息可维护 | 支持维护标签号、SN号、责任人、位置、服务等资产入库必要信息 |
| 入库过程可控制 | 支持按仓库权限创建和执行入库 |
| 台账自动生成 | 执行入库后自动生成资产台账和资产事务 |
| 采购系统可回写 | 入库完成后向采购系统推送入库结果 |
| 状态可闭环 | PO从待接收、已接收到已入库形成完整闭环 |

## 4. 适用范围

本文覆盖：

- 资产类采购接收
- 高耗类采购接收
- 采购接收入库
- 本地资产台账生成
- 入库结果推送采购系统

本文不重点覆盖：

- 低耗、文具的快速入库流程
- NO设备自动入库流程
- 自采接收流程
- 借用归还、退库入库、调拨入库等非采购接收流程

## 5. 用户角色

| 角色 | 主要职责 |
|---|---|
| 资产管理员 | 查看待接收PO、创建接收单、维护资产明细、创建入库单、执行入库 |
| 仓库管理员 | 管理有权限的仓库入库单，执行仓库入库操作 |
| 采购系统 | 接收入库结果回写 |
| 系统管理员 | 维护基础数据、仓库权限、物料、公司板块、服务、成本中心等 |
| 财务/资产管理人员 | 关注资产台账、资产事务、费用账户、入库状态 |

## 6. 用户故事

### 6.1 资产管理员接收采购资产

作为资产管理员，我希望在系统中看到待接收的采购 PO，选择实际到货的 PO 行和数量，生成接收单，以便记录本次采购接收情况。

### 6.2 资产管理员维护资产信息

作为资产管理员，我希望为每一台接收资产维护标签号、SN号、责任人、地点、服务、成本中心等信息，以便后续入库后自动生成完整资产台账。

### 6.3 仓库管理员执行入库

作为仓库管理员，我希望将已接收并维护完整的资产创建入库单，并执行入库，以便资产正式进入资产台账和库存管理。

### 6.4 采购系统接收入库结果

作为采购系统，我希望收到 MMP 推送的入库单号、入库日期、PO行、物料、数量、金额等信息，以便完成采购侧入库闭环。

## 7. 产品主流程

```text
1. 查看待接收PO
2. 打开PO接收详情
3. 选择接收行和接收数量
4. 创建接收单
5. 维护资产明细
6. 提交接收单
7. 创建/绑定入库单
8. 执行入库
9. 生成资产台账
10. 回写PO状态
11. 推送采购系统
```

## 8. 页面与功能

### 8.1 PO接收列表页

页面用途：

- 展示待接收、已接收、已入库的采购 PO。
- 支持按公司、板块、PO号、供应商、接收状态、采购日期等条件查询。
- 支持进入 PO 接收详情。

用户动作：

| 动作 | 说明 |
|---|---|
| 查询PO | 根据筛选条件查询采购订单 |
| 查看PO详情 | 点击 PO 单号进入接收详情 |
| 查看状态 | 判断当前 PO 是待接收、已接收还是已入库 |

主要状态：

| 状态 | 产品含义 |
|---|---|
| 待接收 | 采购资产尚未完成接收 |
| 已接收 | 采购资产已接收，等待入库 |
| 已入库 | 采购资产已完成入库 |

### 8.2 PO接收详情页

页面用途：

- 展示 PO 行明细。
- 展示每行采购数量、已接收数量、草稿数量、本次可接收数量。
- 支持用户选择本次接收行和接收数量。

核心规则：

```text
本次可接收数量 = 采购数量 - 已接收数量 - 草稿数量
```

用户动作：

| 动作 | 说明 |
|---|---|
| 选择接收行 | 勾选本次需要接收的 PO 行 |
| 修改接收数量 | 输入本次实际接收数量 |
| 创建接收单 | 根据选中行和数量生成接收单 |

### 8.3 接收单详情页

页面用途：

- 展示接收单头信息和接收单行。
- 展示本次接收数量、PO信息、供应商、采购员、物料信息。
- 管理接收单状态。

用户动作：

| 动作 | 说明 |
|---|---|
| 查看接收单 | 查看接收单头和行信息 |
| 删除接收行 | 草稿阶段可调整接收内容 |
| 维护明细 | 进入资产明细维护 |
| 提交接收 | 完成接收确认 |

### 8.4 资产接收明细维护页

页面用途：

- 将接收数量拆成一条条资产明细。
- 一台资产对应一条明细。
- 用户维护资产入库必须的信息。

必填/关键字段：

| 字段 | 产品含义 |
|---|---|
| 标签号 | 资产唯一标签 |
| SN号 | 设备序列号 |
| 责任人 | 资产责任人/使用人 |
| 公司 | 资产所属公司 |
| 板块 | 资产所属板块 |
| 成本中心 | 资产成本归属 |
| 地点 | 城市、楼宇、楼层、房间 |
| 服务 | 一级服务 |
| 子服务 | 二级服务 |
| NO位置 | NO设备位置，部分设备使用 |
| 入库数量 | 通常资产类为 1 |
| 价格/税额 | 入库生成资产金额使用 |

校验规则：

| 规则 | 说明 |
|---|---|
| 标签号不能为空 | 资产入库必须有标签号 |
| SN号不能为空 | 资产/高耗接收完成前必须维护 SN |
| SN号不能重复 | 非“缺省”的 SN 不能与其他标签重复 |
| 信息未维护完整不能完成接收 | 标签号或 SN 为空时，接收单停留在待维护 |

### 8.5 入库单列表页

页面用途：

- 展示用户有权限仓库下的入库单。
- 支持查询、创建、查看、编辑、打印、执行入库。

用户动作：

| 动作 | 说明 |
|---|---|
| 查询入库单 | 按入库单号、类型、仓库、状态等查询 |
| 创建入库单 | 创建新的入库单或进入待入库明细 |
| 查看/编辑入库单 | 查看或维护入库单信息 |
| 打印入库单 | 打印采购接收入库单 |
| 执行入库 | 正式完成入库动作 |

### 8.6 入库单详情页

页面用途：

- 展示入库单头和明细。
- 明细来自接收阶段维护好的资产明细。
- 支持维护是否计费、入库仓库、备注等。

核心关系：

```text
入库单头 MMP_SP_PO_PUTIN_HEAD
  -> 通过 PUTIN_HEAD_ID 绑定
入库明细 MMP_SP_PO_LINE_MOST_DIS
```

## 9. 状态流转

### 9.1 PO状态流转

```text
待接收
  -> 已接收
  -> 已入库
```

状态变化规则：

| 流转 | 触发动作 | 条件 |
|---|---|---|
| 待接收 -> 已接收 | 提交接收单 | 累计接收数量达到采购数量 |
| 已接收 -> 已入库 | 执行入库 | 累计入库数量达到采购数量 |

### 9.2 接收单状态流转

```text
草稿
  -> 待维护
  -> 完成
```

状态变化规则：

| 流转 | 触发动作 | 条件 |
|---|---|---|
| 草稿 -> 待维护 | 提交接收 | 资产明细未维护完整 |
| 草稿/待维护 -> 完成 | 提交接收 | 标签号、SN等资产明细维护完整 |

### 9.3 入库单状态流转

```text
草稿
  -> 完成
```

状态变化规则：

| 流转 | 触发动作 | 条件 |
|---|---|---|
| 草稿 -> 完成 | 执行入库 | 入库单明细存在且入库处理成功 |

## 10. 业务规则

### 10.1 接收数量规则

用户本次接收数量不能超过可接收数量。

系统计算口径：

```text
可接收数量 = 采购数量 - 已接收数量 - 草稿数量
```

### 10.2 接收完成规则

资产类接收单完成前，必须满足：

- 已生成接收明细
- 明细已维护标签号
- 明细已维护 SN号
- SN号未重复

### 10.3 入库完成规则

入库完成前，必须满足：

- 入库单头存在
- 入库单明细存在
- 明细已绑定入库单头
- 资产信息足够生成资产台账
- 当前用户有入库仓库操作权限

### 10.4 PO回写规则

PO状态回写不是单纯按操作按钮更新，而是按数量判断：

| 目标状态 | 判断口径 |
|---|---|
| 已接收 | 累计接收数量 = 采购数量 |
| 已入库 | 累计入库数量 = 采购数量 |

### 10.5 采购系统推送规则

执行入库后，系统会向采购系统推送入库结果。

推送成功：

```text
入库单同步标记 = 成功
```

推送失败：

```text
入库单同步标记 = 失败，等待后续重传或人工处理
```

注意：本地资产入库成功与采购系统推送成功是两个动作。采购推送失败不等于本地资产未入库。

## 13. 异常场景

| 场景 | 系统表现 | 产品建议 |
|---|---|---|
| 未维护标签号 | 接收单不能完成 | 提示用户维护标签号 |
| 未维护SN号 | 接收单不能完成 | 提示用户维护SN号 |
| SN号重复 | 保存失败 | 提示重复SN对应信息 |
| 无仓库权限 | 用户看不到或不能处理对应仓库入库单 | 提示联系管理员配置仓库权限 |
| 入库明细为空 | 不能执行入库 | 提示先添加或绑定入库明细 |
| 采购推送失败 | 本地入库成功，但同步标记失败 | 提供重推或运维处理入口 |
| 累计数量不足 | PO状态不更新为已接收/已入库 | 保持部分接收/部分入库状态 |
| 物料类型不匹配 | 入库失败 | 提示物资类型配置异常 |

## 14. 权限控制

入库单列表会按用户仓库权限过滤。

用户只能看到自己有入库权限的仓库单据。

权限维度：

```text
用户
仓库
是否有入库控制权限
```

产品上应确保：

- 用户无权限时不展示不可操作仓库
- 入库按钮只对有权限用户可用
- 权限异常时提示清晰

## 15. 产品验收标准

### 15.1 接收单创建

- 用户可从 PO 列表进入接收详情。
- 用户可选择 PO 行并输入接收数量。
- 创建成功后生成接收单号。
- 接收单行数量与用户选择一致。
- 接收单处于草稿或待维护状态。

### 15.2 资产明细维护

- 系统按接收数量生成资产明细。
- 每条资产明细可维护标签号、SN、责任人、地点、服务等。
- SN重复时系统阻止保存。
- 资产明细未维护完整时，接收单不能完成。

### 15.3 接收完成

- 明细维护完整后，接收单可完成。
- 接收完成后，PO满足数量条件时状态变为已接收。
- 未满足数量条件时，PO不应误变为已接收。

### 15.4 入库单创建

- 已接收资产明细可绑定到入库单。
- 入库单可展示入库仓库、入库类型、明细数量和金额。
- 入库单明细与接收明细保持一致。

### 15.5 执行入库

- 执行入库成功后，入库单状态变为完成。
- 系统生成资产台账。
- 系统生成资产事务。
- PO满足数量条件时状态变为已入库。
- 系统向采购系统推送入库结果。
- 推送失败时保留失败标记和日志。

## 16. 产品关注点

1. 接收和入库是两个阶段，不应在页面文案上混淆。
2. 资产明细维护是流程关键卡点，页面需要突出未维护项。
3. PO状态依赖数量校验，不是单据状态的简单映射。
4. 入库成功和采购推送成功需要分开展示。
5. 低耗/文具流程更短，产品入口和提示应与资产流程区分。
6. NO设备可能由接口数据自动生成接收/入库数据，需要单独标识数据来源。
7. 入库失败时要区分是本地资产入库失败，还是外部采购推送失败。

## 17. 建议优化

| 优化点 | 说明 |
|---|---|
| 增加流程进度条 | 展示“待接收-待维护-待入库-已入库-已同步” |
| 增加未维护字段提示 | 在接收明细列表直接标红缺失标签号/SN的行 |
| 增加入库推送状态 | 页面展示采购系统同步成功/失败 |
| 增加重推入口 | 对采购推送失败的入库单支持手动重推 |
| 增加数量明细弹窗 | 展示采购数量、已接收、已入库、草稿数量来源 |
| 增加异常看板 | 汇总未维护、推送失败、无仓库权限、数量异常等单据 |
| 区分资产与低耗入口 | 避免用户误以为所有物资都必须维护标签号/SN |
