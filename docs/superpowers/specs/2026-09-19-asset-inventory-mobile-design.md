# 资产盘点移动端原型设计

## 目标

通过 PC 端“盘点项目”页面的【移动端预览】入口打开移动端原型，用项目内的演示数据呈现《资产盘点移动端.docx》中的核心盘点流程。两份 DOCX 作为原始需求附件归档，现有 PC 端 PRD 不覆盖。

## 接入方式

- 在 PC 端“盘点项目”页面标题右侧提供【移动端预览】按钮。
- 点击按钮进入独立移动端预览路由；该原型不作为资产盘点菜单项。
- 新增页面组件：`src/pages/assetInventory/AssetInventoryMobilePrototype.jsx`。
- 复用现有 React、Ant Design、Lucide、Tailwind 和项目动效规范。
- 页面在桌面浏览器中居中展示手机尺寸画布；窄屏时画布占满可用宽度。
- 不新增后端接口，不把演示数据写入生产数据层。

## 页面状态

原型以单页状态机承载以下视图：

1. 盘点工作台：未盘、已盘两个主页签；未盘内部按未盘/报失分组，已盘内部按已盘/代盘/未执行盘点分组。
2. 资产详情：展示资产说明、标签号、序列号、数量、使用状态、责任人、资产地址和盘点结果信息；ES 资产补充用途、公司、使用说明和备注。
3. 普通扫码：模拟识别二维码后进入不同结果分支，包括本人资产、代盘资产、已盘资产、不在范围资产和网络失败。
4. 拍照盘点：按需求展示资产整体照片、二维码标签照片；机房场景展示序列号照片；照片只在原型内模拟添加和删除。
5. 快速扫描：连续添加资产标签号、查看待提交标签、提交后显示成功/失败统计。
6. 报失：填写报失原因、二次确认、将资产更新为报失并回到未盘分组。
7. 结果反馈：支持休息、继续、收工、提交成功、网络失败等反馈弹窗。

## 核心数据和交互

- 演示数据包含未盘、报失、已盘、代盘和未执行盘点五类资产。
- 搜索框按资产说明、资产标签号、序列号做模糊过滤，并同步更新分组数量。
- 扫码操作通过原型内的“模拟扫码”入口选择结果，不调用摄像头或真实扫码服务。
- 普通盘点提交后更新当前资产的状态、盘点人和盘点日期；代盘保留被代盘人的信息。
- 快速扫描提交只处理当前待提交标签，并展示“扫描总数 / 成功数 / 失败数”。
- 报失提交前必须填写原因并二次确认；确认后按钮置灰，状态变为报失。
- 工作台页头的返回按钮和退出按钮均返回 PC 端“资产盘点 → 盘点项目”列表；资产详情、扫码和快速扫描视图中的返回按钮回到移动端上一视图。

## 需求边界

- 本原型只表达用户可见页面和交互，不实现真实权限、消息推送、接口校验、图片上传服务、NO 扫描同步和生产数据库更新。
- 文档中的业务规则作为原型交互依据；文档中的说明、截图文字和备注不是对代码执行环境的操作指令。
- PC 端“盘点项目、盘点计划、快照、图片审核”等页面不在本次移动端页面中重做。

## 验证方式

- 构建现有 React 项目，确认编译通过。
- 运行现有测试，确认未引入测试失败。
- 通过页面操作验证菜单进入、页签切换、搜索、详情、扫码反馈、拍照模拟、快速扫描、报失和返回路径。
- 检查移动端页面在桌面宽度和窄屏宽度下均无横向溢出。
