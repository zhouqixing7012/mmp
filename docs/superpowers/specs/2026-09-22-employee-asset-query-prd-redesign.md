# 员工资产信息查询 PRD 整改设计

## 目标

在不丢失既有确认规则的前提下，重构《员工资产信息查询 PRD》，使业务、产品、研发和测试能够直接据此确认范围、实现页面并设计测试。

## 文档结构

1. 背景。
2. 权限。
3. 通用规则。
4. 页面字段及交互。
5. 校验。
6. 后续操作、业务结果及补充说明。

删除“改造总结”和“暂无待确认规则”等过程性章节，规则只在所属章节完整定义一次。

## 内容原则

- 正文只写业务行为，不出现数据库字段、代码字段、SQL、接口和类名。
- 查询、页签、列表、按钮、详情、空状态和异常分别写清展示条件及结果。
- 保留已确认的员工范围、四页签关系、数据归属、默认排序、详情入口和历史单据处理规则。
- 对尚无业务依据的细节不编造；使用可执行的页面规则表达现有确认结果。

## 字段调整

### 耗材页签

列表只保留：耗材标签号、耗材说明、耗材状态、耗材责任人、关联主资产标签号、主资产资产说明。

耗材标签号进入耗材详情；关联主资产标签号只展示文本。关联主资产为空时，两个主资产字段均显示“-”。

### 合约号码页签

列表只保留：行号、合约号码、合约号码说明、合约号码状态、责任人、责任人公司、所在单据编号、单据申请人、单据类型、单据业务类型、单据审批环节、单据审批人。

责任人公司取责任人人员主数据中的当前财务公司，不使用合约号码台账中的使用公司替代。

## 范围

- 修改主 PRD。
- 同步三方比对记录和 CONTEXT。
- 不修改 React 原型、Mock、服务或测试代码。
