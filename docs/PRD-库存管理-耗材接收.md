# 库存管理 - 耗材接收 PRD

## 1. 背景

耗材接收用于处理采购到货后的低值耐用品及普通耗材接收业务。

用户根据采购 PO 查看待接收物资，维护本次实际接收数量并创建接收单。根据采购类型不同，接收完成后的处理方式不同：

| 采购类型 | 接收流程 |
|---|---|
| 低值耐用品 | PO → 创建接收单 → 逐件维护耗材标签号、SN、部件信息 → 接收确认 → 接收完成 → 自动生成采购接收入库草稿单 → 后续执行正式入库 |
| 耗材 | PO → 创建接收单 → 接收确认 → 接收完成并自动完成入库 → 自动生成已完成采购接收入库单 |

资产、服务器、网络设备及其备件不在本模块处理，由“资产接收”模块独立处理。

本次改造统一耗材接收的业务边界、状态、分批接收规则、低值耐用品逐件维护规则、普通耗材自动入库规则、页面字段及交互、校验和后续库存处理。

## 2. 改造总结

| 改造项 | 改造后规则 |
|---|---|
| 采购类型 | 固定为“低值耐用品 / 耗材” |
| 接收单状态 | 固定为“草稿 / 已完成” |
| 分批接收 | 支持分批接收；草稿接收单中的接收数量立即计入草稿占用 |
| 可接收数量 | `采购数量 - 已接收数量 - 草稿数量` |
| 物料、配置修改 | 修改后作为当前 PO 行后续未完成接收的默认值；不追溯修改历史已完成接收数据，不反写采购系统原始 PO |
| 板块、申请批次 | 修改后作为当前 PO 后续未完成接收的默认值；历史已完成接收数据不追溯修改 |
| 低值耐用品 | 按接收数量逐件拆分并维护耗材标签号、SN、部件等信息；接收完成后生成采购接收入库草稿单 |
| 普通耗材 | 不维护接收明细；接收确认后自动完成入库并生成已完成采购接收入库单 |
| 耗材仓 | 按公司唯一匹配耗材仓；无法唯一匹配时阻断接收确认 |
| 低值耐用品部件 | 部件数量 2～100，包含主件；子部件数量 = 部件数量 - 1 |
| SN“缺省” | “缺省”为合法 SN，视为已维护，不参与真实 SN 唯一性校验 |
| 制单人与接收人 | 创建草稿记录制单人、制单时间；接收确认成功后记录接收人、接收时间 |
| PO 状态 | 保留“待接收 / 已接收 / 已入库” |
| 删除草稿接收单 | 删除后释放该接收单占用的全部 PO 草稿数量 |
| 删除接收行 | 草稿状态允许删除，删除后释放该接收行对应草稿数量 |
| 低值耐用品正式入库 | 正式入库成功后增加目标耗材仓库存，生成对应耗材台账卡片，并更新 PO 入库状态 |
| 普通耗材自动入库 | 接收确认成功后立即增加目标耗材仓库存数量 |

## 3. 业务流程

### 3.1 低值耐用品

1. 用户进入耗材接收 PO 页面，系统根据剩余可接收数量计算本次接收数量。
2. 用户可编辑物料、配置、本次接收数量、部件等接收信息。
3. 用户勾选一个或多个 PO 行，点击【创建接收单】。
4. 系统生成草稿接收单，并立即占用相应 PO 草稿数量。
5. 用户进入接收单详情，点击【维护接收明细】。
6. 系统按照“每接收 1 件生成 1 条明细”逐件拆分。
7. 用户生成耗材标签号，并维护 SN、部件等信息。
8. 所有逐件明细满足接收条件后，用户点击【接收确认】。
9. 系统将接收单更新为“已完成”，并自动生成一张“采购接收”类型的草稿入库单。
10. 用户后续进入“库存管理 → 入库”检查入库数据并执行正式入库。
11. 正式入库成功后，系统增加目标耗材仓库存、生成对应耗材台账卡片，并更新 PO 入库状态。

### 3.2 普通耗材

1. 用户进入耗材接收 PO 页面，系统根据剩余可接收数量计算本次接收数量。
2. 用户可编辑物料、配置和本次接收数量。
3. 用户勾选一个或多个 PO 行，点击【创建接收单】。
4. 系统生成草稿接收单，并立即占用相应 PO 草稿数量。
5. 普通耗材不维护接收明细，用户在接收单详情直接点击【接收确认】。
6. 系统根据当前公司匹配唯一耗材仓。
7. 校验通过后，系统一次性完成接收和入库：接收单更新为“已完成”，生成已完成采购接收入库单，并立即增加目标耗材仓库存数量。
8. 系统根据本次实际接收及入库数量重新计算 PO 行和整张 PO 的状态。

普通耗材“接收确认 + 自动入库”属于一个完整业务动作，只允许全部成功或全部失败。

## 4. 通用规则

### 4.1 状态规则

#### 4.1.1 PO 状态

| 状态 | 说明 |
|---|---|
| 待接收 | 当前 PO 任一采购行仍存在未完成接收数量 |
| 已接收 | PO 所有采购行均已完成接收，但仍存在尚未正式完成入库的低值耐用品 |
| 已入库 | PO 对应采购数量均已完成入库 |

PO 状态按照整张 PO 的累计数量判断：

- 任一 PO 行仍存在未接收数量时，整张 PO 保持“待接收”。
- 所有采购行均已完成接收，但低值耐用品仍存在待执行入库的数据时，整张 PO 为“已接收”。
- 所有采购数量均完成入库后，整张 PO 为“已入库”。
- 普通耗材由于接收确认时同步完成入库，全量接收完成后可以直接从“待接收”进入“已入库”。
- 普通耗材部分接收后仍存在剩余未接收数量时，整张 PO 继续保持“待接收”。

#### 4.1.2 PO 行状态

| 状态 | 判断规则 |
|---|---|
| 待接收 | 当前 PO 行仍存在剩余未接收数量 |
| 已接收 | 当前 PO 行采购数量已经全部完成接收，但尚未全部正式入库 |
| 已入库 | 当前 PO 行对应采购数量已经全部完成入库 |

低值耐用品可以按照 `待接收 → 已接收 → 已入库` 流转。

普通耗材全量接收确认时同步完成入库，对应 PO 行可直接从“待接收”进入“已入库”。

#### 4.1.3 接收单状态

| 状态 | 说明 | 是否可修改 |
|---|---|---|
| 草稿 | 接收单已经创建，接收业务尚未完成 | Y |
| 已完成 | 已执行接收确认，接收流程结束 | N |

接收单固定按照 `草稿 → 已完成` 流转。

### 4.2 可接收数量

低值耐用品和普通耗材均支持分批接收。

单条 PO 行当前可接收数量：

`可接收数量 = 采购数量 - 已接收数量 - 草稿数量`

其中：

- 已接收数量：已经完成接收确认的数量。
- 草稿数量：已经被有效草稿接收单占用，但尚未完成接收确认的数量。

创建接收单后，本次接收数量立即计入草稿数量，其他接收单不可重复占用该部分数量。

以下操作释放草稿数量：

| 操作 | 数量处理 |
|---|---|
| 删除草稿接收单 | 释放整单占用的草稿数量 |
| 删除接收行 | 释放该接收行对应的草稿数量 |
| 删除低值耐用品逐件明细 | 来源接收行本次接收数量同步减少，并释放相同草稿数量 |

接收确认成功后，本次数量从“草稿数量”转入“已接收数量”。

### 4.3 接收数据快照

接收单保存本次实际接收时的数据快照。

接收单完成后，历史接收数据不得因为后续继续接收、PO 接收侧默认值调整或采购 PO 数据变化而发生变化。

### 4.4 物料和配置修改规则

用户在 PO 接收页面编辑接收信息时，可以重新选择物料并修改配置。

修改后的物料、配置作为当前 PO 行后续未完成接收的默认值使用：

| 数据范围 | 处理规则 |
|---|---|
| 后续新创建的接收行 | 使用修改后的物料、配置 |
| 尚未完成的后续接收数据 | 使用修改后的默认值 |
| 已完成接收行 | 保留接收完成时的历史快照，不修改 |
| 已完成低值耐用品明细 | 保留原数据，不修改 |
| 采购系统原始 PO | 不反写原始物料编码、物料名称或配置 |

### 4.5 板块和申请批次

板块为必填字段，申请批次为选填字段。

用户修改后立即作为当前 PO 后续未完成接收业务的默认值使用。

| 数据范围 | 处理规则 |
|---|---|
| 后续新创建接收行 | 使用最新值 |
| 尚未完成的后续接收数据 | 使用最新默认值 |
| 已完成接收行 | 保留历史值，不修改 |
| 已完成低值耐用品明细 | 保留历史值，不修改 |

板块和申请批次随接收单继续传递到后续入库单。

PO 状态为“已入库”时，不再存在后续接收业务，板块和申请批次均只读，采购明细不再提供创建新接收单的入口。

### 4.6 耗材仓匹配

低值耐用品和普通耗材均按照公司匹配耗材仓。

每个公司必须唯一匹配一个有效耗材仓。

| 匹配结果 | 处理 |
|---|---|
| 唯一匹配 | 正常继续接收确认 |
| 未匹配 | 阻断接收确认 |
| 匹配多个 | 阻断接收确认，要求检查耗材仓配置 |

未找到耗材仓时提示：`未找到当前公司对应的耗材仓库`。

匹配到多个耗材仓时提示：`当前公司匹配到多个耗材仓库，请检查耗材仓配置`。

低值耐用品匹配到的耗材仓写入后续采购接收入库草稿单；普通耗材匹配到的耗材仓作为本次自动完成入库的目标仓库。

### 4.7 低值耐用品部件规则

普通耗材不支持部件维护。

低值耐用品支持按套件方式维护部件：

| 规则 | 说明 |
|---|---|
| 是否部件 | 是 / 否 |
| 部件数量 | 是否部件=是时必填 |
| 数量范围 | 2～100，包含 2 和 100 |
| 数量含义 | 部件数量包含主件本身 |
| 子部件数量 | 部件数量 - 1 |
| 子部件默认名称 | 自动生成“部件1、部件2……”作为默认名称，允许修改 |
| 子部件标签号 | 主耗材标签号生成后，按“主耗材标签号-N”生成 |
| 部件 SN | 支持真实 SN 或“缺省” |

取消“是否部件”后，同时清空部件数量、部件说明，并禁用部件数量和部件说明维护入口。

### 4.8 SN 规则

SN 仅适用于低值耐用品。

| 类型 | 规则 |
|---|---|
| 真实 SN | 用户录入或扫码录入，需要进行唯一性校验 |
| 缺省 SN | 系统写入“缺省”，视为已完成维护，不参与真实 SN 唯一性校验 |

相同真实 SN 已被其他低值耐用品或资产使用时，不允许保存。

多个明细允许同时使用“缺省”。

真实 SN 在手工编辑保存、扫描写入和接收确认时均执行重复校验。

### 4.9 制单人与接收人

接收单区分草稿创建和接收完成两个业务时间点。

| 字段 | 记录时机 |
|---|---|
| 制单人 | 创建草稿接收单时记录当前操作人 |
| 制单时间 | 创建草稿接收单时记录当前时间 |
| 接收人 | 接收确认成功时记录当前操作人 |
| 接收时间 | 接收确认成功时记录当前时间 |

草稿状态下接收人、接收时间为空。

### 4.10 权限

耗材接收权限按照“公司 + 板块”控制。

具体页面可见范围、操作权限和无权限时页面表现暂留待补充。

## 5. 页面字段及交互

### 5.1 PO 列表

进入耗材接收后，展示当前用户权限范围内的采购 PO。

#### 5.1.1 查询条件

| 字段名称 | 交互方式 | 枚举值 / 数据来源 | 查询规则 |
|---|---|---|---|
| 公司 | 弹窗单选 | 财务公司 | 按所选公司查询 |
| 板块 | 弹窗单选 | 板块数据 | 按所选板块查询 |
| PO 单号 | 输入框 | - | 支持模糊匹配 |
| 供应商 | 弹窗单选 | 供应商数据 | 按所选供应商查询 |
| 接收状态 | 下拉单选 | 全部 / 待接收 / 已接收 / 已入库 | 单选 |
| 采购类型 | 下拉单选 | 低值耐用品 / 耗材 | 单选 |
| 推送日期 | 日期范围 | - | 按推送日期起止范围查询 |

点击【查询】后按照当前条件刷新列表。

点击【重置】清空全部查询条件并恢复全量结果。

#### 5.1.2 列表字段

| 字段名称 | 展示规则 |
|---|---|
| 行号 | 当前分页内连续序号 |
| PO 单号 | 蓝色链接，点击进入当前 PO 接收页面 |
| 接收状态 | 待接收 / 已接收 / 已入库 |
| PO 单名称 | 来源采购 PO |
| 公司 | 来源采购 PO |
| 板块 | 当前 PO 后续接收使用的板块；为空时显示“-” |
| 供应商 | 展示供应商名称 |
| 推送日期 | `yyyy-mm-dd` |
| 采购类型 | 低值耐用品 / 耗材 |
| 操作 | 固定展示【接收】【查看】 |

操作规则：

- 点击 PO 单号或【接收】进入 PO 接收页面。
- 点击【查看】进入该 PO 的接收单列表，并自动将当前 PO 单号带入查询条件后执行查询。
- 【接收】【查看】固定同时展示，不根据当前 PO 状态改变入口语义。

列表 Card 右上角展示当前查询结果数量：`共 X 条`。

分页默认每页 10 条，支持切换每页展示条数。

当前 PO 已存在接收单时，页面底部展示【查看接收单】，点击进入当前 PO 的接收单列表。

页面底部固定展示【返回】，点击返回 PO 列表。

### 5.9 删除低值耐用品明细

草稿状态允许删除逐件接收明细。

未选择时提示：`请先选择需要删除的接收明细`。

删除一条逐件明细后：

1. 删除当前明细。
2. 对应接收行“本次接收数量”同步减少 1。
3. 对应 PO 行草稿数量同步减少 1。
4. PO 可接收数量同步增加 1。
5. 明细行号重新连续编号。

如果某接收行的本次接收数量减少到 0，则该接收行从当前草稿接收单中移除。

删除完成后提示：`已删除所选接收明细并实时保存`。

### 5.10 生成耗材标签号

【生成标签号】仅在草稿状态且至少存在 1 条耗材标签号为空的明细时展示。

点击后只处理标签号为空的明细，已有标签号不得重新生成或覆盖。

标签号按照现有耗材标签生成规则生成，完成后立即保存。

存在子部件时，在主耗材标签号生成后同步生成子部件标签号：

`子部件标签号 = 主耗材标签号-N`

当所有明细均已有耗材标签号后，【生成标签号】自动隐藏，同时扫描输入框可用、【打印标签号】可展示。

成功后提示：`已为 X 条空白耗材标签号生成标签号并实时保存`。

### 5.11 SN 维护与扫描

低值耐用品可通过以下方式维护 SN：

| 方式 | 规则 |
|---|---|
| 单条编辑 | 录入真实 SN，也允许清空后重新维护 |
| 扫描 | 先扫描耗材标签号，再扫描对应真实 SN |
| 批量维护缺省 | 将当前 SN 为空的明细写入“缺省” |

已有真实 SN 不得被批量“缺省”覆盖。

【维护 SN 号】仅在草稿状态且至少存在 1 条 SN 为空的明细时展示。

执行后仅对空 SN 写入“缺省”；全部 SN 已维护后按钮自动隐藏。如果后续再次出现空 SN，按钮重新展示。

批量维护成功后提示：`已为 X 条空白 SN 号维护“缺省”并实时保存`。

扫描流程：

1. 第一次扫描内容视为耗材标签号，在当前接收单内定位明细。
2. 未找到时提示：`未找到对应标签号`。
3. 定位成功后等待扫描该明细 SN。
4. 第二次扫描内容视为真实 SN。
5. 校验通过后写入当前明细并立即保存。
6. 保存完成后重新等待下一条耗材标签号。

真实 SN 重复时统一提示：`SN 号：XXX 已存在！`。

### 5.12 单条低值耐用品明细编辑

草稿状态点击【编辑】打开明细维护弹窗；接收完成后同一入口改为【查看】，全部字段只读。

#### 5.12.2 部件信息

存在子部件时，以表格展示全部子部件；不存在子部件时展示“暂无部件信息”。

| 字段名称 | 交互方式 | 草稿是否可修改 | 规则 |

| 部件 SN | 输入框 | Y | 支持真实 SN 或“缺省” |

同一主件内部多个部件的真实 SN 不允许重复；主件 SN 与部件 SN 之间也不允许重复；“缺省”不参与重复校验。

点击【保存】后修改立即保存，并提示：`明细信息已保存`。

点击【取消】关闭弹窗，不保存本次未确认修改。

已完成接收单进入弹窗时仅允许查看，不展示保存操作。

### 5.13 标签打印

低值耐用品草稿、已完成状态均允许打印标签。

只有当前接收单存在逐件明细且待打印明细均已有耗材标签号时展示【打印标签号】。

存在子部件时，同时打印对应子部件标签；子标签数量 = 部件数量 - 1。

打印批次生成成功后提示：`标签打印批次已生成`。

### 5.14 低值耐用品接收确认

草稿状态点击【接收确认】后，系统校验当前接收单全部逐件明细。

接收确认条件：

- 当前接收单至少存在一条有效接收行。
- 已按全部接收数量生成逐件明细。
- 所有耗材标签号均已维护。
- 所有 SN 均已维护。
- 所有非“缺省”真实 SN 均通过唯一性校验。
- 当前公司能够唯一匹配耗材仓。

存在耗材标签号或 SN 未维护时提示：`有未维护的标签号或 SN 号，请先维护接收明细。`

真实 SN 重复时提示：`接收确认失败：SN号 XXX 已存在`。

接收确认成功后：

| 数据对象 | 处理结果 |
|---|---|
| 接收单 | 状态由“草稿”更新为“已完成” |
| 接收人 / 接收时间 | 记录当前操作人和当前时间 |
| 接收行 | 固化为本次接收快照 |
| 逐件接收明细 | 固化，不再允许修改 |
| PO 草稿数量 | 扣减本次草稿占用数量 |
| PO 已接收数量 | 增加本次实际接收数量 |
| PO 行状态 | 根据累计接收、入库数量重新判断 |
| PO 状态 | 根据整张 PO 累计接收、入库数量重新判断 |
| 入库单 | 自动生成一张“采购接收”类型的草稿入库单，并进入“库存管理 → 入库”列表 |
| 目标仓库 | 当前公司匹配的耗材仓 |
| 后续数据 | 板块、申请批次、耗材标签号、SN、部件等接收结果传递到入库单 |

接收完成和入库草稿单创建属于一个完整业务动作，不得出现接收单已经完成但入库草稿单未生成的半完成状态。

成功提示：`接收确认成功，已生成草稿入库单 XXX`。

接收确认完成后尚未正式入库。

### 5.15 普通耗材接收确认

普通耗材不维护接收明细。

草稿接收单确认接收行数据无误后，直接点击【接收确认】。

接收确认条件：

- 当前接收单至少存在一条有效接收行。
- 各接收行本次接收数量必须大于 0。
- 当前公司能够唯一匹配有效耗材仓。
- 当前草稿占用数量有效，不存在重复接收。

校验通过后，系统一次性完成：

| 数据对象 | 处理结果 |
|---|---|
| 接收单 | 状态由“草稿”更新为“已完成” |
| 接收人 / 接收时间 | 记录当前操作人和当前时间 |
| 接收行 | 固化为本次接收快照 |
| PO 草稿数量 | 扣减本次草稿占用数量 |
| PO 已接收数量 | 增加本次实际接收数量 |
| 入库单 | 自动生成“采购接收”类型的已完成入库单，并进入“库存管理 → 入库”列表 |
| 入库仓库 | 当前公司匹配的耗材仓 |
| 入库数量 | 本次实际接收数量 |
| 库存数量 | 目标耗材仓库存立即增加本次实际入库数量 |
| PO 行状态 | 根据剩余未接收数量及累计入库数量重新判断 |
| PO 状态 | 根据整张 PO 剩余未接收数量及累计入库数量重新判断 |

接收和自动入库必须保持事务一致性：

- 全部成功后才提交本次业务结果。
- 任一步骤失败时，接收单继续保持草稿。
- 不增加已接收数量。
- 不增加库存数量。
- 不生成半完成入库单。
- 用户修正问题后可以重新执行接收确认。

成功提示：`接收确认成功，已完成入库并生成入库单 XXX`。

## 6. 校验与异常处理

本章节汇总会阻断用户操作的关键校验。字段普通展示、默认值、必填和只读规则以对应页面字段表为准。

| 操作 | 校验规则 | 校验失败处理 |
|---|---|---|
| 编辑接收数量 | 必须为正整数 | 不保存，弹窗保持打开 |
| 编辑接收数量 | 不得大于当前可接收数量 | 不保存，提示“接收数量不能超过可接收数量！” |
| 维护低值耐用品部件数量 | 是否部件=是时必须填写 | 不允许保存 |
| 维护低值耐用品部件数量 | 仅允许 2～100 的整数 | 不允许保存，提示“请输入 2～100 之间的整数！” |
| 维护部件说明 | 必须先填写合法部件数量 | 不进入维护，提示“请填写部件数量！” |
| 创建接收单 | 至少选择一条 PO 行 | 不创建，提示“请选择要接收的物料！” |
| 创建接收单 | 板块必填 | 不创建，提示“请选择板块！” |
| 创建接收单 | 所选行至少存在一条有效可接收数据 | 不创建，提示“所选物资当前没有可接收数量” |
| 删除草稿接收单 | 必须选择草稿接收单 | 不执行 |
| 删除接收行 | 仅草稿状态允许且必须先选择 | 不执行 |
| 删除低值耐用品明细 | 仅草稿状态允许且必须先选择 | 不执行 |
| 扫描维护 | 耗材标签号必须已经全部生成 | 扫描框禁用 |
| 保存真实 SN | 不得与其他低值耐用品或资产真实 SN 重复 | 不保存，提示“SN 号：XXX 已存在！” |
| 低值耐用品接收确认 | 所有逐件明细均存在耗材标签号和 SN | 不执行，接收单保持草稿 |
| 低值耐用品接收确认 | 当前公司必须唯一匹配耗材仓 | 不执行，接收单保持草稿 |
| 低值耐用品接收确认 | 接收完成和入库草稿创建必须全部成功 | 任一步失败整体不提交 |
| 普通耗材接收确认 | 每条接收行本次接收数量必须大于 0 | 不执行，接收单保持草稿 |
| 普通耗材接收确认 | 当前公司必须唯一匹配耗材仓 | 不执行，接收单保持草稿 |
| 普通耗材自动入库 | 接收、入库、库存增加必须全部成功 | 任一步失败整体不提交 |

接收确认失败时，当前草稿接收单以及已经维护的有效数据继续保留，用户修正问题后重新执行接收确认。

## 7. 后续操作及补充说明

### 7.1 低值耐用品接收完成后的处理

低值耐用品接收确认成功后，只代表接收业务已经完成，此时尚未正式入库。

系统自动生成一张“采购接收”类型的草稿入库单，用户后续进入“库存管理 → 入库”检查并执行正式入库。

正式入库成功后：

- 入库单更新为已完成。
- 增加目标耗材仓库存。
- 生成对应低值耐用品耗材台账卡片。
- 根据累计入库数量更新 PO 行和整张 PO 的状态。

### 7.2 普通耗材接收完成后的处理

普通耗材接收确认成功时同步完成入库，不需要用户再次进入入库模块执行。

系统自动生成已完成采购接收入库单，并立即增加目标耗材仓库存数量。

### 7.3 已完成接收单

接收单进入“已完成”后：

| 数据 / 操作 | 规则 |
|---|---|
| 接收单头 | 只读 |
| 接收行 | 只读 |
| 低值耐用品耗材标签号 | 不可修改 |
| 低值耐用品 SN | 不可修改 |
| 低值耐用品部件数据 | 不可修改 |
| 低值耐用品备注 | 不可修改 |
| 低值耐用品接收明细 | 允许只读查看 |
| 普通耗材接收明细 | 不存在 |
| 低值耐用品标签打印 | 允许补打 |
| 接收单打印 | 允许 |

### 7.4 本版暂不展开

权限按照“公司 + 板块”控制，但具体权限矩阵暂不在本版定义，由后续补充。
