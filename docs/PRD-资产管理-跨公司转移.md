# 资产管理 - 跨公司转移 PRD

## 1. 背景

跨公司转移用于处理资产发生财务公司或财务板块调整的调账场景。新公司可以与原公司相同，但新公司 + 新板块的组合不能与原公司 + 原板块完全一致。

跨公司转移审批完成后仅进入待报废池，不直接修改正式资产台账。后续由对应账面报废发起人发起账面报废，账面报废完成后正式执行公司、板块、成本中心、责任人、位置和仓库等调账结果。

本业务仅处理资产，不处理耗材和合约号码。

本 PRD 覆盖：

- 机房资产；
- 非机房软件资产；
- 非机房办公设备资产。

## 2. 权限

### 2.1 发起权限

跨公司转移根据资产类型走不同发起路径。

| 资产范围 | 发起人 |
|---|---|
| 机房资产 | 当前资产责任人 |
| 非机房软件资产 | 当前资产责任人 |
| 非机房办公设备资产 | ES 专员角色（当前角色用户为孙志强） |

### 2.2 资产分类判定

非机房资产按资产大类代码区分：

| 业务分类 | 资产大类 |
|---|---|
| 办公设备 | 11.PC / 12.NOTEBOOK / 13.OFFICE EQUIPMENT / 16.FURNITURE / 18.VEHICLE / 19.BUILDINGS / 20.Investment Properties / 21.LEASEHOLD IMPROVEMENT / 22.Park lot land use rights |
| 软件 | 17.SOFTWARE |

机房资产按资产大类判定：14.SERVER、15.NET EQUIPMENT。除机房资产和软件外，本轮涉及的其余资产大类统一按“办公设备”流程处理。

当前跨公司转移仅覆盖以上已明确资产范围。

### 2.3 数据权限

- 资产责任人可发起本人名下机房资产和软件的跨公司转移，只能选择本人当前负责的可转移资产。
- ES 专员角色拥有全公司办公设备的跨公司转移权限，当前角色用户为孙志强；可选择全公司的可转移办公设备，不限于本人名下。
- ES 专员角色用户发起机房资产或软件跨公司转移时，仍按资产责任人规则，只能选择本人名下资产。
- 查询、查看、保存、提交和审批时均重新校验当前用户权限。
- 已正式报废资产不可发起跨公司转移。
- 耗材、合约号码不进入跨公司转移资产选择范围。

### 2.4 公司范围

跨公司转移支持所有有效财务公司。

同一申请单的原公司唯一。新公司允许与原公司相同，也允许同一申请单的不同明细设置不同新公司；是否允许提交按“新公司 + 新板块”与“原公司 + 原板块”的组合判断。

当转入方或转出方涉及以下公司时，触发特殊财务同步规则：

- 新媒体上海分公司；
- 新媒体广州分公司。

特殊处理规则见 3.6。

## 3. 通用规则

板块值统一采用“板块编码.板块名称”格式，例如“17.Corporate”。

### 3.1 单据状态

跨公司转移单据状态：

- 草稿；
- 审批中；
- 已驳回；
- 已完成。

规则：

- 新建单据默认为草稿；
- 草稿可编辑、保存和删除；
- 提交成功后进入审批中；
- 审批驳回后状态变为已驳回，退回发起人，允许修改后重新提交；
- 最后一个审批节点通过并成功进入待报废池后，单据状态变为已完成；
- 已完成单据只读。

### 3.2 单据与审批路径

同一张跨公司转移单只允许包含同一资产范围的数据，且所有资产必须属于同一原公司。

同一单据不限制资产大类必须一致；同一单据可包含多个新公司，每条明细分别记录目标公司和目标板块。

资产范围分为：

1. 机房资产；
2. 软件；
3. 办公设备。

机房资产与软件虽然审批链相同，也不得混在同一张申请单中。不同资产范围必须拆单。

### 3.3 资产选择

资产必须来自正式资产台账。

可选资产必须同时满足：

- 当前用户有发起权限；
- 资产未正式报废；
- 同一资产不存在未结束的跨公司转移或资产报废申请；
- 资产属于当前单据对应的资产范围。

资产选择后，以下原资产信息按同一资产卡片自动带出且只读：

- 资产标签号；
- 资产序列号；
- 资产大类；
- 资产小类；
- 资产说明；
- 原公司；
- 原板块；
- 当前责任人；
- 当前成本中心；
- 当前仓库；
- City；
- Building；
- Floor；
- 资产状态。

公司与资产允许两种录入顺序：

- 先选公司：资产选择和 Excel 导入仅允许加入该原公司的资产；
- 先加资产：不要求先选公司。确认所选资产时校验原公司，全部属于同一原公司后自动将该公司带入单头；如果一次选择或与已有明细合并后出现多个原公司，整批拦截，不加入部分资产。

已有资产明细时，单头公司只读；删除全部资产明细后可重新选择公司。

### 3.4 录入方式

跨公司转移明细支持手工选择资产和 Excel 导入。

Excel 模板字段包括：资产标签号、新公司编码、新板块、新成本中心编码、City、Building、Floor、调账后仓库编码。资产标签号为资产匹配键；责任人为系统只读结果，不提供 Excel 维护。

导入时逐行校验资产是否存在、当前用户是否有权限、资产范围是否与单据一致、资产是否已在当前明细或模板中重复、资产是否处于未结束的跨公司转移或资产报废申请，以及目标字段是否有效。

未提前选择公司时，同一批导入资产也必须属于同一原公司，全部通过后自动带出单头公司。任一行失败时整批不加入明细，并返回包含行号和失败原因的错误结果；全部通过后一次性加入明细。

### 3.5 附件

支持上传附件。

规则：

- 文件格式不限；
- 单文件大小不得超过 20MB；
- 超过 20MB 时阻止上传并提示；
- 已上传附件支持查看文件名和删除。

### 3.6 上海 / 广州新媒体特殊财务同步

所有有效财务公司均可进行跨公司转移。

如果转入方或转出方为“新媒体上海分公司”或“新媒体广州分公司”，系统自动识别为特殊分公司调账，不要求用户手工维护“调拨”标签。

跨公司转移的转入方或转出方涉及新媒体上海分公司、新媒体广州分公司时，执行特殊财务同步：

1. 系统给原资产号增加后缀后，将调账单据推送财务系统；
2. 财务系统完成同步变更后，目标分公司按原资产号手工新增资产；
3. 该场景不按普通调账规则直接把原资产卡修改为目标公司的资产卡；
4. 非上海、广州新媒体相关转移按普通调账规则处理。

资产系统生成财务推送资产号：在原资产号后追加三位顺序后缀，从 `-001` 开始；同一原资产号的后缀已占用时依次使用 `-002`、`-003`，取当前未使用的最小顺序号。

### 3.7 调账后仓库与责任人

调账后仓库根据每条资产最终选择的“新公司 + City”进行匹配。

- 新公司和 City 均已确定且只匹配到 1 个有效资产仓库时，自动带出调账后仓库；
- 新公司或 City 变化后，重新执行匹配；
- 调账后仓库允许用户在符合当前新公司和 City 条件的有效资产仓库中调整；
- 无法唯一匹配时不自动猜测仓库，由用户选择有效仓库后再提交。

责任人不提供编辑入口。

- 资产状态为在库时，按最终调账后仓库自动带出该仓库对应的虚拟库管员；
- 调账后仓库变化后，责任人同步重新带出；
- 非在库状态资产不因跨公司转移手工修改责任人，保持原责任人；
- 在库资产无法匹配有效虚拟库管员时不得提交。

### 3.8 调账资产处置规则

跨公司转移属于调账业务。调账资产完成后续账面报废后不进入实物处置流程，也不生成资产处置单。

系统不维护“是否处置”字段；是否进入实物处置由资产大类、报废类型和报废方式直接判断。

- 同一资产不存在未结束的跨公司转移或资产报废申请。

### 4.3 审批流程

#### 4.3.1 机房资产 / 软件

流程：

> 发起人提交 → 责任人 5 级及以上直属领导审批 → 责任人 7 级及以上直属领导审批 → 进入待报废池 → 流程结束

规则：

- 发起人为资产责任人；
- 5 级及以上直属领导按发起人组织关系自动匹配；
- 7 级及以上直属领导按发起人组织关系自动匹配；
- 如果 5 级及以上直属领导与 7 级及以上直属领导为同一人，第二个重复审批节点自动跳过，只审批一次；
- 任一审批节点驳回，单据退回发起人；
- 发起人修改后可重新提交；
- 软件资产流程结束后，向对应账面报废发起人发送服务号通知；机房资产流程结束后，向申请人及实际审批人发送服务号通知。

#### 4.3.2 非机房办公设备

流程：

> ES 专员提交 → ES 主管确认 → 进入待报废池 → 流程结束

规则：

- 发起人为 ES 专员；
- 审批节点为 ES 主管确认；
- ES 主管驳回后，单据退回发起人；
- 发起人修改后可重新提交；
- 流程结束后，向对应账面报废发起人发送服务号通知。

#### 4.3.3 审批页面

审批页面中：

- 审批页展示申请单号、申请人、申请日期、公司、办公区、联系电话、邮箱、部门、备注和附件；
- 基本信息只读；从提交后进入或从详情进入时，申请人信息字段和值保持一致，审批页单头不展示单据状态；
- 提交进入审批后，在资产明细对应字段内同时展示原值和调账后目标值；字段未变化时只展示当前值，不另设“资产信息变更”区块；
- 责任人字段使用“责任人”，不再使用“新责任人”；
- 审批信息字段为审批环节、申请人/审批人、审批状态、审批时间、审批意见；包含发起人提交记录、历史审批动作和当前待审批环节；
- 审批意见在审批信息区内展示，最多 400 字；同意时可不填，驳回时必填；
- 当前审批人可执行【同意】【驳回】；审批页和详情页均提供【返回】；
- 附件支持查看；
- 页面不展示当前审批节点字段；当前节点只用于判断审批人和可执行的操作。

审批页面与已提交单号详情页展示相同的申请人信息、资产明细和审批信息，且均提供返回操作；详情页不展示单据状态。仅审批页面显示审批意见和当前节点的同意、驳回操作；详情页保持只读。审批页面不提供编辑申请操作；草稿和已驳回单据从只读详情页进入编辑。

## 5. 校验

### 5.1 保存

保存草稿时：

- 允许资产明细暂未完整；
- 已填写字段必须满足基础数据合法性；
- 首次保存后生成申请单号。

### 5.2 提交

提交时必须校验：

1. 至少存在 1 条资产明细；
2. 单据内所有资产属于同一资产范围、同一原公司且走同一审批路径；
3. 当前发起人符合对应资产范围的发起权限；
4. 资产未正式报废；
5. 资产不存在未结束的跨公司转移或资产报废申请；
6. 每条资产的“新公司 + 新板块”组合不得与“原公司 + 原板块”组合完全相同；公司未变化但板块发生变化时允许提交；
7. 新公司、新板块、新成本中心、责任人、City、Building、Floor、调账后仓库均已确定；
8. 在库资产的责任人必须与最终调账后仓库对应的虚拟库管员一致；
9. Building 必须属于所选 City；
10. 调账后仓库必须为符合最终新公司和 City 条件的有效资产仓库；
11. 附件单文件不得超过 20MB；
12. Excel 导入数据全部通过同一套资产和字段校验。

任一资产校验失败时，不允许部分提交。

### 5.3 重复提交

提交处理中：

- 禁止重复提交；
- 同一申请不得重复创建审批实例。

## 6. 后续操作 / 业务结果 / 补充说明

### 6.1 流程完成后的业务结果

最后一个审批节点通过后，系统按以下顺序处理：

1. 将单据内资产写入待报废池；在库资产状态更新为“在库-待报废”，员工名下资产状态保持不变；
2. 待报废池来源业务标记为“跨公司转移”，后续账面报废明细的资产报废方式固定为“调账”；
3. 保存本次调账目标信息，包括新公司、新板块、新成本中心、责任人、City、Building、Floor、调账后仓库和备注；
4. 跨公司转移单据状态更新为已完成；
5. 软件和办公设备向对应账面报废发起人发送服务号通知，提醒发起后续账面报废；机房资产向申请人及实际审批人发送服务号通知；
6. 后续进入账面报废流程。

跨公司转移审批完成时不直接修改正式资产台账中的公司、板块、成本中心、责任人、位置和仓库。

正式台账变更由后续账面报废执行环节完成。

涉及新媒体上海分公司或新媒体广州分公司的资产，在后续财务同步时按 3.6 节执行特殊资产号处理。

### 6.3 服务号通知

跨公司转移流程结束后发送服务号通知：软件和办公设备通知对应账面报废发起人；机房资产通知申请人及实际审批人。自动跳过的重复审批节点不作为实际审批人重复通知。

通知时点：跨公司转移最后一个审批节点通过、资产成功进入待报废池后。

通知内容：

- 申请单号；
- 跨公司转移流程已完成；
- 资产数量；
- 后续状态：已进入待报废池，等待后续账面报废。

点击通知进入跨公司转移单据详情。
