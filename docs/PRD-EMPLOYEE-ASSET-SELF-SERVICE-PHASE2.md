# 员工自助新版——ES 配给与汇总采购 PRD

## 1. 范围

本阶段承接业务审批完成后的资产申请，仅处理资产，不处理耗材。

覆盖：

- ES 配给待办生成
- 配给单拆分
- 库存领用
- 统一采购
- 取消申请
- 待汇总池
- ES 汇总采购
- 原申请单进度回写

旧版资产配给与统一申请汇总页面继续保留。

## 2. ES 配给

### 2.1 入口

- 顶部导航：个人工作台 → 员工自助新版-资产配给
- 路由：`/employee-self-service/asset-allocation`

### 2.2 配给人规则

| 申请人公司 | 配给处理人 |
|---|---|
| 集团媒体 | 王英、何文，或签 |
| 视频 | 杨芊、何文，或签 |
| 焦点 | 孙志强、何文，或签 |
| 上海媒体分公司 | 卢铭华 |
| 广州媒体分公司 | 李琴宝 |
| 未匹配 | 杨芊 |

### 2.3 配给单生成

业务审批全部完成后，根据申请行和申请数量拆分配给单。

示例：

```text
申请行：ThinkPad T14，数量 3
→ 生成 3 张独立配给单
```

每张配给单只处理一件资产，保存源申请单号、源申请行和申请人信息。

### 2.4 列表字段

- 配给单号
- 申请单号
- 申请人
- 资产说明
- 处理人
- 匹配状态
- 任务状态
- 操作

支持按配给单号、申请单号、申请人和状态模糊查询。

### 2.5 申请人名下资产

配给人员可查看申请人名下状态为以下范围的资产：

- 在用-使用中
- 在用-借用中且未超期

页面展示名下资产总数和未超期借用资产数。

### 2.6 匹配状态

| 处理方式 | 规则 | 提交结果 |
|---|---|---|
| 库存领用 | 必须选择匹配资产 | 进入资产领用流程 |
| 统一采购 | 不选择匹配资产 | 实时进入待汇总池 |
| 取消申请 | ES 意见必填 | 回写原申请行已取消 |

同一申请单允许不同配给单选择不同处理方式。

### 2.7 库存资产范围

匹配资产需同时满足：

1. 与申请资产物料一致。
2. 在申请人公司板块领取权限范围内。
3. 资产状态为在库-待处理、在库-新增或在库-再利用。
4. 资产标记为空。
5. 是否锁定为否。

库存领用提交时未选择资产则拦截。

### 2.8 配给提交

必填：

- 匹配状态
- 库存领用时的匹配资产
- ES 审核意见

提交后：

- 配给单状态改为已配给。
- 库存领用进入待领用。
- 统一采购进入待汇总。
- 原申请单根据全部配给单结果显示待领用、待汇总或领用/待汇总。

## 3. 汇总采购

### 3.1 入口

- 顶部导航：个人工作台 → 员工自助新版-汇总采购
- 路由：`/employee-self-service/purchase-summary`

### 3.2 待汇总池

统一采购配给单提交后实时进入待汇总池。

系统按以下维度合并：

- 公司
- 申请人所在一级部门

同一部门尚未提交的统一采购数据进入同一张待汇总单。

### 3.3 列表字段

- 汇总单号
- 公司
- 部门
- 汇总数量
- 预计费用
- 状态
- 操作

支持按部门查询。

### 3.4 汇总单字段

#### ES 汇总说明

系统自动生成，支持修改：

> XXXX年XX月部门XXXX统一申请已统计完毕，申请采购资产共计X件，预计采购费用XXX.XX元。ES已核实员工申请需求，目前无可用库存进行调配。

#### 项目用途与说明

提交采购时必填。

#### 部门申请明细

- 申请人
- 申请单号
- 资产说明
- 配置
- 数量
- 预计费用
- 是否超标
- ES 建议
- 处理方式
- 驳回原因

处理方式默认为采购，可改为驳回。选择驳回时驳回原因必填。

#### 附件信息

支持上传多个附件，演示阶段仅保存文件列表信息。

### 3.5 部门现资产参考使用量

按申请资产类别展示：

- 现使用量
- 现人均用量 = 现使用量 / 部门在职正式人数
- 申请采购量
- 采购后人均用量 =（现使用量 + 申请采购量）/ 部门在职正式人数
- 公司人均用量

### 3.6 提交采购

提交时校验：

1. 项目用途与说明已填写。
2. 所有驳回行均填写驳回原因。

提交后：

- 汇总单状态改为已汇总。
- 采购行进入采购系统和 PR 系统流程。
- 原申请单当前节点改为采购与 PR 系统流程。
- 若同一申请同时存在库存领用支线，显示资产领用/采购与 PR 系统流程。

## 4. 状态流转

```text
业务审批完成
→ 待配给
→ ES 配给
   ├─ 库存领用 → 待领用
   ├─ 统一采购 → 待汇总 → 已汇总 → 采购与 PR 系统流程
   └─ 取消申请 → 已取消
```

## 5. 演示数据

演示阶段使用统一 mock 和 localStorage：

- 申请单数据
- 配给单数据
- 待汇总池数据
- 可用库存资产
- 申请人名下资产
- 部门资产参考使用量

页面不得直接操作 localStorage，统一通过 service 读写。

## 6. 验收标准

1. 旧配给和旧汇总页面可正常访问。
2. 业务审批完成后可生成配给待办。
3. 申请数量为 3 时生成 3 张配给单。
4. 配给人根据申请人公司自动匹配。
5. 可查看申请人名下资产。
6. 库存领用未选择资产时不能提交。
7. 库存领用提交后原申请进入待领用。
8. 统一采购提交后数据进入待汇总池。
9. 同一申请可同时存在库存领用和统一采购。
10. 汇总页面可编辑说明、项目用途、处理方式和附件。
11. 驳回行未填写原因时不能提交。
12. 提交采购后原申请进入采购与 PR 系统流程。
13. 刷新浏览器后配给和汇总数据仍存在。
