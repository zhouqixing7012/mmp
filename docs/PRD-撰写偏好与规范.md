# 我的 PRD 偏好与写作规范

## 一、总原则

| 项目 | 要求 |
| --- | --- |
| 写作口径 | 用业务语言写清楚角色、动作、条件、校验和结果，让业务、产品、测试能直接理解。 |
| 细节要求 | 保留字段、状态、校验、异常、保存节点、单据或批次关系、业务结果等细节；不能为了精简而把不同业务链路合并。 |
| 目标导向 | PRD 写未来要实现的最终业务规则，不因现有页面、旧系统、代码或模板已存在，就默认它是目标需求。 |
| 范围控制 | 只写本次范围内的模块、角色、数据和动作；范围外内容只说明边界，不擅自补充需求。 |
| 未确认内容 | 统一放入“当前尚未定义”，不猜测、不以“沿用现状”“研发确认”“视情况处理”替代规则。 |
| 技术分离 | 主 PRD 不写数据库、接口、代码、实现方式、打印驱动、视觉位置等内容；技术证据和现状差异放入单独的对比或测试材料。 |

## 二、默认章节结构

除非业务确实不适用，PRD 默认按以下六章顺序编写，不单列验收标准。本文后续标题是写作要求的分类，不是要求在 PRD 中照搬的章节：

1. 背景
2. 权限
3. 通用规则
4. 页面字段及交互
5. 校验
6. 后续操作 / 业务结果 / 补充说明

新内容优先归入原有章节，非必要不新增章节：

| 内容 | 归入章节 |
| --- | --- |
| 范围、范围外事项 | 背景 |
| 数据范围 | 权限 |
| 状态、草稿、正式执行 | 通用规则或后续操作 / 业务结果 / 补充说明 |
| 是否可编辑、是否必填、组件规则 | 页面字段及交互 |
| 当前尚未定义 | 后续操作 / 业务结果 / 补充说明 |

## 三、背景与范围

范围与范围外事项写在 PRD 的“背景”章内，不另开顶层章节。

| 项目 | 要求 |
| --- | --- |
| 背景 | 说明要解决的业务问题、使用场景和目标，不复述技术背景。 |
| 本次范围 | 写清包含哪些页面、角色、数据对象和操作。 |
| 不在本次范围 | 明确列出不包含的页面、角色、数据范围和后续动作，防止实施时扩大范围。 |
| 跨模块依赖 | 只写本模块依赖对方提供的业务前提，不替对方模块定义需求。 |
| 现状差异 | 目标规则与现有系统不一致时，分别写“目标规则”和“现状差异”，不能混写。 |

## 四、权限与数据范围

数据范围写在 PRD 的“权限”章内，不另开顶层章节。

权限不只写“能不能操作”，还要写“能看到和处理哪些数据”。

| 角色 | 可查看的数据范围 | 可执行操作 | 操作限制 | 无权限结果 |
| --- | --- | --- | --- | --- |

需要明确：

- 数据范围是本人、所属部门、指定组织还是全部数据。
- 无权查看、无权编辑、记录失效、记录已被他人处理时，页面和操作分别如何表现。
- 每项关键操作都要有对应角色和限制条件。
- 涉及敏感信息时，要说明谁可查看、谁可编辑、是否允许导出或下载。

## 五、通用规则

只写真正跨页面生效的业务规则，例如数据归属、状态限制、主从关系、重复处理原则、编号规则和历史保留原则。

页面专属规则必须写在对应页面中，不能放进笼统的“页面固定口径”或视觉规范中。

## 六、页面字段、交互与组件

这些内容写在 PRD 的“页面字段及交互”章内，不另开顶层章节。

页面规则优先使用下表：

| 页面字段 / 组件 / 操作 | 业务含义 | 是否展示 | 是否可编辑 | 是否必填 | 数据来源或默认值 | 交互规则 | 校验 | 成功结果 | 异常结果 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

字段必须写清：

- 是否展示、是否可编辑、是否必填，并按新增、编辑、草稿、提交后、作废后等不同状态分别说明。
- 字段类型、格式、长度、最大或最小值、是否允许为空、是否允许清空、是否唯一。
- 数据来源、默认值、修改后的影响范围和保存后的业务用途。
- 字段修改、清空或联动变化后，哪些字段自动带出、重算、清空、隐藏、变为必填、重新校验或不可编辑。
- 只读字段不可编辑的业务原因；可编辑字段在什么条件下允许修改。
- 涉及敏感信息时的查看、编辑和导出限制。

交互组件必须写清：

| 组件类型 | 需要说明的规则 |
| --- | --- |
| 下拉框 / 单选 / 多选 | 可选范围、默认值、是否支持搜索、多选、手工输入、清空、禁用及联动规则。 |
| 日期 / 时间 | 默认值、可选范围、先后关系、是否允许历史日期或未来日期、过期后的处理。 |
| 选择器 | 入口、查询条件、结果列表字段、选择限制、选择后回填字段、已选项如何移除、无数据和加载失败时的表现。 |
| 上传附件 | 是否允许上传、文件类型、数量、大小、下载和删除权限、上传失败后的处理。 |
| 表格明细 | 是否允许新增、复制、编辑、删除、排序、批量操作；明细数量限制、汇总规则、删除后的影响。 |
| 按钮 | 显示条件、可点击条件、二次确认要求、点击结果、失败提示和用户下一步可做的事。 |

页面生命周期还要写清：

- 首次进入、加载中、无数据、查询失败、保存成功后的刷新方式。
- 返回列表时，查询条件、筛选、分页、页大小和排序是否保留。
- 离开未保存页面、重复点击、重复提交时的业务结果。
- 编辑从只读详情进入时，保存、取消、关闭后回到哪里。

## 七、查询、列表与明细

查询、列表与明细规则写在 PRD 的“页面字段及交互”章内，不另开顶层章节。

查询和列表必须写清：

| 项目 | 要求 |
| --- | --- |
| 查询条件 | 支持哪些字段查询、默认查询范围、模糊或精确匹配规则。 |
| 查询结果 | 显示哪些列、默认排序、是否可排序、分页规则和空结果表现。 |
| 重置规则 | 重置后恢复哪些默认值，是否重新查询。 |
| 批量操作 | 可选择哪些记录、最多可选多少条、哪些状态下禁止处理、执行结果是什么。 |
| 导出 | 导出范围、字段、权限、是否包含草稿或已作废数据。 |
| 明细关系 | 主记录与明细如何新增、编辑、删除、复制；汇总值如何计算；已产生后续业务结果的明细能否修改或删除。 |

## 八、流程、草稿、状态与正式执行

状态、草稿、正式执行及流程规则按内容写在 PRD 的“通用规则”或“后续操作 / 业务结果 / 补充说明”章内，不另开顶层章节。

所有关键流程优先按“入口—校验—草稿—正式执行—结果/异常”说明。

| 阶段 | 需要说明的内容 |
| --- | --- |
| 入口 | 谁从哪里发起，适用于哪些记录或数据条件。 |
| 草稿 | 草稿保存哪些内容、是否可编辑或删除、草稿是否影响其他业务。 |
| 正式执行 | 何时提交、确认、审批、接收、打印或执行；正式执行前必须满足什么条件。 |
| 状态变化 | 每个状态的含义、进入条件、允许动作、禁止动作、退出条件和关联对象变化。 |
| 撤回 / 作废 / 恢复 | 是否允许、由谁操作、适用条件、对已产生数据和历史的影响。 |
| 完成结果 | 新增、更新、失效或关联了哪些业务对象；用户可在哪里查看结果。 |

如涉及审批或协作，还需写清提交、审批、退回、转交、催办等环节的角色、意见、时限、退回后的可修改范围和最终结果。

## 九、校验与提示

每条校验都要写清：

| 校验项 | 触发时机 | 校验对象 | 判断条件 | 处理方式 | 用户提示 | 修正方式 |
| --- | --- | --- | --- | --- | --- | --- |

校验应覆盖适用范围内的必填、格式、长度、唯一性、关联关系、额度、时间、状态、权限、数据完整性和重复处理。

特别要求：

- 写清是阻止操作、仅提示，还是需要二次确认。
- 涉及“重复”“超额”“不允许”等判断时，必须写清判断范围。
- 成功、失败、警告、确认提示都要说明触发条件和用户接下来能做什么，不能只写“系统提示”。

## 十、后续操作、业务结果与可追溯性

每个关键动作都要明确业务结果，不能只写“操作成功”。

| 操作 | 新增或更新的业务对象 | 状态变化 | 后续可执行动作 | 查询或历史位置 | 是否通知相关人员 |
| --- | --- | --- | --- | --- | --- |

按功能适用写清：

- 是否生成单据、明细、批次、历史、打印记录或其他业务对象。
- 主记录、明细、批次、历史、任务等对象是否独立，不能因名称相近而混为一谈。
- 是否支持附件、打印、补打、导出、作废及对应前置条件。
- 是否触发待办、站内信或其他通知；通知谁、何时触发、通知后是否影响业务。
- 修改已有流程时，原有记录、已完成单据、历史数据和进行中草稿是否受影响。
- 统计或报表数据的计算范围、时间口径、状态口径，以及是否包含草稿、已作废或历史数据。

## 十一、当前尚未定义

未确认内容统一集中写在 PRD 的“后续操作 / 业务结果 / 补充说明”章内，不另开顶层章节，并按下表表达：

| 待确认问题 | 涉及页面或操作 | 未确认时无法确定的业务结果 | 需要确认的角色或事项 |
| --- | --- | --- | --- |

要求：

- 原需求、原型、现有实现、业务访谈结论冲突时，不自行选择其中一个。
- 页面只能证明展示和交互；静态代码只能证明实现路径；配置、模板和生产数据只能证明各自范围内的事实。
- 没有足够证据时，保留为“当前尚未定义”。
- 确认后必须回填到对应业务章节，不能长期只留在待确认清单中。

## 十二、完稿检查清单

| 检查项 | 完成标准 |
| --- | --- |
| 范围 | 已写明本次范围和不在范围内的内容。 |
| 角色与数据 | 每个关键操作的权限和数据范围明确。 |
| 字段 | 已写清展示、编辑、必填、来源、格式、联动和保存影响。 |
| 组件 | 选择器、下拉、日期、附件、明细表、按钮等规则完整。 |
| 流程 | 入口、校验、草稿、正式执行、结果和异常完整。 |
| 状态 | 每个状态的含义、进入条件和可执行动作明确。 |
| 业务对象 | 主记录、明细、批次、历史、任务等未混淆。 |
| 结果 | 每个关键操作都写清新增、更新、状态变化和查询位置。 |
| 未定义事项 | 未确认内容集中记录，未自行补规则。 |
| 语言 | 无数据库、接口、代码、实现方式和纯视觉细节。 |
