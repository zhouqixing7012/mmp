# 库存管理 - 转移 PRD

> 本文以当前 PC 原型 `src/pages/inventoryManagement/TransferPage.js` 为页面基线，并结合原版《库存管理—转移》业务规则及本轮确认结果收口。
> 已明确的新规则优先于原版旧交互；原版仍有效但无需前端模拟的规则继续作为正式研发规则保留。

## 1. 背景

“转移”用于管理资产责任人变更及转移后相关资产信息调整。

转移完成后，可根据业务规则同步调整：

- 资产责任人；
- 部门；
- 成本中心；
- City / Building / Floor / Room；
- 用途；
- 业务线；
- 项目；
- 使用说明；
- 特殊 NO 资产的 SN、NO 地点、服务、子服务等信息。

后台手工创建的转移单与员工前台申请后形成的核心转移单，统一进入库存管理 → 转移进行管理。

## 2. 改造总结

本次按当前资产系统交互规范对转移业务进行重构，确认规则如下：

1. 转移入口统一为“库存管理 → 转移”。
2. 后台手工创建转移单时，制单人取当前登录人。
3. 新建页首次进入转移单号显示“自动生成”。
4. 用户首次点击【添加物资】时，如单据尚未保存，系统先自动保存单头并生成正式 AT 转移单号，再打开添加转移物资弹窗。
5. 单据首次保存生成 AT 单号后，公司锁定为只读。
6. 单据尚无物资明细时备注可编辑；存在任一物资明细后备注锁定为只读。
7. 转入人选择后自动带出转入板块、转入部门、转入成本中心；转入成本中心不允许人工修改。
8. SERVER 资产转移时成本中心不随转入人变化，继续保留资产原成本中心。
9. 资产状态仅展示当前资产状态，不允许在转移明细中修改。
10. 转移数量自动取当前资产数量，不提供用户输入。
11. 删除转移单时只删除草稿；已完成单据保留。混合选择时允许草稿部分成功删除。
12. 特殊 NO 资产继续保留 NO 资产变更信息区域及对应更新规则。
13. 普通业务弹窗继续遵循项目统一最大 960px 规范，超宽内容内部横向滚动。

## 3. 通用规则

### 3.1 单据来源

核心转移单存在两类来源：

| 来源 | 说明 | 申请单号 | 制单人 |
|---|---|---|---|
| 后台手工创建 | 后台人员直接创建转移单 | 无上游申请时为空 | 当前登录人 |
| 员工前台发起 | 员工转移申请形成核心转移单 | 记录上游申请单号 | 系统管理员 |

员工前台形成核心转移单后，必须进入本功能统一管理。后台列表保留核心转移单号和上游申请单号，用于从执行单据追溯至员工原始申请。员工前台来源单据与后台手工单共用后续核心转移执行规则。

### 3.2 单据状态

状态：

- 草稿
- 已完成

状态流转：

`草稿 → 转移确认 → 已完成`

当前 PC 原型仍需继续补齐【转移确认】和已完成详情完整闭环；本 PRD保留正式业务规则。

### 3.3 单号

- 核心转移单号前缀：`AT-`。
- 新建页首次进入显示“自动生成”。
- 点击【添加物资】时，如果尚未生成单号，系统先自动保存单头并生成正式 AT 单号。
- 手工点击【保存草稿】时，如果尚未生成单号，同样完成首次保存和单号生成。
- 转移单号生成后不可修改。

### 3.4 公司

- 公司必填。
- 新建后台手工转移单默认取**当前登录人的公司**。
- 尚未生成转移单号时，用户允许重新选择公司。
- 一旦转移单号生成，公司变为只读，不允许再修改。
- 正式资产选择范围必须受当前转移单公司约束。

### 3.5 制单人和制单时间

后台手工创建：

- 制单人 = 当前登录人；
- 制单时间 = 当前系统时间；
- 均不可人工修改。

### 3.6 备注

- 尚无转移物资明细：可编辑；
- 已存在任一转移物资明细：只读；
- 已保存的备注随单据保留。

### 3.7 资产锁

正式系统规则：

- 资产加入转移草稿后建立业务锁；
- 删除转移明细时释放该资产锁；
- 删除草稿转移单时释放该单全部资产锁；
- 转移成功后释放本次转移锁；
- 已被其他业务锁定的资产不得重复加入。

原型可简化锁实现，但候选范围、删除结果和正式提交结果必须符合该规则。

1. 资产财务公司 = 当前转移单公司；
2. 资产状态符合转移可选范围；
3. 资产未被其他业务锁定；
4. 资产满足当前人员/板块/资产领取权限相关限制；
5. 同一转移单内不得重复加入同一资产标签号。

### 4.3.5 转入人联动

选择转入人后：

- 自动带出转入板块；
- 自动带出转入部门；
- 自动带出转入成本中心；
- 三个联动字段不允许用户人工修改。

正式候选人员仍需按公司、板块、成本中心、办公区及资产领取权限规则过滤。

同一张后台手工转移单中的多条资产必须保持：

- **转出人一致**；
- **转入人一致**。

新增或编辑任一明细后如导致上述任一人员不一致，不允许保存该明细。

### 4.3.6 SERVER 成本中心特殊规则

SERVER 资产保留特殊规则：

- 责任人仍可按正常流程变更；
- 转入板块、转入部门仍根据转入人带出；
- **成本中心不随转入人变化**；
- 转入成本中心继续使用该 SERVER 资产转移前的原成本中心。

SERVER 识别应使用正式资产分类编码/字典，不允许前端通过展示文案猜测。

### 4.3.7 特殊 NO 资产变更信息

满足正式 NO 特殊资产条件时，额外展示【NO 资产变更信息】：

| 原信息 | 新信息 |
|---|---|
| 原 SN 号 | 新 SN 号 |
| 原 NO 地点 | 新 NO 地点 |
| 原服务 | 新服务 |
| 原子服务 | 新子服务 |

规则：

- 原值从资产当前数据读取，只读；
- 新值按业务规则维护；
- 正式命中范围以既有 NO 资产分类/内部标识为准；
- 不允许为了原型展示自行创造新的资产范围；
- 普通资产不展示该区域。

### 4.3.8 转移数量

转移数量规则调整为：

- 系统自动取当前资产数量；
- 页面不提供转移数量输入框；
- 用户不能修改；
- 正式保存前仍需校验当前资产数量有效；
- 如资产数量发生并发变化，以正式提交时最新资产数据校验为准。

### 4.3.9 添加操作

新增物资弹窗：

- 【添加并继续】
- 【添加并关闭】
- 【取消】

【添加并继续】保存当前行后保持弹窗，继续添加下一件。

【添加并关闭】保存当前行并关闭。

编辑已有明细时保存后更新当前行，不新增重复行。

## 5. 校验

## 5.1 页面即时校验

| 场景 | 规则 |
|---|---|
| 公司为空 | 不允许保存或添加物资 |
| 未选择资产 | 不允许保存明细 |
| 转入人为空 | 不允许保存明细 |
| 转入成本中心为空 | 不允许保存明细 |
| City为空 | 不允许保存明细 |
| Building为空 | 不允许保存明细 |
| Floor为空 | 不允许保存明细 |
| 用途为空 | 不允许保存明细 |
| 转移日期为空 | 不允许保存明细 |
| 重复资产标签号 | 同一转移单不得重复 |
| 已完成单据删除 | 不删除，保留原单 |

### 5.2 转移确认前重新校验

点击【转移确认】后不得仅信任草稿保存时数据，应重新读取最新数据校验：

1. 转移单至少存在一条有效明细；
2. 同一单据不存在重复资产标签号；
3. 资产仍处于允许正式转移的状态；
4. 转入人存在且有效；
5. 业务锁仍属于当前转移流程；
6. Book Type 满足现有转移规则；
7. 成本科目信息能够正常生成；
8. SERVER 成本中心规则正确执行；
9. 特殊 NO 资产所需新信息满足对应校验。

任一校验失败时，本次转移确认整体不生效。

### 5.3 公司 / 板块不一致

保留原业务规则。

保存转移明细时比较待转移资产当前公司、板块与转入人相关公司、板块信息。

如存在不一致，不直接阻断，弹出确认：

`待转移物资公司或板块同转入人信息不一致，是否确认？`

- 用户取消：不保存本次明细；
- 用户确认：允许继续保存；
- 该二次确认不替代正式的公司板块领取资产权限校验。

### 5.4 人员一致性和权限

正式系统继续保留：

- 转入人有效性；
- 公司 / 板块 / 成本中心 / 办公区限制；
- 公司板块领取资产权限；
- 多资产转移时转出人、转入人均保持一致。

具体正式权限由后端服务控制，前端候选集仅展示有权限结果。

## 6. 后续操作或补充说明

### 6.1 转移确认后的资产变化

转移成功后按最终明细更新：

- 资产责任人；
- 部门；
- 成本中心；
- City；
- Building；
- Floor；
- Room；
- 用途；
- 使用说明；
- 业务线；
- 项目；
- 相关成本核算信息。

SERVER 成本中心按特殊规则不随责任人变化。

特殊 NO 资产如维护了新值，同步更新：

- SN；
- NO Location；
- Service；
- Sub Service。

### 6.2 快照和事务

正式转移前保存转移前资产快照。

转移完成后：

- 单据状态更新为已完成；
- 保存最后修改人、最后修改时间；
- 生成资产转移事务 / 操作历史；
- 关联转移单号；
- 有申请单号时同时记录关联申请单号；
- 转移成功后释放资产锁。

### 6.3 已完成查看

已完成单据为只读查看态，不展示：

- 添加物资；
- 删除物资；
- 保存草稿；
- 转移确认；
- 编辑明细。

保留：

- 转移单基本信息；
- 转移物资明细；
- 单条明细查看；
- 打印；
- 导出。

### 6.4 Excel

正式转移功能继续保留：

- 【模板下载】
- 【Excel导入】

已从原版业务资料确认的规则：

1. Excel 导入用于**批量新增转移单物资明细**；
2. 执行导入前必须已选择公司；
3. 导入请求/上下文需要携带：
   - 转移单 ID；
   - 单据类型；
   - 单据状态；
   - 公司；
   - 业务类型；
4. 历史上传类型为 `uploadType=transfer`；

### 6.5 权限

数据权限及操作权限继续沿系统权限模型控制。

- 用户只能操作有权限公司/板块下的数据；

- 转入人候选范围受公司板块领取资产权限控制；
- 服务端正式提交再次校验权限，不依赖页面候选结果。
