# 库存管理 - 转移 PRD

> 本文以当前 PC 原型 `src/pages/inventoryManagement/TransferPage.js` 为现状基线进行整理。
> 用户提供的原版《库存管理—转移》作为历史业务规则来源，用于后续三方比对，不将原型尚未实现的历史规则直接写成本版“已实现”能力。

## 1. 背景

“转移”用于管理资产责任人及相关使用信息的转移单据。

当前 PC 原型位于库存管理下，提供：

- 转移单列表查询；
- 后台手工创建转移单；
- 维护转移物资及转入信息；
- 保存草稿；
- 草稿转移物资编辑；
- Excel 导入入口。

当前原型的状态范围为：

- 草稿；
- 已完成。

当前原型尚未形成“草稿 → 转移确认 → 已完成”的完整执行闭环，已完成单据主要作为列表演示数据存在。

## 2. 改造总结

当前原型相较历史页面已按项目统一 B 端规范进行了页面重构，核心变化如下：

1. 转移入口统一按“库存管理 → 转移”组织。
2. 列表查询使用统一三列 QueryBar。
3. 列表主按钮统一为【创建】，不再重复写“创建转移单”。
4. 转移单创建页使用“转移单信息 + 转移物资”两块 Card。
5. 页面级操作统一放在底部居中。
6. 添加转移物资采用弹窗方式，区分“选择物资 / 物资信息 / 转移单信息”三个区域。
7. 资产、人员、公司、City、Building、业务线、项目等选择类字段统一使用选择弹窗。
8. 只读业务信息直接以文本展示，不使用 disabled Input 模拟只读。
9. 业务弹窗受项目统一 960px 最大宽度限制，超宽内容通过内部横向滚动查看。
10. 当前原型仅实现草稿创建与明细维护，不将历史 PRD 中尚未落入原型的资产锁、转移确认、事务生成、特殊 NO 信息等能力视为已实现。

## 3. 通用规则

### 3.1 单据状态

当前原型状态字典：

| 状态 | 当前原型含义 |
|---|---|
| 草稿 | 后台手工创建并保存后的转移单 |
| 已完成 | 历史演示数据中的完成状态 |

当前创建页仅能生成草稿。

### 3.2 单据来源

当前列表同时存在：

- 有申请单号的历史转移单；
- 后台手工创建、申请单号为空的转移单。

当前创建入口只支持后台手工创建。

### 3.3 编号

- 转移单号前缀为 `AT-`。
- 新建页首次进入显示“自动生成”。
- 当前原型点击【保存草稿】后生成正式转移单号。
- 申请单号后台手工创建时为空。

### 3.4 公司

- 新建页默认公司为 `101.新时代`。
- 公司通过选择弹窗维护。
- 保存草稿时公司必填。
- 当前原型未限制“添加物资前必须先保存转移单”。

### 3.5 物资范围

当前原型仅提供资产型转移演示数据。

添加物资时通过资产选择弹窗选定一件资产，选定后读取该资产当前信息并维护转入信息。

当前原型未实现以下后台过滤逻辑：

- 按公司动态过滤资产；
- 按资产状态集合过滤；
- 按业务锁过滤；
- 按责任人权限过滤。

以上内容如需保留，应在三方比对确认后补入原型或明确为服务端规则。

### 3.6 弹窗规范

- 普通选择场景统一使用 `SelectModal`。
- 查询区使用三列 QueryBar。
- 表格使用 Ant Design Table。
- 业务 Modal 最大宽度为 960px。
- 内容超过弹窗宽度时使用弹窗内部或表格横向滚动。
- 新增转移物资弹窗提供【添加并继续】【添加并关闭】【取消】。
- 编辑已有转移物资时复用同一弹窗结构。

【删除】当前原型规则：

2. 选择后弹出二次确认；
3. 确认后直接删除所有已选择单据；
4. 删除成功提示 `已删除所选转移单`。

当前原型尚未限制“仅草稿可删除”，也未实现混合状态部分删除规则。

### 4.2.4 保存草稿

点击【保存草稿】：

1. 校验公司不能为空；
2. 生成 `AT-YYYYMMDDNNNN` 格式转移单号；
3. 单据状态保存为“草稿”；
4. 申请单号为空；
5. 制单人为 `admin-系统管理员`；
6. 物资数量按所有明细的转移数量合计；
7. 列表查询所需的转移原因、转出部门、转出地点、板块、转入部门、转入地点从第一条明细形成演示数据；
8. 保存成功返回列表。

当前原型每次创建都按“新增一张草稿”处理，不支持从列表重新进入草稿编辑页。

### 4.3.5 添加并继续 / 添加并关闭

点击保存明细时：

1. 必须先选择资产；
2. 校验必填字段；
3. 转移数量自动取资产数量或可用数量；
4. 转出人自动取资产当前责任人；
5. 转出成本中心自动取资产当前成本中心；
6. 保存当前行。

【添加并继续】：

- 保存当前物资；
- 弹窗保持打开；
- 清空当前资产；
- 清空转移原因、使用说明；
- 继续添加下一件。

【添加并关闭】：

- 保存当前物资；
- 关闭弹窗。

【取消】：

- 不保存当前修改并关闭。

### 4.3.6 编辑已有明细

点击列表【编辑】重新打开同一弹窗。

保存后更新当前行，不新增新行。

当前原型未限制编辑时替换资产，也未实现删除当前明细。

## 5.2 当前原型尚未实现的历史校验

以下规则存在于原版业务文档，但当前原型未实现，因此本版不将其描述为“当前已实现”：

- 资产状态可选范围 3 / 6 / 7 / 8；
- 转移确认时资产状态必须为 6；
- 资产未锁定才能添加；
- 添加明细后锁定资产；
- 删除明细 / 删除草稿后解锁资产；
- 同一转移单资产标签号重复校验；
- 转入人有效性校验；
- 转入人公司 / 板块 / 成本中心 / 办公区 / 资产领取权限校验；
- 多资产转入人、转出人一致性校验；
- 可用数量与转移数量校验；
- 公司 / 板块不一致二次确认；
- Book Type 校验；
- 成本科目生成校验；
- 特殊 SERVER 成本中心规则；
- 特殊 NO 资产规则；
- Excel 原子导入及失败行回传。

这些规则进入三方比对后再决定“补原型 / 保留为服务端规则 / 废弃”。

### 6.2 三方比对原则

后续三方比对固定以：

1. 原版 PRD：历史业务规则；
2. 当前原型：当前用户可见交互与演示逻辑；
3. 本 PRD：当前原型的文档化结果；

进行逐项核对。

处理结论只使用以下四类：

- **原型应补**：原版规则仍有效，但原型缺失；
- **PRD应跟原型**：原型已确认改造，原版规则过时；
- **仅后端规则**：无需在原型模拟，但正式研发仍必须实现；
- **待确认**：原版与原型存在真实业务冲突，不能自行裁决。
