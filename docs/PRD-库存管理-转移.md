# 库存管理 - 转移 PRD

> 本文以当前 PC 原型 `src/pages/inventoryManagement/TransferPage.js` 为页面基线，并结合原版《库存管理—转移》业务规则及本轮确认结果收口。
> 已明确的新规则优先于原版旧交互；原版仍有效但无需前端模拟的规则继续作为正式研发规则保留。

## 1. 背景

“转移”用于管理资产责任人变更及转移后相关资产信息调整。

转移完成后，可根据业务规则同步调整：

- 资产责任人；
- 部门；
- 成本中心；
- City / Building / Floor / Room；
- 用途；
- 业务线；
- 项目；
- 使用说明；
- 特殊 NO 资产的 SN、NO 地点、服务、子服务等信息。

后台手工创建的转移单与员工前台申请后形成的核心转移单，统一进入库存管理 → 转移进行管理。

## 2. 改造总结

本次按当前资产系统交互规范对转移业务进行重构，确认规则如下：

1. 转移入口统一为“库存管理 → 转移”。
2. 后台手工创建转移单时，制单人取当前登录人。
3. 新建页首次进入转移单号显示“自动生成”。
4. 用户首次点击【添加物资】时，如单据尚未保存，系统先自动保存单头并生成正式 AT 转移单号，再打开添加转移物资弹窗。
5. 编辑页“公司”业务含义明确为**财务公司**；当前原型使用 `114.新媒体` 作为默认 Mock。生成 AT 单号本身不锁定财务公司，只有实际存在至少一条转移物资明细后才锁定为只读。
6. 单据尚无物资明细时备注可编辑；存在任一物资明细后备注锁定为只读。
7. 转入人选择后自动带出转入板块、转入部门、转入成本中心；转入成本中心不允许人工修改。
8. SERVER 资产转移时成本中心不随转入人变化，继续保留资产原成本中心。
9. 资产状态仅展示当前资产状态，不允许在转移明细中修改。
10. 转移数量自动取当前资产数量，不提供用户输入。
11. 删除转移单时只删除草稿；已完成单据保留。混合选择时允许草稿部分成功删除。
12. 特殊 NO 资产继续保留 NO 资产变更信息区域及对应更新规则。
13. 普通业务弹窗使用项目统一最大 960px 规范；本页“添加转移物资”使用三列详情布局，表单区不增加横向滚动。

## 3. 通用规则

### 3.1 单据来源

核心转移单存在两类来源：

| 来源 | 说明 | 申请单号 | 制单人 |
|---|---|---|---|
| 后台手工创建 | 后台人员直接创建转移单 | 无上游申请时为空 | 当前登录人 |
| 员工前台发起 | 员工转移申请形成核心转移单 | 记录上游申请单号 | 申请人 |

员工前台形成核心转移单后，必须进入本功能统一管理。后台列表保留核心转移单号和上游申请单号，用于从执行单据追溯至员工原始申请。员工前台来源单据与后台手工单共用后续核心转移执行规则。

### 3.2 单据状态

状态：

- 草稿
- 已完成

状态流转：

`草稿 → 转移确认 → 已完成`

当前 PC 原型已实现草稿保存、草稿重新编辑、【转移确认】二次确认、已完成只读查看的完整可见闭环。正式资产台账更新、事务写入等仍由后端实现。

### 3.3 单号

- 核心转移单号前缀：`AT-`。
- 新建页首次进入显示“自动生成”。
- 点击【添加物资】时，如果尚未生成单号，系统先自动保存单头并生成正式 AT 单号。
- 手工点击【保存草稿】时，如果尚未生成单号，同样完成首次保存和单号生成。
- 转移单号生成后不可修改。

### 3.4 财务公司

- 编辑页“公司”统一指**财务公司**。
- 财务公司必填。
- 当前原型默认 Mock 为 `114.新媒体`。
- 尚未存在转移物资明细时，财务公司始终允许重新选择；即使已经因点击【添加物资】自动保存并生成 AT 单号，只要最终还没有物资明细，财务公司仍可修改。
- 一旦存在至少一条转移物资明细，财务公司变为只读。
- 正式资产选择范围必须受当前转移单财务公司约束。

### 3.5 制单人和制单时间

后台手工创建：

- 制单人 = 当前登录人；
- 制单时间 = 当前系统时间；
- 均不可人工修改。

员工前台申请形成转移单：

- 制单人 = 申请人；
- 制单时间 = 核心转移单生成时间；
- 申请单号继续记录员工原始申请单号。

### 3.6 备注

- 尚无转移物资明细：可编辑；
- 已存在任一转移物资明细：只读；
- 已保存的备注随单据保留。

### 3.7 资产锁

正式系统规则：

- 资产加入转移草稿后建立业务锁；
- 删除转移明细时释放该资产锁；
- 删除草稿转移单时释放该单全部资产锁；
- 转移成功后释放本次转移锁；
- 已被其他业务锁定的资产不得重复加入。

当前原型使用“草稿明细派生占用”模拟本业务锁：

- 资产加入任一草稿后，其他草稿不再展示该资产；
- 删除草稿明细后立即释放；
- 删除草稿单后全部释放；
- 转移确认完成后不再进入草稿占用集合，视为释放。

正式系统仍必须使用服务端持久化业务锁，不能仅依赖前端集合。

### 4.1.2 列表字段

除“选择 / 行号”外，列表所有业务字段均支持点击表头排序：

- 转移单号；
- 申请单号；
- 单据状态；
- 公司；
- 制单日期；
- 制单人；
- 物资数量。

转移单号入口规则：

- 列表不展示“操作”列；
- 草稿：点击转移单号进入草稿编辑页；
- 已完成：点击转移单号进入只读详情页；
- 转移单号是单据编辑 / 查看唯一入口；
- 列表行号按当前分页连续编号。

### 4.1.3 列表操作

提供：

- 【创建】
- 【删除】

删除规则：

1. 未选择数据时提示先选择；
2. 仅草稿允许删除；
3. 已完成单据始终保留；
4. 混合选择草稿 + 已完成时：
   - 删除其中草稿；
   - 已完成保留；
   - 操作结束后明确反馈删除数量和保留数量；
5. 删除草稿时同步删除单头、明细并释放该单产生的资产锁。

## 4.2 创建 / 编辑转移单

### 4.2.1 单据信息

| 字段 | 交互 | 必填 | 规则 |
|---|---|---:|---|
| 转移单号 | 只读 | - | 未保存显示“自动生成”；首次保存后显示 AT 单号 |
| 单据类型 | 只读 | - | 固定“转移单” |
| 单据状态 | 只读 | - | 新建/编辑草稿显示“草稿” |
| 财务公司 | 选择 / 只读 | Y | 原型默认 `114.新媒体`；存在转移物资明细前可选，存在明细后只读 |
| 制单人 | 只读 | - | 后台手工创建取当前登录人；员工前台来源取申请人 |
| 制单时间 | 只读 | - | 系统时间 |
| 备注 | TextArea / 只读 | N | 无明细可编辑；存在明细后只读 |

### 4.2.2 添加物资前自动保存

用户点击【添加物资】：

1. 校验财务公司已选择；
2. 若当前尚未生成转移单号：
   - 自动保存单头；
   - 生成 AT 转移单号；
   - 状态置为草稿；
   - 保存当前财务公司、制单人、制单时间、备注；
3. 自动保存成功后再打开【添加转移物资】弹窗；
4. 仅生成 AT 单号但最终没有新增任何转移物资时，财务公司仍保持可编辑；
5. 第一条转移物资保存成功后，财务公司锁定为只读；
6. 自动保存失败时不得打开添加物资弹窗。

### 4.2.3 转移物资列表

业务字段固定为：

| 行号 | 资产标签号 | 物资说明 | 物资总类 | 物资大类.小类 | 转移数量 | 转出人 | 转出成本中心 | 转入人 | 转入成本中心 | 转入城市 | 转入建筑物 |
|---|---|---|---|---|---:|---|---|---|---|---|---|

规则：

- 上述 12 个字段为业务明细字段；
- 表格最右侧额外固定【操作】列，并冻结在右侧；
- 【操作】列每行提供【编辑】【删除】；
- 转移数量为系统值，不提供列表内编辑；
- 删除明细后释放当前草稿对该资产的占用。

Card 操作：

- 【添加物资】
- 【模板下载】
- 【Excel导入】

当前原型已提供【模板下载】【Excel导入】入口；模板列、逐行校验、整批失败回传和上传后暂时锁定按 6.5 执行。

### 4.2.4 页面级操作

草稿页：

- 【保存草稿】
- 【转移确认】
- 【返回】

【转移确认】展示条件：

- 已生成正式 AT 转移单号；
- 当前仍为草稿；
- 至少存在 1 条转移物资。

点击后先执行确认前校验，再弹出二次确认；确认成功后单据状态更新为“已完成”，页面返回列表。

## 4.3 添加转移物资

“添加转移物资”使用三列详情布局 Modal：

- 最大宽度 960px；
- 视口不足时仍受视口宽度约束；
- 三列 DetailGrid 不设置额外最小宽度；
- 表单内容区不使用横向滚动；
- “选择转移资产”结果表字段较多时，在选择表格内部使用横向滚动。

### 4.3.1 资产选择范围

正式候选必须满足：

1. 资产财务公司 = 当前转移单公司；
2. 资产状态符合转移可选范围；
3. 资产未被其他业务锁定；
4. 资产满足当前人员/板块/资产领取权限相关限制；
5. 同一转移单内不得重复加入同一资产标签号。

当前原型已按当前转移单公司过滤真实 Mock 资产源，并过滤明确锁定资产及其他草稿已占用资产。正式状态码 3 / 6 / 7 / 8、跨业务锁和权限仍需服务端再次校验。

### 4.3.2 转移资产选择

“资产标签号”和“SN号”不再作为两个独立选择入口，合并为一个【转移资产】选择字段。

点击【转移资产】打开“选择转移资产”弹窗。添加转移物资 Modal 与资产选择 SelectModal 使用同级结构：打开资产选择时暂时隐藏添加弹窗，关闭或确认选择后恢复添加弹窗，禁止将选择弹窗嵌套在带 destroyOnHidden 的父 Modal 内。

查询条件固定为：

- 标签号；
- SN号；
- 板块；
- 资产说明。

查询结果固定字段：

| 字段 | 说明 |

| 标签号 | 资产标签号 |
| SN号 | 资产序列号 |
| 公司 | 财务公司 |
| 板块 | 当前资产板块 |
| 资产大类 | 当前资产大类 |
| 资产小类 | 当前资产小类 |
| 资产说明 | 资产说明 |
| 品牌 | 品牌 |
| 数量 | 当前资产数量 |

| 成本中心 | 当前成本中心 |

选定资产后读取资产当前主数据和转移前快照。当前原型复用库存业务公共资产 Mock 数据源，避免移库与转移针对同一标签号维护两份不同属性。

选择资产后，转移单信息中的【用途】默认取该资产卡片当前用途；该值只是默认值，不锁定，用户仍可从用途字典重新选择。

### 4.3.5 转入人选择及联动

点击【转入人】打开“选择转入人”弹窗。

查询条件固定为：

- 工号；
- 姓名。

当前原型的人员候选由公共库存资产 Mock 中已有资产责任人信息生成，避免为转移单独编造另一套人员组织 / 办公区数据。

选择转入人后自动带出：

- 转入板块；
- 转入部门；
- 转入成本中心；
- City；
- Building；
- Floor；
- Room；
- 业务线；
- 项目。

字段编辑规则：

- 转入板块、转入部门、转入成本中心继续保持只读；
- City、Building、Floor、Room、业务线、项目先按转入人默认值带出，之后仍按各字段原交互规则允许调整；
- SERVER 资产的转入成本中心仍执行 4.3.6 特殊规则，不随转入人覆盖。

正式候选人员仍需按公司、板块、成本中心、办公区及资产领取权限规则过滤。

同一张后台手工转移单中的多条资产必须保持：

- **转出人一致**；
- **转入人一致**。

新增或编辑任一明细后如导致上述任一人员不一致，不允许保存该明细。

### 4.3.6 SERVER 成本中心特殊规则

SERVER 资产保留特殊规则：

- 责任人仍可按正常流程变更；
- 转入板块、转入部门仍根据转入人带出；
- **成本中心不随转入人变化**；
- 转入成本中心继续使用该 SERVER 资产转移前的原成本中心。

SERVER 识别应使用正式资产分类编码/字典，不允许前端通过展示文案猜测。

### 4.3.7 特殊 NO 资产变更信息

满足正式 NO 特殊资产条件时，额外展示【NO 资产变更信息】：

| 原信息 | 新信息 |
|---|---|
| 原 SN 号 | 新 SN 号 |
| 原 NO 地点 | 新 NO 地点 |
| 原服务 | 新服务 |
| 原子服务 | 新子服务 |

规则：

- 原值从资产当前数据读取，只读；
- 新值按业务规则维护；
- 正式命中范围以既有 NO 资产分类/内部标识为准；
- 不允许为了原型展示自行创造新的资产范围；
- 普通资产不展示该区域。

### 4.3.8 转移数量

转移数量规则调整为：

- 系统自动取当前资产数量；
- 页面不提供转移数量输入框；
- 用户不能修改；
- 正式保存前仍需校验当前资产数量有效；
- 如资产数量发生并发变化，以正式提交时最新资产数据校验为准。

### 4.3.9 添加操作

新增物资弹窗：

- 【添加并继续】
- 【添加并关闭】
- 【取消】

【添加并继续】保存当前行后保持弹窗，继续添加下一件。

【添加并关闭】保存当前行并关闭。

编辑已有明细时保存后更新当前行，不新增重复行。

## 5. 校验

## 5.1 页面即时校验

| 场景 | 规则 |
|---|---|
| 财务公司为空 | 不允许保存或添加物资 |
| 未选择资产 | 不允许保存明细 |
| 转入人为空 | 不允许保存明细 |
| 转入成本中心为空 | 不允许保存明细 |
| City为空 | 不允许保存明细 |
| Building为空 | 不允许保存明细 |
| Floor为空 | 不允许保存明细 |
| 用途为空 | 不允许保存明细 |
| 转移日期为空 | 不允许保存明细 |
| 重复资产标签号 | 同一转移单不得重复 |
| 已完成单据删除 | 不删除，保留原单 |

### 5.2 转移确认前重新校验

点击【转移确认】后不得仅信任草稿保存时数据，应重新读取最新数据校验。当前原型会再次检查单据明细、重复资产、人员一致性、转移日期和可见锁状态；正式服务端仍需完成以下完整校验：

1. 转移单至少存在一条有效明细；
2. 同一单据不存在重复资产标签号；
3. 资产仍处于允许正式转移的状态；
4. 转入人存在且有效；
5. 业务锁仍属于当前转移流程；
6. Book Type 满足现有转移规则；
7. 成本科目信息能够正常生成；
8. SERVER 成本中心规则正确执行；
9. 特殊 NO 资产所需新信息满足对应校验。

任一校验失败时，本次转移确认整体不生效。

### 5.3 公司 / 板块不一致

保留原业务规则。

保存转移明细时比较待转移资产当前公司、板块与转入人相关公司、板块信息。

如存在不一致，不直接阻断，弹出确认：

`待转移物资公司或板块同转入人信息不一致，是否确认？`

- 用户取消：不保存本次明细；
- 用户确认：允许继续保存；
- 该二次确认不替代正式的公司板块领取资产权限校验。

### 5.4 人员一致性和权限

正式系统继续保留：

- 转入人有效性；
- 公司 / 板块 / 成本中心 / 办公区限制；
- 公司板块领取资产权限；
- 多资产转移时转出人、转入人均保持一致。

具体正式权限由后端服务控制，前端候选集仅展示有权限结果。

## 6. 后续操作或补充说明

### 6.1 转移确认后的资产变化

转移成功后按最终明细更新：

- 资产责任人；
- 部门；
- 成本中心；
- City；
- Building；
- Floor；
- Room；
- 用途；
- 使用说明；
- 业务线；
- 项目；
- 相关成本核算信息。

SERVER 成本中心按特殊规则不随责任人变化。

特殊 NO 资产如维护了新值，同步更新：

- SN；
- NO Location；
- Service；
- Sub Service。

当前原型在已完成详情中展示最终转入信息和转移前快照，用于验证结果态；不直接修改资产维护模块的正式数据源。

### 6.2 快照和事务

正式转移前保存转移前资产快照。

当前原型在转移确认时保存当前转出责任人、成本中心、公司、板块、部门、位置、资产状态等快照，用于完成态回看；正式系统仍需保存可审计快照及事务记录。

转移完成后：

- 单据状态更新为已完成；
- 保存最后修改人、最后修改时间；
- 生成资产转移事务 / 操作历史；
- 关联转移单号；
- 有申请单号时同时记录关联申请单号；
- 转移成功后释放资产锁。

### 6.3 已完成查看

已完成单据为只读查看态，不展示：

- 添加物资；
- 删除物资；
- 保存草稿；
- 转移确认；
- 编辑明细。

单头固定展示：

- 转移单号；
- 申请单号；
- 单据状态；
- 财务公司；
- 制单人；
- 制单日期；
- 备注。

已完成详情单头**不展示完成人、完成时间、物资数量**。

保留：

- 转移物资明细；
- 【打印】；
- 【导出明细】。

【导出明细】生成 Excel `.xlsx` 文件，文件名为“转移单号-明细.xlsx”；导出字段与当前转移物资明细保持一致。

### 6.4 打印

仅已完成转移单提供【打印】。

打印不直接复用当前详情页，而是生成独立“物资转移单”打印版式，字段和样式沿原版套打模板。

#### 6.4.1 单头

打印单头仅展示：

- 转移单号；
- 转移日期；
- 公司。

其中：

- 转移日期优先取明细转移日期；
- 公司打印名称，不强调页面“财务公司”字段标签。

#### 6.4.2 明细

打印明细固定字段：

| 序号 | 资产类别 | 资产标签号 | 资产说明 | 数量 | 移出部门 | 移出责任人 | 移出资产地点 | 移入部门 | 移入责任人 | 移入资产地点 | 使用说明 含：变动原因 |
|---|---|---|---|---:|---|---|---|---|---|---|---|

字段来源：

- 资产类别：资产大类 + 资产小类；
- 移出部门 / 移出资产地点：取转移前快照；
- 移出责任人：取转出人；
- 移入部门 / 移入资产地点：取转移后的目标信息；
- 移入责任人：取转入人；
- 使用说明同时承载变动原因。

#### 6.4.3 样式

套打样式按原版：

- 顶部左侧搜狐黄色 Logo；
- 标题居中“物资转移单”；
- 标题下方横线；
- 明细使用细黑色边框表格；
- 无数据区域补空白行；
- 表格底部展示“合计”数量；
- 底部签字栏：
  - 转移人（签字）/时间；
  - 部门领导（签字）/时间；
- 页面右侧竖排展示“一联 转出方”；
- 使用 A4 横向打印布局，保证 12 列字段在单页宽度内完整展示。

点击【打印】后打开独立打印页面并调用浏览器打印，不打印后台详情页本身。

### 6.5 Excel

转移单编辑页提供【模板下载】和【Excel导入】。上传上下文携带转移单、单据类型、单据状态、公司和业务类型；历史接口类型为 `uploadType=transfer`。

#### 6.5.1 模板字段

模板第一张表名为“资产转移导入模板”，第一列固定为错误回写列，字段顺序固定为：

| 列 | 字段 |
|---:|---|
| 1 | 错误提示 |
| 2 | 资产标签号* |
| 3 | SN号 |
| 4 | 转入人（员工编号）* |
| 5 | 成本中心 |
| 6 | City* |
| 7 | Building* |
| 8 | Floor* |
| 9 | Room |
| 10 | 转移日期（YYYY-MM-DD） |
| 11 | 转移原因 |
| 12 | 用途* |
| 13 | 业务线 |
| 14 | 项目 |
| 15 | 转移说明 |

模板第二张表为填写辅助字典。下拉选项只用于填写辅助，导入时仍以系统基础资料校验结果为准。公司不在 Excel 中填写，取当前转移单已选择的公司。

#### 6.5.2 导入校验

导入时逐行执行以下规则：

1. 资产标签号有值时优先按资产标签号匹配；标签号为空时按 SN 号匹配。
2. 资产必须属于当前转移单公司，且未被其他业务占用。
3. 转入人填写时校验员工存在且有效；留空的行继续进入导入结果，但在后续确认转移时仍需满足转入人要求。
4. City、Building、Floor 必填；City 必须是系统有效城市，Building 必须属于所选 City，Floor 必须是系统有效楼层。
5. 转移日期填写时必须为 `yyyy-MM-dd`；为空时使用上传当天日期。
6. 用途填写时必须是系统已有用途；为空时沿用资产原用途。
7. 业务线、项目填写时校验系统基础资料；为空允许通过。
8. 成本中心单元格不直接覆盖系统成本中心：普通资产使用转入人资料中的成本中心，SERVER 资产保留原成本中心。
9. 标签号、SN 号同时填写时只按标签号匹配。
10. 文件内或当前转移单中同一资产重复时，该行失败。

#### 6.5.3 批量结果与状态

1. 任意一行校验失败，整份 Excel 不保存；每一行错误写回结果文件第一列，用户下载错误结果文件修改后重新上传。
2. 全部行通过后，生成转移单明细并暂时锁定资产；上传成功不代表资产台账已经完成转移。
3. 点击【确认转移】时重新检查资产当前状态。资产不再处于“在用—使用中”时，确认失败。
4. 确认成功后才更新责任人、部门、成本中心、City、Building、Floor、Room、用途、业务线和项目等资产信息，并解除锁定。

### 6.6 权限

权限采用“公司/板块数据范围 + 仓库操作权限”两层控制：

1. 公司、板块决定用户可查看和查询的转移单、资产候选及人员候选范围；
2. 仓库权限决定用户能否创建、编辑、添加或删除物资、导入、确认转移、删除草稿、打印和导出；
3. 打开单据、选择资产、保存草稿和确认转移时均重新校验当前权限。

同时确保：

- 用户只能操作有权限公司/板块下的数据；
- 资产候选范围受权限控制；
- 转入人候选范围受公司板块领取资产权限控制；
- 提交转移时再次校验权限，不依赖页面候选结果。
