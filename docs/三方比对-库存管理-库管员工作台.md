# 库存管理 - 库管员工作台 三方比对

> 比对对象
>
> 1. 原版 PRD：用户提供《库管员工作台》；
> 2. 当前原型：`src/pages/inventoryManagement/WarehouseWorkbenchPage.js`；
> 3. 新 PRD：`docs/PRD-库存管理-库管员工作台.md`。
>
> 仓库现有 `docs/PRD-库存管理-库管员工作台及员工领用退库打印补充.md` 作为已存在的后续补充口径，用于判断“原版规则是否已经被新交互覆盖”，但不作为第四套现状。

## 1. 结论分类

| 分类 | 含义 |
|---|---|
| 原型应补 | 原版规则仍有效，当前原型缺失 |
| PRD应跟原型 | 当前原型/现有补充口径已经明确覆盖历史交互 |
| 仅后端/流程规则 | 正式系统必须实现，但不要求 PC 原型模拟底层技术过程 |
| 待确认 | 原版、当前原型和补充口径仍无法自行得出唯一答案 |

## 11. 与现有补充 PRD 的一致/冲突

现有补充 PRD 已经明确以下新口径，因此不再作为待确认：

1. 删除“资产出入库”单页签；
2. 删除右上角【扫码】；
3. 删除右上角【刷卡】；
4. 保留【员工页面】【刷新员工页面】；
5. 扫码枪和刷卡设备仍可直接向对应查询输入框写值。

该补充 PRD 同时包含“员工领用/退库自动库存单打印追加《员工领用信息》页”，属于入库/出库打印链路，不是本工作台页面自身功能，继续独立维护。

## 12. 当前需要确认的事项

目前真正需要产品确认的只剩两类：

### 12.1 工作台权限是否继续写死具体人员

原版写当前使用人：

- 杨芊；
- 孙志强。

当前原型没有人员硬限制，系统其他库存能力已经逐步按仓库/角色/公司板块权限处理。

需要确认：

- A：仍只允许上述具体人员；
- B：改为按库管员角色 / 仓库操作权限控制，不写死姓名。

### 12.2 员工离职是否仍进入库管员工作台

原版业务类型表中包含“员工离职”，但原版整理的导出数据中没有 ED 流程记录，并明确标记为待验证。

需要确认：

- A：继续作为工作台单据类型；
- B：不再从库管员工作台展示，由离职流程自己的待办入口处理。
