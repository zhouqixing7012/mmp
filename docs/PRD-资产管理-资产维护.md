# 资产管理 - 资产维护 PRD

## 1. 背景

资产维护用于统一查询、查看和维护已经形成正式资产卡片的资产数据。

本模块覆盖全部正式资产卡片，包括普通资产和机房资产。资产卡片由入库等上游资产业务生成，资产维护页面本身不提供新增资产卡片和删除资产卡片能力。

资产维护需要同时满足以下目标：

1. 为授权用户提供统一的资产卡片查询、查看、编辑、批量修改和导出入口。
2. 按财务公司和板块控制资产数据范围，避免跨权限查看、维护和导出。
3. 单条维护只允许修改明确开放的 10 个字段，其余资产核心字段保持只读，并通过对应业务单据维护。
4. 资产卡片统一保留价值、维修、盘点、资产事务和 RFID 历史，支持资产全生命周期追溯。
5. 机房资产和普通资产使用同一资产维护入口，机房资产在资产卡片中额外展示 NO 位置和服务信息。
6. 资产字段发生人工维护后，记录修改结果并形成可追溯的资产维护事务。

## 2. 范围与权限

### 2.1 业务范围

资产维护展示全部已经生成正式资产卡片的资产，包括：

- 普通资产；
- 机房资产；
- 已报废但仍需留存查询的资产。

以下能力不属于资产维护：

- 直接新增资产卡片；
- 直接删除资产卡片；
- 通过资产维护直接执行资产报废；
- 修改未开放的资产核心字段。

### 2.2 数据隔离

资产数据按“财务公司 + 板块”进行权限隔离。

用户只能查询、查看、维护和导出其授权范围内的数据。查询条件、分页、排序、导出均不得突破当前用户的数据权限范围。

台账至少区分以下业务范围：

- 集团台账；
- 115 新媒体上海分公司台账，板块为 11；
- 116 新媒体广州分公司台账，板块为 11。

### 2.3 查看权限

| 台账范围 | 查看人员 |
|---|---|
| 集团台账 | ES 资产组及 ES 领导 |
| 上海媒体分公司台账 | ES 卢铭华 |
| 广州媒体分公司台账 | ES 李琴宝 |

### 2.4 编辑权限

| 台账范围 | 编辑人员 |
|---|---|
| 集团台账 | ES 资产组穆晓丹、吕静 |
| 上海媒体分公司台账 | ES 卢铭华 |
| 广州媒体分公司台账 | ES 李琴宝 |

编辑权限采用“人员 + 数据范围 + 字段范围”三重控制：

1. 无编辑权限用户只能查看和按权限导出资产，不展示编辑及批量修改入口。
2. 有编辑权限用户只能维护其数据权限范围内的资产。
3. 单条编辑和 Excel 批量修改均只能修改本 PRD 明确开放的 10 个字段。
4. 权限校验必须在服务端再次执行，不得仅依赖前端按钮显隐。

## 3. 通用规则

### 3.1 默认加载与排序

进入“资产管理 → 资产维护”后，系统直接查询当前用户权限范围内的资产。

用户未主动排序时，默认排序固定为：

`最后修改时间倒序 → 资产标签号升序`

用户手工调整排序后，按照当前排序展示；页面重新进入或刷新后恢复默认排序。

资产入库、资产维护保存以及其他会改变资产卡片主数据的正式业务动作，应统一维护资产最后修改时间。

### 3.2 数字与日期展示

- 数量等计数型字段使用整数及千分位展示。
- 原值、净值、EBS 净值、税额、升级金额等金额字段使用千分位 + 2 位小数。
- 日期统一展示为 `yyyy-MM-dd`。
- 日期时间统一展示为 `yyyy-MM-dd HH:mm:ss`。
- 标签号、序列号、员工编号、单据号等标识类字段不得使用千分位格式。
- 空值在普通详情字段中展示为 `-`；独立业务分组无数据时按对应空状态文案展示。

### 3.3 资产状态规则

资产列表和资产卡片允许展示全部有效资产状态：

- 在用-使用中；
- 在库-修理；
- 在库-新增；
- 在用-借用中；
- 在库-待处理；
- 再利用-使用中；
- 已报废-已处置；
- 已报废-待处置；
- 再利用-待报废。

资产维护编辑时：

- “已报废-已处置”“已报废-待处置”不得作为人工可选目标状态；
- 正式报废状态必须由资产报废业务产生；
- “再利用-待报废”暂保留为可编辑状态；
- 已经处于正式报废状态的资产，其报废结果不得通过资产维护改写为新的报废结果。

### 3.4 查询条件关系

- 不同查询条件之间使用 AND 关系。
- 同一多选查询条件中的多个值使用 OR 关系。
- 支持多值的文本条件中，多个输入值之间使用 OR 关系。
- 未填写的条件不参与过滤。
- 点击【重置】后清空全部基础查询条件和更多查询条件，并恢复当前权限范围内默认资产列表。
- 点击【查询】或在文本查询条件中按 Enter 均执行查询。
- 每次重新执行查询后返回第一页，并清空当前页勾选状态。

### 3.5 选择范围

资产列表复选框用于导出等批量动作。

- 支持选择当前页一条或多条资产。
- 表头全选只选择当前页。
- 不保留跨分页勾选结果；翻页后清空上一页勾选状态。
- 单条编辑不依赖复选框，直接通过当前行右侧【编辑】进入。

## 4. 资产列表

### 4.1 页面结构

页面由以下区域组成：

1. 页面标题“资产维护”；
2. 基础查询条件；
3. 可展开/收起的“更多查询条件”；
4. 资产列表 Card；
5. 列表 Card 右上角展示当前查询结果 `共 X 条`；
6. 列表工具区展示【批量修改】【导出】；
7. 表格右侧固定【操作】列，单行展示【编辑】。

查询条件在 PC 端按统一三列栅格展示，即一行 3 个查询条件；更多查询条件展开后继续按相同三列规则向下排列，不使用单列纵向堆叠。

页面不提供【新增】【删除】资产卡片入口。

- 默认每页 10 条；
- 支持切换每页展示数量；
- 分页时保留查询条件及排序条件；
- 翻页后清空当前勾选结果；
- 总数始终按相同数据权限和查询条件重新计算。

## 5. 资产卡片弹窗

### 5.1 打开方式与尺寸

资产卡片使用 Modal 弹窗承载，不跳转独立页面。

入口：

- 点击资产列表“标签号”进入资产卡片查看态；
- 点击右侧固定【编辑】直接进入同一资产卡片的编辑态。

弹窗不做全屏。PC 端建议宽度约 1100px，并限制最大视口宽度；内容超过可视高度时，仅弹窗内容区纵向滚动，页面背景不随内容滚动。

### 5.2 页签

资产卡片固定包含 6 个页签：

1. 详细信息；
2. 价值信息；
3. 资产维修记录；
4. 资产盘点历史；
5. 资产操作历史；
6. RFID资产操作历史。

默认进入“详细信息”。

查看态为纯查看，不在底部重复提供等价关闭按钮，仅保留右上角关闭入口。

编辑态展示【保存】【取消】；保存成功后继续展示同一资产的最新查看态。

### 5.3 详细信息布局

详细信息使用项目统一 3 列 DetailGrid 展示。配置、备注、使用说明、资产要求等长文本字段整行展示。

详细信息按以下分组展示：

1. 基础信息；
2. 账务信息；
3. NO 信息；
4. 报废信息；
5. 扩展信息；
6. 耗材信息；
7. 部件信息。

每个信息分组标题左侧增加蓝色竖向区块，用于强化不同信息分组的视觉边界。

分组折叠规则：

- “基础信息”始终展开，不提供折叠入口；
- “账务信息、NO 信息、报废信息、扩展信息、耗材信息、部件信息”均支持独立展开 / 收起；
- 打开资产卡片或切换到另一张资产卡片时，上述可折叠分组默认全部展开；
- 折叠仅影响当前分组内容展示，不清空分组数据，也不清空编辑态中尚未保存的字段值；
- 展开 / 收起入口位于对应分组标题区域，使用明确的箭头和“展开 / 收起”文案。

业务分组无数据时不隐藏整个分组，而是展示对应空状态，例如：

- `无 NO 信息`；
- `无报废信息`；
- `无耗材信息`；
- `无部件信息`。

## 6. 价值信息页签

### 6.1 数据规则

价值数据由 EBS / 资产价值数据同步结果提供，资产维护只负责查看，不提供手工修改入口。

价值页展示以下字段：

| 字段 | 规则 |
|---|---|
| 原值 | 千分位 + 2 位小数 |

## 11. 单条资产编辑

### 11.1 编辑入口

资产列表右侧固定【操作】列展示【编辑】。

点击【编辑】后打开当前资产的资产卡片弹窗，并直接进入编辑态。

编辑态仍完整展示资产卡片，不单独生成只包含可编辑字段的表单。

### 11.2 可编辑字段

只允许修改以下 10 个字段：

| 字段 | 编辑方式 | 规则 |
|---|---|---|
| 成本中心 | 单选选择 | 使用有效成本中心；展示“编码.名称” |
| City | 单选下拉 | 使用有效 City；变更后清空 Building、Floor |
| Building | 单选下拉 | 必须属于当前 City；未选 City 时不得选择 |
| Floor | 单选下拉 | 受 City / Building 限制；允许为空 |
| 资产状态 | 单选下拉 | 正式报废状态不可作为人工目标值；再利用-待报废暂可选 |
| 资产序列号 | 单行文本 | 非必填；有值时校验格式及唯一性 |
| 备注 | 多行文本 | 支持清空 |
| 资产标记 | 单选下拉 | 硬件老化 / 组件缺失 / 设备故障 / 物理损伤 / 空 |
| 使用说明 | 多行文本 | 支持清空 |
| 资产用途 | 单选下拉 | 部门公用 / 员工用机 / 其他用途 / 专业用途 / 空 |

除以上 10 个字段外，资产卡片其他字段全部只读，必须通过对应业务流程维护。

### 11.3 保存校验

点击【保存】时至少执行：

1. 当前用户编辑权限和资产数据权限校验；
2. City / Building / Floor 关联有效性校验；
3. 成本中心有效性校验；
4. 资产状态合法性校验；
5. 资产序列号非空时执行格式和唯一性校验；
6. 字典字段执行有效值校验；
7. 未发生任何字段变化时，不生成无效资产维护事务。

资产序列号与其他资产重复时阻断保存并提示明确错误。

### 11.4 保存结果

保存成功后：

1. 更新资产卡片对应字段；
2. 更新资产最后修改时间；
3. 记录修改人、修改时间、修改前值和修改后值；
4. 根据现有规则重新校验 / 计算必要财务归属数据；
5. 调用资产手工修改事务处理，形成“资产维护修改”事务快照；
6. 资产操作历史可追溯本次变化，并按相邻事务差异标黄；
7. 按现有财务接口规则推送需要同步的资产变更信息；
8. 弹窗切换回当前资产最新查看态并提示：`保存成功！`。

保存任一关键步骤失败时，本次资产维护不得被视为成功，并展示后台返回的明确失败原因。

### 12.1 入口

点击后打开“资产批量修改”弹窗，提供：

### 12.2 模板字段

模板只允许包含并修改以下字段：

| 序号 | 字段 | 说明 |
|---:|---|---|
| 1 | 资产标签号 | 必须填写，用于定位已有资产，不允许新增资产 |
| 2 | 成本中心 | 覆盖更新 |
| 3 | City | 覆盖更新 |
| 4 | Building | 覆盖更新 |
| 5 | Floor | 覆盖更新 |
| 6 | 资产状态 | 覆盖更新 |
| 7 | 资产序列号 | 覆盖更新 |
| 8 | 备注 | 覆盖更新 |
| 9 | 资产标记 | 覆盖更新 |
| 10 | 使用说明 | 覆盖更新 |
| 11 | 资产用途 | 覆盖更新 |

### 12.3 覆盖规则

Excel 批量修改采用覆盖式更新：

- 资产标签号以外的 10 个维护字段均按模板单元格实际值覆盖原资产字段；
- 模板单元格为空时，表示将原字段覆盖为空，不表示“忽略该字段”；
- 不额外提供 `#CLEAR#` 等清空标识；
- 如果清空后的结果违反字段必填、关联关系或其他业务校验，则该行校验失败，并按整批失败规则处理。

### 12.4 文件校验

系统读取第一个有效工作表，跳过表头后处理有数据的行。

每行至少校验：

1. 资产标签号必填；
2. 标签号必须已存在且在当前用户可维护权限范围内；
3. 不允许通过模板新增或删除资产；
4. 成本中心必须为有效基础资料；
5. City / Building / Floor 必须为有效位置，Building 必须属于 City；
6. 资产状态必须为有效状态，正式报废状态不得通过批量修改设置；
7. 资产序列号非空时校验格式及唯一性；
8. 资产标记、资产用途必须使用有效字典值；
9. 文本字段执行接口规定的最大长度校验；
10. 每项修改继续执行单条编辑涉及的财务归属、事务和财务推送校验。

### 12.5 原子保存

批量修改采用整文件原子处理：

- 所有行全部校验通过后才允许保存；
- 任意一行校验失败，本次 Excel 全部不保存；
- 失败结果必须至少返回：Excel 行号、资产标签号、失败原因；
- 不允许出现部分资产已保存、部分资产失败的半完成结果。

保存成功后记录上传人、上传时间、文件名、处理行数及修改结果，并刷新资产维护列表。

成功提示：`修改成功！`

## 14. 校验与异常处理

| 场景 | 处理 | 页面文案 / 结果 |
|---|---|---|
| Building 未先选择 City | 不允许选择 | `请先选择城市！` |
| Building 与 City 不匹配 | 阻止保存 | 提示位置关系无效 |
| 资产序列号重复 | 阻止保存 | `当前资产序列号不唯一！` 或接口实际错误 |
| 编辑保存成功 | 更新当前资产并形成事务 | `保存成功！` |
| 编辑保存失败 | 不进入成功态 | 优先展示后台实际错误；通用文案 `保存失败,请检查数据！` |
| 批量修改未上传文件 | 不提交 | 提示先选择上传文件 |
| Excel 任一行校验失败 | 整批不保存 | 返回行号 + 标签号 + 失败原因 |
| 批量修改成功 | 刷新列表 | `修改成功！` |
| 无可导出结果 | 不导出 | 提示当前没有可导出数据 |
| 查询日期起止不合法 | 不查询 | 提示日期范围不合法 |
| 原值最小值大于最大值 | 不查询 | 提示金额范围不合法 |
