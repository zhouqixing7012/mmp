# 资产管理 - 资产维护 PRD

## 1. 背景

资产维护用于统一查询、查看和维护已经形成正式资产卡片的资产数据。

业务范围覆盖全部正式资产卡片，包括普通资产、机房资产以及已报废但仍需保留查询的资产。

资产卡片由入库等上游资产业务生成。资产维护仅维护已有正式资产卡片，不提供资产卡片新增、删除和正式报废入口。

## 2. 权限

资产数据按“财务公司 + 板块”进行权限隔离。查看权限和编辑权限独立控制。

| 权限范围 | 数据范围 | 查看人员 | 编辑人员 |
|---|---|---|---|
| 集团台账 | 集团授权范围 | ES 资产组及 ES 领导 | ES 资产组穆晓丹、吕静 |
| 上海媒体分公司台账 | 115 新媒体上海分公司，板块 11 | ES 卢铭华 | ES 卢铭华 |
| 广州媒体分公司台账 | 116 新媒体广州分公司，板块 11 | ES 李琴宝 | ES 李琴宝 |

规则：

- 用户只能查询、查看、导出其授权范围内的资产。
- 只有编辑人员可以执行单条编辑和批量修改。
- 编辑人员只能修改其授权公司、板块范围内的资产。
- 资产卡片查看权限不代表编辑权限。
- 单条保存、批量保存、导出时均重新校验当前数据权限和操作权限。

## 3. 通用规则

### 3.1 维护范围

资产维护针对已经生成正式资产卡片的数据。

本页面：

- 支持查询、查看、单条编辑、Excel 批量修改和导出；
- 不新增资产卡片；
- 不删除资产卡片；
- 不直接执行资产报废；
- 不允许修改本 PRD 未开放的资产核心字段。

### 3.2 默认加载与排序

进入“资产管理 → 资产维护”后，自动查询当前用户权限范围内的资产。

用户未主动排序时，默认：

最后修改时间倒序 → 资产标签号升序

资产列表除选择列、操作列外的业务字段均支持表头升序 / 降序排序。

用户主动排序后，以当前排序为准。

重新进入页面或清空排序后恢复默认排序。

### 3.3 数量、金额、空值与日期

- 数量、件数等计数型字段按业务原值展示，不强制千分位。
- 原值、EBS原值、净值、EBS净值、配置参考价值、升级金额等金额字段统一使用千分位 + 2 位小数。
- 金额真实值为 0 时展示 0.00。
- 上游没有记录或字段为空时展示空值，不使用 0、0.00 或“-”伪造业务值。
- 数量、金额参与排序时，空值与真实数值 0 必须按不同值处理。
- 日期统一展示 yyyy-MM-dd。
- 日期时间统一展示 yyyy-MM-dd HH:mm:ss。
- 标签号、序列号、员工编号、单据号等标识类字段按文本展示，不使用千分位。

页面表格或详情需要占位时可显示“-”；Excel 导出空值必须写为空单元格。

### 3.4 资产状态

资产状态有效值固定为：

1. 在用-使用中；
2. 在库-修理；
3. 在库-新增；
4. 在用-借用中；
5. 在库-待处理；
6. 再利用-使用中；
7. 已报废-已处置；
8. 已报废-待处置；
9. 再利用-待报废。

资产维护对状态的维护权限：

| 目标状态 | 是否可由资产维护设置 |
|---|---:|
| 在用-使用中 | Y |
| 在库-修理 | Y |
| 在库-新增 | Y |
| 在用-借用中 | Y |
| 在库-待处理 | Y |
| 再利用-使用中 | Y |
| 再利用-待报废 | Y |
| 已报废-待处置 | N |
| 已报废-已处置 | N |

“已报废-待处置”“已报废-已处置”必须由资产报废业务产生。

当资产当前状态已经为以上任一正式报废状态：

- 资产状态字段锁定；
- 资产维护不得将状态修改为其它状态；
- 其他开放维护字段仍可按权限修改。

### 3.5 开放编辑字段

单条编辑和 Excel 批量修改统一只开放以下 10 个业务字段：

- 数量；
- 单位；
- 主资产标签号；
- 仓库；

### 3.6 SN 规则

资产序列号保存前去除首尾空格。

规则：

- 空值允许；
- “缺省”为合法占位值；
- “缺省”不参与唯一性冲突，可存在于多张资产卡片；
- 除“缺省”外的真实 SN 必须满足正式格式规则并全局唯一；
- 单条保存按保存时资产全集校验；
- 批量修改按整批保存后的最终结果校验，而不是逐行使用上传前快照机械判断。

批量最终状态示例：

A 资产原 SN=SN001，B 资产原 SN=SN002。同一批中 A 改为 SN003、B 改为 SN001，只要最终全局 SN 唯一，则允许保存。

### 3.7 位置规则

位置字段关系：

- City 必填；
- Building 必填；
- Building 必须属于当前 City；
- Floor 非必填；
- Floor 非空时必须存在于有效 Floor 基础资料；
- Floor 不要求与 Building 建立强关联。

查询条件中的 Floor 可独立选择，不要求先选择 Building。

### 3.8 查询组合规则

- 不同查询条件之间使用 AND。
- 同一多选条件中的多个值使用 OR。
- 支持多值的文本条件中，多个值使用 OR。
- 文本多值支持英文逗号 ,、中文逗号 ， 和换行分隔。
- 每个文本值去除首尾空格、忽略空值并去重。
- 点击【查询】或在支持回车的文本条件中按 Enter 执行查询。
- 点击【重置】清空基础条件和更多条件。
- 重新查询后返回第 1 页，并清空当前页勾选。
- 多选弹窗再次打开时回显当前已选数据，可取消部分或全部已选值。

公司、部门、责任人、成本中心、位置等查询条件使用稳定编码 / ID 作为实际查询值，页面展示名称或“编码.名称”。

部门“包含下级组织”时：

- 根据组织树和稳定部门编码 / ID 展开；
- 查询范围为“选中部门自身 + 当前有效下级组织”；
- 不按部门名称前缀或字符串层级名称推断上下级关系。

### 3.9 列表选择范围

列表复选框只保留当前页选择，不跨分页保留。

单条编辑通过最右侧【编辑】进入，不依赖复选框。

以下行为发生后清空当前勾选：

- 查询；
- 重置；
- 翻页；
- 修改每页条数；
- 切换列表排序；
- 单条编辑保存成功后刷新列表。

### 3.10 修改事务与审计

每一次发生实际变化的资产维护必须形成一笔资产维护事务。

资产卡片更新与资产维护事务属于同一次本地业务提交：

- 两者均成功才视为本地修改成功；
- 任一失败均不产生部分结果。

资产维护事务必须记录：

- 修改人；
- 修改时间；
- 10 个开放编辑字段的修改前值；
- 10 个开放编辑字段的修改后值；
- 实际发生变化的字段集合。

资产操作历史页面没有展示某字段，不影响后台审计记录完整性。

手工资产维护事务：

- 单据编号为空；
- 申请单号为空。

修改人取当前登录用户。

操作日期、最后修改时间、批量处理时间使用系统服务时间。

### 3.11 并发与重复提交

单条编辑：

- 打开编辑时记录资产版本信息；
- 保存时再次校验资产是否已被其他用户或业务修改；
- 发现版本变化时拒绝旧版本覆盖。

批量修改：

- 提交时重新读取每一资产最新版本；
- 整批提交期间发现任一资产发生并发变化，整批不保存。

重复提交：

- 同一次单条保存或批量提交重复点击、超时重试、网络重放，只产生一次有效修改；
- 不重复生成资产维护事务；
- 不重复更新时间；
- 不重复创建财务同步任务；
- 用户后续明确再次提交同一个 Excel 文件，应视为新的业务批次，而不是因文件内容相同永久去重。

### 3.12 后台联动与财务同步

保存资产时同步执行以下业务联动：

1. 校验资产责任人存在且所属板块属于资产系统管理范围。
2. 根据公司、板块、资产类别、City、资产责任人和成本中心重新计算费用账户。
3. 本次保存的有效成本中心直接参与费用账户计算，不额外按责任人、使用部门或机房资产限制成本中心候选范围。
4. 根据板块取得资产账簿。
5. 资产缺少启用日期时，根据购买日期计算默认启用日期。
6. 资产标记保存到资产标记字段，不与资产用途、使用说明混用。
7. 费用账户、账簿、责任人、状态、位置、序列号等关键联动校验失败时，本地资产修改不提交。

本地资产修改成功后生成财务同步任务。

财务同步任务记录：

- 发起时间；
- 同步结果；
- 失败原因；
- 重试次数。

财务同步失败：

- 已成功的本地资产修改和资产维护事务保持有效；
- 不回滚本地结果；
- 失败任务进入可重试状态；
- 重试财务同步不得重复生成资产维护事务。

财务同步字段至少包括：

- 行号；
- 资产标签号；
- 资产序列号；
- 资产说明；
- 资产大类；
- 资产关键字；
- 父资产标签号；
- 资产账簿；
- 启用日期；
- 员工编号；
- 费用账户；
- 地点；
- 资产更换日期；
- 资产变更业务类型；
- 资产调整成本；
- 财务接口要求的其他字段。

页面是否展示上述字段不影响后台财务同步字段范围。

- 真实 SN 按整批最终状态执行唯一性校验。

## 5. 校验

### 5.1 查询校验

购买日期、启用日期：

- 结束日期不得早于开始日期。

原值范围：

- 最小金额不得大于最大金额；
- 原值为空的资产不按 0 参与范围命中。

Building：

- 查询时先选择 City；
- 仅显示当前 City 下有效 Building。

### 5.2 单条编辑

保存前校验：

- 当前用户具有该资产编辑权限；
- 成本中心必填且有效；
- City 必填且有效；
- Building 必填且属于 City；
- Floor 非空时必须有效；
- 资产状态必填且有效；
- 正式报废状态不得通过资产维护设置；
- 当前已为正式报废状态时，状态不得改变；
- 资产序列号按 3.6 节校验；
- 资产标记非空时必须为有效枚举；
- 资产用途非空时必须为有效枚举；
- 备注、使用说明不得超过字段最大长度；
- 修改后的关键字段必须能够完成费用账户、账簿等后台联动校验。

未发生任何字段变化：

- 不提交修改；
- 不更新时间；
- 不生成资产维护事务；
- 提示：资产信息未发生变化。

### 5.3 单条编辑提示

### 5.4 Excel 模板校验

模板表头必须与 4.11.2 完全一致。

以下情况整文件不进入保存：

- 缺少模板字段；
- 重复表头；
- 列名不匹配；
- 出现模板外业务列；
- 使用公式单元格产生业务值。

公式单元格错误返回：

- 行号；
- 字段；
- 失败原因。

### 5.5 Excel 行级校验

每一行执行：

1. 结构化文本去除首尾空格；
2. 只包含空格的值按空白处理；
3. 资产标签号必填、存在、文件内不重复；
4. 当前用户具有该资产数据权限和编辑权限；
5. 成本中心必填，按编码校验有效基础资料；
6. City 必填并唯一匹配；
7. Building 必填、唯一匹配且属于 City；
8. Floor 非空时唯一匹配有效基础资料；
9. 资产状态必填并符合 3.4 节规则；
10. 当前为正式报废状态时只能填写原状态；
11. 资产序列号按文本语义读取；
12. 真实 SN 按整批最终状态校验唯一性；
13. 备注、使用说明按最大长度校验；
14. 资产标记、资产用途非空时校验有效枚举；
15. 当前资产版本仍有效。

资产标签号、资产序列号禁止先转数值再转字符串。

如果 Excel 已经把前导零或超长编号破坏为数值 / 科学计数法，系统按实际读取值校验，不猜测恢复。

### 5.6 Excel 整批校验

任意一行失败：

- 整批数据不保存；
- 不生成部分资产修改；
- 不生成部分资产维护事务；
- 不生成部分财务同步任务。

页面一次返回多条错误，至少包含：

- 行号；
- 资产标签号；
- 字段；
- 失败原因。

以下情况均属于整批失败：

- 必填字段为空；
- 基础资料不存在或无法唯一匹配；
- 表头错误；
- 公式单元格；
- 任一资产权限失败；
- 任一资产状态失败；
- 任一真实 SN 最终冲突；
- 任一资产在提交前发生并发变化；
- 任一关键联动校验失败。

### 5.7 Excel 无变化行

标准化后与数据库当前值比较。

如果该行 10 个开放字段最终值与当前资产完全一致：

- 该行记为无变化；
- 不更新最后修改时间；
- 不生成资产维护事务；
- 不创建财务同步任务；
- 不影响整批其他有效修改继续提交。

批量处理结果区分：

- 上传总行数；
- 实际修改行数；
- 无变化行数。

### 5.8 导出校验

当前查询结果和当前页勾选均为空时：

- 不生成导出文件；
- 提示：当前没有可导出的数据。

导出前重新校验当前用户数据权限。

## 6. 后续操作 / 业务结果 / 补充说明

### 6.1 单条修改结果

单条保存成功后：

1. 更新资产卡片 10 个开放字段中的实际变化项；
2. 完成费用账户、资产账簿等后台联动；
3. 生成一笔资产维护事务；
4. 保存修改前值、修改后值和变化字段集合；
5. 更新最后修改人、最后修改时间；
6. 生成财务同步任务；
7. 刷新资产维护列表。

本地资产修改和资产维护事务必须同时成功。

### 6.2 批量修改结果

整文件全部校验通过后才提交。

所有发生变化的资产：

- 作为同一批本地业务提交；
- 任一资产本地保存或关键联动失败时整批不保存；
- 每一项实际变化资产分别生成资产维护事务；
- 每条事务保存 10 个开放字段的修改前 / 修改后快照和实际变化字段集合。

批量处理记录保存：

- 上传人；
- 上传时间；
- 文件名；
- 上传总行数；
- 实际修改行数；
- 无变化行数；
- 处理结果。

本地批量提交成功后，为实际变化资产创建财务同步任务。

### 6.3 资产操作历史结果

资产维护成功后生成的历史记录：

- 操作类型为资产维护类业务；
- 操作日期使用系统时间；
- 操作人为当前登录用户；
- 单据编号为空；
- 申请单号为空；
- 记录资产维护后的业务值。

资产操作历史中的变化标黄按照 4.8 节执行。

### 6.4 财务同步结果

财务同步在本地资产修改成功后执行。

同步成功：

- 更新财务同步任务结果。

同步失败：

- 本地资产卡片和资产维护事务保持成功状态；
- 记录失败原因和重试次数；
- 后续可重新推送；
- 重试只执行财务同步，不重复资产修改。

### 6.5 列表刷新

单条修改成功：

- 保留查询条件；
- 保留用户手工排序；
- 清空勾选；
- 回到第 1 页；
- 重新查询。

批量修改成功：

- 刷新列表；
- 清空当前勾选；
- 按最新最后修改时间反映实际变化资产。

### 6.6 导出结果

导出工作簿按 4.12 节生成。

导出操作：

- 不修改资产卡片；
- 不生成资产操作历史；
- 不改变最后修改时间；
- 不触发财务同步。

### 6.7 尚未定义的业务规则

以下业务规则需要补充明确值：

- 备注最大长度；
- 使用说明最大长度；
- 除“缺省”外的资产序列号正式格式规则。

在以上规则明确前，不使用“系统默认”“已有规则”等模糊口径替代。

### 6.8 接口与基础数据依赖

以下接口或基础数据映射必须能够支撑本 PRD 规则：

- EBS 原值 / EBS 净值同步映射；
- 机房资产配置参考价值数据来源；
- 统一机房资产分类编码映射；
- MIS 维修字段映射；
- 财务变更同步接口、失败重试与对账；
- 资产账簿取得与费用账户计算能力；
- 各资产状态和业务字典正式编码；
- 组织树、成本中心、City、Building、Floor 基础资料及稳定编码 / ID 映射。

接口实现方式不改变本 PRD 已定义的页面字段、校验、事务和业务结果。
