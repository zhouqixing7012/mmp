# 资产管理 - 资产维护 PRD

## 1. 背景

资产维护用于统一查询、查看和维护已经形成正式资产卡片的资产数据。

本模块覆盖全部正式资产卡片，包括普通资产和机房资产。资产卡片由入库等上游资产业务生成，资产维护页面本身不提供新增资产卡片和删除资产卡片能力。

## 2. 范围与权限

### 2.1 业务范围

资产维护展示全部已经生成正式资产卡片的资产，包括普通资产、机房资产以及已报废但仍需留存查询的资产。

页面不直接新增或删除资产卡片，不直接执行资产报废，也不允许修改未开放的资产核心字段。

### 2.2 权限

资产数据按“财务公司 + 板块”进行权限隔离。用户只能查询、查看、维护和导出其授权范围内的数据。

现有台账权限范围继续保留：

| 台账范围 | 数据范围 | 查看人员 | 编辑人员 |
|---|---|---|---|
| 集团台账 | 集团授权范围 | ES 资产组及 ES 领导 | ES 资产组穆晓丹、吕静 |
| 上海媒体分公司台账 | 115 新媒体上海分公司，板块 11 | ES 卢铭华 | ES 卢铭华 |
| 广州媒体分公司台账 | 116 新媒体广州分公司，板块 11 | ES 李琴宝 | ES 李琴宝 |

查看权限和编辑权限分开控制。无编辑权限用户不展示编辑及批量修改入口；有编辑权限用户只能修改其数据范围内、且本 PRD 明确开放的字段。权限校验必须在服务端再次执行，不能只依赖前端按钮显隐。

当前 PC 原型不模拟不同用户身份和权限按钮显隐。

## 3. 通用规则

### 3.1 默认加载与排序

进入“资产管理 → 资产维护”后，系统直接查询当前用户权限范围内的资产。

用户未主动排序时，默认排序为：`最后修改时间倒序 → 资产标签号升序`。

资产列表除选择列、操作列外的业务字段支持点击表头进行升序 / 降序排序。用户主动排序后，以用户当前排序为准；重新进入页面或清空排序后恢复默认排序。

### 3.2 数字、空值与日期展示

- 数量等计数型字段使用整数及千分位展示；字段无值时展示空值，不得把无值自动转换为 `0`。
- 原值、EBS原值、净值、EBS净值、配置参考价值、升级金额等金额字段使用千分位 + 2 位小数。
- 金额真实值为 `0` 时展示 `0.00`；上游未提供记录或字段无值时展示空值，不得用 `0.00` 冒充“未同步 / 无数据”。
- 日期统一展示为 `yyyy-MM-dd`。
- 日期时间统一展示为 `yyyy-MM-dd HH:mm:ss`。
- 标签号、序列号、员工编号、单据号等标识类字段不得使用千分位格式。

### 3.3 资产状态

资产状态有效值固定为：

1. 在用-使用中；
2. 在库-修理；
3. 在库-新增；
4. 在用-借用中；
5. 在库-待处理；
6. 再利用-使用中；
7. 已报废-已处置；
8. 已报废-待处置；
9. 再利用-待报废。

“已报废-已处置”“已报废-待处置”不得通过资产维护人工设置，正式报废状态必须由资产报废业务产生；“再利用-待报废”暂保留为可编辑状态。

当资产当前状态已经为“已报废-已处置”或“已报废-待处置”时，资产维护中的“资产状态”字段锁定，不允许通过资产维护将其改回任何其它状态，包括非报废状态；其他允许维护的字段仍按权限及本 PRD 规则处理。

### 3.4 查询关系

- 不同查询条件之间使用 AND 关系。
- 同一多选条件中的多个值使用 OR 关系。
- 支持多值的文本条件中，多个值按 OR 处理。
- 文本多值统一支持英文逗号 `,`、中文逗号 `，` 和换行分隔；系统对每个值去除首尾空格、忽略空值并去重后参与查询。
- 点击【查询】或在文本条件中按 Enter 均执行查询。
- 点击【重置】清空全部基础条件及更多条件。
- 重新查询后返回第一页并清空当前页勾选状态。
- 多选弹窗再次打开时必须回显当前已经选择的数据；用户可以取消部分已选项，也可以全部取消后确认以清空该查询条件。

### 3.5 选择范围

资产列表复选框仅保留当前页选择状态，不保留跨分页勾选。单条编辑不依赖复选框，通过右侧固定操作列【编辑】进入。

以下行为发生后必须清空当前勾选，避免“已选择数据”与当前页实际内容不一致：重新查询、重置、翻页、修改每页条数、切换列表排序，以及单条编辑保存成功后刷新列表。

## 4. 资产列表

### 4.1 查询条件布局

PC 端查询条件固定按 **一行 3 个字段** 展示。

- 每个字段标签固定宽度并右对齐；
- 基础查询条件和展开后的更多查询条件共用同一 3 列栅格；
- 不允许把整组查询条件堆叠到单列中；
- 查询、重置、更多条件操作位于查询区右侧。

查询条件在前端显示名称或“编码.名称”，正式接口参数必须使用对应稳定编码 / ID；不得因为名称相同而把不同公司、部门、成本中心合并成同一条件。

### 4.3 更多查询条件

更多查询条件默认收起，展开后继续按一行 3 个字段排列。

### 4.4 列表字段

列表固定展示：标签号、公司、板块、资产大类、资产小类、资产说明、数量、原值、净值、资产责任人、资产状态、成本中心、仓库、启用日期、资产类型。

标签号为蓝色链接，点击打开资产卡片；右侧固定操作列仅展示【编辑】。

## 5. 资产卡片弹窗

### 5.1 通用交互

资产卡片使用 Modal 弹窗承载，不跳转独立页面。弹窗不做全屏，内容超高时在弹窗内部纵向滚动。

固定包含 6 个页签：详细信息、价值信息、资产维修记录、资产盘点历史、资产操作历史、RFID资产操作历史。

历史表格列宽总和超过弹窗内容区时使用表格横向滚动，不允许压缩到字段内容不可读，也不得让末列溢出或被裁切。

### 5.2 详细信息分组

详细信息使用 3 列 DetailGrid 展示，分组为：基础信息、账务信息、NO 信息、报废信息、耗材信息、部件信息。

每个分组标题左侧展示蓝色区块。基础信息固定展开；其他分组支持独立展开 / 收起。无数据分组不隐藏，展示对应“无信息”空状态。

### 5.5 NO 信息

机房资产只展示 NO位置、服务。普通资产或未关联 NO 数据的资产显示 `无 NO 信息`。

正式实现的“机房资产”判断必须复用系统统一资产分类口径，不允许在资产维护页面单独维护一套手工布尔标记。当前 PC 原型中的机房标记仅用于 Mock 展示。

### 5.6 报废信息

存在报废记录时展示报废原因、报废日期、报废类型、是否处置、报废数量、ES 实物报废期；无记录时展示 `无报废信息`。

### 5.7 耗材信息

存在关联耗材时展示耗材标签号、耗材说明、启用日期；无数据时展示 `无耗材信息`。

### 5.8 部件信息

存在部件时展示部件名称 / 说明、部件标签号、部件 SN 号；无数据时展示 `无部件信息`。

## 6. 价值信息页签

普通资产只读展示：

- 原值；
- 净值；
- EBS净值；
- EBS原值；
- 折旧年限；
- 折旧剩余月份。

机房资产在以上字段基础上额外展示 **配置参考价值**。

价值信息页签不展示税额。EBS 或价值数据没有有效记录时展示空值；只有上游明确返回数值 0 时才展示 `0.00`。

## 7. 资产维修记录页签

维修记录来自 MIS 系统同步，只读展示。维修单号按普通文本展示，不定义下钻。

表格字段固定为：

| 顺序 | 字段 |
|---:|---|
| 1 | 行号 |
| 2 | 维修单号 |
| 3 | 资产标签号 |
| 4 | 申请人姓名 |
| 5 | 故障描述 |
| 6 | 诊断人 |
| 7 | 诊断说明 |
| 8 | 维修状态 |
| 9 | 申请时间 |
| 10 | 来源单据号 |

其中“申请人姓名”按历史口径展示“员工编号-员工姓名”，“诊断人”展示“诊断人工号-姓名”。没有维修记录时展示 `暂无资产维修记录`。

## 8. 资产盘点历史页签

资产盘点历史根据资产标签号查询资产盘点项目及盘点计划中的关联记录，**只展示项目状态为“盘点关闭”的项目中当前资产记录**。资产盘点模块正式项目类型为：初盘、抽盘、复盘。

默认按 **盘点项目启动时间倒序** 排列，而不是按当前资产的盘点执行时间排序；若项目启动时间相同，则继续按盘点项目创建序号 / 主键倒序，保证结果稳定。

表格字段固定为：盘点类型、盘点标识、盘点项目名称、盘点状态、盘点时间、盘点说明、盘点执行人、导入方式。

字段来源：

- 盘点类型：盘点项目“项目类型”，展示初盘 / 抽盘 / 复盘；
- 盘点标识：盘点项目“盘点类型-期间”，例如 `年度-2026`；
- 盘点项目名称：盘点项目名称；
- 盘点状态：盘点计划中当前资产的盘点状态；
- 盘点时间：盘点计划中当前资产的盘点时间；
- 盘点说明：盘点计划中当前资产的盘点备注；
- 盘点执行人：当前资产实际盘点人；
- 导入方式：当前资产盘点结果的来源方式映射结果。

资产维护的盘点历史中，盘点状态固定只展示两种：

- 已盘；
- 代盘。

导入方式按资产盘点模块实际扫描 / 导入方式映射：

| 资产盘点来源方式 | 资产维护展示文案 |
|---|---|
| 狐小e扫码 | APP 导入 |
| 狐小e快速扫描资产 | 快速盘点导入 |
| 人工上传盘点结果 | 空白 |
| 扫码枪 | 扫码枪导入 |

## 9. 资产操作历史页签

资产操作历史默认按操作日期倒序展示。操作日期精确到秒；若多笔事务的操作日期完全相同，则必须继续按事务创建序号 / 主键倒序，保证顺序稳定且可重复，不得依赖数据库或前端的非确定性返回顺序。

单据编号、申请单号均为只读文本。数据关系必须符合真实业务：

- 正式业务事务若存在申请单号，则必须同时存在单据编号；
- 不允许出现只有申请单号、没有单据编号的业务事务；
- 手工资产维护修改允许单据编号和申请单号同时为空。

表格字段固定为：操作类型、操作日期、操作人、单据编号、申请单号、资产标签号、序列号、主资产标签号、类别、资产说明、责任人、成本中心、费用科目、公司、地点、用途、资产状态、使用说明、备注、服务、配置、NO位置、升级金额。

不展示资产担保人。

相邻事务按上述稳定顺序从新到旧排列后，将当前事务与紧邻的上一笔历史事务进行比较。以下字段发生变化时，对当前事务对应单元格使用浅黄色背景标识：

- 序列号；
- 主资产标签号；
- 责任人；
- 成本中心；
- 公司；
- 地点；
- 用途；
- 资产状态；
- 使用说明；
- 备注；
- 服务；
- 配置；
- NO位置；
- 升级金额。

不在以上范围内的字段仅展示，不参与标黄比较。

资产手工维护事务必须在后台审计数据中记录本次 10 个开放编辑字段的修改前值和修改后值，包括资产标记；即使某字段不在当前历史表格展示列中，也不得因为页面不展示而丢失审计数据。

## 10. RFID资产操作历史页签

RFID 资产操作历史与资产核心事务历史为独立数据来源，只读展示，不与资产操作历史合并。

表格字段固定为：变更类型、变更时间、印刷号、标签号、序列号、类别、说明、员工编号、责任人、部门、公司、地点、用途、ES状态、IDC状态、服务、小服务、配置、CPU配置、硬盘配置、内存配置、IP地址1、IP地址2、IP地址3。

没有 RFID 历史时展示 `暂无 RFID 资产操作历史`。

## 11. 单条资产编辑

### 11.1 可编辑字段

编辑态仍展示完整资产卡片，只允许修改以下 10 个字段：

1. 成本中心；
2. City；
3. Building；
4. Floor；
5. 资产状态；
6. 资产序列号（资产卡片展示名称为“序列号”）；
7. 备注；
8. 资产标记；
9. 使用说明；
10. 资产用途（资产卡片展示名称为“用途”）。

其中必填关系固定为：**成本中心、City、Building、资产状态必填**；Floor、资产序列号、备注、资产标记、使用说明、资产用途非必填。

可编辑字段继续在其所属分组的原位置切换为编辑控件。成本中心位于“账务信息”，其余字段按本 PRD 的资产卡片字段位置展示。

### 11.2 前端及业务校验

保存前至少执行以下校验：

- 用户具备当前资产的数据权限和编辑权限；
- 成本中心必填，且候选范围按当前资产责任人的有效成本中心取得；机房资产按使用部门成本中心的特殊规则取得，保存值必须来自该资产允许的候选范围；
- City 必填；
- Building 必填且必须属于当前 City；
- Floor 非必填；非空时必须属于当前 City / Building 位置关系；
- 资产状态必填，且必须为第 3.3 节有效状态值；“已报废-已处置”“已报废-待处置”不得通过资产维护设置；当前已经为正式报废状态时状态字段锁定且不得改回任何其它状态；
- 资产序列号非必填；保存时去除首尾空格；非空真实 SN 校验格式及全局唯一性；`缺省` 作为允许的占位值，不参与唯一性冲突，可存在于多张资产卡片；
- 资产标记只能为硬件老化、组件缺失、设备故障、物理损伤或空；
- 资产用途只能为部门公用、员工用机、其他用途、专业用途或空；
- 备注、使用说明按系统最终长度限制校验；
- 未发生任何字段变化时不保存、不生成无效事务。

进入编辑态时必须记录当前资产版本号或最后修改时间。正式保存时服务端再次比较当前版本；如资产在用户打开编辑后已被其它用户或业务流程修改，则拒绝本次旧版本覆盖，提示用户刷新后重新编辑。尤其当资产在编辑期间被其它流程变为正式报废状态时，不允许用旧编辑快照把状态或其它并发更新覆盖回去。

### 11.3 保存后的后台联动

以下规则属于正式后台业务处理要求，当前 PC 原型不模拟接口、财务推送和后台事务执行过程，但研发实现时必须保留：

1. 保存前再次校验资产责任人存在且所属板块属于资产系统管理范围。
2. 根据公司、板块、资产类别、City、资产责任人和成本中心重新计算费用账户；机房资产成本中心沿用按使用部门成本中心的特殊规则。
3. 根据板块重新取得资产账簿。账簿属于后台账务联动数据，本版资产卡片不展示该字段。
4. 资产缺少启用日期时，根据购买日期按现有资产规则计算默认启用日期。
5. 资产标记保存到资产标记对应数据字段，不得与资产用途、使用说明混用。
6. 资产卡片更新、资产手工修改事务、最后修改时间、修改人和修改前后值属于同一笔本地业务事务，必须原子提交；其中任一项失败时本次资产修改全部失败，不允许只更新资产卡片但未生成历史。
7. 手工资产维护修改事务的单据编号、申请单号均为空。
8. 修改人必须取服务端当前登录用户身份；操作日期、最后修改时间、批量处理时间等审计时间必须取服务端 / 数据库时间，不接受前端传入时间作为最终审计依据。
9. 本地事务提交成功后生成财务同步任务，向财务系统推送变更信息；同步任务必须记录发起时间、结果、失败原因和重试次数。
10. 财务系统属于外部系统，财务推送失败不得回滚已经成功提交的本地资产卡片和资产操作历史；失败任务进入可重试状态，避免为了跨系统回滚造成“本地已改、历史丢失”或重复事务。
11. 费用账户、账簿、责任人、状态、位置、序列号或其它保存前关键联动校验失败时，本地事务不得提交；页面优先展示接口返回的具体失败原因。

保存成功后，列表继续使用保存前的查询条件和当前手工排序口径重新查询，并清空当前勾选、返回第一页。若修改后的资产已经不满足当前查询条件，则该资产从列表结果中消失；若仍满足且用户未主动排序，则按“最后修改时间倒序 → 资产标签号升序”重新排序。

财务推送字段至少覆盖：行号、资产标签号、资产序列号、资产说明、资产大类、资产关键字、父资产标签号、资产账簿、启用日期、员工编号、费用账户、地点、资产更换日期、资产变更业务类型、资产调整成本，以及正式接口要求的其他字段。页面已删除或不展示的字段不代表后台财务接口字段同步取消。

### 11.4 并发与幂等

- 单条保存请求必须携带资产版本号 / 最后修改时间进行乐观锁校验，禁止静默覆盖其它并发修改。
- 同一次保存请求必须具备请求幂等标识；客户端重复点击、网络重试或服务重试不得重复生成资产维护事务、重复更新时间或重复创建财务同步任务。
- 若相同幂等请求已经成功处理，重复请求直接返回原处理结果；若上一次处理失败且未提交本地事务，可按同一业务请求安全重试。

## 12. Excel 批量修改

### 12.1 入口与模板

列表提供【批量修改】，点击后打开上传弹窗；弹窗内提供【下载模板】和 Excel 上传。

模板仅用于修改已有资产，不允许新增、删除或报废资产。系统读取第一个有效工作表，跳过表头并处理有数据的行。

模板表头固定且只允许以下 11 列：资产标签号、成本中心、City、Building、Floor、资产状态、资产序列号、备注、资产标记、使用说明、资产用途。缺少必需表头、重复表头、列名不匹配或出现模板外业务列时，整文件判定为模板不合法，不进入数据保存。

Excel 单元格必须按字面值读取；模板中不允许使用公式单元格产生业务值。检测到公式时整文件校验失败，并返回对应行号、字段和原因。

### 12.2 字段及覆盖规则

资产标签号必须填写，用于定位已有资产。10 个维护字段继续采用覆盖式更新，但必填字段不能通过空白覆盖为空：

- **成本中心、City、Building、资产状态：每一行均必填；单元格为空时该行校验失败，整批不保存。**
- Floor、资产序列号、备注、资产标记、使用说明、资产用途：非必填；单元格有值时覆盖原值，单元格为空时将原字段覆盖为空。
- 不使用额外清空标识。

模板字段固定为：资产标签号、成本中心、City、Building、Floor、资产状态、资产序列号、备注、资产标记、使用说明、资产用途。

正式报废状态属于状态锁定例外，但不豁免必填校验：当资产当前状态已经是“已报废-待处置”或“已报废-已处置”时，模板中的“资产状态”仍必须填写，且只能填写与当前状态完全相同的值；空白或任何其它状态均判定失败。其它 9 个可编辑字段继续按本节必填 / 覆盖规则处理。

### 12.3 整文件校验

提交保存前先完成整文件校验。每一行先复用第 11.2 节的单条资产字段、权限、状态、位置、SN、字典及并发校验，再叠加以下文件级校验：

- 对资产标签号、成本中心、City、Building、Floor、资产状态、资产序列号、资产标记、资产用途等结构化文本先去除首尾空格再校验；只包含空格的单元格按空白处理。备注、使用说明按文本原文保存，但全空格内容按空白处理；
- 资产标签号必填且必须存在；去除首尾空格后再做存在性和同文件重复校验；
- 同一文件中资产标签号重复时判定失败；
- 成本中心必填，且必须存在于有效基础资料并属于该资产按责任人 / 机房使用部门规则允许的成本中心范围；
- City 必填；Building 必填且必须属于该 City；Floor 非必填，非空时必须属于当前 City / Building；
- 资产状态必填且必须为第 3.3 节有效状态值；正式报废状态不得通过批量修改设置；当前已经为正式报废状态的资产只能填写原状态，空白同样判定失败；
- 资产序列号保存前去除首尾空格；`缺省` 不参与唯一性冲突，可重复使用；
- 批量真实 SN 唯一性按**整批保存后的最终状态**校验，而不是逐行对上传前数据库快照机械校验：先计算本批全部资产更新后的最终 SN，再校验批内最终真实 SN 不重复，并与本批范围外资产的真实 SN 不重复；因此同一批内 A 资产使用 B 资产本次释放掉的旧 SN，在最终结果唯一时允许保存；
- 备注、使用说明校验最大长度；
- 资产标记、资产用途非空时必须是有效字典值；
- 每一行均校验当前用户对该资产的编辑权限和数据权限。

任意一行校验失败时，整批数据不得保存。页面返回失败行号、资产标签号和具体失败原因，可一次返回多条错误供用户集中修改。

### 12.4 批量保存与后台联动

整文件全部校验通过后才允许批量保存。所有资产卡片更新、各自产生的资产维护事务和批量处理记录必须在同一本地数据库事务中原子提交：任一资产在本地保存或关键联动校验过程中失败，本次文件全部不落库，不允许部分成功。

批量处理在服务端读取当前资产版本后，必须在同一数据库事务内通过行锁或版本条件再次校验并完成保存，防止“整文件校验完成后、实际提交前”被其它用户或业务流程插入修改。Excel 模板本身不携带可编辑的版本号字段。

每一次用户发起的批量提交生成独立的**提交幂等键**。客户端重复点击、超时重试或网络重放必须复用同一幂等键，避免重复修改资产、重复生成事务或重复创建财务同步任务。不得仅使用文件内容哈希作为幂等键：用户后续明确再次上传同一个文件时，应允许作为新的业务批次重新提交。

对每一行完成标准化后再与数据库当前值比较。若该行 10 个维护字段最终值与当前资产完全一致，则该行视为“无实际变化”：不更新资产最后修改时间、不生成资产维护事务、不创建财务同步任务，但不因此判定整批失败。批量处理记录需区分上传总行数、实际修改行数和无变化行数。

本地批量事务提交成功后，再为发生变化的资产创建财务同步任务。单个外部财务推送失败不回滚已经原子提交成功的整批本地修改，而是记录失败并按财务同步机制重试。

每一项发生实际变化的资产修改均沿用单条资产编辑的后台规则，包括费用账户重新计算、后台资产账簿取得、启用日期补齐规则、资产手工修改事务、最后修改时间、财务系统推送及相关校验。

批量保存成功后记录上传人、上传时间、文件名、上传总行数、实际修改行数、无变化行数和处理结果，并刷新资产维护列表；列表按最新最后修改时间重新查询。

当前 PC 原型只展示模板下载、上传入口、必填 / 覆盖式更新说明和整批成功 / 失败业务口径，不实现真实 Excel 解析、后台原子事务及财务推送。

## 15. 异常与反馈

| 场景 | 系统处理 | 页面反馈 |
|---|---|---|
| 单条编辑成本中心为空 | 阻止保存 | 请选择成本中心 |
| 单条编辑 City 为空 | 阻止保存 | 请选择 City |
| 单条编辑 Building 为空 | 阻止保存 | 请选择 Building |
| Building 与 City 不匹配 | 阻止保存 | 当前 Building 与 City 关系无效 |
| Floor 不属于当前 Building | 阻止保存 | 当前 Floor 与 Building 关系无效 |
| 资产状态为空 | 阻止保存 | 请选择资产状态 |
| 真实序列号重复 | 阻止保存 | 当前资产序列号不唯一！ |
| 序列号为 `缺省` | 允许保存，不参与唯一性冲突 | - |
| 尝试设置正式报废状态 | 阻止保存 | 报废状态必须通过资产报废功能处理 |
| 已报废资产尝试改回其它状态 | 阻止保存 | 已报废资产状态不允许通过资产维护修改 |
| 资产已被其它用户或业务流程修改 | 拒绝旧版本覆盖，不保存 | 资产信息已发生变化，请刷新后重新编辑 |
| 编辑未发生变化 | 不保存、不生成事务 | 资产信息未发生变化 |
| 编辑保存成功 | 原子更新资产并生成资产维护修改事务；刷新当前查询并返回第一页 | 保存成功！ |
| 本地编辑保存失败 | 不保存任何修改 | 优先展示接口真实失败原因；兜底文案为“保存失败，请检查数据！” |
| 财务同步失败 | 不回滚已成功的本地资产修改；记录失败任务并重试 | 原型不模拟；正式系统按同步任务监控处理 |
| 批量模板必填字段为空或仅包含空格 | 整批不保存 | 返回行号、资产标签号、缺失字段及失败原因 |
| 批量模板表头错误或存在公式单元格 | 整文件不进入保存 | 返回模板 / 行号 / 字段的具体错误原因 |
| 批量文件任一行校验失败 | 整批不保存 | 返回行号、资产标签号和失败原因 |
| 批量本地保存过程任一资产失败 | 整批不保存 | 保存失败并展示具体原因 |
| 批量行与当前资产完全一致 | 不更新资产、不生成事务和财务同步任务；整批仍可继续处理 | 计入无变化行数 |
| 批量修改成功 | 刷新列表 | 修改成功！ |
| 当前无数据执行导出 | 不执行导出 | 当前没有可导出的数据 |

## 16. 研发前需确认

研发前需结合正式接口和基础资料确认：

- EBS 原值 / EBS 净值同步规则；
- 机房资产配置参考价值来源；
- 系统统一机房资产分类规则在正式接口中的字段 / 编码映射；
- MIS 维修字段映射；
- 财务变更同步接口协议、时点、失败重试和对账机制；
- 后台资产账簿和费用账户重新计算规则的正式接口；
- 备注、使用说明等文本字段最大长度；
- 资产序列号除 `缺省` 外的正式格式规则；
- 各基础资料与状态字典正式编码；
- Excel 批量修改模板最终文件格式及接口字段映射。
