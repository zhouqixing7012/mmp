# 工程规范

本文件维护资产系统的有效工程约束。任务启动、授权边界和文档同步按根目录 `AGENTS.md`、`AI_RULES.md` 执行；UI 数值、组件选择与交互细节以 `docs/UI_DESIGN_GUIDELINES.md` 为准，动效以 `docs/UI_MOTION_GUIDELINES.md` 为准，不在本文件重复定义。

## 1. 项目与技术边界

- 本项目是用于产品演示的企业资产管理前端，不是生产系统。演示需支持连续业务操作、刷新后保留数据、同一对象跨页面一致和明确操作反馈；演示数据不得冒充真实业务结果。
- 使用 React 19 函数组件、Create React App、Ant Design 6、Tailwind CSS 和 React Router。日期计算复用现有 dayjs 工具。
- 不引入 Redux，不创建后端代码；未经任务明确允许，不新增依赖，不修改 `package.json` 或构建工具。图表和动效优先使用已有能力。
- 主要后台入口为 `src/pages/yewurules.js`；菜单状态由 `activeMenu`、`activeSubMenu`、`activeTab` 管理。菜单清单和实际路由查当前配置，不把历史菜单数量当作新增限制。
- 新页面放在 `src/pages/`；需要独立路由时接入 `src/config/routes.js`，需要后台菜单和标签页时接入 `src/pages/yewurules.js`。只修改本次需要的入口，不给所有页面机械增加两套入口。
- 项目运行、构建、测试命令集中维护在 `README.md`；验收与部署状态判断遵循 `AI_RULES.md`“每次修改后的自检”。预览地址应含实际部署前缀和业务路由；异常时先核对部署版本、`PUBLIC_URL` 和 Router basename。

## 2. 复用与职责划分

- 新建组件、状态配置或页面前先搜索相似实现，复用现有公共能力。禁止复制整个页面再改标题；遇到两个相似旧组件时，不顺手合并或重构。
- 页面文件建议不超过 300 行，普通组件建议不超过 200 行；禁止新增超过 500 行的页面文件及超过 1000 行的其他单文件。已有大文件按本次影响范围调整，不为行数单独扩散重构。
- 大型表格列配置独立为 `columns`；枚举、状态映射、Select options 集中管理；Modal / Drawer 超过约 80 行时拆成独立组件。审批操作等业务逻辑不写入纯展示组件。
- 公共组件复用不能覆盖业务差异：字段集合、可编辑条件或流程不同，应通过明确参数或独立视图表达；不得把一个页面的确认要求扩散到其他页面。
- 不擅自改变现有路由、数据字段和功能。同一实体保持相同字段命名；页面名称使用真实业务名称，不使用页面编号、“采购1”“审批2”等无意义名称。
- 不留下 lorem、TODO 或无行为占位按钮。资料待补时明确未实现范围，不生成随机“导入成功”数据或假接口地址。
- 用户在本项目要求“展示页面”时，默认在现有页面提供可见演示态；独立 HTML 仅在明确要求时创建。

## 3. 数据访问与一致性

- 演示数据统一放在 `src/mock/`。页面通过 Service 层调用统一演示数据入口 `src/mock/businessRulesMock.js`，不在组件直接操作 localStorage，不直接 import 大块 mock 数组作为最终数据源；JSX 文件内不得写超过 20 条的大型 mock 数组。
- 新增、编辑、审批等操作应沿同一记录流转，在相关页面产生一致变化并按项目机制持久化；禁止用独立预置数据顶替真实流转结果。
- 统计数字由同一数据源集中计算，不分别硬编码卡片指标。演示字段和值使用现有业务模型、正式枚举，不另造近义状态。
- 列表提供详情入口时，演示数据应包含详情依赖的行数据，并覆盖任务涉及的主要业务分支，不能只有单头。
- 页面限制与保存入口校验须一致。移除业务概念时检查 UI、数据源、快照、明细、导入导出、下游结果及对应 PRD，按授权范围同步调整。
- 源字段变化后，派生默认值按业务规则重算；允许独立调整的派生字段不得反向修改源字段。组合编码由各段编码组成，不用中文描述代替编码。
- 数据库操作、文件删除及生产数据边界统一遵守 `AGENTS.md`，不因演示项目而扩大操作授权。

### 3.1 物料与仓库参考数据

| 参考源 | 要求 |
| --- | --- |
| `src/mock/reference/materialCatalog.js` | 物料维度组合的真实整行记录；覆盖启用的“物料总类 + 物料大类”组合 |
| `src/mock/reference/warehouseCatalog.js` | 源表启用仓库及其真实关联属性 |

- 物料编号、物料说明、大类、小类、品牌、规格型号、配置、单位、级别、主资产关联、MIS 审核、退库鉴定、参考价格、申请/停产/盘点标识必须来自同一条物料记录，不得跨记录拼接。
- 仓库编码、仓库描述、City、Building、Floor、地址、仓库类型、仓库用途、公司、库管员、是否虚拟库必须来自同一条仓库记录，不得自行组合地点和组织关系。

- 所需具体物料未被覆盖时，先从原始基础资料补录真实整行记录；不得为了凑场景编造品牌、型号、分类、配置或仓库关系。
- 标签号、SN、单据号、数量、业务状态、操作时间属于交易演示数据，可按已确认业务规则生成，但不得破坏基础目录固定关联。
- 用户信息中的“联系电话”演示值使用座机格式，如 `010-xxxxxxxx`；合约号码、电话号码等号码资产字段按各自业务规则处理。

## 4. 结构与交互实现

- 禁止用正则表达式处理嵌套 JSX、HTML、XML；使用能识别嵌套结构的解析器或状态机，修改后检查实际结构。
- 列增删、Tabs 显隐、字段显隐、编辑/查看态差异、查询拆并和范围控件替换，必须修改 JSX、`columns`、Tabs `items` 或条件渲染。
- 禁止用全局 `:has()`、`nth-child`、DOM 顺序或 Ant Design 内部层级隐藏业务字段、列和页签；公共组件不得按字段名称自动改写具体业务结构。CSS 只负责视觉。
- 结构修改完成后核对最终源码中的实际渲染结构；构建成功不能代替该检查。具体检查见 `docs/IMPLEMENTATION_GUARDRAILS.md`。
- 弹窗选择字段复用 `SelectModal`：输入区整体可点击，输入控件设为 `readOnly`，需要时用 `pointer-events-none` 将点击交给带 `cursor-pointer` 和 `onClick` 的父容器。禁止在 disabled input 上直接绑定点击事件。这里的只读选择控件是可操作入口，纯查看字段仍使用文本或状态展示。
- 业务 Modal 暂时隐藏以打开 SelectModal 时，二者同级渲染；选择弹窗不得放在会因 `open=false + destroyOnHidden` 卸载的父 Modal 内容树中。
- 列表到选择的两步弹窗流程可用显式视图状态（如 `roleView: 'list' / 'select'`）原位替换，不叠加两层 Modal。返回入口只保留一处，Footer 按 UI 规范统一处理，不沿用旧居中按钮样式。
- 动效和加载只表达真实状态，复用公共出口；没有异步等待时不制造 Loading，不用定时器伪造业务结果。

## 5. 文件、环境与接口资料

- 文件读写使用 UTF-8，修改已有文件保持原编码；代码注释使用中文。含中文文件不用 sed/awk 修改，使用 Node.js 或 Python。PowerShell 先设置 UTF-8 输出和 `chcp 65001`，读取显式指定 `-Encoding UTF8`。
- Python 优先使用已有项目虚拟环境，Windows 为 `venv/Scripts/python.exe`，Unix 为 `venv/bin/python`；已有 `.venv` 时使用其对应解释器。均不存在时以 `python -m venv .venv` 创建，随后使用 `.venv` 内解释器，不混用全局环境和项目环境。
- API 资料优先查仓库现有文档。用户本机 `/Users/ifengz/CodingCase/002_DevelopSpec/1.Doc/` 仅在当前环境实际可访问时读取；不可访问时明确缺口，不声称已参考，不虚构路径、接口或协议。
- 网络、证书、代理异常先检查固定域名入口及反向代理配置；不凭临时 IP、端口访问失败判断数据库损坏。

## 6. 验证与修改边界

- 原因分析、自检顺序、按影响选择验证及结果报告遵循 `AI_RULES.md`“开始前”“每次修改后的自检”“对用户的输出”，本节仅补充工程特定检查。
- UI 重画且要求功能不变时，不改业务含义、必填、资格校验、触发条件、状态节点、Service 调用、拆单和持久化语义。公共样式明确作用域，排除工作台首页、移动端等独立设计页面。
- 涉及持久化时检查刷新后的数据，涉及下游时检查相关页面结果；涉及路由时从实际入口验证。需要重置演示数据时遵守已有授权边界，不为测试擅自删除文件或数据。
