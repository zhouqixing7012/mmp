# 耗材维护

## 1. 背景

当前“资产管理 → 耗材维护”原型已由通用台账页改造为独立耗材业务页面，用于统一查询、查看和维护低值耐用品耗材卡片。

本次需求需要同时保证：

1. 页面字段、查询、编辑、批量修改和导出规则清晰完整。
2. 耗材卡片与主资产、责任人、公司、仓库等基础资料关系正确。
3. 单条维护和批量维护均不得绕过字段白名单和业务校验。
4. 修改后必须可通过资产操作历史追溯。
5. 低值耐用品继续与 EBS 自动同步规则隔离。

## 2. 改造总结

1. “资产管理 → 耗材维护”固定查询低值耐用品，不提供直接新增和删除。
2. 耗材标签号为蓝色链接，点击进入耗材卡片。
3. 耗材卡片固定保留“详细信息 / 资产操作历史”两个页签。
4. 耗材卡片详细信息严格只展示本 PRD 明确的 29 个字段。
5. 单条“编辑”改为列表最右侧固定冻结“操作”列中的行级入口，不再依赖勾选后点击顶部编辑按钮。
6. 列表复选框继续用于批量修改和勾选导出，不作为单条编辑入口。
7. 单条编辑仅允许修改白名单字段，板块、耗材说明、数量等字段不可编辑。
8. 修改公司后，仓库候选按编辑页当前公司动态刷新，并仅保留启用且仓库用途为 `IU0001`（耗材库）或 `IU0003`（资产高耗库）的仓库。
9. Floor 候选固定为全部启用状态的 Floor，不按 Building 进一步收窄。
10. “用途”不作为耗材维护查询条件，也不进入耗材批量修改模板。
11. 批量修改采用覆盖策略，可编辑字段空白即覆盖为空；公司、责任人、City、Building 为空时直接校验失败。
12. 批量修改采用全文件原子保存，任一行校验失败则整份文件不保存。
13. 批量上传必须先完成文件及逐行校验，并向用户展示校验结果；校验通过后才能保存。
14. 单条编辑启用日期有值时保存页面值；留空时由后台调用既有“根据购买日期计算启用日期”规则，不直接保存为空。
15. 修改责任人后重新获取部门；非 SOHU 虚拟用户部门为空时不允许保存并提示联系管理员补充部门。
16. 保存时继续执行既有财务归属、账套、成本中心及费用账户计算逻辑。
17. 耗材修改成功后更新最后修改时间并生成操作历史；未发生变化不生成无效历史。
18. 低值耐用品不纳入 EBS 资产自动同步范围。
19. 页面及文档中原“购置日期”统一改称“购买日期”；底层数据字段仍可继续使用既有 `purchaseDate`，不因展示名称调整改变数据结构。
20. 查询选择类控件统一使用显式清空能力，不提供“双击清空”等隐藏交互。
21. 编辑态点击“取消”放弃本次未保存修改，直接关闭编辑弹窗并返回耗材列表，不再进入当前耗材卡片查看态。
22. 编辑态内打开公司、责任人、主资产等选择弹窗时，选择弹窗必须显示在当前编辑弹窗最上层。
23. 已正式报废且不允许在本页面修改的耗材状态，编辑态直接展示只读文本，不展示 disabled 下拉框。

## 3. 通用规则

### 3.1 数据范围

1. 页面固定查询低值耐用品耗材卡片。
2. 已报废或已失效卡片继续保留在列表中供查询和查看。
3. 页面不提供直接新增耗材卡片入口。
4. 页面不提供直接删除耗材卡片入口。
5. 耗材卡片由采购接收、入库或其他正式业务流程生成。

### 3.2 数据权限

耗材台账按“财务公司 + 板块”隔离。

| 台账范围 | 查看人员 | 编辑人员 |
| --- | --- | --- |
| 集团台账 | ES 资产组及 ES 领导 | ES 资产组穆晓丹、吕静 |
| 上海媒体分公司台账 | ES 卢铭华 | ES 卢铭华 |
| 广州媒体分公司台账 | ES 李琴宝 | ES 李琴宝 |

权限规则：

1. 用户只能查看、编辑和导出授权范围内的数据。
2. 没有编辑权限的用户不展示右侧“编辑”操作和批量修改入口。
3. 有编辑权限的用户也只能修改本 PRD 明确的可编辑字段。
4. 导出必须同时叠加当前用户数据权限和当前查询条件。

### 3.3 空值展示

1. 列表、卡片和操作历史中的普通空值统一展示为 `-`。
2. 编辑控件中的空值保持为空，不使用 `-` 作为提交值。
3. 批量修改中的可编辑字段空白单元格按照覆盖策略处理，不表示“保留原值”。
4. 单条编辑的启用日期为特殊规则：留空表示交由后台按既有购买日期规则重新计算，不直接落空值。
5. 已明确不可编辑的字段直接展示只读文本，不使用 disabled 输入控件模拟只读状态。

### 3.4 默认排序

1. 首次进入按“最后修改时间倒序 → 耗材标签号升序”。
2. 新增入库或耗材信息实际发生变化后更新最后修改时间。
3. 用户可对支持排序的业务列执行升序或降序。
4. 手动排序只改变当前展示顺序，不改变数据权限和查询范围。
5. 页面刷新后不保留手动排序条件。
6. 最右侧“操作”列固定冻结，横向滚动列表时始终可见。

### 4.5 单条编辑

列表每行最右侧固定“操作”列展示 `编辑`。

用户点击某一行 `编辑` 后，直接打开该耗材卡片编辑态，不需要先勾选记录，也不存在“未选择 / 多选不能编辑”的单条编辑校验。

复选框继续用于批量修改及勾选导出，与单条编辑入口相互独立。

编辑态底部操作：

1. `保存`：按本文校验规则保存；保存成功后继续停留当前编辑态并使用最新数据刷新。
2. `取消`：放弃本次未保存修改，直接关闭编辑弹窗并返回耗材列表；不再进入当前耗材卡片查看态。
3. 编辑态内打开公司、责任人、主资产等选择弹窗时，选择弹窗必须覆盖在当前编辑弹窗之上；确认或关闭选择后仍回到原编辑弹窗。

#### 4.5.1 可编辑字段

| 字段 | 控件 | 规则 |
| --- | --- | --- |
| 公司 | 公司选择器 | 必填；修改后立即刷新仓库候选 |
| 序列号 | 文本框 | 最多 120 字；真实序列号唯一；`缺省`不参与唯一性冲突；唯一性比较去除首尾空格并忽略英文字母大小写，但保存和展示保留用户输入的原始大小写 |
| 耗材状态 | 下拉 / 只读文本 | 正常状态可改；报废必须走报废功能；当前记录已正式报废时直接展示状态文本，不展示 disabled 下拉 |
| 耗材责任人 | 人员选择器 | 必填；选择后重新获取责任人姓名和部门；已有主资产不再属于新责任人时清空主资产关联 |
| City | 下拉/选择 | 必填；修改后清空 Building，不清空 Floor |
| Building | 下拉/选择 | 必填；必须属于当前 City |
| Floor | 下拉 | 可为空；候选为全部启用状态的 Floor，不要求属于当前 Building |
| 启用日期 | 日期选择 | 有值保存页面值；留空时由后台按购买日期既有规则计算 |
| 主资产标签号 | 主资产选择器 | 可为空；点击选择前必须已有责任人；候选为当前责任人的未报废主资产；不得关联自身；选择后同步主资产说明；通过显式“清空”按钮解除关联 |
| 仓库 | 下拉 | 候选按当前公司动态生成，并同时满足启用状态和仓库用途规则 |
| 使用说明 | 多行文本 | 可为空 |
| 备注 | 多行文本 | 可为空 |

#### 4.5.2 不允许手工变更字段

除上述可编辑字段外，耗材卡片其他字段全部只读。

其中明确禁止修改：

1. 板块。
2. 耗材说明。
3. 数量。
4. 耗材大类。
5. 耗材小类。
6. 耗材标签号。
7. 原值。
8. 购买日期。
9. 新增类型。
10. 单位。
11. PR 单号、申请单号、入库单号、PO 单号。
12. 部门不允许独立编辑，只随责任人选择结果更新。
13. 成本中心只读。

#### 4.5.3 公司与仓库联动

仓库候选必须同时满足以下条件：

1. 仓库状态为启用。
2. 仓库公司 = 编辑页面当前选择的公司。
3. 仓库用途为 `IU0001`（耗材库）或 `IU0003`（资产高耗库）。此处“用途”指仓库基础资料中的仓库用途，不是耗材卡片的资产用途字段。

联动规则：

1. 修改公司后立即重新计算仓库候选。
2. 原仓库仍满足新公司下全部候选条件时可继续保留。
3. 原仓库不满足新公司下候选条件时立即清空，用户必须重新选择。
4. 打开既有耗材时，如果当前已保存仓库因基础资料调整变为停用、用途变化或其他原因退出正常候选，但公司未变化，仍允许继续展示并原样保留；只有用户主动修改仓库或公司后才按当前候选重新校验。
5. 保存时再次校验仓库状态、当前公司和仓库用途，不能只依赖前端候选范围。

#### 4.5.4 责任人与部门

1. 责任人与公司独立选择，修改责任人不会自动修改公司或板块。
2. 选择责任人后，系统重新根据员工主数据获取责任人姓名和部门，不直接信任页面提交的姓名或部门文本。
3. 员工存在部门时，部门按主数据结果刷新。
4. 员工没有部门时，部门清空。
5. 非 `SOHU` 开头的普通员工没有部门时，不允许保存并提示：`该员工对应的部门为空，请联系管理员添加`。
6. `SOHU` 开头虚拟用户继续走既有虚拟用户处理逻辑。
7. 责任人必须属于 MMP 管理范围，否则提示：`该员工所在的板块不属于MMP管理范围内！`。

#### 4.5.5 启用日期特殊规则

单条编辑与批量覆盖的空值语义不同：

1. 单条编辑有填写启用日期：保存页面值。
2. 单条编辑留空：后台调用现有“根据购买日期计算启用日期”规则，不能直接把启用日期保存为空。
3. 本 PRD 不重新定义既有启用日期计算公式，研发继续复用现有后台规则。
4. 批量修改仍按本次确认的覆盖策略执行，模板中启用日期空白表示覆盖为空，不套用单条编辑的自动计算规则。

### 4.6 批量修改

#### 4.6.1 模板字段

批量修改模板固定包含：

| 字段 | 作用 | 是否写回 |
| --- | --- | --- |
| 耗材标签号 | 定位既有耗材 | 否 |
| 公司 | 可编辑字段 | 是 |
| 板块 | 只读核对字段 | 否 |
| City | 可编辑字段 | 是 |
| Building | 可编辑字段 | 是 |
| Floor | 可编辑字段 | 是 |
| 耗材说明 | 只读核对字段 | 否 |
| 主资产标签号 | 可编辑字段 | 是 |
| 数量 | 只读核对字段 | 否 |
| 耗材责任人工号 | 可编辑字段 | 是 |
| 耗材状态 | 可编辑字段 | 是 |
| 仓库 | 可编辑字段 | 是 |
| 启用日期 | 可编辑字段 | 是 |

板块、耗材说明、数量虽然保留在模板中用于人工核对和上传校验，但不得通过批量上传写回修改，也不得通过接口补传绕过限制。

“用途”不属于本次批量修改模板字段，不读取、不校验，也不允许通过批量接口附带修改用途。

#### 4.6.2 覆盖策略

1. 耗材标签号只用于定位既有耗材，不能修改。
2. 板块、耗材说明、数量只用于核对，不参与覆盖。
3. 其余可编辑模板字段全部采用覆盖策略。
4. 可编辑单元格有值：使用模板值覆盖原值。
5. 可编辑单元格空白：将原字段覆盖为空。
6. 公司、责任人、City、Building 为必填字段，因此对应单元格空白时直接校验失败，不允许把必填字段覆盖为空。
7. 不再存在“空白表示保留旧值”的规则。
8. 不再定义额外“清空标识”，可编辑字段的空白本身就是清空指令。

#### 4.6.3 文件与逐行校验

1. 文件必须符合固定模板、表头和列顺序。
2. 耗材标签号必填且必须存在。
3. 同一文件中的耗材标签号不得重复。
4. 板块、耗材说明、数量必须与系统当前卡片值一致；任一不一致时该行校验失败，不执行写回。
5. 公司必须存在。
6. 责任人工号必须存在并属于 MMP 管理范围。
7. 非 SOHU 普通责任人没有部门时，该行校验失败。
8. City 必须存在；Building 必须属于 City。
9. Floor 有值时必须属于全部启用状态的 Floor 清单，不要求属于当前 Building。
10. 耗材状态必须存在；报废状态禁止通过批量修改写入。
11. 主资产标签号有值时必须存在、未报废、不得等于当前耗材标签号，并且主资产责任人必须与模板中的当前耗材责任人一致。
12. 仓库有值时必须同时满足：仓库启用、仓库公司 = 模板当前公司、仓库用途为 `IU0001`（耗材库）或 `IU0003`（资产高耗库）。
13. 启用日期有值时按 `yyyy/MM/dd` 格式读取并校验合法日期；空白按覆盖策略写空。
14. 板块、耗材说明、数量以及其他非白名单字段禁止通过任何批量接口变更。

#### 4.6.4 校验结果展示

1. 用户上传文件后，先执行文件和全部数据行校验，不直接保存。
2. 校验结果需要展示给用户。
3. 校验失败时至少展示：行号、耗材标签号、失败原因。
4. 有多条错误时一次返回全部已识别错误，不要求用户逐条修改后重复发现下一条。
5. 任一行失败时明确提示本次文件未保存。
6. 全部行通过时展示“校验通过”，用户确认保存后才执行正式写入。
7. 原型仅演示“校验 → 结果 → 保存”闭环，不承担真实 Excel 解析；正式研发必须按真实工作簿内容逐行校验。

#### 4.6.5 保存策略

1. 全部行先完成校验，再进入保存。
2. 任一行校验失败，整份文件不保存。
3. 不允许部分成功。
4. 保存成功后，实际发生变化的耗材分别更新最后修改时间并生成耗材维护修改事务。
5. 页面提示 `上传成功！` 并刷新列表。

### 4.7 耗材操作历史

1. 按耗材标签号查询当前耗材事务。
2. 按操作时间从早到晚展示。
3. 相邻两条事务中发生变化的业务字段使用黄色背景标识。
4. 人工保存未发生字段变化时不生成历史。
5. 旧系统迁移历史与当前系统历史统一在该页签展示。

### 4.8 导出

1. 勾选耗材时提示 `确定要导出选中的数据吗?`，只导出勾选且有权限的数据。
2. 未勾选时提示 `确定要导出列表中的数据吗?`，导出当前查询条件下全部结果，不只导出当前分页。
3. 两种导出都叠加当前用户数据权限。
4. 文件名：`导出耗材卡片信息-日期.xlsx`。
5. 工作表名称：`低值耐用品明细`。

## 5. 校验

### 5.1 单条保存

| 校验项 | 规则 |
| --- | --- |
| 公司 | 必填且必须有效 |
| 责任人 | 必填且必须有效，并属于 MMP 管理范围 |
| 责任人部门 | 非 SOHU 普通员工必须存在部门；否则提示联系管理员 |
| City | 必填且必须有效 |
| Building | 必填且必须属于 City |
| Floor | 有值时必须属于全部启用 Floor 清单，不要求属于 Building |
| 序列号 | 最多 120 字；真实序列号唯一；去除首尾空格并忽略大小写进行唯一性比较，保存时保留原始大小写 |
| 耗材状态 | 必须有效；报废走专门报废功能 |
| 主资产 | 有值时必须有效、未报废、不得关联自身，且责任人必须与当前耗材责任人一致 |
| 仓库 | 新选择仓库必须启用、属于当前公司，且仓库用途为 `IU0001` 或 `IU0003`；历史已保存但退出候选的仓库可在公司未变化时原样保留 |
| 启用日期 | 有值保存；留空触发现有后台自动计算规则 |
| 字段白名单 | 页面和保存接口都必须校验，禁止修改非白名单字段 |

保存接口不能直接信任页面显示值：责任人姓名、部门、公司编码、主资产说明等派生字段必须根据主数据重新获取，防止通过接口伪造。

### 5.2 保存结果

1. 保存成功提示 `保存成功！`。
2. 保存成功后继续停留在当前耗材编辑页，并使用保存后的最新数据刷新当前页面。
3. 保存失败展示真实失败原因，保留当前输入，不产生半条历史。
4. 没有字段变化时提示 `耗材信息未发生变化`，继续停留编辑态，不更新最后修改时间，不生成事务。
5. 编辑态点击“取消”不触发保存，直接关闭编辑弹窗并返回耗材列表。

## 6. 后台保存规则

### 6.1 公司、板块与账套

1. 板块在耗材维护页面只读，修改责任人时不得自动把板块改成员工板块。
2. 保存时根据当前耗材公司 + 当前板块继续执行既有 Book Type / 账套映射规则。
3. 公司修改后使用新公司参与账套和财务归属计算。

### 6.2 成本中心

1. 耗材卡片中的成本中心在本页面只读。
2. 保存时继续使用既有成本中心规则。
3. 当前资产已有可用成本中心时继续使用当前值。
4. 当前值为空时，按照既有规则回退使用责任人员工成本中心。
5. `SOHU` 开头虚拟用户继续使用既有虚拟用户成本中心处理逻辑。

### 6.3 费用账户

保存时继续根据现有后台逻辑，结合至少以下业务信息重新计算费用账户和内部费用账户：

1. 成本中心。
2. 责任人。
3. 资产大类。
4. City。
5. 公司。
6. 服务。

费用账户计算失败时，本次保存失败并提示：`获取费用账户失败，请联系管理员！`。

本 PRD 只恢复既有财务保存规则，不重新定义 Book Type、成本中心或费用账户的具体计算公式；研发继续复用现有后台实现。

## 7. 后续操作及补充说明

### 7.1 主资产联动

耗材通过主资产标签号与主资产建立关联。主资产执行借用、归还、报废等正式操作后，关联低值耐用品可按既有业务规则同步责任人、仓库、状态、City、Building、Floor、部门、成本中心等信息；该联动属于跨业务流程，不在耗材维护页面通过额外按钮触发。

### 7.2 EBS

1. 低值耐用品不纳入 EBS 资产自动同步。
2. 耗材维护页面不提供手工 EBS 同步入口。
3. 低值耐用品的入库、编辑、借用、归还、报废和主资产联动不得生成低值耐用品 EBS 自动同步任务。
4. 普通资产与低值耐用品的 EBS 规则必须相互隔离。

### 7.3 历史数据

旧系统历史迁移后统一进入“资产操作历史”，页面不再单独提供旧系统历史页签。

### 7.4 保存后的事务

1. 人工修改耗材并实际发生字段变化后，生成耗材维护修改事务。
2. 事务保存修改后的业务快照和字段变化信息。
3. 事务进入现有资产事务处理链路。
4. 页面通过“资产操作历史”继续追溯本次人工修改。
