## 1. 规范层级与优先级

本文件是 UI 数值、布局和组件使用的统一维护位置；工程结构与数据访问见 `docs/ENGINEERING_GUIDELINES.md`，动效细节见 `docs/UI_MOTION_GUIDELINES.md`。历史说明中的查询标签 88px / 96px、详情默认 Descriptions 和所有点击强制 Loading 不再作为实现依据，分别按第 21、15、28 节执行。

实现页面时按以下优先级判断：

1. **明确业务规则与用户已确认口径**：审批节点、字段、按钮、是否可编辑、员工确认方式等业务规则优先级最高。
2. **本文件中的资产系统业务页面规则**：决定页面如何组织以及基础组件在具体业务场景中如何使用。
3. **ERP Figma Design System**：决定基础视觉 Token 和基础组件的视觉状态。
4. **Ant Design 默认能力**：当 ERP Figma 当前没有覆盖某个组件时，继续使用项目现有 Ant Design 规范，不自行创造新的“ERP 标准”。

### 1.1 组件能力不等于业务使用方式

ERP Design System 可以提供带图标按钮、Success Button、居中 Dialog、可删除 Tag、悬浮球等能力，但资产系统业务层仍可限制具体场景：

- 流程按钮仍统一纯文字，不因为基础 Button 支持图标就增加图标。
- “同意”等审批主操作仍按资产系统业务规则选择按钮类型，不因存在 Success Button 就自动改成绿色。
- 页面底部流程操作仍居中；Dialog Footer 则按 Dialog 规范处理，两者不可混淆。
- `Tag` 是通用标签组件，不替代资产系统统一业务状态出口 `StatusTag`。
- `Dropdown` 是操作菜单，不等同于表单选择器 `Select`。
- `Grid` 负责页面级布局，不替代资产系统详情字段的 `DetailGrid` 三列规则。
- `Affix`、`FloatButton` 等能力只在真实业务需要时使用，不因为设计系统存在组件就默认加入页面。

### 1.2 Figma 当前组件覆盖边界

当前已拆解的 ERP Figma 节点覆盖：

- Design Token：颜色、字体、间距、圆角、阴影、语义变量方向。
- 已确认基础组件：Button、Link、全局提示、Loading、Skeleton、Dialog、Input、Radio、Checkbox、Switch、Breadcrumb、Dropdown、Pagination、Tag、Badge、Popover、Grid、Layout、Divider、Anchor、Affix、FloatButton。

当前节点**仍未提供可作为 ERP 本地标准的完整 Select、Table、Form、DatePicker、Upload 规范**。因此：

- 不得凭经验补写这些未覆盖组件的 ERP 高度、圆角、边框或状态规范。
- 继续优先使用 Ant Design 6.x 和项目现有公共组件。
- 按钮、输入框等不得另写一套样式；既有 `AntButton / AntInput / AntSelect / AntRadio / AntModal / AntTable` 封装按适用场景复用。
- `Dropdown ≠ Select`，不得因为已有下拉菜单规范就推断表单选择器规范已经完整。
- 后续取得对应 ERP Figma 组件节点后，再补充进本文件。

---

### 1.3 桌面端与移动端的适用边界

- 颜色、文字语义、状态与操作命名跨端保持一致；布局和选择方式按使用端设计。
- 第三部分及基础组件中的桌面端尺寸、三列详情、三列查询、页面按钮居中、桌面Modal宽度与Footer规则用于桌面端；移动端按第四部分执行。
- 移动端采用单列卡片、底部选择层或独立选择页，继续使用同一业务候选、标识及权限；复用业务数据不要求复用桌面端表格和弹窗外观。
- 已确认的页面结构与业务交互优先于通用版型。UI调整涉及新增字段、状态、统计或权限时，先更新对应业务规则；不能以套用参考稿为由扩大功能。

### 1.4 历史作品的吸收方式

- 历史作品提供页面模式参考，不覆盖本规范已确认的主题、尺寸和业务规则。先辨认任务，再选择模式；不按截图逐页堆叠组件。
- 优先研究完整页面及正常、展开、空、失败等关联状态。草稿、备选、过程稿和走查标注用于理解问题，不视为已发布标准。
- 从截图可确认信息层级、版式和可见状态；条件暂存、返回恢复、请求失败和权限行为属于本项目实施要求，须在后续实现时验证。
- 同一页面可以组合下表模式，但只保留一个清晰的主要任务；没有业务依据时不新增指标、消息、AI、审批或发布能力。

| 用户任务 | PC 默认模式 | 移动端默认模式 | 规则入口 |
|---|---|---|---|
| 查找并处理一批记录 | 筛选区、工具区、表格、条件出现的批量条 | 搜索、筛选页、单列摘要卡片 | 第20、21、29A.2节 |
| 阅读或办理单据 | 对象标识、分组详情、明细、流程记录 | 对象标识、分组内容或Tab、底部动作 | 第15、23、29A.4节 |
| 比较指标与定位异常 | 期间/范围、分组指标表、明细下钻 | 关键指标与阶段卡片、详情下钻 | 第14.4、29A.8节 |
| 配置并核对结果 | 分步配置、编辑与预览并列、最终确认 | 单列配置、独立预览、返回继续编辑 | 第22.5节 |
| 查看耗时任务结果 | 基本信息、局部处理状态、结果、记录 | 同序单列、就近状态、可达的结果操作 | 第28.2、29A.7节 |

# 第一部分：ERP Design System

## 2. Design Token 总则

页面和公共组件应优先读取统一 Theme / Design Token，禁止在业务页面中反复硬编码视觉值。

不推荐：

```jsx
<div className="text-blue-500 border-gray-200 rounded-lg shadow-md" />
```

推荐思路：

```text
业务语义
  ↓
公共组件 / Ant Design Component Token
  ↓
ERP Semantic Token
  ↓
ERP 基础色板
```

业务页面只表达“这是主操作 / 危险状态 / 次要文字 / Card”，不自行决定具体色值、阴影和圆角。

### 2.1 语义 Token 优先于基础色号

Figma 新增亮色 / 暗色语义变量对照，说明设计系统正在从“直接使用 blue/gray 色号”转向“先表达用途，再由 Theme 映射实际色值”。

资产系统应优先建立和使用以下语义层：

| 类别 | 语义角色示例 |
|---|---|
| 背景 | 页面底色、Card/容器底色、输入区底色、覆盖层 |
| 文字 | 主文字、次要文字、第三级文字、占位符、禁用、品牌色、成功/警告/危险 |
| 图标 | 主图标、次要图标、品牌、成功/警告/危险、禁用 |
| 边框 | 分割线、容器描边、激活指示线 |

规则：

- 业务页面优先引用“主文字 / 次要文字 / 分割线 / 危险”等语义，不直接引用 `gray/7`、`red/6` 等基础色号。
- 亮色 / 暗色的具体映射由 Theme 负责，业务组件不维护两套颜色分支。
- Figma 语义变量表中出现的聊天、通讯录、消息气泡等场景仅是设计系统应用示例，**不得复制成资产系统业务规则**。
- `StatusTag`、Button、Input、Divider、Popover 等公共组件应逐步从统一语义 Token 取值。

### 3.1 主品牌色

ERP 核心主色：

| Token | 色值 | 典型用途 |
|---|---|---|
| Blue-1 | `#E5F1FF` | 蓝色弱背景、加强提示背景 |
| Blue-2 | `#C2DCFF` | 禁用、弱选中 |
| Blue-3 | `#96C0FF` | 禁用文字、弱交互 |
| Blue-4 | `#6AA1FF` | 辅助蓝 |
| Blue-6 | `#145CFF` | **ERP 主品牌色、Primary、标准 Link** |
| Blue-7 | `#0D42D2` | Active / Press |
| Blue-10 | `#17204D` | 最深蓝扩展 |

### 3.2 Figma 源文件存在差异的色值

当前 Figma 源文件在以下 Token 上存在“色板文字”和“实际组件绑定 Style”不一致：

- Blue-5：色板文字与实际组件 Style 不一致。
- Blue-9：色板文字与实际 Style 不一致。

处理原则：

- **业务页面不得硬编码 Blue-5、Blue-9。**
- 后续接入 Theme 时优先读取正式设计 Token / 组件绑定 Style。
- 在设计侧确认最终标准值前，不在项目文档中人为指定唯一值。

### 3.4 语义色

资产系统状态和基础反馈优先使用 ERP 第 6 阶语义色：

| 语义 | Token | 色值 |
|---|---|---|

### 4.3 资产系统字体使用规则

- 桌面业务页面以面包屑承载页面名称，正文不重复展示页面大标题；独立的全局标题栏使用T5（20/28）。
- 普通正文、详情字段、按钮文字优先对应 T2（14/20）。
- 常规业务表格保持正文 14px；信息密度通过第20.3节的行高控制，不为压缩行高将正文缩为12px。T1继续用于辅助信息；原有独立报表等明确的字体规则按其场景保留。
- 个人工作台业务 Card 为高密度二级分区，继续采用项目统一紧凑标题，不因 Figma 的 T4 定义机械放大为 18px。
- 不使用超大字号装饰普通 B 端业务页面。

## 5. 间距 Spacing

Figma 全局布局梯度：

**4 / 8 / 16 / 24 / 32 / 40px**

适用于横向 H-spacing 与纵向 V-spacing。

资产系统建议：

| 场景 | 推荐间距 |
|---|---:|
| Icon 与文字 | 4px |
| 紧密操作 / 小组件内部 | 8px |
| 个人工作台 Card 间距 | 16px |
| 区块内较大分组 | 24px |
| 页面级大分区 | 32px |
| 超大留白 | 40px |

说明：

- Figma 基础组件内部仍存在 12px 等组件级间距，因此全局梯度不等于禁止其他组件内部尺寸。
- 页面底部流程按钮当前统一间距 12px，继续保留，不为了凑全局梯度机械改成 8px 或 16px。

## 6. 圆角 Radius

Figma 设计语言中已明确展示：

| Token | 数值 |
|---|---:|
| radius 0 | 2px |
| radius 1 | 4px |
| radius 2 | 6px |
| radius 3 | 8px |
| radius 5 | 10px |
| radius 6 | 16px |
| radius 7 | 20px |
| radius 8 | Full |

同时 Dialog 实际组件明确使用 **12px** 圆角。

### 6.1 已知缺口

- 当前圆角梯度节点没有展示 radius 4 的最终值。
- Dialog 的 12px 不在上述展示梯度中，说明实际体系可能同时存在“基础梯度”和“组件特定圆角”。

因此：

- 不得自行猜测 radius 4。
- Button 明确按 4px。
- Message 明确按 8px。
- Dialog 明确按 12px。
- 其他组件优先走 Ant Design / 公共组件 Token，未确认前不在业务页自行创建新圆角标准。

## 7. 阴影 Shadow

ERP Figma 将阴影按层级分为 S1～S4：

| 阴影 | 典型场景 |
|---|---|
| S1 | 顶导、侧导 |
| S2 | Card |
| S3 | Hover、点击、悬浮状态 |
| S4 | Dialog、Popover 等高层浮层组件 |

阴影采用多层叠加以模拟物理层级，不建议业务页面自行写单层 `box-shadow`。

### 7.1 S4 明确示例

```css
box-shadow:
  0 1px 8px rgba(0, 0, 0, 0.05),
  0 7px 14px 2px rgba(0, 0, 0, 0.07),
  0 8px 16px 4px rgba(0, 0, 0, 0.08);
```

### 7.2 资产系统使用规则

- 单层个人工作台画布规则继续保留，禁止再套大面积白色外壳和页面级重阴影。
- Figma 的 S2 表示 Card 可以拥有层级阴影，并不代表个人工作台每个紧凑业务 Card 都必须加重阴影。
- 高密度业务 Card 优先保持轻边框 / 弱层级；Dialog、Popover、Dropdown 等浮层必须明显高于 Card。
- 阴影统一在 Theme 或公共组件层实现，业务页面不得各自声明一套阴影。

# 第二部分：ERP 基础组件

## 8. Button 按钮

### 8.1 尺寸

| Size | 高度 |
|---|---:|
| Mini | 24px |
| Small | 28px |
| Medium | 32px |
| Large | 36px |

标准业务按钮：

- 默认高度：32px
- 最小宽度：72px
- 圆角：4px
- 字体：T2 14/20

### 8.2 类型

Figma 提供：

- Primary
- Secondary
- Primary Outline
- Secondary Outline
- Text
- Icon Button

### 8.3 状态

按钮至少支持：

- Default
- Hover
- Active / Press
- Disabled
- Loading

核心状态：

- Default：Blue-6 `#145CFF`
- Active / Press：Blue-7 `#0D42D2`
- Disabled：Blue-2 / 弱灰阶
- Hover：读取正式 Blue-5 Token，当前不在业务页硬编码

### 8.4 语义按钮

基础组件提供 Standard / Success / Warning / Danger 四类能力，但资产系统业务层决定是否使用。

资产系统流程按钮继续执行：

- 主操作：`type="primary"`
- 驳回、删除等危险操作：`danger`
- 返回、取消：默认按钮
- 提交、同意、驳回、确认、取消、返回、加签、转签等**业务流程按钮不带图标**
- 搜索、选择、添加、上传、下载、删除、刷新等工具按钮可以使用含义明确的图标

语义：Standard / Success / Warning / Danger。

尺寸可对应 12px、14px、16px 文本层级。

资产系统规则：

- 在 `DetailItem` / `Descriptions.Item` 内优先使用 `Button type="link" size="small" className="px-0"` 或项目统一 Link 封装。

定义：由用户操作触发的轻量级全局反馈。

标准视觉：

- Icon：16px
- Icon 与文字间距：4px
- 水平 Padding：16px
- 垂直 Padding：12px
- 圆角：8px

2. **加强样式**：语义浅色背景 + 对应语义色 Border。

所有用户操作必须有明确反馈：

```text
点击操作 → 按实际处理状态反馈 → 成功 / 失败提示 → 数据更新
```

## 11. Loading

Loading 用于组件、局部区块等待异步数据或渲染。

尺寸：

|---|---:|
| Small | 12 |
| Default | 16 |
| Large | 20 |
| Custom | 按明确场景自定义 |

样式可分：

- 强化加载
- 普通加载
- 反白加载

- 无文字：仅 Spinner
- 左右布局：Spinner + “加载中...”
- 上下布局：Spinner 在上、文字在下

### 11.1 区块 Loading

局部容器加载优先保留原内容结构，并使用：

```text

  ↓
半透明白色遮罩 rgba(255,255,255,0.6)
  ↓
轻度 backdrop blur
  ↓
中央 Spinner / Spinner + 文案
```

避免因每次请求都把区块替换为空白而产生明显跳动。

## 12. Skeleton 骨架屏

Skeleton 只用于**内容形态可预估的首次加载**。

核心规则：

- 只在第一次加载数据时优先使用 Skeleton。
- 已有内容后的刷新、提交或局部重载优先使用 Loading Overlay，而不是反复切回 Skeleton。
- 图片 → Rectangle
- Avatar → Circle
- 文本 → Long Bar
- 渐变：Gray-2 `#F2F5FA` → Gray-3 `#E2E6F0`

业务页面不得另建一套 `#f0f0f0 → #e0e0e0` 等自定义 Skeleton 灰阶。

## 13. Dialog / Modal

Dialog 是在当前页面打开的浮层，用于承载相关操作。

### 13.1 构成

```text
标题区
内容区
按钮区
```

标准：

- 水平内边距：20px
- Header / Footer 垂直内边距：12px
- Body 垂直内边距：16px
- 普通业务弹窗不单独恢复 24px 以上通用内边距；打印预览、图片审核等特殊画布须明确声明适用范围
- Border：Gray-4
- 圆角：12px
- 阴影：S4
- Close Icon：16px，外层可点击区域约 24px
- Dialog 内只保留一个主标题，不重复放蓝色二级标题
- 弹窗相对承载它的内容视口水平、垂直居中，不以固定顶部偏移模拟居中。内容超出可用高度时只滚动正文，标题和底部操作保持可见；底部不能遮挡最后一个字段。

### 13.2 宽度

Figma 当前存在以下源文件差异：

- 基础规则：Small 400 / Medium 560 / Large 720px
- 实际大号示例：700px

资产系统在此基础上增加统一业务上限：

- Small：400px
- Medium：560px
- Large：700～720px
- 数据密集型弹窗默认最大宽度为 **960px**
- **四列表单型弹窗允许例外放宽到 1000px**，前提是该宽度用于正常承载四列 DetailGrid，而不是为了宽表格无限扩张
- 实际可用宽度同时不得超过视口宽度减 32px
- 四列表单型弹窗在 1000px 内应优先调整栅格、标签宽度和字段 span，**表单本体不使用横向滚动**
- 表格型/列表选择型弹窗字段超宽时继续在 Table 内部使用横向滚动，不继续放大 Modal
- 业务页面不得再直接使用 1120 / 1200 / `94vw` 等方式把弹窗铺满屏幕

公共默认仍以 `--mmp-modal-max-width: 960px` 为统一出口；四列表单例外必须使用明确的业务 class 单独声明 1000px 上限。

### 13.3 Footer 布局

Figma 提供：

1. **对角线布局（优选）**：标题左、操作区右；Footer 按钮右对齐。
2. 居中线布局：标题、内容和 Footer 居中。

资产系统 V2.3 统一采用：

- 普通、新增、编辑和确认 Dialog 的 Footer 整体右对齐；取消/返回在左，保存/确认等主要操作在最右。
- 弹窗本体居中与 Footer 对齐分别处理；不得因为弹窗用于确认就自动将 Footer 居中。已有明确的特殊业务布局不通过全局选择器覆盖。
- 多选弹窗若需要展示“已选择 X 项”，可左侧显示选择数量、右侧显示操作按钮。
- **页面底部流程操作仍统一居中**，不要因为 Modal Footer 右对齐而修改审批页、办理页等页面级按钮布局。

### 13.4 选择型弹窗

通用列表选择场景统一使用 `SelectModal`，底层使用 Ant Design `Modal`：

- 查询区统一使用 `QueryBar + QueryItem`，由 QueryBar 按自身实际可用宽度自动决定列数，业务页面不得自行指定两列或三列。
- 查询区同时受页面断点与自身容器限制：页面列数上限按第21节，容器不足时额外降列，保障单个字段的标签和输入区可读。具体计算由 `src/components/QueryBar.jsx` 单点维护，不在页面或文档另写一套容器阈值。
- 弹窗按查询区实际可用宽度决定列数，不按Modal声明宽度或宽屏窗口强塞三列；小弹窗可自然降为单列。
- 查询操作按第21节成组放入末行空位，末行排满时另起一行右对齐；不再在三列栅格右侧另设竖排按钮栏。
- 输入控件与表格使用 Ant Design 原生组件。
- Table 是否出现横向滚动按各列合理最小宽度之和是否超过表格可用宽度决定，不按“超过几列”判断。
- Table columns 应为序号、状态、日期、编号、说明、配置等字段声明合理 `width`；选择弹窗统一使用 `scroll={{ x: 'max-content' }}`，只有真实超宽时出现横向滚动。
- 表格字段过多时保持弹窗最大 960px，通过 Table 内部横向滚动查看，不继续扩大 Modal。
- Footer 默认右对齐，顺序为【取消】【确定】；多选场景可在左侧展示“已选择 X 项”。
- 普通标题使用纯文字，不为普通业务弹窗额外增加装饰性图标。
- 不在业务页面自行复制一套超宽选择弹窗、查询栅格或横向滚动判断。

## 13A. Input 输入框

### 13A.1 已确认类型

Figma 已覆盖：

- 单行输入框
- Textarea
- 前后置内容输入框
- 组合输入框
- IP 地址输入框
- 搜索框
- 可清空输入框
- 密码输入框

资产系统仍优先使用 Ant Design `Input` / `Input.TextArea` / 公共封装，不在业务页手写边框、状态和图标。

### 13A.2 状态

输入框至少包含：

- Normal
- Hover
- Click / Focused
- Disabled
- Error
- Success

规则：

- 校验反馈优先通过 Ant Design Form / Input 状态统一输出，不在单页自己实现红绿边框。
- 只读业务字段直接展示文本或状态，不用 readOnly/disabled 输入框模拟只读。
- 项目现有“点击只读输入框打开 SelectModal”的选择型输入场景继续按公共交互规则实现，它属于业务选择入口，不代表普通只读字段也要画成 Input。

### 13A.3 尺寸

| Size | 高度 |
|---|---:|
| Small | 28px |
| Medium | 32px |
| Large | 36px |

规则：

- 默认高度：32px。
- 同一业务场景内 Input / Select 等表单控件高度保持一致。
- 宽度由内容区和表单栅格决定，不为了“看起来完整”统一拉满无关字段。
- 具体圆角、边框色等仍通过 Theme / Ant Design Component Token 落地，不在业务页重复硬编码。

## 13B. Radio / Checkbox / Switch

### 13B.1 Radio

Figma 已覆盖基础型与按钮型 Radio。

状态：Normal / Hover / Selected / Disabled，并区分未选中、已选中及禁用态。

按钮型尺寸：

| Size | 高度 |
|---|---:|
| Small | 24px |
| Medium | 32px |
| Large | 36px |

资产系统优先使用 Ant Design `Radio` / `Radio.Group` / `Radio.Button`。

### 13B.2 Checkbox

Figma 已覆盖：

- 未选中
- 已选中
- 部分选中（Indeterminate）
- 各自禁用态
- 基础型 / 按钮型
- Normal / Hover / Selected / Disabled

Figma 已覆盖 Normal / Disabled 基础状态。

资产系统规则：

- Switch 只用于“立即切换并能明确理解开/关结果”的布尔配置。
- 需要填写表单后统一提交、危险确认或存在复杂审批含义的动作，不用 Switch 代替正式按钮或表单字段。

## 13C. Breadcrumb 面包屑

Figma 定义面包屑用于识别当前页面在层级结构中的位置，并支持向上返回。

能力包括：

- 自定义分隔符
- 自定义图标
- 带下拉菜单
- 层级过多时省略
- 长文案截断

尺寸：12px / 14px；**页面级导航优先 14px**。

资产系统规则：

- 多层内部页面优先使用 Ant Design `Breadcrumb`，保持当前项目已有动态面包屑能力。
- 真实可返回的上级使用深色可点击链接；没有有效返回动作的分组层级使用灰色纯文本。当前页使用主题蓝且不可点击，并声明 `aria-current="page"`。
- 所有桌面业务页面以面包屑替代与侧栏、路径重复的大标题，移除标题专属的空白行、外壳和间距；卡片分区、弹窗标题及报表正文标题保留。移动端独立导航栏继续承担返回和页面定位，不套用桌面正文标题规则。层级按真实信息架构配置，不为套用三级示例制造无效上级链接；业务单号、对象名等必要身份信息继续保留。
- Figma 示例以 8 个中文字符作为长文案截断参考；实际实现优先使用稳定的单行省略，不让超长页面名撑坏布局。
- 面包屑是导航，不替代页面底部“返回”操作；流程页仍按业务保留底部返回按钮。

## 13D. Dropdown 下拉菜单

Figma 已覆盖：

- 文字型下拉菜单
- 按钮型下拉菜单
- 带图标下拉菜单
- 多级菜单
- Normal / Hover / Click / Disabled / Selected
- 小 / 中 / 大尺寸

资产系统规则：

- Dropdown 用于一组“操作命令”的展开选择，例如更多操作、批量动作等。
- **Dropdown 不等于 Select**：字段取值仍使用 Ant Design `Select` 或项目统一选择弹窗，不能用 Dropdown 替代表单控件。
- 菜单项只保留当前上下文可执行动作；危险动作继续走二次确认。
- 多级菜单只有真实存在层级关系时才使用，不为收纳按钮机械增加层级。

- 基础分页
- 显示数据总量
- 页面展示数量选择
- 快速跳转
- 简易分页器
- Normal / Hover / Selected / Disabled

尺寸：

| Size | 高度 |
|---|---:|
| Medium | 24px |
| Large | 32px |

规则：

- 列表页继续使用 Ant Design Pagination / Table Pagination，不自行重画。
- 业务列表默认保持紧凑密度，优先映射 Figma Medium 24px；若现有 Theme 尚未统一，不在单页用 CSS 强制改尺寸。
- “共 X 条”继续按资产系统规则放在列表右上角；Pagination 是否同时显示 total 由页面信息密度决定，不重复堆两份相同总数。

## 13G. Popover 气泡卡片

- 操作型气泡
- 带图标气泡
- 顶 / 底 / 左 / 右方向

尺寸：

- 最小宽度：160px。
- 最大宽度不强制固定，设计建议不超过 360px。

资产系统规则：

- 纯文字 Popover 适合字段解释、名称补充等轻量信息。
- 操作型 Popover 适合低干扰的轻确认或小操作。
- 删除、报废、停用等高风险动作仍优先使用 `Popconfirm` / Dialog，不因 Popover 可放按钮就降低确认强度。

## 13H. Grid / Layout

### 13H.1 Grid

Figma 支持 12 栅格和 24 栅格，默认 12 栅格；响应断点：

**768 / 992 / 1200 / 1920**。

资产系统规则：

- ERP Grid 负责页面级区块、查询区、响应式列宽等整体布局。
- 资产系统 `DetailGrid` 负责详情字段稳定三列对齐，两者职责不同，**不得用 12 栅格推翻详情三列业务规则**。
- 后台查询区按第21节的走查专用断点实现三/二/一列；上述ERP通用断点不覆盖已确认的筛选布局。选择弹窗按第13.4节的实际容器宽度收缩，页面不各自定义断点。

### 13H.2 Layout

Figma 常见布局示例包含 Header、Aside、Main、Footer，其中展示过 Header 60px、Aside 200px、Footer 80px 的组合，并支持自定义宽高。

资产系统规则：

- 这些值视为设计系统常见版型示例，**不作为资产系统现有应用壳层的强制改造值**。
- 主框架尺寸统一由项目 Layout / Theme 管理，业务页面不得自行定义另一套 Header / Aside 宽高。
- Main 区域优先自动填充剩余空间。

## 13I. Divider 分割线

Figma 对 Divider 的核心定义：**只用于内容分组与层级区隔，不承载操作含义；优先通过留白建立层级，仅在需要明确边界时使用。**

基础规则：

| 项目 | 规则 |
|---|---|
| 颜色 | Gray-4 |
| 粗细 | 1px |
| 方向 | 水平 / 垂直 |
| 推荐间距 | spacing 8～24px |
| 竖向 Divider | 默认高度约 12px，两侧各 spacing/8 |

资产系统规则：

- 页面分组优先顺序：**留白 → 分组结构 → 必要的 Divider → 新增容器**。
- 不为每个字段组都增加边框 / Divider，避免 Card 套 Card、边框套边框。
- 水平 Divider 用于同层级纵向内容区隔；竖向 Divider 只用于同一行并列信息或操作项。
- Divider 不可当作可点击控件、步骤状态或权限边界。

## 13J. Anchor / Affix / FloatButton

这些组件已经出现在 ERP Library，但资产系统只按真实业务场景使用：

- **Anchor**：适用于很长的单页内容，需要快速跳转到稳定分区时使用；普通审批 / 办理页不默认增加。
- **Affix**：适用于确实需要滚动时持续可见的操作或导航；不得与页面底部固定流程操作形成两套重复入口。
- **FloatButton**：当前资产系统不作为默认交互模式；只有明确存在跨页面高频快捷动作时再使用。

# 第三部分：资产系统业务页面规范

## 14. 页面画布与区块

### 14.1 个人工作台

- 页面嵌入个人工作台后只保留一层画布，不重复增加独立背景、圆角大容器或页面级外层阴影。
- 页面内容区块优先使用 Ant Design `Card`，统一 `size="small"`。
- 相邻 Card 默认间距 16px，使用 `Space direction="vertical" size={16}` 或等价布局。
- 桌面业务页面正文不再放置与面包屑重复的标题及独立标题占位行；查询、列表、详情、创建和审批页统一执行。业务单号、对象名称、状态及操作保留，按业务信息展示，不随标题一起删除。
- 不使用自定义 `section` 模拟 Card 标题栏、边框和内边距。

### 14.2 后台管理页面

- 继续优先复用项目现有布局、QueryBar、Table、Drawer / Modal 结构。
- 页面底色使用 `#F2F5FA`，查询、数据等实际业务区块使用白色内容卡片；通过留白建立层次，避免整页连续白底和多重白色外壳。主按钮、链接、选中态统一使用主题蓝 `#145CFF`，弱选中/批量条使用 `#E5F1FF`。
- 主题值集中由 Theme / 公共组件输出，不在页面复制取色值。工作台单层画布和移动端独立布局仍按各自规则，不因后台卡片式布局而增加外壳。
- 不为追求“ERP 化”给后台页面增加无意义渐变、大面积阴影、玻璃拟态或运营化视觉。
- B 端信息密度、可扫描性和字段可操作性优先于装饰。
- 桌面端演示以 1440×900 完整可用为基准；移动端独立页面按其已确认布局验证，不套用桌面端列数。
- 列表网格位于纵向 Flex 容器并承担剩余空间时，明确使用 `grid-auto-rows: max-content`、`align-content: start`，避免卡片被纵向拉伸。

### 14.3 导航与内容宽度

- 顶部负责系统身份和全局入口，侧栏负责模块层级，面包屑负责当前位置；不要用多套导航重复展示同一层级。
- 后台侧栏采用浅色背景；当前实现展开224px、收起64px，通过底部按钮切换。收折按钮支持Tab与Enter/Space；菜单支持方向键、Enter和Escape。展开分组与业务选中状态分别维护，展开其他分组不切换正文。
- 侧栏收折只改变占用空间，不改变当前模块、展开路径和业务状态；选中项与展开项分别表达。收起后图标需有可读名称提示，键盘聚焦也能取得名称与子菜单。
- 深层菜单按业务分组逐层展开，当前页面所属路径可定位；图标风格、尺寸与文字起点保持一致。一级菜单使用各不相同且符合业务含义的图标，不再复用同一图标代表不同主模块；图标不替代文字名称及可访问提示。
- 主区按侧栏变化重新计算可用宽度。数据密集列表利用可用宽度；阅读型长文可设置内容最大宽度并居中，避免超长行。不得把会议页的1200px内容上限或版权侧栏235/56px直接设为全站标准。
- 收折、浏览器缩放与窄容器均须检查；菜单不能遮住查询动作，正文不得因固定画板宽度横向溢出。

### 14.4 指标看板与比较

- 先展示统计期间和作用范围，再展示指标；全局条件作用于哪些区块必须清楚，局部条件靠近其区块。
- 对同一对象的多类指标使用分组表头；指标值、单位、比较期间、变化方向各有明确含义。同比、环比和绝对变化不能只显示一个无标签百分数。
- 上升不自动代表良好、下降不自动代表异常；方向用箭头或正负号，结果好坏按业务定义的语义色。不得照搬历史看板的红涨绿跌到全部指标。
- 指标说明入口解释口径、时间范围和计算规则；无正式规则不创造健康度评分或阈值。缺失、零值与不适用分别处理，沿用业务字段定义。
- 可下钻值提供明确链接与对应明细；进入明细携带当前期间和范围，返回保持原上下文。不存在下钻能力的值不着色伪装链接。
- 看板可吸收分组与主次关系，不复制装饰性渐变、无依据的排名和占位数据；盘点报表的独立格式继续按其专属规则。

## 15. DetailGrid 与详情字段布局

### 15.1 统一三列

详情/只读 Modal 默认使用三列 `DetailGrid`；只有用户明确确认特殊业务或视觉列数时才例外，不因旧截图较密就沿用四列。个人工作台中需要多个 Card 严格保持三列字段边界一致时：

- 统一使用公共 `DetailGrid` + `DetailItem`。
- 不要分别使用多个 `Descriptions` 依赖浏览器自动计算列宽。
- `DetailGrid` 默认三列，每组由“96px 标签列 + 等分内容列”组成。
- 不同 Card 使用同一默认配置，保证第一、第二、第三列起始位置一致。
- `DetailGrid` 的边框、背景、文字读取 Ant Design / ERP Theme Token，页面不得重复硬编码。

### 15.2 何时仍可使用 Descriptions

单独存在、结构简单、且不要求与其他 Card 像素级对齐的详情区域，可以继续使用：

```jsx
<Descriptions bordered size="small" column={3} />
```

不得再把 `Descriptions` 写成个人工作台多 Card 详情的默认方案。

### 15.3 长文本

申请原因、退库原因、备注、配置、详细说明、长使用说明等字段：

- 默认 `DetailItem span={3}` 单独一行，并从完整新行开始；上一行只有一到两组字段时不得把整行字段接入剩余空位。
- 仅当内容和业务结构明确适合两列时才使用 `span={2}`。
- 不为了视觉填满一行擅自改变长文本宽度。

### 15.4 删除字段后的自然补位

删除详情字段后：

- **禁止为了填满一行机械拉宽相邻字段。**
- 先判断下一行字段语义与长度。
- 普通短字段（状态、日期、仓库、责任人、数量、资产标记等）可以自然上移补位。
- 长文本 / 原因 / 说明 / 备注 / 配置等继续保持独立整行，必要时允许上一行留空。
- 原则：**自然补位优先，不强行拉宽。**

### 15.5 真正的空位

需要保留空列时：

- 使用真实网格空结构。
- 不使用 `\u00a0`、空格字符、空标签文字等可见文本占位。
- 不依赖 Ant Design `Descriptions` 的空 Item 去“骗”自动布局；需要严格留空时使用 `DetailGrid` 显式网格。

### 15.6 空值与滚动

- 空值统一展示 `-`，不混用“无”“暂无”“空”。
- 正常详情 Card 默认不得出现独立横向滚动条。
- `DetailGrid` 只有在明确设置 `minWidth` 且确实无法保持可读性时才开启横向滚动。
- 页面空间不足时优先保持三列结构稳定，不在单字段上临时改列宽。
- 只读字段直接展示文本或状态，不用 disabled/readOnly 输入框模拟查看态；可点击的弹窗选择字段属于操作入口，按工程规范实现。
- 原型业务页面不展示“演示记录、未连接外部系统、真实定时发送尚未接入”等实施说明；数据来源、接入状态和运行限制记录在项目交付文档。后台定时通知规则不作为查询页说明横幅。
- “原资产标签号”“主资产标签号”等长标签须完整显示，不为了压缩栅格截断名称。
- 不需要内部滚动的原因、说明等内容应自动增高，避免固定高度 TextArea 或栅格产生独立滚动条。

- 标签号、单据号等链接同时保留光标拖选和复制文本能力。
- 业务列表 Card 右上角默认展示当前筛选结果“共 X 条”，可与常驻工具并列；依赖勾选的动作按第21.1节放入独立批量操作条。

## 20. 表格 Table

当前 ERP Figma 节点未提供完整本地 Table 组件规范，因此现阶段：

- 继续使用 Ant Design Table。
- 业务表格默认 `size="small"`、`bordered`。
- 只展示当前操作所需核心字段。
- 禁止通过 `scroll={{ x: 2000 }}` 等方式一次性暴力展示全部字段。
- 非核心字段放入详情区、Drawer 或 Modal。
- 列表必须具备空状态、查询无结果、查询、重置、分页，并在真实等待时展示 Loading；不为同步筛选伪造等待。
- Modal 中核算选择列、固定列、普通列总宽度与内容宽度；超宽时按第 13.4 节设置表格内部滚动，检查最右列背景、边框和裁切。
- 表格内 Input / InputNumber / Select 受单元格可用宽度约束；InputNumber 显式 `width: 100%` 并允许收缩，不沿用固定默认宽度造成跨列溢出。
- 多个独立业务入口分别使用真实动作名，不按状态把不同入口合并成含义不明的动态按钮。
- 正文密度遵循第4.3及20.3节，不通过缩小字号解决行高与长文本问题。
- Pagination 已有 ERP 基础规范，但仍通过 Ant Design Table / Pagination 公共能力统一落地，不在 Table 页面单独重画。

### 20.0 自动列宽

新接入的 PC 只读表格使用公共 `AutoWidthTable`；已覆盖盘点报表，并按2026-10-29用户授权接入申请与资产报表查询主表；不自动改变其他页面。列宽按表头、格式化内容的实际字体像素宽度、左右内边距、边框、安全余量及排序/筛选图标计算；内容限制在字段类型边界内，完整叶子表头宽度作为硬下限；参数权威定义在 `src/components/tableSizing/columnSizing.js`，页面只声明类型和显示文本，不重复硬编码列宽。

| 类型 | 最小～最大宽度（px） | 内容取样 | 空余空间 |
|---|---|---|---|
| 名称 text | 120～280 | 第95百分位 | 不伸展 |
| 分类/指标 label | 96～320 | 最长值 | 不伸展 |
| 描述 description | 180～360 | 第95百分位 | 权重2 |
| 编号 code | 140～280 | 最长值 | 不伸展 |
| 数量 number | 88～180 | 最长值 | 不伸展 |
| 金额 money | 130～220 | 最长值 | 不伸展 |
| 比例 percent | 112～180 | 最长值 | 不伸展 |
| 日期 date | 112～160 | 最长值 | 不伸展 |
| 年份 year | 80～110 | 最长值 | 不伸展 |
| 状态 status | 96～180 | 全部已提供枚举；未提供时取数据最长值 | 不伸展 |
| 序号 index | 64～96 | 最长值 | 不伸展 |

- 先格式化金额、日期、百分比及零值再测量；自定义渲染提供对应纯文本测量函数，图标占位计入文本/额外空间。合并小计标题不当作单列普通内容。
- 叶子表头单行显示，宽度不被类型的内容上限截断；分组表头按子列宽度之和校验，受最大宽度限制仍不足时允许组标题换行。分类、指标使用label类型，按最长名称计算，不用P95忽略少数较长分类。名称/长文本超出上限省略并通过悬停查看全文，编码等超过上限时允许换行。
- 名称、分类、指标不自动分摊剩余宽度；剩余宽度只在描述等可伸展列或显式flex配置的上限内分配；总宽超出容器时由 Table 内部横向滚动，页面本身不溢出。紧凑模式保持内容计算宽度，不拉满容器；盘点三列表格原620px容器上限保留，承载该表的白底Card按页面可用宽度铺满，卡片宽度与表格宽度分别控制。
- 同一挂载实例记录各列固有宽度，翻页/筛选不收窄，新增长内容可扩宽；容器伸展量不进缓存，因此窗口收窄可回收空间。字体和主题字号变化重新测量；空数据使用表头和类型边界。
- 此规则只控制页面展示，Excel 列宽、行高、合并及单元格位置仍按各导出模板独立定义。

### 20.1 层级与分组表头

- 真实存在父子关系的列表使用展开箭头与缩进表达层级；同层级名称起点一致，子级有稳定缩进。展开箭头与名称链接分别承担展开、进入详情的动作。
- 汇总、明细、小计通过层级、字重或弱背景区分；汇总行不伪装成普通明细，不为增加层级感改动业务分组或计算口径。
- 多个字段共同描述一个指标时，可使用分组表头，例如金额、数量或期间分项；组名说明共同业务含义，子列保留名称、单位及必要时间范围。
- 横向滚动时保留识别记录所需的关键列；固定操作列按实际操作需要设置。不得以增加固定列挤占正文。

### 20.2 单元格的信息主次

- 单元格先展示用户判断所需的主值，确有必要的构成、来源或补充说明可用次级文字另起一行。
- 次级信息不能承载唯一的状态、错误原因或关键限制；文字仍须清晰可读。
- 前后值、变化量、总量和构成须有明确名称；数值格式按第17A节，统计含义和公式按业务PRD。
- 附件、图片入口靠近其说明或审核对象，减少跨列、跨页面反复比对。

### 20.3 行高与密度

- 当前仅在物料基础数据维护（物料维度组合视图）保留32 / 40 / 44 / 48px四档切换用于效果评估，默认40px。其他页面暂不提供行高切换按钮、状态及偏好恢复，维持各自既定默认行高。密度属于展示偏好，不改变筛选、选择、排序、分页或数据。
- 保持正文14px和可读行距，优先保障编号、物料说明、配置等识别列宽；长文本省略后提供全文提示或既有详情入口。
- 行高是普通单行记录的目标高度。带编辑控件、多行必要信息、分组合并表头的行按内容增高，不裁切字段或遮挡控件。空状态不套用单行行高。
- 密度实现集中于公共表格/样式出口，业务页不分别维护四套padding。独立移动端卡片和有明确版式的报表不强行套用；Excel导出行高仍按模板。

## 21. 查询区

- 同一业务字段在查询、编辑表单、弹窗中优先复用已认可的业务选择组件及候选来源。人员角色名称变化不另造人员选择器；成本中心共用编码与名称列；板块、用途、新增类型使用共享下拉。不同状态业务保留各自字典，同一状态字段跨页面共用；单多选及可选范围由业务明确传入，不因复用组件扩大权限。

- 查询区域统一复用 `QueryBar` + `QueryItem`。
- 查询字段顺序按主要检索路径组织，不为了填满一行随意改变字段宽度。
- 查询、重置必须真实生效。
- 公共查询字段默认按业务对象使用正确选择组件：资产责任人为人员选择弹窗，责任人职级为多选下拉框，资产类别为大类、小类两级树形多选，City 为带搜索建议的下拉框，子公司为下拉框。页面可限定候选数据范围，不因过滤差异改成自由文本框。
- 启用日期等短日期查询控件保持普通字段宽度，不用整行拉伸。层级列表的名称对齐按第20.1节处理。
- 搜索、刷新等属于工具操作，可以使用含义明确的图标。
- 查询区输入类控件默认按 32px 中尺寸保持统一；已有公共组件未统一 Theme 前，不在单页用 CSS 强制改高。
- QueryBar默认标签宽度为 **84px（六个14px汉字）**，标签与控件间距8px，右对齐、单行省略。超长标签保留全文提示及完整可访问名称，不能靠扩大标签宽度挤压输入区；详情标签仍按第15节，不与查询标签混用。
- 页面宽度>1180px时最多三列，761–1180px时两列，≤760px时一列。标签与输入控件作为完整字段换行；窄内容容器须继续收缩列数，不能因浏览器宽而强塞三列。弹窗按第13.4节的容器宽度规则；仅一个条件时默认占满可用宽度；盘点报表的盘点年份例外，保持一个标准查询字段位，操作按钮使用剩余区域，窄屏仍按容器收为一列。
- 高频条件默认显示，其他条件通过“展开更多/收起”控制，展开前后使用相同栅格；收起只改变显示，不清除条件或偷偷执行查询。
- `AntInput` 默认 `w-full`，外包 `flex-1` 容器控制伸缩；`AntSelect` 的 `className` 作用于外层，可使用 `flex-1`。
- “展开更多/收起、重置、查询”按此顺序成组右对齐，查询为最右侧主按钮。末行有空位时与筛选项同行，排满后另起一行；不额外挤窄每个输入区，不拆散标签和控件。极窄空间下操作组允许自然换行且保持顺序。
- 范围查询由业务页面显式使用 RangePicker 等控件，公共 QueryBar 不按字段名合并或改写查询。
- 扫码若只是查询字段录入方式，放入 QueryBar 并支持回车查询；快捷添加/验证属于业务动作，按对应 PRD 处理。扫描框与按钮同行时保持普通查询字段宽度，不用 `flex-1` 填满整行，窄屏可换行。
- 查询/重置复用公共结果区刷新反馈，不叠加整页动画或假 Loading；非 Ant Design Table/List 的结果根节点声明 `data-mmp-query-result`。

---

### 21.1 查询、工具与批量操作的分区

- 高频条件优先展示，低频条件按需要收进更多条件；查询、重置与查询条件保持同一区域。
- 常驻工具栏右对齐，已有新增动作放在最右。导入、业务规则、导出筛选结果等常驻操作在勾选前后都保留；不为了照抄示例增加原业务不存在的动作。
- 勾选后在表头上方追加浅蓝批量操作条，展示已选数量及范围，集中放置已有的启停、导出所选、删除所选等动作；未选中或取消选择后收起，不能用禁用的批量按钮挤占常驻栏。
- “导出筛选结果”作用于已生效筛选结果，“导出所选”仅作用于勾选记录；名称与实际范围一致，不把选择集合静默当作全部结果。
- 本页选择型列表明确显示“已选本页 N 条”；查询、重置、翻页或改变每页条数时清除选择，避免操作范围误判。已经明确支持跨页选择的业务按其既定规则展示范围，不将本页行为全局覆盖。
- 批量条只组织已有能力，不新增启停、删除、撤销等业务权限或持久化语义；危险操作保留二次确认。
- 筛选生效后提供可理解的条件摘要及清除入口；条件较多时优先展示关键值和条件数量，避免标签挤占列表。
- 从详情或子页面返回列表时，保留当前查询、分页和浏览位置；已有页面的特殊返回规则仍按业务定义处理。

## 22. 页面级按钮与操作区

### 22.1 流程按钮

- 提交、同意、驳回、确认、取消、返回、加签、转签等流程按钮统一纯文字，不带图标。
- 主操作：Primary。
- 驳回、删除等危险操作：Danger。
- 返回、取消：Default。
- 页面底部流程操作统一居中，按钮间距 12px。
- 返回属于页面级操作，不放在 Card 标题、表格工具栏或查询区；分区查询、导出、删除所选、增行等留在对应区块。

### 22.2 工具按钮

搜索、选择、添加、上传、下载、删除、刷新等工具操作可以使用图标，但必须与操作语义一致。

### 22.3 危险操作

删除、报废、停用等危险操作必须二次确认，优先使用 `Popconfirm` 或明确确认 Dialog。

---

### 22.4 操作前的影响预览

- 对会改变资产范围、地点或重要业务结果的操作，在填写区域或最终确认处展示当前对象、变更前后值及关键影响，帮助用户在提交前判断。
- 前后值并列或按“原值 → 变更后”呈现；不同单位、统计范围或取值时点必须标明，不能只靠颜色区分。
- 仅展示业务已定义且能够可靠计算的结果；计算失败或资料不足时说明缺口，不显示猜测的预计值。
- 与操作直接有关的限制就近说明；业务拦截仍按对应PRD，不能把原本阻止提交的校验改成提示。
- 主按钮使用准确动作名，例如保存草稿、提交结果、提交审批；同一页面避免多个同等突出的主动作。

### 22.5 分步配置与结果预览

- 仅当任务存在明确先后依赖或内容过长时拆为步骤；步骤名称说明任务，区分已完成、当前和未开始。普通短表单不强行加步骤条。
- 编辑区与预览区在宽屏并列，空间不足时改为顺序区块或独立预览；预览反映当前待提交输入，并标明“预览”，不能被误认为已保存或已发布结果。
- 上一步保留已输入内容；下一步只校验当前必需内容，最终提交核对完整数据。是否支持草稿、跨会话保存由业务定义，不能用步骤切换暗示已持久化。
- 内容类型切换需说明影响；有丢失已输入内容的风险时先确认，不能静默清空。字段错误就近展示，不能只在预览区报错。
- 最终确认集中展示对象、范围、关键参数和真实可计算的影响；预览与提交使用同一份待提交数据。检查状态由真实校验产生，不复制参考稿中的静态“检查通过”。
- PC流程操作位置沿第22.1节，移动端沿第29A.5节；不照搬历史消息稿的紫色、超大圆角、英文按钮或右侧流程按钮布局。

## 23. 审批页面

审批页默认结构顺序：

```text
申请人 / 业务信息
→ 资产或物资信息
→ 审批信息 / 流程记录
→ 审批意见
→ 审批操作
```

审批记录标准列：

- 审批环节
- 申请人 / 审批人
- 审批状态
- 审批时间
- 审批意见

规则：

- 只有业务真实支持代理审批且存在代理数据时才展示“代理人”。
- 禁止固定展示一列全为 `-` 的代理人。
- 同意时审批意见可选；驳回、鉴定不通过时审批意见必填。
- 不同审批页面的操作集合以真实业务为准，不因为页面相似就混用按钮，例如“退库审批”与“领导退库审批”的加签能力必须分别按业务定义。

---

### 23.1 流程进度与历史记录

- 步骤条用于快速定位流程阶段，记录表或时间线用于查看谁在何时做了什么，两者职责不同，不互相替代。
- 仅在业务有明确节点时显示步骤；已完成、当前、未开始以及退回等异常以文字配合视觉区分，不能虚构顺序、待办人或完成进度。
- 记录按业务时间顺序组织；变更记录可展示“原值 → 新值”、原因和附件，保留对象、操作人及时间上下文。审批状态与业务对象状态不得混为同一个状态。
- 历史查看页和只读Tab不因参考稿保留“保存”按钮而新增写操作；查看型弹窗仍按第27节。

## 24. 状态标签 StatusTag

- 所有状态统一使用 `StatusTag`。
- 页面不得自行维护状态颜色映射或直接写 `Tag color`。
- 通用业务状态使用 `type="business"`。
- 是 / 否、启用 / 停用、停产状态继续使用现有 `yesNo`、`enabled`、`stop` 类型。
- 同一状态在所有页面必须保持相同颜色。
- 空状态值展示 `-`；是/否值兼容 `'1'`、`true`、`'是'`。
- `StatusTag` 底层色值后续应映射到 ERP Semantic Token，不改变页面业务状态定义。
- ERP `Tag` 只补充通用标签能力，不改变本条状态规则。

## 25. 员工确认方式

本次资产系统重构全面取消电子签确认。

所有员工确认页面均不得提供：

- 电子签 Tab
- 签名区域
- 签名按钮
- 电子签确认方式
- 电子签数据字段

适用范围包括：

- 员工资产领用
- 资产借用
- 资产更换
- 资产退库
- 耗材领用
- 合约号码领取
- 合约号码退库

统一只保留两类确认入口：

1. 刷卡或由管理员录入员工工号确认。
2. 狐小 e 扫码确认。

校验规则：

- 管理员录入工号按刷卡确认处理，必须校验录入工号与业务申请人工号一致。
- 管理员完成扫码按员工扫码确认处理，必须作用于当前真实待确认节点。
- 不得因为旧 PRD、旧 Mock 或历史页面仍存在电子签字段而恢复电子签能力。

## 26. 空状态

- 表格无记录且无已生效筛选时显示“暂无数据”；存在已生效筛选且无匹配项时显示“暂无匹配结果”。按已执行条件判断，不能按尚未查询的输入值误报状态。
- 表格空状态居中显示统一蓝色插图与文案，保留适当留白；插图使用已取得的设计原素材，保持比例，不拉伸或放大占满表格。原素材缺失时记录待补，不把新绘图形声称为原图。
- 表格空状态区域只保留插图与文案；无匹配结果通过筛选区原“重置”入口恢复，按钮仍叫“重置”，不增设重复恢复按钮。
- 无待办等独立业务空页面可继续说明缺少的对象，例如“暂无待审批的资产借用申请”；此类页面已有返回入口统一称“返回工作台”。正常业务页面底部仍称“返回”。
- 评审样例中的“体验空状态/恢复数据”和旧/新样式切换仅用于演示对照，不加入正式业务页面；可通过正常查询验证无结果和恢复。

## 27. Modal / Drawer 业务规则

在 ERP Dialog 基础规范之上，资产系统补充：

- 弹窗只保留一个主标题，不增加重复蓝色条或二级标题。
- 资产选择弹窗统一命名为“选择资产”。
- 添加目录弹窗统一命名为“添加资产”。
- 搜索区域统一复用 `QueryBar` 和 `QueryItem`。
- Dialog相对内容视口居中；Footer整体右对齐，取消/返回在左，保存/确认在最右。长表单正文内部滚动，操作区保持可见。
- 多选弹窗可以左侧展示已选择数量，操作按钮在右侧。
- Drawer / Modal 超过约 80 行实现时优先拆分为独立组件，避免页面文件失控。
- 纯查看 Modal 没有确认或保存动作时只保留右上角 X，不重复提供 Footer“关闭”；新增、编辑、确认类保留业务 Footer。
- 普通 Modal 不设置导致无意义纵向滚动的全局 `overflow-x: auto`，滚动放在确实超宽的表格容器内。
- 选择弹窗点击与同级挂载要求见 `docs/ENGINEERING_GUIDELINES.md` 第 4 节；原位替换视图仍使用本规范 Footer，不复制旧的居中、装饰分隔线样式。
- 查询列表通过标签号或业务编号打开只读详情弹窗；具有编辑权限且记录允许编辑时显示【编辑】，在当前弹窗进入编辑态。保存或取消后返回只读详情态；关闭详情后保留列表查询条件、更多条件展开状态、分页、每页条数和排序。后续修改其他模块时同步该已确认规则，不据此宣称全模块已经改造完成。

---

### 27.1 弹窗内的信息组织

- 同一业务对象下较独立的编辑、审批记录、操作记录，可按Tab分组；标题持续说明当前对象，切换后保持上下文。
- 当前任务需要同时核对的信息保持同屏，例如原值与拟变更值、资产信息与照片；不因减少弹窗高度而拆到互斥Tab。
- Tab不改变查看、编辑或审批权限；页面没有对应历史能力时，不为了对齐参考稿新增空Tab。
- 表单较长时优先清楚分组，并使主操作易于找到；底部操作不遮挡末行字段。

## 28. 加载、提交与交互反馈

所有用户操作必须有与实际动作匹配的反馈：

1. 同步操作直接更新界面或提示；异步操作等待期间展示 Loading，完成后反馈成功或失败并更新数据。没有真实等待时禁止制造 Loading。
2. 表单支持必填校验、编辑回填、关闭后重置和防重复提交；异步提交时使用按钮 Loading。
3. 处理期间禁止重复产生业务记录；Loading 或禁用状态随真实处理状态结束。
4. 首次真实等待且内容可预估时优先 Skeleton；已有内容后的局部异步刷新使用 Loading Overlay，不反复切回骨架屏。
5. 不使用 `setTimeout` 伪造业务状态、结果或等待。
6. 页面切换、查询结果、浮层和行高亮统一复用 `docs/UI_MOTION_GUIDELINES.md` 的公共实现，不在业务页面叠加同层整页动画。

---

### 28.1 异常与处理结果就地展示

- 表单错误放在对应字段附近；审核退回、导入失败等逐条结果放在对应记录旁，展示状态、原因和可执行的下一步。
- 全局Message用于告知本次动作结果，不能代替需要持续查看或修正的逐行错误。
- 异常行可使用语义弱背景辅助定位，同时保留明确文字和必要图标；不只用红绿颜色传达结果。
- 只在业务支持时提供重试、修改或重新提交入口，入口受原状态与权限限制。

### 28.2 耗时任务、部分结果与失败恢复

- 仅在真实存在导入、导出、生成等异步任务时采用此模式；区分尚未开始、处理中、成功、失败及输入不足，不能把全部状态都显示为“暂无数据”。
- 处理状态附着于对应区块，已有基本信息和其他有效结果仍可阅读；加载失败不能清空整页或遮住返回入口。
- 成功后提供业务已支持的查看、复制或下载；复制成功须确认实际复制完成，下载入口须对应真实可用文件。失败展示原因及允许的恢复路径。
- 可重试错误与无输入、条件不满足分别处理；后者先说明缺少什么，不能机械提供无效重试。任务处理中防止重复提交。
- 如有重新生成或覆盖结果，明确作用对象及旧结果处理方式；业务未定义覆盖、版本或恢复规则时不自行添加。
- 多区块结果分别显示状态；仅有局部结果时不报告全局完成。“查看更多”只在确有隐藏内容时出现，已完整显示时不保留空入口。
- 任务失败区可以就地提供真实重试；表格无匹配结果仍通过查询区原“重置”恢复，两类状态不得混用。

## 29. B 端视觉原则

ERP 品牌方向强调统一、高效、简洁、专业、易用。资产系统落实为：

- 信息层级清晰优先于装饰。
- 字段对齐、状态一致、操作可预期优先于“填满页面”。
- 页面分组优先使用留白，Divider 只在需要明确边界时出现。
- 不使用无意义动画、过度渐变、玻璃拟态、大面积彩色背景。
- 不为了视觉丰满擅自增加业务字段、说明 Card、统计数字或按钮。
- 设计系统的目标是减少页面自行决定视觉值，而不是让页面变得更花哨。

# 第四部分：移动端 UI 与交互

## 29A. 移动端页面组织

### 29A.1 工作台与资产卡片

- 工作台按业务任务组织总览、分类和待处理事项；指标只在确有决策或导航用途时出现，不为填充页面新增统计。
- 可下钻的数字或卡片提供明确入口，进入与其名称及范围一致的清单；指标的数量口径、状态划分由业务PRD定义。
- 列表使用纵向单列卡片，首层突出资产标签号或主要名称及状态，责任人、地点、日期等按任务需要分层排列；非核心信息放入详情。
- 卡片的查看入口与盘点、报失、提交等业务动作分开。已确认点击卡片为只读详情的页面，整卡点击继续进入只读详情，不能触发提交或状态变化。

### 29A.2 搜索与筛选

- 高频搜索留在列表顶部，多条件筛选进入独立筛选页或足够高度的浮层；筛选字段使用单列布局。
- 筛选页底部集中放置“重置、应用筛选”。修改的是待应用条件，点击应用后统一更新列表；取消或返回保留原已应用条件。
- 返回列表后展示已应用条件摘要、结果数量及清除入口，避免用户忘记当前列表受哪些条件限制。
- 从资产详情返回时保留已应用条件、分组展开及列表浏览位置。
- 同一日期的起止条件合为一个区间；允许单端、起止包含等业务规则按具体字段定义，不因移动布局改变。
- 字段含义应持续可辨，不能仅靠选中后消失的占位文字表示条件名称。

### 29A.3 按选择复杂度确定交互

| 选择场景 | 默认交互 | 确认与取消 |
|---|---|---|
| 少量、无层级的简单单选 | 底部选项列表，清楚标识当前值 | 点击选项立即回填并关闭，不额外增加确定；取消保留原值。 |
| 层级选择、多选或需要核对已选内容 | 可搜索的选择层或独立选择页，支持层级展开及已选状态 | 选择过程暂存，确定后回填；取消不改变原字段，多选展示已选数量或内容。 |
| 多项查询条件组合 | 在筛选页集中编辑 | 按第29A.2节统一应用，不因某个子选择器关闭就提前更新列表。 |
| 会提交业务、产生费用或改变重要结果的选择 | 按业务流程提供确认及影响说明 | 不套用简单单选的点选即生效。 |

- 层级箭头负责展开/收起，选择标记负责选中，触控范围清楚分开；层级关系和选中范围按业务定义。
- 选择层区分搜索、清空选择和确定；清空不应同时隐式提交业务。
- 底部选择层内容可滚动，标题和必要操作保持可达；长列表或深层组织优先独立选择页，避免多层浮层叠加。
- 单多选、候选来源、标识及权限与对应业务规则一致；移动端不从当前列表临时拼一套候选。

### 29A.4 详情与表单

- 详情先展示当前对象的关键标识和状态，再按实际业务分组展示字段；同一分组中短标签和值可左右排列。
- 长部门、资产说明、原因和地点允许换行并占用必要宽度；关键标识提供完整查看及复制途径，不能因右对齐而被挤成不可读的窄列。
- 编辑表单优先单列，标签持续可见；较长字段可采用标签在上、输入在下的布局。
- 相关字段多到需要分Tab时，当前对象身份保持可见；横向Tab明确提示还有内容，选中项容易找到，不截断关键名称。
- 需要同时比对的资产、照片和前后值按当前任务保持邻近；不为增加卡片层次给每个字段单独套容器。

### 29A.5 操作、触控与反馈

- 底部主操作保持清楚、易触达，次操作降低视觉权重；固定操作区为内容预留空间，兼顾底部安全区和软键盘，不遮挡最后一个字段或错误。
- 图标的触控区域大于图形本身；选择行尽量整行可点，选择标记、展开及业务按钮之间留出避免误触的空间。
- 资产状态与权限决定操作是否提供；不能因为复制参考稿就给只读、已关闭记录增加编辑或提交。
- 驳回、上传失败等原因就近展示，颜色配合文字；提交等待、防重复操作、失败保留输入按第28节及业务规则处理。
- 保证主文字、辅助文字、选中状态与背景有足够区分；不照搬参考稿中过淡的小字或过小的行内操作。

### 29A.6 后续改造验证

- 分别检查列表 → 筛选 → 子选择 → 应用 → 详情 → 返回的条件、选择及浏览位置是否连续。
- 按实际设备宽度检查长名称、字体放大、横向Tab、底部安全区及软键盘，不能仅在一张375px静态稿上验收。
- 验证点选关闭、确认回填、取消恢复、清空、无结果及加载失败；这些交互须实际操作验证，静态设计图只能证明布局。
- 桌面与移动端复用主题、状态和业务数据契约；新增移动组件时优先集中复用，不逐页维护不同的选择与筛选方式。

### 29A.7 摘要展开、长内容与局部表格

- 业务记录卡片一张对应一个可识别对象；默认展示标识、状态和决策必需摘要。有关联记录时用“已关联N条”等真实数量与展开箭头，展开后以次级背景或分隔区呈现子记录。
- 展开只揭示内容，不能隐式触发预订、提交或状态变更；父级摘要和子记录状态分开，部分失败不能被父级成功标签掩盖。
- 折叠时不得隐藏阻断当前操作的原因；每条异常就近说明。非核心详情可收起，但必须能重新展开查看完整内容。
- 长文按短标题、段落、清单分组，保持阅读顺序；PC并列区块到移动端按同一语义顺序堆叠，避免把宽屏截图缩小塞进卡片。
- 确实需要逐行逐列对照的数据可在卡片内部横向滚动，优先保留记录识别列并提示还有列；页面本身不横滑。普通资产列表仍默认卡片，不据此恢复整屏宽表。
- 横向Tab、卡片展开和局部表格横滑分别处理；点按表内链接不应误触整卡跳转。长文本、文件名和按钮在字体放大后仍可读。
- 文件行展示类型、名称和实际可用动作；图标有可访问名称。会议稿的录制文件行只作为媒体场景参考，不替换第19.1节资产附件结构和权限。

### 29A.8 移动看板与任务入口

- 首页按“关键概况 → 需要处理的阶段/提醒 → 常用功能”组织，是否出现某区块由真实任务决定；不能为了套版增加指标。
- 只有需要对比且宽度足够的少量指标并排；长标题或字体放大时转单列。指标名称、数值、单位和范围持续可见，不能只剩大数字。
- 业务支持下钻的阶段数量与阶段名称成组，点击时携带对应范围；提醒显示对象、时间窗口及入口，不从HR示例复制45天、30天等阈值。
- 功能入口按任务分组，图标配文字；参考稿中的空白占位图标不是正式图标资产，不作为页面实现标准。

### 29A.9 移动浮层与跨端尺寸

- 短确认用居中对话框，选择按第29A.3节使用底部选择层或独立选择页，长任务优先独立页。多段说明先突出关键限制，再展示步骤和帮助链接；不以整段红字代替信息层级。
- 弹窗宽度由视口、两侧留白与内容共同决定；历史作品同时出现16px和24px侧距，不认定其中一个为所有移动弹窗的固定Token。宽度不足时换行，不裁切或缩小文字。
- 标题、关闭入口、正文、操作区各有明确层级；正文过长可滚动，关闭及主要操作保持可达；固定底部区为内容及系统安全区预留空间。
- 确认文案说明实际动作和对象；“继续”不代表已经成功。取消和关闭不提交，涉及未保存编辑时按业务决定是否提示。
- 375px画板、44px导航栏和图中状态栏只是参考尺寸；不要把系统状态栏、底部手势条烘焙进业务页面。软键盘、字体放大、横竖屏及iOS/Android分别验证。
- 小图标不等于小热区，热区需避免相邻操作重叠；按钮文字、复选标记和加载图标不被固定行高切割。具体热区尺寸在移动组件规范中统一验证，不能直接套桌面32px控件高度。
