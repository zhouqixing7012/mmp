# 合约号码维护

## 1. 背景

当前“资产管理 → 合约号码维护”用于查询和维护合约号码/合约机资产。原页面基于通用台账组件，字段、查询、编辑边界和合约号码业务规则没有完整落地，且旧说明中同时混有目标规则和历史代码现状，存在可编辑字段口径冲突。

本次改造将合约号码维护收敛为独立业务页面，统一列表、查询、卡片、单条编辑、批量编辑、导出和操作历史规则，并将保存权限收口到明确字段白名单。

## 2. 改造总结

1. 页面固定查询资产大类 `34` 的合约号码/合约机资产。
2. 页面不直接新增或删除合约号码资产；卡片由入库或其他正式资产业务流程产生。
3. 列表展示未报废和已报废数据，报废后不从台账删除。
4. 标签号为蓝色链接，点击打开“合约号码信息”。
5. 卡片固定保留“详细信息 / 合约号码操作历史”两个页签。
6. 单条编辑仅允许修改本 PRD 明确的白名单字段；旧页面曾可编辑但未进入目标白名单的字段不得继续放开。
7. 号码状态与仓库强关联：状态名称含“在用”时仓库必须为空；其他状态仓库必须有值。
8. 报废状态必须同时维护报废日期和报废原因；非报废状态不得保留报废字段。
9. 责任人通过人员选择器选择，姓名、部门、子公司、员工职级以系统人员主数据重新带出，不信任页面伪造值。
10. 批量编辑继续沿用既有 11 列模板，空白表示保留原值，全部校验通过后才允许保存。
11. 实际发生变化时更新最后修改时间并生成“合约号码台账维护”来源的修改事务；无变化不生成无效历史。

## 3. 通用规则

### 3.1 数据范围

1. 固定查询资产大类 `34`。
2. 查询结果同时满足当前账号数据权限和页面查询条件。
3. 已报废资产仍保留在列表，可继续查询和查看历史。
4. 页面不提供新增、删除入口。

### 3.2 权限

1. 没有查看权限的用户不能查看合约号码台账数据。
2. 没有编辑权限的用户不展示“编辑”和“批量编辑”入口。
3. 有编辑权限的用户也只能修改本 PRD 明确的单条或批量白名单字段。
4. 导出结果必须同时满足账号数据权限和当前查询条件。
5. 页面控件限制与保存接口字段白名单必须同时生效，不能仅依赖前端禁用状态。

### 3.3 空值展示

1. 列表、卡片、操作历史的普通空值统一展示为 `-`。
2. 编辑控件空值保持为空，不使用 `-` 作为提交值。
3. 单条编辑按字段本身规则保存空值。
4. 批量模板空白单元格统一表示“保留原值”，不得静默清空已有数据。

### 3.4 排序与分页

1. 首次进入按“最后修改时间倒序 → 标签号升序”。
2. 支持业务列手动升序或降序。
3. 排序只改变展示顺序，不改变数据权限和查询范围。
4. 页面刷新后不保留手动排序条件。
5. 翻页后不保留上一页勾选记录。

### 4.2 基础查询

| --- | --- | --- |
| 标签号 | 文本框 | 支持模糊、多值；多个值 OR |
| 合约号码 | 文本框 | 支持模糊、多值；多个值 OR |
| 使用公司 | 多选 | 多个值 OR |
| 品牌 | 多选 | 多个值 OR |
| 资产小类 | 多选 | 合约机、合约号码 |

| 套餐内容 | 文本框 | 模糊匹配 |

| 仓库 | 多选 | 多个值 OR |
| 责任人 | 人员弹窗多选 | 展示员工编号、姓名、部门；回填 `工号-姓名` |

### 4.3 更多查询

| 查询条件 | 控件 | 规则 |
| --- | --- | --- |
| 合约期限 | 日期范围 | 开始日期不得晚于结束日期 |
| 金额 | 最小值 + 最大值 | 未填写一端不限制；最小值不得大于最大值 |
| 子公司 | 多选 | 多个值 OR |
| 部门 | 多选 | 查询所选部门及其下级部门数据 |
| 员工职级 | 多选 | 多个值 OR |
| 领用日期 | 日期范围 | 包含起止日期 |
| 领用原因 | 多选 | 4级升5级、5级（含）以上入职、业务使用、空 |
| 领用说明 | 文本框 | 模糊、多值 |
| 申请单号 | 文本框 | 模糊、多值 |
| 报废状态 | 单选 | 已报废、未报废 |
| 报废原因 | 文本框 | 模糊、多值 |
| 报废日期 | 日期范围 | 包含起止日期 |

查询通用规则：

1. 不同查询条件之间使用 AND。
2. 同一多选条件内使用 OR。
3. 未填写条件不参与过滤。
4. 只有明确标记支持多值的文本条件才按逗号/换行拆分多个值。
5. 文本条件支持回车查询。
6. 查询条件支持双击清空当前条件。
7. 重置后恢复当前账号权限范围内默认列表。
8. 查询、分页和排序不得突破数据权限。

### 4.5 单条编辑

用户勾选记录后点击“编辑”。

| 场景 | 处理 |
| --- | --- |
| 未选择 | `请选中要编辑的数据！` |
| 选择超过一条 | `只能选中一条要编辑的数据！` |
| 恰好一条 | 打开“合约机详细信息编辑页” |

#### 4.5.1 单条编辑白名单

只有以下字段允许通过合约号码维护页面修改：

| 字段 | 控件 | 规则 |
| --- | --- | --- |
| 使用公司 | 公司选择器 | 必填，必须是有效公司 |
| 责任人 | 人员选择器 | 必填，必须是有效员工 |
| 合约号码 | 文本框 | 最长 25 字；按本 PRD 手机号规则校验 |
| 合约号码说明 | 下拉选择 | 从有效业务值中选择 |
| 套餐内容 | 下拉选择 | 从有效业务值中选择 |
| 合约期限 | 日期范围 | 开始日期不得晚于结束日期 |
| 金额 | 数字 | 最多 8 位整数 + 2 位小数 |
| 号码状态 | 下拉 | 必须符合状态/仓库关系 |
| 仓库 | 下拉 | 当前业务固定有效仓库范围 |
| 备注 | 多行文本 | 最多 120 字 |
| 报废日期 | 日期 | 仅报废状态允许填写；报废状态必填 |
| 报废原因 | 多行文本 | 仅报废状态允许填写；报废状态必填 |
| 领用原因 | 下拉 | 只能选择管理员配置业务值 |
| 领用说明 | 多行文本 | 可为空 |

#### 4.5.2 只读字段

以下字段不得通过单条编辑接口修改：

1. 标签号。
2. 资产大类、资产小类。
3. 品牌、资产说明、配置。
4. 数量。
5. 子公司。
6. 部门。
7. 员工职级。
8. 领用日期。
9. 申请单号。
10. 身份证号码。
11. 副卡。
12. 维修记录。
13. 最后修改时间。

旧页面历史上曾允许直接修改身份证号码、子公司、领用日期、副卡、维修记录等字段，本次目标 PRD 未将其纳入单条编辑白名单，因此单条维护统一按只读处理；不得因兼容旧页面而继续放开。

### 4.6 合约号码校验

合约号码按现有业务规则校验为 11 位手机号，支持以下号段：

- 13 开头
- 14 开头
- 15 开头
- 17 开头
- 18 开头

不满足规则时阻止保存并提示号码格式错误。

### 4.7 责任人及人员派生字段

1. 责任人选择器查询有效员工。
2. 选择责任人后重新从人员主数据获取姓名、部门、子公司和员工职级。
3. 页面提交的责任人姓名、部门、子公司和员工职级文本不能作为可信保存值。
4. 非 `SOHU` 开头普通员工没有部门时不允许保存，并提示：`该员工对应的部门为空，请联系管理员添加`。
5. `SOHU` 开头虚拟用户继续走既有特殊逻辑。
6. 责任人必须属于 MMP 管理范围。

### 4.8 状态与仓库

1. 号码状态名称包含“在用”时，仓库必须为空。
2. 其他状态下仓库必须有值。
3. 当前既有业务仓库范围为 `I10086.集团合约机库`。
4. 状态改为“在用”时页面立即清空仓库。
5. 保存接口必须再次校验状态/仓库关系。
6. 不匹配时提示：`仓库和状态不匹配。`

### 4.9 报废字段

1. 号码状态为报废状态时，报废日期和报废原因必填。
2. 报废日期必须是合法日期。
3. 非报废状态不允许填写或保留报废日期、报废原因。
4. 状态从报废改为非报废时，页面同步清空报废日期和报废原因。

### 4.10 金额

1. 金额必须是合法数字。
2. 最多 8 位整数 + 2 位小数。
3. 列表和导出按千分位、两位小数展示。

### 4.11 合约号码操作历史

1. 按当前资产标签号查询操作事务。
2. 按操作日期从早到晚展示。
3. 展示字段：操作类型、操作日期、操作人、单据编号、申请单号、标签号、合约号码、类别、说明、责任人、公司、状态、仓库、备注。
4. 相邻两条事务中发生变化的主要业务字段使用黄色背景标识。
5. 单条维护实际发生变化时生成“合约号码维护修改”事务。
6. 事务来源明确为：`合约号码台账维护`。
7. 无实际字段变化时不生成新事务、不更新最后修改时间。

### 4.12 导出

1. 有勾选记录时提示：`确定要导出选中的数据吗?`，只导出勾选且有权限的数据。
2. 无勾选记录时提示：`确定要导出列表中的数据吗?`，导出当前查询条件下全部结果，不只导出当前页。
3. 导出同时叠加用户数据权限。
4. 导出字段覆盖列表业务字段：标签号、合约号码、使用公司、品牌、资产小类、合约号码说明、套餐内容、合约期限、数量、金额、号码状态、仓库、备注、报废原因、报废日期、责任人、子公司、部门、员工职级、领用日期、领用原因、领用说明、申请单号。

### 4.13 批量编辑

#### 4.13.1 固定模板

当前批量编辑继续使用既有 11 列模板：

| 顺序 | 字段 | 空白含义 |
| ---: | --- | --- |
| 1 | 标签号 | 必填，用于定位既有资产 |
| 2 | 责任人工号 | 保留原值 |
| 3 | 身份证号码 | 保留原值 |
| 4 | 资产状态 | 保留原值 |
| 5 | IMEI/电话号码 | 保留原值 |
| 6 | 金额 | 保留原值 |
| 7 | 仓库 | 保留原值 |
| 8 | 领用原因 | 保留原值 |
| 9 | 副卡 | 保留原值 |
| 10 | 备注 | 保留原值 |
| 11 | 维修记录 | 保留原值 |

合约期限、套餐内容、报废日期、报废原因、领用说明暂不扩展到当前 11 列批量模板；后续如扩展必须先明确批量字段存储、权限和空值语义。

#### 4.13.2 批量校验

1. 校验文件格式、表头、列顺序和模板版本。
2. 标签号不能为空且必须存在。
3. 标签对应资产必须属于大类 `34`。
4. 同一文件标签号不得重复。
5. 责任人工号填写时必须存在并属于 MMP 管理范围。
6. 资产状态填写时必须存在于合约号码状态字典。
7. 金额填写时必须可转换为数字。
8. 仓库填写时必须存在于系统仓库数据。
9. 身份证号码在既有批量模板中填写即可，当前批量流程不新增格式校验。
10. 领用原因填写后按既有业务值处理。
11. 副卡、备注、维修记录按既有模板规则读取。
12. 全部行校验结束后一次性返回所有已识别错误，不只返回第一条。

#### 4.13.3 批量保存

1. 全部校验通过后才允许保存。
2. 任一行失败时整份文件不保存，不允许部分成功。
3. 空白单元格表示保留原值，不得误清空已有值。
4. 保存前按标签号重新读取最新资产，避免覆盖上传期间已经发生的更新。
5. 每条实际发生变化的资产生成修改事务。
6. 成功返回成功条数；失败返回真实失败状态、行号、标签号和原因。
7. 模板格式不一致提示：`导入的EXCEL和系统要求的模板不一致，请核查`。
8. 标签号为空提示：`第 N 行,资产标签号不能为空`。
9. 标签号不存在提示：`第 N 行,资产标签号不存在`。
10. 责任人工号不存在提示：`第 N 行,责任人员工编号不存在`。
11. 状态不存在提示：`第 N 行,资产状态不存在`。
12. 仓库不存在提示：`第 N 行,仓库不存在`。
13. 金额格式错误提示：`第 N 行,金额为数字`。

## 5. 校验

### 5.1 单条保存校验

| 校验项 | 规则 |
| --- | --- |
| 字段白名单 | 只允许 4.5.1 字段；接口再次校验 |
| 使用公司 | 必填且必须有效 |
| 责任人 | 必填且必须有效；属于 MMP 管理范围 |
| 人员派生字段 | 姓名、部门、子公司、职级必须由系统重新获取 |
| 合约号码 | 11 位，按指定号段校验 |
| 合约期限 | 日期合法；开始日期不得晚于结束日期 |
| 金额 | 数字；最多 8 位整数 + 2 位小数 |
| 号码状态 | 必须是有效状态 |
| 状态/仓库 | 在用时仓库为空；其他状态仓库有值 |
| 备注 | 最多 120 字 |
| 报废字段 | 报废时日期、原因必填；非报废时必须为空 |
| 领用原因 | 必须是管理员配置业务值 |

### 5.2 保存结果

1. 保存成功提示 `保存成功！`。
2. 保存成功后继续停留当前编辑页，并用保存后的最新数据刷新。
3. 保存失败保留当前输入，不产生半条历史。
4. 无实际变化时提示 `合约号码信息未发生变化`，不更新时间、不生成事务。
5. 不存在的资产标签/记录不得静默返回成功。

## 6. 后续操作及补充说明

### 6.1 资产与扩展数据一致性

正式实现保存时需要保证资产主表、扩展信息和资产修改事务一致，不允许只更新其中一部分后返回成功。

### 6.2 财务字段

合约号码维护修改责任人或使用公司时，不执行普通资产维护中的成本中心、Book Type、账簿、费用账户和内部费用账户自动重算，继续沿用合约号码既有处理逻辑。

### 6.3 原型边界

当前前端原型用于表达业务页面和交互，不伪造以下正式系统能力：

1. 真实账号权限和数据隔离。
2. 真实 Excel 工作簿解析和批量数据库事务。
3. 正式人员主数据、公司和仓库接口。
4. 主表/扩展表/事务表真实数据库事务。
