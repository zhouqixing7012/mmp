# 合约号码维护

## 1. 背景

当前“资产管理 → 合约号码维护”用于查询和维护合约号码/合约机资产。原页面基于通用台账组件，字段、查询、编辑边界和合约号码业务规则没有完整落地，且历史说明中混有目标规则和旧代码现状，存在字段口径冲突。

本次改造将合约号码维护收敛为独立业务页面，统一列表、查询、卡片、单条编辑、批量编辑、导出和操作历史规则，并以当前确认口径作为最终规则。

## 2. 改造总结

1. 页面固定查询资产大类 `34` 的合约号码/合约机资产。
2. 页面不直接新增或删除合约号码资产；卡片由入库或其他正式资产业务流程产生。
3. 列表展示未报废和已报废数据，报废后不从台账删除。
4. 标签号为蓝色链接，点击打开“合约号码信息”详情弹窗。
5. 卡片固定保留“详细信息 / 合约号码操作历史”两个页签。
6. 详细信息不再按业务模块分组，20 个字段统一使用单一 3 列字段网格平铺展示。
7. 合约号码卡片严格只展示当前确认的 20 个字段；列表业务字段与这 20 个字段严格一一对应，不保留品牌、资产说明、配置、子公司、身份证号码、副卡、维修记录、备注、领用原因、领用说明等卡片外字段；列表仅额外保留选择框和最右侧固定操作列。
8. 单条“编辑”改为列表最右侧固定冻结“操作”列中的行级入口，不再依赖勾选一条记录后点击顶部编辑按钮。
9. 复选框仍用于批量编辑和勾选导出，不作为单条编辑入口。
10. 单条编辑仅允许修改卡片内明确开放的字段，保存接口同步执行字段白名单校验。
11. 号码状态与仓库强关联：状态名称含“在用”时仓库必须为空；其他状态仓库必须有值。
12. 报废状态必须同时维护报废日期和报废原因；非报废状态不得保留报废字段。
13. 责任人通过人员选择器选择，姓名、部门、子公司、员工职级和身份证号码以系统人员主数据重新带出，不信任页面伪造值；卡片只展示责任人、部门和员工职级。
14. `申请类型`为只读流程字段，枚举值固定为：业务申请、个人申请、管理者配送。
15. 批量编辑继续沿用既有 11 列模板，空白表示保留原值；该模板为历史批量维护口径，与卡片 20 字段集合独立。
16. 实际发生变化时更新最后修改时间并生成“合约号码台账维护”来源的修改事务；无变化不生成无效历史。

## 3. 通用规则

### 3.1 数据范围

1. 固定查询资产大类 `34`。
2. 查询结果同时满足当前账号数据权限和页面查询条件。
3. 已报废资产仍保留在列表，可继续查询和查看历史。
4. 页面不提供新增、删除入口。

### 3.2 权限

1. 没有查看权限的用户不能查看合约号码台账数据。
2. 没有编辑权限的用户不展示右侧“编辑”操作和“批量编辑”入口。
3. 有编辑权限的用户也只能修改本 PRD 明确的单条或批量白名单字段。
4. 导出结果必须同时满足账号数据权限和当前查询条件。
5. 页面控件限制与保存接口字段白名单必须同时生效，不能仅依赖前端禁用状态。

### 3.3 空值展示

1. 列表、卡片、操作历史的普通空值统一展示为 `-`。
2. 编辑控件空值保持为空，不使用 `-` 作为提交值。
3. 单条编辑按字段本身规则保存空值。
4. 批量模板空白单元格统一表示“保留原值”，不得静默清空已有数据。

### 3.4 排序与分页

1. 首次进入按“最后修改时间倒序 → 标签号升序”。
2. 支持业务列手动升序或降序。
3. 排序只改变展示顺序，不改变数据权限和查询范围。
4. 页面刷新后不保留手动排序条件。
5. 翻页后不保留上一页勾选记录。
6. 最右侧“操作”列固定冻结，横向滚动列表时始终可见。

## 4. 页面字段及交互

### 4.1 合约号码列表

列表业务字段必须与当前合约号码卡片的 20 个详情字段严格一一对应，不展示卡片外业务字段：

| 字段 | 展示规则 |
| --- | --- |
| 选择框 | 用于批量编辑、勾选导出 |
| 标签号 | 蓝色链接，点击打开合约号码卡片 |
| 合约号码 | 手机号文本 |
| 使用公司 | 公司名称 |
| 资产小类 | 合约机 / 合约号码 |
| 合约号码说明 | 套餐名称或物料型号 |
| 套餐内容 | 套餐配置文本 |
| 合约期限 | `yyyy-MM-dd 至 yyyy-MM-dd` |
| 数量 | 数字，默认 1 |
| 金额 | 会计格式，千分位，两位小数 |
| 号码状态 | 状态标签 |
| 仓库 | 仓库描述 |
| 使用说明 | 文本 |
| 报废原因 | 文本 |
| 报废日期 | `yyyy-MM-dd` |
| 责任人 | `工号-姓名` |
| 部门 | 部门名称 |
| 员工职级 | 职级文本 |
| 领用日期 | `yyyy-MM-dd` |
| 申请类型 | 业务申请 / 个人申请 / 管理者配送 |
| 申请单号 | 申请单号文本 |
| 操作 | 固定冻结在最右侧；展示“编辑” |

除选择框和操作列外，列表不得出现详情卡片 20 个字段之外的业务字段。明确不展示：品牌、资产说明、配置、子公司、身份证号码、副卡、维修记录、备注、领用原因、领用说明。即使这些字段仍存在于后台历史数据、批量模板、导出或操作历史中，也不得因此重新出现在合约号码列表。

列表右上角展示 `共 X 条`。

列表顶部操作：

1. 批量编辑。
2. 模板下载。
3. 导出。

单条编辑入口仅位于每行最右侧固定“操作”列。

### 4.2 基础查询

| 查询条件 | 控件 | 规则 |
| --- | --- | --- |
| 标签号 | 文本框 | 支持模糊、多值；多个值 OR |
| 合约号码 | 文本框 | 支持模糊、多值；多个值 OR |
| 使用公司 | 多选 | 多个值 OR |
| 资产小类 | 多选 | 合约机、合约号码 |
| 合约号码说明 | 文本框 | 单值模糊匹配 |
| 套餐内容 | 文本框 | 单值模糊匹配 |
| 号码状态 | 多选 | 多个值 OR |
| 仓库 | 多选 | 多个值 OR |
| 责任人 | 人员弹窗多选 | 展示员工编号、姓名、部门；回填 `工号-姓名` |

### 4.3 更多查询

| 查询条件 | 控件 | 规则 |
| --- | --- | --- |
| 合约期限 | 日期范围 | 开始日期不得晚于结束日期 |
| 金额 | 最小值 + 最大值 | 未填写一端不限制；最小值不得大于最大值 |
| 部门 | 多选 | 查询所选部门及其下级部门数据 |
| 员工职级 | 多选 | 多个值 OR |
| 领用日期 | 日期范围 | 包含起止日期 |
| 申请类型 | 多选 | 业务申请、个人申请、管理者配送 |
| 申请单号 | 文本框 | 模糊、多值 |
| 报废状态 | 单选 | 已报废、未报废 |
| 报废原因 | 文本框 | 模糊、多值 |
| 报废日期 | 日期范围 | 包含起止日期 |

查询通用规则：

1. 不同查询条件之间使用 AND。
2. 同一多选条件内使用 OR。
3. 未填写条件不参与过滤。
4. 只有明确标记支持多值的文本条件才按逗号/换行拆分多个值；合约号码说明、套餐内容等单值模糊条件不拆分。
5. 文本条件支持回车查询。
6. 查询条件支持双击清空当前条件。
7. 重置后恢复当前账号权限范围内默认列表。
8. 查询、分页和排序不得突破数据权限。

### 4.4 合约号码卡片

点击标签号打开标题：`合约号码信息：标签号`。

固定页签：

1. 详细信息。
2. 合约号码操作历史。

合约号码卡片只允许展示以下 20 个字段，不增加其他字段：

| 序号 | 字段 | 展示/来源 |
| ---: | --- | --- |
| 1 | 标签号 | 资产标签号 |
| 2 | 合约号码 | 手机号码 |
| 3 | 使用公司 | 当前使用公司 |
| 4 | 资产小类 | 合约机 / 合约号码 |
| 5 | 合约号码说明 | 套餐名称或物料型号 |
| 6 | 套餐内容 | 套餐配置文本 |
| 7 | 合约期限 | `yyyy-MM-dd 至 yyyy-MM-dd` |
| 8 | 数量 | 数字 |
| 9 | 金额 | 两位小数、千分位 |
| 10 | 号码状态 | 状态文案 |
| 11 | 仓库 | 仓库描述 |
| 12 | 使用说明 | 合约号码实际使用说明 |
| 13 | 报废原因 | 报废状态下的原因 |
| 14 | 报废日期 | `yyyy-MM-dd` |
| 15 | 责任人 | `工号-姓名` |
| 16 | 部门 | 随责任人主数据展示 |
| 17 | 员工职级 | 随责任人主数据展示 |

| 19 | 申请类型 | 业务申请 / 个人申请 / 管理者配送 |
| 20 | 申请单号 | 上游申请单号 |

卡片不得额外展示：品牌、资产说明、配置、子公司、身份证号码、副卡、维修记录、备注、领用原因、领用说明等未进入上述 20 项的字段。

### 4.5 单条编辑

列表每行最右侧固定“操作”列展示 `编辑`。

用户点击某一行 `编辑` 后，直接打开该行合约号码卡片编辑态，不需要先勾选记录，也不存在“未选择 / 多选不能编辑”的单条编辑校验。

复选框继续用于批量编辑及勾选导出，与单条编辑入口相互独立。

#### 4.5.1 单条编辑白名单

只有以下卡片字段允许通过合约号码维护页面修改：

| 字段 | 控件 | 规则 |
| --- | --- | --- |
| 使用公司 | 公司选择器 | 必填，必须是有效公司 |
| 责任人 | 人员选择器 | 必填，必须是有效员工 |
| 合约号码 | 文本框 | 最长 25 字；按本 PRD 手机号规则校验 |
| 合约号码说明 | 下拉选择 | 从有效业务值中选择 |
| 套餐内容 | 下拉选择 | 从有效业务值中选择 |
| 合约期限 | 日期范围 | 开始日期不得晚于结束日期 |
| 金额 | 数字 | 最多 8 位整数 + 2 位小数 |
| 号码状态 | 下拉 | 必须符合状态/仓库关系 |
| 仓库 | 下拉 | 当前业务有效仓库范围 |
| 使用说明 | 多行文本 | 可为空 |
| 报废日期 | 日期 | 仅报废状态允许填写；报废状态必填 |
| 报废原因 | 多行文本 | 仅报废状态允许填写；报废状态必填 |

#### 4.5.2 卡片只读字段

以下卡片字段不得通过单条编辑接口直接修改：

1. 标签号。
2. 资产小类。
3. 数量。
4. 部门。
5. 员工职级。
6. 领用日期。
7. 申请类型。
8. 申请单号。

其中部门、员工职级属于责任人派生字段：用户不能独立编辑，但修改责任人后系统必须根据人员主数据同步刷新。

除卡片 20 字段以外的其他历史字段也不得借单条编辑接口绕过白名单修改，例如：备注、领用原因、领用说明、副卡、维修记录、子公司、身份证号码等。

### 4.6 合约号码校验

合约号码按现有业务规则校验为 11 位手机号，支持以下号段：

- 13 开头
- 14 开头
- 15 开头
- 17 开头
- 18 开头

不满足规则时阻止保存并提示号码格式错误。

### 4.7 责任人及人员派生字段

1. 责任人选择器查询有效员工。
2. 选择责任人后重新从人员主数据获取姓名、部门、子公司、员工职级和身份证号码。
3. 页面提交的责任人姓名、部门、子公司、员工职级和身份证号码文本不能作为可信保存值。
4. 卡片只展示责任人、部门和员工职级；子公司、身份证号码仍可作为后台派生数据保存，但不进入合约号码卡片字段集合。
5. 非 `SOHU` 开头普通员工没有部门时不允许保存，并提示：`该员工对应的部门为空，请联系管理员添加`。
6. `SOHU` 开头虚拟用户继续走既有特殊逻辑。
7. 责任人必须属于 MMP 管理范围。

### 4.8 状态与仓库

1. 号码状态名称包含“在用”时，仓库必须为空。
2. 非“在用”状态必须选择有效仓库。
3. 状态或仓库任一变更后保存前重新校验组合关系。
4. 不符合规则时提示：`仓库和状态不匹配。`
5. 当前原型有效仓库为：`I10086.集团合约机库`。

### 4.9 报废字段

1. 报废状态下，报废日期必填且必须为合法日期。
2. 报废状态下，报废原因必填。
3. 非报废状态下，报废日期和报废原因必须为空。
4. 切换回非报废状态时页面自动清空报废日期和报废原因。

### 4.10 申请类型

1. 申请类型由上游申请流程生成，本页面只读。
2. 枚举固定为：业务申请、个人申请、管理者配送。
3. 不允许通过单条维护接口直接修改申请类型。
4. 申请单号同样由上游流程生成，本页面只读。

### 4.11 合约号码操作历史

1. 根据标签号查询当前合约号码事务。
2. 按操作日期从早到晚展示。
3. 展示操作类型、操作日期、操作人、单据编号、申请单号、标签号、合约号码、类别、说明、责任人、公司、状态、仓库、备注等历史快照字段。
4. 相邻事务发生变化的主要业务字段使用黄色背景标识。
5. 单条保存未发生实际变化时不生成事务。
6. 本页面人工修改事务来源明确为 `合约号码台账维护`。

## 5. 校验

### 5.1 单条保存

| 校验项 | 规则 |
| --- | --- |
| 使用公司 | 必填且必须有效 |
| 责任人 | 必填且必须有效 |
| 责任人部门 | 非 SOHU 普通员工必须存在部门 |
| 合约号码 | 11 位手机号；13/14/15/17/18 开头 |
| 合约期限 | 日期合法；开始日期不得晚于结束日期 |
| 金额 | 数字；最多 8 位整数 + 2 位小数；不得小于 0 |
| 号码状态 | 必须是有效状态 |
| 状态 / 仓库 | 在用 → 仓库为空；非在用 → 有有效仓库 |
| 报废日期 | 报废状态必填且有效 |
| 报废原因 | 报废状态必填 |
| 使用说明 | 可为空 |
| 字段白名单 | 页面和保存接口同时限制，禁止修改卡片只读字段和卡片外字段 |

### 5.2 保存结果

1. 保存成功提示 `保存成功！`。
2. 保存成功后停留当前编辑页，并用保存后的最新数据刷新页面。
3. 保存失败保留用户输入，不产生半条历史。
4. 未发生实际变化时提示 `合约号码信息未发生变化`，不更新最后修改时间，不生成事务。
5. 最后修改时间只能由系统生成，不接受客户端伪造。

## 6. 批量编辑

### 6.1 模板字段

批量编辑继续沿用既有 11 列模板：

| 顺序 | 字段 | 空白含义 |
| ---: | --- | --- |
| 1 | 标签号 | 必填，用于定位既有资产 |
| 2 | 责任人工号 | 保留原值 |
| 3 | 身份证号码 | 保留原值 |
| 4 | 资产状态 | 保留原值 |
| 5 | IMEI/电话号码 | 保留原值 |
| 6 | 金额 | 保留原值 |
| 7 | 仓库 | 保留原值 |
| 8 | 领用原因 | 保留原值 |
| 9 | 副卡 | 保留原值 |
| 10 | 备注 | 保留原值 |
| 11 | 维修记录 | 保留原值 |

说明：批量模板属于既有历史维护能力，不等于合约号码卡片字段集合。卡片中未展示的字段仍可按既有批量接口规则处理，但不得因此在单条卡片增加字段或开放单条编辑入口。

### 6.2 文件及逐行校验

1. 文件必须符合固定模板、表头、列顺序和模板版本。
2. 标签号不能为空且必须存在。
3. 标签对应资产必须属于资产大类 `34`。
4. 同一文件标签号不得重复。
5. 责任人工号填写时必须存在并属于 MMP 管理范围。
6. 资产状态必须存在。
7. 金额必须能转换为数字。
8. 仓库填写时必须存在。
9. 全部行校验后一次性返回已识别错误，不只返回第一条。

校验失败至少展示：行号、标签号、失败原因。

### 6.3 保存策略

1. 全部数据先校验，再进入保存。
2. 任一行校验失败，整份文件不保存。
3. 空白单元格表示保留原值。
4. 正式保存前按标签号重新读取最新资产，避免覆盖导入期间的其他更新。
5. 实际发生变化的记录分别生成修改事务。
6. 成功提示 `修改成功！`，失败展示真实失败原因及行级错误。
7. 原型仅演示“上传 → 校验 → 错误明细 → 保存”流程，不承担真实 Excel 解析。

## 7. 导出

### 7.1 导出范围

1. 勾选记录时提示 `确定要导出选中的数据吗?`，只导出勾选且有权限的数据。
2. 未勾选时提示 `确定要导出列表中的数据吗?`，导出当前查询条件下全部结果，不只当前页。
3. 导出叠加当前账号数据权限。

### 7.2 导出字段

导出继续覆盖合约号码台账既有字段，不受卡片 20 字段限制。卡片字段约束仅作用于详情/单条编辑页面，不表示删除后台或导出中的其他历史字段。

## 8. 后续操作及补充说明

### 8.1 保存边界

1. 合约号码保存逻辑使用独立 Service，避免与普通资产、耗材维护逻辑互相污染。
2. 历史兼容入口必须转发到同一专用保存逻辑，不能保留可绕过白名单的旧通用 patch 入口。
3. 公司编码、责任人姓名、部门、子公司、员工职级和身份证号码等派生值必须由系统重新获取。

### 8.2 原型边界

当前原型不具备真实登录权限上下文、真实 Excel 解析和正式后端主数据接口；这些能力按本 PRD 由正式研发接入，原型不伪造“已实现”。
