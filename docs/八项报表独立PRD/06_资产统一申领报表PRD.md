# 资产统一申领报表PRD（现状）

## 1. 背景

用于查询统一申请从申请、子流程审批到领用的处理结果。现有源码分为“统一申请库存领用报表”和“统一申请统一采购报表”两个独立页面，分别记录库存直接领用和需要统一采购后的领用链路。本文分别说明，不合并其查询字段与金额口径。

## 2. 权限

页面具有查询和导出入口；具体允许访问的角色、菜单授权未在所提供页面和报表Action中定义，待确认。页面虽然传递登录账号，但这四个报表的可见查询代码未按登录人、公司或部门追加数据范围；不能宣称仅可见本人或所在公司数据。全局拦截或报表源内部是否限权须另行确认。

## 3. 通用规则

所有查询条件均可不填。不填的条件不限制结果；多个不同条件同时填写时须全部满足，同一弹窗多选条件命中任一选项即可。文本匹配先去除首尾空格，再按包含匹配；源码直接使用LIKE，百分号与下划线未作字面转义。页面只读，不提供新增、编辑、删除、审批。点击查询或按回车提交当前条件；双击查询区后确认可清空条件，但不会自动执行新查询。

列表与导出使用同一查询及同一筛选条件，但统一采购页存在导出列写错问题，见补充说明。分页统计为源返回行数，不是申请单数；不在页面按单据合并，也不另做去重。
两页默认按申请单号倒序、申请日期倒序。同一物料申请数量大于1时，资产入库／领用后会将申请信息拆为多行，申请数量在每行保持原值。不得直接逐行合计申请数量；现有页面提示采用行计数统计，但尚未入库、领用的数据未拆行，因此“行数等于总申请台数”并非全阶段成立。

#### 查询与列表操作

查询选择弹窗回显所选名称并保存对应编码，可单独清空；日期从、至分别展示。资产大类与小类联动：选定大类后，小类弹窗限定其下小类；调整大类后只保留属于新大类的小类。没有选择大类时可以直接选小类。列表字段均不可编辑，单号为文本，没有明细跳转或查看进度操作。

## 5. 校验

申请日期从不得晚于至，至不得早于从，日期选择器双向限制。没有必填查询条件校验，部门框的样式标记不能解释成业务必填。

库存领用页申请人条件的现有服务代码使用全角左括号拼接IN表达式，可能使选人后查询及导出失败；本PRD记录应按任一所选工号筛选的字段语义，同时单列此实现问题，未修改源码。申请数量、预计采购金额、实际采购金额均没有报表页计算或提交校验。

## 6. 后续操作 / 业务结果 / 补充说明

导出当前条件下全部匹配行，不限于当前页，每批读取20,000行，生成xlsx。没有数据时生成仅表头文件；导出不改变业务数据。空值导出为空白，不替换为0或“否”。金额页面采用千分位两位小数，导出用数字格式化后的文本；页面的50字显示限制不截断导出内容。库存领用和统一采购的申请日期、完成时间导出调用COMMON.DATA_FORMAT，具体格式须配置确认；库存领用出库日期直接导出源字符串，统一采购出库日期调用COMMON.DATA_FORMAT。
统一采购页的“是否弃领”“领用出库单号”导出存在明确写错：对应字段为空时导出空白，非空时均误写子流程类型名称。页面列表仍分别显示正确字段；本文不将错误导出值解释为业务取值规则，需修复后与列表一致。

两页导出名称分别为“统一申请库存领用报表-日期.xlsx”“统一申请统一采购报表-日期.xlsx”。导出分别保留30、36个业务字段，不含序号。采购页物资总类列与导出中的物资总类名称仅标题不同，取值一致。

两页直接查询M0009_FCT_APPLY_CA、M0009_FCT_APPLY_EUA，未提供这些报表源的创建定义／刷新任务。因此母申请与资产如何关联、拆行的唯一键、重复消除规则、刷新频率、组织名称是历史还是当前、审批人与节点的拼接规则、完成时间归属、采购金额计算及税口径均待确认。不能把PURCHASE_PRICE自行改写成单价×数量，也不能把TAX_PRICE自行定义为含税单价×数量。
