# 员工资产信息查询 PRD

## 1. 背景

“员工资产信息查询”位于：

> 资产管理 → 员工资产信息查询

该功能面向资产管理后台用户，以员工为核心查询维度，集中查看指定员工当前关联的资产、耗材、合约号码以及与该员工相关的资产业务单据。

主要使用场景：

1. 核对员工当前名下资产。
2. 核对员工当前责任耗材。
3. 核对员工当前持有的合约号码。
4. 查询员工历史及当前处理中的资产业务单据。
5. 支持员工离职、调动、资产核查等场景下的一站式资产关系核对。

页面默认进入“资产”页签。

## 2. 改造总结

1. 页面统一以“员工信息”为核心查询条件，员工单选后同时作为资产、耗材、合约号码、单据信息四个页签的查询对象。
2. 页面设置四个页签：资产、耗材、合约号码、单据信息。
3. 切换页签时保留当前查询员工，不要求重复选择员工。
4. 不同页签只展示当前业务适用的辅助查询条件。
5. 资产页签只查询“资产责任人 = 当前查询员工”的资产。
6. 耗材页签只查询“耗材当前责任人 = 当前查询员工”的耗材。
7. 合约号码页签只查询“合约号码当前责任人 = 当前查询员工”的当前有效合约号码。
8. 单据信息页签按业务类型使用对应员工关系查询：普通员工业务及 CAA/CAC 业务按单据头申请人/领用人员关联；独立入库按入库明细退回人员关联；独立出库按出库明细责任人关联；独立资产转移按转移明细责任人或申请人关联。
9. 资产标签号、耗材标签号、申请单号、核心单据等具备详情入口的字段按对应业务对象进入详情。
10. 页面仅提供查询与查看能力，不在本页面修改资产、耗材、合约号码或业务单据。
11. 空结果按当前页签分别展示明确的空状态文案。
12. 历史单据点击详情时跳转至旧系统对应单据详情页，本 PRD 不维护具体旧系统 URL。

## 3. 通用规则

### 3.1 员工查询规则

“员工信息”为四个页签共用的核心查询条件。

员工选择规则：

1. 使用人员选择器选择员工。
2. 员工选择为单选。
3. 人员选择器支持按员工编号、员工姓名、部门查询。
4. 选择完成后页面展示：
   > 员工编号 - 员工姓名
5. 页面首次进入时员工信息为空，不预置默认员工。
6. 重新选择员工后，四个页签后续查询对象统一切换为新员工。
7. 已查询员工发生变化时，清空其他页签此前保留的辅助查询条件；当前页签正在填写的辅助条件保留，并在点击“查询”后与新员工一起生效。

员工信息未选择时，不执行员工资产信息查询。

### 3.2 页签联动规则

页面页签顺序：

1. 资产
2. 耗材
3. 合约号码
4. 单据信息

页签位于页面标题下方、查询条件区域上方，作为整页数据视图切换入口，而不是仅作为列表内部页签。

切换页签时：

1. 已完成一次员工查询后，切换页签继续使用当前已查询员工。
2. 切换页签后自动展示该员工在目标页签下的数据，不要求再次点击“查询”。
3. 当前页签不适用的辅助查询条件不参与查询。
4. 同一员工下，返回原页签后，该页签此前已经查询生效的辅助条件继续保留。
5. 如果用户重新选择了其他员工但尚未点击“查询”，清空当前结果并等待用户确认查询；点击“查询”后，再以新员工作为四个页签的公共查询对象。
6. 员工切换并重新查询后，其他页签针对上一员工保留的辅助条件清空，避免隐藏条件影响新员工查询结果。

### 3.3 查询条件适用范围

| 查询条件 | 资产 | 耗材 | 合约号码 | 单据信息 |
| --- | --- | --- | --- | --- |
| 员工信息 | √ | √ | √ | √ |
| 资产标签号 | √ |  |  |  |
| 耗材标签号 |  | √ |  |  |
| 合约号码 |  |  | √ |  |
| 单据编号 |  |  |  | √ |
| 单据状态 |  |  |  | √ |

页面只展示当前页签适用的辅助查询条件。

### 3.4 查询结果原则

1. 查询结果必须属于当前查询员工。
2. 不得因为员工曾经作为申请人参与某业务，就把不属于其当前责任范围的资产、耗材或合约号码带入对应“当前持有”页签。
3. “资产 / 耗材 / 合约号码”用于查询当前责任或当前持有关系。
4. “单据信息”用于查询当前及历史业务关系，可包含已完成、处理中、已驳回记录。
5. 当前页签无数据时展示对应空结果，不切换到其他页签数据。

### 3.5 页面能力边界

本页面为查询页面，不提供：

- 新增资产、耗材、合约号码。
- 编辑资产、耗材、合约号码。
- 审批业务单据。
- 修改业务单据状态。

详情入口只负责跳转或打开对应业务对象的只读/业务详情。

## 4. 页面字段及交互

### 4.1 页面结构

页面由三部分组成：

1. 页面标题下方的业务页签区。
2. 当前页签对应的查询条件区。
3. 当前页签查询结果列表区。

默认进入“资产”页签。

### 4.2 员工信息查询

| 字段 | 控件 | 规则 |
| --- | --- | --- |
| 员工信息 | 人员选择器 | 必选；单选；支持员工编号、员工姓名、部门查询；回显“员工编号 - 员工姓名” |

### 4.3 资产页签

#### 4.3.1 查询条件

| 字段 | 控件/规则 |
| --- | --- |
| 员工信息 | 共用人员选择器 |
| 资产标签号 | 文本输入；支持按标签号包含匹配 |

#### 4.3.2 数据范围

资产页签查询满足以下条件的数据：

1. 资产责任人 = 当前查询员工。
2. 资产状态代码属于：`3`、`6`。
3. 状态代码 `3` = `在用-借用中`。
4. 状态代码 `6` = `在用-使用中`。
5. 物资大类 = 资产。

#### 4.3.3 列表字段

| 字段 | 规则 |
| --- | --- |
| 行号 | 当前查询结果序号 |
| 资产标签号 | 资产唯一标签号；蓝色链接；点击打开资产卡片详情 |
| 资产说明 | 资产名称/说明 |
| 资产状态 | 按资产状态字典展示 |
| 资产责任人 | 当前资产责任人员工编号/信息 |
| 单据申请人 | 当前资产关联业务单据申请人 |
| 所在单据编号 | 当前资产关联业务单据编号 |
| 单据类型 | 单据类型名称 |
| 单据业务类型 | 当前业务类型 |
| 单据状态 | 当前业务单据状态 |
| 单据审批环节 | 当前业务所处审批/办理环节 |
| 单据审批人 | 当前处理人 |
| 公司 | 资产/责任人对应公司 |
| 板块 | 对应板块 |

#### 4.3.4 详情入口

1. 资产标签号使用蓝色链接，点击打开对应资产卡片详情。
2. 资产存在关联单据时，“所在单据编号”使用蓝色链接，点击打开对应业务单据详情或流程信息。
3. 无关联单据时展示 `-`，不提供空链接。

#### 4.3.5 默认排序

资产页签默认按以下顺序排序：

1. 按所在单据编号字段 `sp_po_putin_num` 降序。
2. `sp_po_putin_num` 为空的记录统一排在非空记录之后。
3. `sp_po_putin_num` 相同时，按标签号字段 `tag_number` 升序。
4. 排序字段是否在列表展示，不影响排序规则。

### 4.6 单据信息页签

#### 4.6.1 查询条件

| 字段 | 控件/规则 |
| --- | --- |
| 员工信息 | 共用人员选择器 |
| 单据编号 | 文本输入；按申请单号或当前查询链路支持的单据编号过滤 |
| 单据状态 | 下拉：已完成 / 处理中 / 已驳回 |

#### 4.6.2 单据查询范围

| 类型 | 查询范围 |
| --- | --- |
| 普通员工业务单据 | 员工领用、员工退库、员工转移、员工借用、员工续借、资产更换、担保相关、合约号码相关、新员工领用等员工业务 |
| CAA/CAC 库存类单据 | 员工库存类申请及该申请形成的后续库存业务单据 |
| CAA/CAC 采购类单据 | 员工采购类申请及该申请形成的后续采购、接收或执行单据 |
| 独立入库单 | 无前置申请单的退库、借用归还等入库业务 |
| 独立出库单 | 无前置申请单的出库业务 |
| 独立资产转移单 | 无前置申请单的资产转移业务 |

#### 4.6.3 员工关联规则

不同业务分支必须按各自真实员工关系查询，不允许统一简化成“按申请人查询”。

| 业务分支 | 员工关联规则 |
| --- | --- |
| 普通员工业务单据 | 优先使用单据头申请人员；申请人员为空时，使用单据头领用人员作为兜底。技术字段可对应申请人员字段及 `payPersonId` 等领用人员字段 |
| CAA/CAC 库存类 | 按员工申请单上的申请人员或领用人员关联，并继续关联展示由该申请形成的后续库存业务单据 |
| CAA/CAC 采购类 | 按员工申请关系中的申请人员或领用人员关联，并继续关联展示由该申请形成的采购、接收或后续执行单据 |
| 独立入库单 | 按入库明细中的退回人员关联；员工不要求是单据头申请人 |
| 独立出库单 | 按出库明细中的责任人关联；员工不要求是单据头申请人 |
| 独立资产转移单 | 按转移明细中的责任人或申请人关联，任一关系命中即可 |

边界规则：

1. 普通员工业务单据不再反向使用出库明细责任人替代单据头人员关系。
2. 独立入库单不得使用单据头申请人替代入库明细退回人员。
3. 独立出库单不得使用单据头申请人替代出库明细责任人。
4. 独立资产转移单不能只认责任人，明细申请人同样属于有效员工关系。
5. 所有分支最终返回的记录都必须能够通过对应业务关系明确归属于当前查询员工。

#### 4.6.7 单据详情路由

1. 申请单号或核心单据存在详情入口时，根据单据类型打开对应业务详情。
2. 当前需要支持的详情类型包括：退库、转移、借用、续借、更换、统一申请、合约号码、新员工领用、入库、出库、资产转移、仓库移库等对应业务详情。
3. 历史单据不进入新系统详情，统一跳转至旧系统对应单据详情页。
4. 当前单据存在，但系统未配置对应详情页面时，点击后提示：
   > 暂无明细展示页面！请联系维护人员添加。
5. 不允许因为未配置详情页面而阻断单据本身的查询和列表展示。

## 5. 校验

### 5.1 员工信息校验

1. 员工信息未选择时，不执行查询。
2. 离职员工允许通过人员选择器查询、选择，并可正常查询其关联资产、耗材、合约号码和单据信息。
3. 查询工号不存在，且系统无法取得对应员工信息时，提示：
   > 未查询到对应员工信息。

### 5.2 页签查询条件校验

1. 当前页签不适用的查询条件不得参与接口查询。
2. 资产页签的资产标签号只作用于资产页签。
3. 耗材页签的耗材标签号只作用于耗材页签。
4. 合约号码条件只作用于合约号码页签。
5. 单据编号、单据状态只作用于单据信息页签。
6. 单据状态候选固定为：已完成、处理中、已驳回。

### 5.3 数据归属校验

1. 资产必须满足资产责任人 = 当前查询员工。
2. 耗材必须满足耗材当前责任人 = 当前查询员工。
3. 合约号码必须满足合约号码当前责任人 = 当前查询员工。
4. 普通员工业务和 CAA/CAC 业务按单据头申请人/领用人员关系校验，其中普通员工业务申请人为空时才使用领用人员兜底。
5. 独立入库按入库明细退回人员校验；独立出库按出库明细责任人校验；独立资产转移按转移明细责任人或申请人校验。
6. 不允许跨业务分支混用员工关系字段，例如用普通员工业务的出库明细责任人替代其单据头人员关系。
7. 不允许使用“申请人命中”替代资产、耗材、合约号码的当前责任关系判断。

### 5.4 详情入口校验

1. 资产标签号只能打开对应资产卡片。
2. 耗材标签号只能打开对应耗材详情。
3. 申请单号存在对应申请单时才提供详情入口。
4. 核心单据存在对应执行单据时才提供详情入口。
5. 历史单据详情跳转至旧系统对应单据详情页。
6. 当前单据对象存在但未配置详情页面时，保留可点击入口并提示“暂无明细展示页面！请联系维护人员添加。”
7. 无对应详情对象时展示普通文本，不提供空链接。
