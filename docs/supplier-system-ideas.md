## 2026-10-22｜供应商 AI 问答助手

**状态：用户提出，待细化；尚未形成正式 PRD或实施计划。**

### 用户原话

> 我目前想到的一个项目是供应商的AI问答，在供应商管理平台和协同门户增加一个AI助手解答用户的疑问，因为平常供应商和员工的使用问题反馈都比较多

### 痛点与目标

供应商和员工的使用问题反馈较多。拟在供应商管理平台、协同门户增加 AI 助手，帮助用户解决疑问。讨论建议将项目目标聚焦于降低使用门槛、减少重复人工咨询；具体指标尚未确认。

### 讨论形成的建议（待用户确认）

| 方面 | 初步建议 |
|---|---|
| 服务对象 | 协同门户面向供应商，管理平台面向内部员工，共用知识底座并按受众控制可见范围 |
| 一期范围 | 优先操作与规则咨询，覆盖常见异常排查和转人工；具体业务进度查询仅选择少量场景试点 |
| 供应商问题 | 注册、登录、资料填写、证照上传、银行账户维护、驳回修改、报价 |
| 员工问题 | 邀请供应商、准入及变更流程、黑名单操作、评分规则、审批职责、异常处理 |
| 知识建设 | 从真实咨询记录整理高频 20—30 个问题，明确知识责任人、适用对象、来源和版本 |
| 回答方式 | 给出操作步骤、适用条件、来源及入口；依据不足时明确说明并转人工 |
| 人工衔接 | 转交时携带问题上下文，记录接收人及处理结果 |
| 权限 | 业务数据查询由后端校验身份与数据权限，不能只用提示词区分供应商和员工 |
| 运营 | 统计高频问题、未解决问题、错误回答及知识缺口，持续更新 |

### 效果评估建议（指标与目标值待定）

- 高频问题回答是否准确，操作指引能否帮助用户完成任务。
- 人工咨询量是否下降，同一问题是否重复转人工。
- 用户是否解决问题，未解决问题是否被接收和跟进。
- 是否发生越权查询或错误引用规则。

### 待明确事项与下一步

1. 抽样最近一个月的咨询记录，区分操作规则、业务进度、系统异常，识别可直接优化页面或提示的问题。
2. 确认两个入口各自的高频问题、现有手册/制度/FAQ与知识责任人。
3. 确定一期是否查询实时业务数据；若查询，列出场景、接口、身份及权限边界。
4. 明确人工承接渠道、负责人、处理流程及咨询量基线。
5. 根据样本再确认一期范围和验收目标，形成单独功能 PRD。

## 2026-10-22｜其他整改方向备忘

**状态：此前讨论中的助手建议，用户尚未确认立项或优先级。**

此前基于“供应商系统现代码.zip”的静态评估提出以下方向。本次仅整理已有对话，未重新读取压缩包、核查供应商后端代码或连接生产环境，不能将其作为本次代码审计结论。

| 方向 | 建议范围 |
|---|---|
| 主数据一致性与变更闭环 | 变更生效台账、持久化同步任务、分系统重试补偿、幂等与版本保护、异常处理及高风险变更证据；可考虑银行账户变更与 EBS/采购同步试点 |
| 持续有效性管理 | 证照到期提醒、更新、复审、暂停合作及恢复，区分审批状态和合作资格状态 |
| 存量数据治理 | 重复识别、人工确认、合并、下游编码映射 |
| 绩效结果应用 | 低分整改、复评、分级及采购使用规则 |

优先级取决于真实反馈：若主要问题是不会操作、重复咨询，可优先评估 AI 助手；若主要是流程卡住或数据不一致，需要同时处理对应流程和系统问题。该判断为讨论建议，尚未替用户确定项目排序。
