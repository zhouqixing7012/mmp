# 库存管理 - 库管员工作台及员工领用/退库打印补充 PRD

## 1. 背景

本次调整包含两部分：

1. 收口库管员工作台页面结构，移除当前无实际业务分流价值的单页签及重复快捷按钮；
2. 对员工领用、员工退库流程自动生成的库存单据补充员工操作留痕打印页，确保纸质/导出打印结果能够还原员工实际确认行为。

## 2. 改造总结

### 2.1 库管员工作台

- 删除“资产出入库”页签；
- 删除页面右上角【扫码】按钮；
- 删除页面右上角【刷卡】按钮；
- 保留【员工页面】【刷新员工页面】；
- 原有查询区域保留“资产标签号”“员工卡号”等查询字段，扫码枪或刷卡设备仍可直接向对应输入框录入数据，不再额外提供重复快捷按钮。

### 2.2 员工领用/退库自动单据打印

针对以下系统自动生成单据：

- 员工领用流程自动生成的出库单；
- 员工退库流程自动生成的入库单。

打印原库存单据时，在原打印内容后追加一张独立的 **《员工领用信息》** 页面。

普通手工创建的入库单、出库单不追加该页面；借用/借用归还本次不纳入该规则。

## 3. 通用规则

### 3.1 自动单据识别

员工领用自动出库与员工退库自动入库必须保留明确的来源流程标识或来源申请单号，用于打印时判断是否追加员工领用信息页。

当前原型中：

- 员工领用自动出库通过员工领用申请来源识别，例如 `EUA-...`；
- 员工退库自动入库通过员工退库申请来源识别，例如 `ERA-...`。

正式实现不得仅依赖“领用出库”“退库入库”业务类型判断，因为同类型下可能存在手工创建单据。

### 3.2 打印页顺序

符合条件的单据打印顺序：

`原入库单/出库单打印页 → 员工领用信息页`

员工领用信息页必须作为独立打印页，不与原单据表格挤在同一页。

### 3.3 数据快照

员工领用信息页使用员工实际领用/退库确认动作发生时保存的数据快照，不得在打印时根据当前员工档案重新计算。

例如：员工后续发生部门调整，历史单据重新打印时，仍展示当时记录的部门全称。

## 4. 库管员工作台页面字段及交互

页面顶部展示“库管员工作台”标题。

右上角操作仅保留：

- 【员工页面】；
- 【刷新员工页面】。

页面不再展示“资产出入库”页签。

查询条件保持：

| 查询条件 | 说明 |
|---|---|
| 资产标签号 | 支持扫描枪录入或人工输入 |
| 员工卡号 | 支持刷卡设备录入或人工输入 |
| 员工姓名 | 文本查询 |
| 资产名称 | 文本查询 |
| 单据编号 | 文本查询 |
| 单据类型 | 下拉查询 |

删除右上角扫码/刷卡按钮后，不影响扫描枪、刷卡设备直接向输入框写值的能力。

## 5. 员工领用信息打印页

页面标题：**员工领用信息**。

固定展示以下字段：

| 字段 | 展示规则 |
|---|---|
| 领用人（工号-姓名） | 展示员工工号与姓名，格式 `工号-姓名` |
| 领用人部门（全称） | 展示领用动作发生时员工所属部门完整路径，不使用简称 |
| 领用方式 | 仅展示 `扫码` / `刷卡` |
| 领用时间 | 精确到秒，格式 `yyyy-MM-dd HH:mm:ss` |

### 5.1 员工领用自动出库

员工完成领用确认后，系统生成出库单时同步保存：

- 领用人；
- 领用人部门全称；
- 领用方式；
- 领用时间。

后续打印该自动生成出库单时，追加员工领用信息页。

### 5.2 员工退库自动入库

员工执行退库并由系统生成入库单时，需要把该退库业务对应的员工领用信息一并关联到入库单打印上下文。

后续打印该自动生成入库单时，同样追加员工领用信息页。

本页字段仍按“领用人 / 领用人部门 / 领用方式 / 领用时间”统一展示，便于追溯该退库资产原员工领用确认信息。

## 6. 校验

1. 非员工流程自动生成单据不得追加员工领用信息页；
2. 领用方式仅允许 `扫码`、`刷卡`；
3. 领用时间必须精确到秒；
4. 领用人不能为空；
5. 领用人部门必须保存并打印完整组织路径；
6. 员工领用信息属于历史业务快照，重新打印时不得被当前员工信息覆盖；
7. 若历史数据缺少上述信息，打印页对应字段显示 `-`，不得临时推断或补造数据。

## 7. 后续操作或补充说明

- 本次只调整库存单据打印内容，不改变员工领用、退库流程本身的审批和库存落账逻辑；
- 借用出库、借用归还是否也追加类似操作留痕页，本次不扩展，后续如有需要单独确认；
- 正式后端应在员工确认动作成功时持久化上述四个快照字段，不建议只在前端打印阶段临时拼接。
