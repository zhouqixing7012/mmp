# 标签打印、打印历史、标签预打印 PRD

## 1. 背景

现状中“标签打印”“标签预打印”“标签打印历史”为三个独立菜单，功能之间存在跳转分散、打印日志口径不统一、标签流水并发和重复风险不够明确等问题。

本次改造统一收口至：

> **资产管理 → 标签打印**

标签打印用于打印已经存在的资产/耗材标签；标签预打印用于在资产实际形成前按标签编码规则提前生成标签号；打印历史用于统一追溯普通标签补打、预打印、接收入库打印等打印行为。

## 2. 改造总结

1. 原三个菜单合并为一个“标签打印”菜单，不再保留独立“标签预打印”“标签打印历史”菜单。
2. 默认进入标签打印列表；点击“预打印”进入标签批次页。
3. 标签批次页同时承担批次历史查询和新建预打印入口。
4. 下钻关系为：**标签打印 → 标签批次 / 预打印 → 标签清单 / 打印历史 → 单标签打印历史**。
5. 标签打印支持打印所选、打印全部、导出、预打印。
6. 标签打印、标签预打印、接收入库打印均生成详细打印日志。
7. 打印日志增加打印份数、打印来源和打印状态，确保能够与累计打印次数核对。
8. 标签流水号必须按规则维度维护，不允许依赖页面临时状态；正式实现需要服务端事务锁、唯一约束及幂等控制。
9. 预打印生成数量、部件数量、号段剩余量均需要校验，避免一次性生成过量数据或越过流水最大值。
10. 标签大小本次不再维护。
11. 规则名称统一为“高耗标签规则”。
12. 标签打印查询不保留“是否在员工名下”“标签类型”。
13. 本轮对抗性测试**不调整现有部件标签识别规则**，继续沿用本文“部件标签模板”章节原有规则。

## 3. 通用规则

### 3.1 菜单与入口

进入“资产管理 → 标签打印”后：

1. 默认展示已有资产/耗材标签查询、补打、批量打印和导出能力；
2. 点击“预打印”进入“标签批次 / 预打印”页面；
3. 标签批次页面可查看标签清单或直接查看该批次打印历史；
4. 标签清单内可继续查看单标签打印历史。

### 3.2 数据权限

1. 标签打印查询、打印、导出继续遵循当前用户的**公司 + 板块**数据权限；
2. 用户只能查询、打印和导出本人有权访问的数据；
3. 预打印生成标签需具有标签生成权限；
4. 账套候选范围需结合用户可操作权限控制，不允许通过前端篡改账套编码绕过权限；
5. 正式接口层必须再次校验权限，不只依赖按钮显隐和前端查询条件。

### 3.3 标签流水唯一性

标签流水必须由服务端统一维护，禁止以浏览器页面内存中的“当前最大序号”作为最终依据。

正式生成流程：

1. 根据当前标签规则计算唯一的**流水规则键**；
2. 服务端锁定对应流水规则；
3. 在锁内重新读取最新 `CurrentValue`；
4. 校验本次生成数量是否超过规则 `MaxValue`；
5. 一次性预占本次所需主标签流水区间；
6. 生成标签批次和标签明细；
7. 更新 `CurrentValue`，并设置 `NextValue = CurrentValue + 1`；
8. 标签批次、标签号、流水更新在同一事务内提交；
9. 任一步失败整体回滚，不允许只更新流水、不生成标签，或生成标签后未推进流水。

数据库至少需要：

- 标签批次号唯一约束；
- 标签号唯一约束；
- 流水规则维度唯一约束；
- 生成接口幂等控制，避免双击、重复请求或网络重试造成重复批次和重复标签。

### 3.4 流水规则维度

不同规则不得共用一个页面级全局流水值。

| 规则 | 流水维度 |
| --- | --- |
| 常规标签规则 | 账套 + 资产类型 + 年份对应规则 |
| 高耗标签规则 | 按实际标签前缀规则区分；`QT-`、`P-`、`N-` 不得互相串用流水 |
| 特殊规则-家具 | 家具公共流水 |
| 特殊规则-手机 | 手机公共流水 |
| 特殊规则-备件 | 按备件流水规则维护，不允许不同备件类型错误串号 |

常规、高耗标签规则不存在当年规则时，沿用现有规则：尝试寻找前一年规则；前一年未用完时继续编号，已用完时从新规则最小值开始；无历史规则时从最小值开始。

家具、手机、备件不存在规则时，不查历史年度规则，按对应规则最小值新建。

### 3.5 批次号唯一性

批次号由服务端生成并保证唯一，前端不得自行拼接后直接作为最终批次号。

并发情况下，即使多个用户在同一时刻点击生成，也必须得到不同批次号。

### 3.6 打印日志与打印状态

所有打印链路统一进入详细打印日志：

- 普通标签打印；
- 标签预打印；
- 接收入库打印。

每一条日志代表一次用户打印动作中的一个标签，至少记录：

| 字段 | 规则 |
| --- | --- |
| 标签批次 | 本次打印所属批次 |
| 标签号 | 本次标签 |
| 打印来源 | 标签打印 / 预打印 / 接收入库打印 |
| 打印份数 | 本次该标签实际请求打印的份数 |
| 打印状态 | 待打印 / 已提交打印 / 打印成功 / 打印失败 |
| 打印时间 | 当前系统时间 |
| 打印 IP | 当前客户端 IP |
| 打印人 | 当前登录用户 |
| 失败原因 | 打印失败时记录；成功为空 |

**不再使用“每条日志打印次数固定写 1”作为最终口径。**

累计打印次数应与成功打印日志中的“打印份数”能够核对。

### 3.7 打印成功时机

正式打印流程：

1. 用户选择打印范围并设置打印份数；
2. 服务端创建打印任务/日志，初始状态为“待打印”；
3. 浏览器调用 Brother b-PAC 打印组件；
4. 已调用组件后可记录“已提交打印”；
5. 仅收到可确认的成功回执后，才更新：
   - 打印日志 = 打印成功；
   - 标签累计打印次数 `+= 本次打印份数`；
   - 标签明细“是否已打印” = 是；
   - 批次“是否已打印” = 是（只要该批次至少存在一条打印成功记录）；
6. 插件失败、打印机异常或明确返回失败时记录“打印失败”，不增加累计打印次数；
7. 如果插件无法提供可信成功回执，只能记录“已提交打印”，不得直接宣称“打印成功”。

当前 PC 原型无法真实连接 Brother 打印机，因此统一模拟成功回执；原型中的“打印成功”仅用于验证状态联动，不代表已完成真实硬件联调。

### 3.8 打印次数一致性

1. 普通标签打印列表中的累计打印次数，与该标签在标签清单/打印历史中的成功打印份数保持一致；
2. 普通标签打印后生成的追溯批次，如果后续从标签清单再次重打，应同步增加普通标签打印主列表对应标签的累计次数；
3. 预打印标签不存在正式资产卡片时，仅维护标签明细自己的累计打印次数；
4. 失败日志不计入累计打印次数。

4. 正式导出需防止 Excel 公式注入：以 `= + - @` 等公式触发字符开头的文本必须按纯文本安全写出；
5. 导出范围继续受公司 + 板块数据权限控制。

## 4.3 生成标签

### 选择账套

账套必填，候选来源：

> `MMP_ASSETS_TAG_ACCOUNT`

展示：

> 账套编码 - 账套名称

### 标签编码规则

| 规则 | 需要设置的信息 |
| --- | --- |
| 常规标签规则 | 资产类型 + 年份 |
| 高耗标签规则 | 高耗大类 + 高耗小类 + 年份 |
| 特殊规则-家具 | 家具类型；当前最大序号允许人工调整但不可回退覆盖已使用流水 |
| 特殊规则-手机 | 固定手机标签规则 |
| 特殊规则-备件 | 备件类型 |

年份字段属于规则组成部分；常规、高耗规则年份清空时禁止生成，不允许偷偷回退成当前年份。

### 标签生成设置

| 字段 | 规则 |
| --- | --- |
| 打印标签数量 | 默认 1；整数；1～500 |
| 部件数量 | 默认 1；整数；1～99 |
| 标签明细总数 | `打印标签数量 × 部件数量`，单批不得超过 5000 条 |
| 标签批次 | 生成前展示“生成标签后自动生成” |
| 操作员 | 当前登录用户 |
| 当前日期 | 当前系统日期 |
| 备注说明 | 用户填写 |

部件数量含义：每个主资产总共生成 `X-1` 张关联标签。

因此：

> **标签明细总数量 = 主标签数量 × 部件数量**

### 家具最大序号

1. 必须为正整数；
2. 不能小于当前服务端已使用最大流水；
3. 允许向前跳号，但跳号后的新区间仍需检查标签唯一性；
4. 不能只和一个固定初始值比较；每次生成前均以服务端最新 `CurrentValue` 为准。

若存在重复：

> 当前输入的流水号，存在已经被使用的情况！

### 生成数量与号段校验

生成前必须校验：

- 主标签数量和部件数量为整数；
- 单批主标签数量不超过 500；
- 单批明细总数不超过 5000；
- 当前规则剩余流水足够；
- 生成后的任一标签号不与现有标签重复；
- 批次号不重复。

任何校验失败，不生成部分成功数据。

### 防重复提交

1. 点击“生成标签”后按钮进入处理中状态；
2. 处理中禁止再次提交；
3. 后端仍必须使用幂等键、事务锁和唯一约束防止双击、并发用户或网络重试；
4. 前端按钮禁用不能替代后端防并发。

### 生成成功

成功后：

- 回填标签批次号；
- 刷新当前规则最大流水；
- 展示“打印标签”按钮；
- 将批次和标签明细写入统一标签批次体系。

失败：

> 标签生成失败

失败不得推进流水号。

## 4.5 部件标签模板

**本轮对抗性测试按用户确认，不调整本章节现有识别口径。**

预打印标签中，如果标签号属于部件标签：

> 标签号包含 `-`，同时不是 `-V` 特殊形式

系统将其识别为：

> 部件标签

打印时使用部件标签模版，普通标签继续使用标准标签模板。

| 来源 | 标签打印 / 预打印 / 接收入库打印 |
| 打印份数 | 本次动作打印份数 |
| 打印状态 | 待打印 / 已提交打印 / 打印成功 / 打印失败 |
| 打印时间 | 当前日志时间 |
| 打印 IP | 客户端 IP |
| 打印人 | 当前登录用户 |

默认最近打印记录优先。

单标签打印历史继续从“批次 → 标签清单 → 打印历史”下钻。

## 5. 标签编码规则

### 5.1 常规标签规则

#### PC.显示器

资产类型编码为 `11`：

> 标签号 = 账套编码 + 11 + 年份后两位 + 5位流水号 + `-V`

示例：

> `123112000277-V`

#### 普通常规标签

> 标签号 = 账套编码 + 资产类型编码 + 年份后两位 + 5位流水号

示例：

> `11216122300746`

如果标签号长度超过 15 位，按现有规则去掉两位年份。

有部件数量时，部件标签号在对应资产标签号后增加 `-01`、`-02`……

### 5.2 高耗标签规则

高耗大类和小类沿用现有配置。

主要标签前缀：

- 合约机 + 合约手机：`P-` + 年份后两位 + 4位流水；
- 合约机 + 合约电话卡：`N-` + 年份后两位 + 4位流水；
- 其他高耗：`QT-` + 年份后两位 + 4位流水。

`P-`、`N-`、`QT-` 为不同规则前缀，正式流水不得错误共用一个页面级 `CurrentValue`。

### 5.3 特殊规则-家具

> 标签号 = 6位流水号 + 家具类型编码

家具类型：

- 工位-A；
- 柜子-D；
- 桌子-E；
- 椅子-Y；
- 其他-Q。

家具公共流水不清零。

### 5.4 特殊规则-手机

> 标签号 = `NE` + 4位流水号

所有手机使用同一手机流水，不清零。

### 5.5 特殊规则-备件

> 标签号 = 备件编码 + 5位流水号

备件类型：

- 备件-CPU；
- 板卡配件-Card；
- 硬盘备件-HD；
- 内存备件-ME；
- 板块备件-SP。

### 5.6 最大序号位数

| 规则类型 | 位数 |
| --- | --- |
| 常规 | 5位 |
| 家具 | 6位 |
| 手机 | 4位 |
| 备件 | 5位 |
| 高耗标签 | 4位 |

生成前必须校验本次预占区间不超过该规则允许的最大值。

## 6. 本地打印环境

正式资产标签打印不是服务器生成 PDF，而是调用用户电脑上的本地打印组件。

当前主要要求：

- Google Chrome；
- Brother b-PAC 浏览器打印组件。

## 7. 校验

### 7.1 标签生成

1. 账套必填；
2. 常规规则：资产类型、年份必填；
3. 高耗规则：高耗大类、高耗小类、年份必填；
4. 家具规则：家具类型必填，人工最大序号必须为正整数且不得回退覆盖已使用流水；
5. 备件规则：备件类型必填；
6. 打印标签数量为 1～500 整数；
7. 部件数量为 1～99 整数；
8. 单批标签明细总数不超过 5000；
9. 本次生成区间不得超过规则最大流水；
10. 标签号和批次号必须全局唯一；
11. 任一校验失败，本次生成整体失败。

### 7.2 打印

1. 打印所选必须至少选择一条；
2. 打印份数为 1～99 整数；
3. 普通标签打印校验公司英文名和标签中文名来源；
4. 打印失败不增加累计打印次数；
5. 打印成功后日志份数与累计次数必须一致；
6. 批次“已打印”只表示该批次至少存在一次成功打印行为，不表示所有标签均已打印。

### 7.3 查询

1. 创建时间结束日期不得早于开始日期；
2. 打印时间结束日期不得早于开始日期；
3. 选择弹窗字段支持正常清空；
4. 查询、打印、导出均必须应用数据权限。

## 8. 后续操作或补充说明

1. 当前原型中的流水池用于模拟“离开生成页面后流水不会重置”，正式系统必须改为服务端持久化流水规则表，不得复制前端实现作为最终方案。
2. 当前原型批次号增加高精度时间与随机片段仅用于降低前端 Mock 冲突；正式批次号仍由后台统一生成并受唯一约束保护。
3. 当前原型统一模拟 Brother 打印成功；真实硬件失败、超时、回执不可信等场景需在联调环境补测。
4. 正式打印接口需要至少拆分“创建打印任务”和“确认打印结果”，避免在浏览器尚未实际打印前就提前累计次数。
5. 接收入库打印链路虽然不在当前 PC 原型中完整实现，但必须使用同一套批次、日志字段和打印结果状态。
6. 本轮对抗性测试确认的部件标签识别规则暂不调整，继续沿用 4.5 节现状口径。
