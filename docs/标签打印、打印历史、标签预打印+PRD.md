# 标签打印、打印历史、标签预打印 PRD

## 1. 背景

现状中“标签打印”“标签预打印”“标签打印历史”为三个独立菜单，功能入口分散，且普通标签补打、预打印、接收入库打印在批次、日志和累计打印次数上的追溯口径不完全一致。

本次改造统一收口至：

> **资产管理 → 标签打印**

三个业务能力仍保留原有职责：

- **标签打印**：打印已经存在的资产/耗材标签，用于补打、批量打印；
- **标签预打印**：在资产实际形成前，按照标签编码规则提前批量生成标签号；
- **打印历史**：统一追溯标签打印、预打印、接收入库打印等打印行为。

本次同时补充标签流水并发、全局唯一性、打印任务状态、详细日志、历史累计次数衔接等规则，避免重复标签号、重复累计打印次数以及“系统显示已打印但实际未打印”等问题。

## 2. 改造总结

1. 原“标签打印 / 标签预打印 / 标签打印历史”三个菜单合并为一个“标签打印”菜单。
2. 默认进入标签打印列表，点击“预打印”进入“标签预打印”页面。
3. 标签预打印页同时承担标签批次查询和新建预打印入口。
4. 下钻关系统一为：**标签打印 → 标签预打印 → 标签清单 / 打印历史 → 单标签打印历史**。
5. 标签打印支持打印所选、打印全部、导出、预打印。
6. 标签打印、预打印、接收入库打印均进入统一标签批次、标签清单和详细打印日志体系。
7. 标签打印列表动态获取资产卡片、耗材卡片最新信息；台账字段变化后按标签号展示最新卡片信息。
8. 预打印与资产接收生成标签必须使用**同一套标签生成服务、同一流水规则表和同一 CurrentValue**，不得分别维护流水。
9. 标签流水正式实现必须由服务端事务控制，禁止依赖浏览器页面中的临时“当前最大序号”。
10. 标签号需要在统一标签空间内全局唯一，至少覆盖标签清单、资产卡片、耗材卡片及接收过程中已占用标签号。
11. 打印日志增加打印来源、打印份数、打印状态、失败原因和打印任务标识，支持与累计打印次数核对。
12. 标签大小本次不再维护。
13. 规则名称统一为“高耗标签规则”。
14. 标签打印查询删除“是否在员工名下”“标签类型”。
15. 本轮对抗性测试按用户确认，**不调整现有部件标签识别规则**。
16. UI统一使用“标签预打印”“标签清单”“是否已打印”“打印确认”等固定名称，不在业务界面展示“原型模拟 / 正式环境 / 后端回执”等研发说明文案。

## 3. 通用规则

### 3.1 菜单与入口

进入“资产管理 → 标签打印”后：

1. 默认展示已有资产/耗材标签查询、补打、批量打印和导出能力；
2. 点击“预打印”进入“标签预打印”；
3. 标签预打印页可查看标签清单或直接查看该批次打印历史；
4. 标签清单可继续查看单标签打印历史；
5. 不再提供独立“标签预打印”“标签打印历史”菜单。

### 3.2 标签打印数据来源

1. 标签打印列表动态获取当前系统中的资产卡片和耗材卡片；
2. 默认展示用户权限范围内全部可打印标签记录；
3. 资产/耗材台账信息变更后，标签打印列表根据标签号展示最新卡片信息，不保存一份长期不更新的独立快照作为列表数据源；
4. 资产接收、耗材接收形成标签后，进入统一标签清单和标签打印追溯体系；
5. 资产接收完成机房资产等标签标识后，标签打印模块应产生相应可追溯记录；
6. 预打印生成标签和资产接收生成标签均必须写入统一标签清单，不允许出现两套互不知晓的标签号池。

### 3.3 数据权限

1. 标签打印查询、打印、导出继续遵循当前用户的**公司 + 板块**数据权限；
2. 用户只能查询、打印和导出本人有权访问的数据；
3. 预打印生成标签需具有标签生成权限；
4. 账套候选范围结合用户可操作权限控制；
5. 不允许通过篡改前端账套编码、公司、板块或查询参数绕过权限；
6. 正式接口层必须再次校验权限，不只依赖按钮显隐和前端过滤。

### 3.4 统一标签号全局唯一性

正式生成标签前必须在统一标签空间校验标签号是否已被占用。

至少包括：

- 标签清单已有标签；
- 正式资产卡片已有标签；
- 耗材卡片已有标签；
- 资产/耗材接收链路已生成或已占用的标签；
- 其他共享同一标签号体系的业务记录。

数据库层需要标签号唯一约束。即使按照 CurrentValue 理论上不会重复，也不得省略最终唯一性校验。

任一标签号重复：本批次整体失败，不产生部分成功标签。

### 3.5 标签流水正式事务规则

标签流水必须由服务端统一维护。

正式生成流程：

1. 根据当前标签规则计算唯一流水规则键；
2. 服务端锁定对应流水规则；
3. 在锁内重新读取最新 `CurrentValue`；
4. 当本年度规则不存在时，按本文跨年规则寻找上一年度规则；
5. 校验本次主标签数量、明细数量及剩余号段；
6. 计算本次预占的主标签流水区间；
7. 根据流水区间生成全部标签号；
8. 校验本批次全部标签号全局唯一；
9. 生成标签批次；
10. 生成标签明细；
11. 更新对应流水规则 `CurrentValue`，并设置 `NextValue = CurrentValue + 1`；
12. 批次、标签明细、流水更新必须在同一事务内提交。

任一步失败均整体回滚，不允许出现：

- 流水已推进但标签未生成；
- 标签已生成但流水未推进；
- 只生成部分标签；
- 批次写入失败但流水已经被占用。

数据库至少需要：

- 标签批次号唯一约束；
- 标签号唯一约束；
- 流水规则键唯一约束；
- 标签生成接口幂等控制。

### 3.6 流水规则维度

| 规则 | 流水维度 |
| --- | --- |
| 常规标签规则 | 账套 + 资产类型 + 年份对应规则；跨年按历史规则续号 |
| 高耗标签规则 | `QT-`、`P-`、`N-` 三类前缀分别维护自己的公共流水，不区分公司，跨年不清零 |
| 特殊规则-家具 | 所有家具共用一组流水，不区分家具类型，跨年不清零 |
| 特殊规则-手机 | 所有手机共用一组流水，跨年不清零 |
| 特殊规则-备件 | **所有备件共用一组流水**，CPU / Card / HD / ME / SP 只决定标签前缀，不拆分 CurrentValue，跨年不清零 |

特别说明：

> 特殊规则-备件不得按 CPU、Card、HD、ME、SP 分别建立独立流水。

### 3.7 跨年续号

预打印与资产接收标签生成规则相同，并共用同一流水体系，跨年不清零。

常规规则按“账套 + 资产类型 + 年份”查找规则：

1. 当年规则存在：取当年 `CurrentValue`；
2. 当年规则不存在：尝试查找最近上一年度规则；
3. 上一年度规则未用完：新年度继续使用上一年度当前值继续编号；
4. 上一年度规则已达到 `MaxValue`：按新规则最小值开始；
5. 没有任何历史规则：按规则最小值开始。

该规则尤其适用于“标签长度超过15位时去掉年份”的常规标签。即使最终标签文本中不包含年份，也必须保证跨年流水继续递增，避免不同年份生成相同标签号。

高耗 `QT- / P- / N-`、家具、手机、备件均按各自公共流水继续编号，不因年份切换清零。

### 3.8 批次号唯一与生成时间

1. 标签批次由服务端统一生成并保证唯一；
2. 前端拼接高精度时间/随机数只能作为原型演示，不能作为正式唯一性方案；
3. 多用户同一时间生成必须得到不同批次号；
4. 标签生成时间以用户实际执行“生成标签”并成功创建批次的业务时刻为准；
5. 批次号重复时本次生成整体失败且流水不得推进。

### 3.9 标签生成接口幂等

1. 点击“生成标签”后按钮进入处理中状态；
2. 前端处理中禁止再次提交；
3. 正式接口仍必须接受唯一请求幂等键；
4. 同一幂等键重复请求只能返回同一业务结果，不得重复生成批次和标签；
5. 浏览器重试、网络超时重发、用户双击均不得造成重复生成。

### 3.10 打印任务与打印结果幂等

每一次打印动作生成唯一 `printTaskId`。

打印动作包括：

- 标签打印页打印所选；
- 标签打印页打印全部；
- 标签清单打印所选；
- 标签清单打印全部；
- 接收入库打印。

正式打印结果确认接口必须按 `printTaskId` 幂等：

1. 同一任务第一次确认成功后，累计打印次数只增加一次；
2. Brother组件重复回调、网络重试或前端重复提交成功结果，不得再次增加打印次数；
3. 同一任务已经成功后再次提交“成功”仅返回已有结果；
4. 失败任务重试需建立明确的重试动作或新的打印尝试，不得覆盖历史失败记录后失去审计链路。

### 3.11 打印日志

所有打印链路统一生成详细打印日志：

- 标签打印；
- 预打印；
- 接收入库打印。

每一条日志代表“一次打印任务中的一个标签”。至少记录：

| 字段 | 规则 |
| --- | --- |
| 打印任务ID | 本次打印动作唯一 `printTaskId` |
| 标签批次 | 本次打印所属批次 |
| 标签号 | 本次标签 |
| 打印来源 | 标签打印 / 预打印 / 接收入库打印 |
| 打印份数 | 本次标签请求打印份数 |
| 打印状态 | 待打印 / 已提交打印 / 打印成功 / 打印失败 |
| 打印时间 | 当前业务时间 |
| 打印 IP | 当前客户端 IP |
| 打印人 | 当前登录用户 |
| 失败原因 | 失败时记录；成功为空 |

不再使用“每条日志打印次数固定写1”作为最终口径。

### 3.12 打印状态更新时机

正式打印流程：

1. 用户选择打印范围；
2. 设置打印份数；
3. 服务端创建打印任务，日志初始状态“待打印”；
4. 浏览器调用 Brother b-PAC；
5. 成功调用组件后可更新为“已提交打印”；
6. 仅收到可信成功回执后，才更新：
   - 日志状态 = 打印成功；
   - 累计打印次数 `+= 本次打印份数`；
   - 对应标签明细“是否已打印” = 是；
   - 批次“是否已打印” = 是；
7. 明确失败时记录“打印失败”和失败原因，不增加累计打印次数；
8. 若 Brother 组件无法提供可信成功回执，只能记录“已提交打印”，不得直接宣称“打印成功”。

上述正式实现说明只保留在 PRD / 技术实现中，**不作为原型页面提示文案展示给用户**。

### 3.13 打印次数一致性

1. 普通标签打印列表“打印次数”为成功打印累计份数；
2. 标签清单“打印次数”为该标签在当前标签体系中的成功打印累计份数；
3. 普通补打批次从标签清单再次重打时，必须同步增加主标签打印列表对应记录的打印次数；
4. 预打印标签尚未形成正式资产/耗材卡片时，仅维护标签清单累计次数；
5. 失败、待打印、已提交但未确认成功的任务不计入累计打印次数。

### 3.14 历史累计次数基线

系统上线前可能已经存在“累计打印次数”，但历史系统未保存完整打印时间、IP、打印人等详细日志。

不得为了让新日志合计等于旧累计次数而伪造历史详细日志。

迁移口径：

1. 上线时记录每个标签的“历史累计打印次数基线”；
2. 上线前历史次数只作为基线，不反向伪造打印时间、IP、打印人；
3. 上线后所有打印必须生成详细日志；
4. 当前累计打印次数校验公式：

> **当前累计打印次数 = 历史累计打印次数基线 + 上线后打印成功日志的打印份数合计**

5. 如历史系统本身已有可信详细日志，可按真实数据迁移，不适用“伪造基线日志”。

## 4. 页面字段及交互

### 4.1 标签打印

#### 查询条件

| 查询项 | 交互 | 规则 |
| --- | --- | --- |
| 公司中文名称 | 文本输入 | 按现有查询框架过滤 |
| 公司英文名称 | 文本输入 | 按现有查询框架过滤 |
| 部门 | 选择弹窗 | 支持清空；支持键盘 Enter / Space 打开 |
| 板块中文名称 | 文本输入 | 按现有字段查询 |
| 资产状态 | 下拉 | 使用 `ASSET_STATUS` |
| 资产标签号 | 文本输入 | 按标签号查询 |
| 序列号 | 文本输入 | 按 SN 查询 |
| 使用人 | 人员选择弹窗 | 按责任人员工编号查询；选择后展示 `工号-姓名`；支持清空；支持键盘 Enter / Space 打开 |
| 资产类别 | 选择弹窗 | 支持清空；支持键盘 Enter / Space 打开 |
| 城市 | 下拉/选择 | 来源现有 City 数据 |

不展示：

- 是否在员工名下；
- 标签类型。

#### 默认排序

默认按照：

> **City → 使用人编号升序 → 资产标签号升序**

列表支持表头排序。

#### 列表字段

| 字段 | 说明 |
| --- | --- |
| 选择 | Checkbox，可多选 |
| 资产标签号 | 当前资产/耗材标签 |
| 资产名称 | 当前最新资产/耗材说明 |
| 部门 | 当前部门 |
| 地点 | 当前标签对应地点 |
| 公司中文名称 | 当前公司中文名 |
| 公司英文名称 | 当前公司英文名 |
| 板块中文名 | 当前板块中文名 |
| 序列号 | 当前 SN |
| 资产类别 | 当前资产类别 |
| 资产状态 | 当前资产状态 |
| 使用人 | `工号-姓名` |
| 打印次数 | 历史基线 + 上线后成功打印份数 |

普通数量、次数、条数按业务原值展示，不强制增加千分位；金额、原值、净值等财务数字继续按财务格式展示。

#### 页面操作

| 操作 | 规则 |
| --- | --- |
| 打印所选 | 主要操作；打印已勾选标签；未勾选时按钮禁用并展示当前选择数量 |
| 打印全部 | 打印当前查询条件范围内全部标签，不只当前分页 |
| 导出 | 有勾选导出所选；无勾选导出当前查询条件范围全部结果 |
| 预打印 | 次级入口，进入标签预打印 |

#### 打印前校验

未选择资产时“打印所选”按钮禁用，不发起打印。

公司英文名称为空：

> 资产标签号为“XXX”项没有公司英文名！

标签中文名优先取板块中文名称；板块为空时回退公司中文名称；仍为空：

> 资产标签号为“XXX”项没有公司中文名！

#### 打印确认

点击打印操作后打开“打印确认”弹窗：

- 展示本次标签数量；
- 打印份数默认 1；
- 打印份数必须为整数；
- 打印份数范围 1～99；
- 明确展示：`标签数量 × 打印份数 = 总打印张数`。

仅打印成功后：

> `累计打印次数 += 本次打印份数`

#### 导出

1. 已勾选记录：导出所选；
2. 未勾选：导出当前查询条件范围内全部结果，不只当前分页；
3. 导出业务字段与标签打印列表一致；
4. 以 `= + - @` 等公式触发字符开头的文本按纯文本安全写出，防止 Excel 公式注入；
5. 导出范围继续受公司 + 板块数据权限控制。

### 4.2 标签预打印

页面由标签打印页点击“预打印”进入。

页面标题：

> **标签预打印**

页面底部提供“返回标签打印”，不在页面标题区域重复放置返回按钮。

该页统一展示以下来源：

- 预打印；
- 标签打印；
- 接收入库打印。

#### 查询条件

| 查询项 | 规则 |

#### 标签生成设置

| 字段 | 规则 |
| --- | --- |
| 打印标签数量 | 默认 1；整数；1～500 |
| 部件数量 | 默认 1；整数；1～99 |

| 标签批次 | 生成前显示“生成标签后自动生成” |

> **标签明细总数量 = 主标签数量 × 部件数量**

#### 家具当前最大序号

1. 必须为正整数；
2. 不得小于服务端当前已使用最大流水；
3. 允许向前跳号；
4. 向前跳号后的标签区间仍需全局唯一性校验；
5. 每次生成前重新读取服务端最新 `CurrentValue`，不能只和页面初始值比较。

#### 生成成功

成功后：

- 回填标签批次；
- 刷新当前最大流水；
- 展示“打印标签”；
- 批次和全部标签明细写入统一标签体系；
- 标签清单明细数与批次“生成标签数量”一致。

失败：

> 标签生成失败

失败不得推进流水号，也不得保留部分标签明细。

## 5. 标签编码规则

### 5.1 常规标签规则

#### PC.显示器

资产类型编码为 `11`：

> 标签号 = 账套编码 + 11 + 年份后两位 + 5位流水号 + `-V`

示例：

> `123112000277-V`

#### 普通常规标签

> 标签号 = 账套编码 + 资产类型编码 + 年份后两位 + 5位流水号

示例：

> `11216122300746`

如果标签号长度超过15位，按现有规则去掉两位年份。

有部件数量时：

> 部件标签号 = 主标签号 + `-01`、`-02`……

常规规则跨年不得从头重新使用已经出现过的流水；尤其去掉年份后的标签必须继续流水以保证标签号唯一。

### 5.2 高耗标签规则

高耗规则主要前缀：

- 合约机 + 合约手机：`P-` + 年份后两位 + 4位流水；
- 合约机 + 合约电话卡：`N-` + 年份后两位 + 4位流水；
- 其他高耗：`QT-` + 年份后两位 + 4位流水。

`P-`、`N-`、`QT-` 分别维护一组流水，不区分公司，跨年不清零。

### 5.3 特殊规则-家具

家具规则使用现有 `RULE_SPECIAL_FURNITURE` 对应规则。

> 标签号 = 6位流水号 + 家具类型编码

家具类型：

- 工位-A；
- 柜子-D；
- 桌子-E；
- 椅子-Y；
- 其他-Q。

所有家具共用一组流水，不清零。

### 5.4 特殊规则-手机

原始特殊手机规则适用于对应物料分类条件（历史口径：第二级分类编码 `13` 且第三级分类编码 `004`）。

> 标签号 = `NE` + 4位流水号

所有手机共用一组流水，不清零。

### 5.5 特殊规则-备件

备件规则使用现有 `RULE_SPECIAL_SPARE_PARTS` 对应规则。

> 标签号 = 备件编码 + 5位流水号

备件类型：

- 备件-CPU；
- 板卡配件-Card；
- 硬盘备件-HD；
- 内存备件-ME；
- 板块备件-SP。

**所有备件共用同一组5位流水号，不清零。**

例如 CPU 和 HD 只是前缀不同，不能各自重新从同一个数值起号。

### 5.6 最大序号位数

| 规则类型 | 位数 |
| --- | --- |
| 常规 | 5位 |
| 家具 | 6位 |
| 手机 | 4位 |
| 备件 | 5位 |
| 高耗标签 | 4位 |

生成前必须校验本次预占区间不超过该规则最大值。

## 8. 校验

### 8.1 标签生成

1. 账套必填；
2. 常规规则资产类型、年份必填；
3. 高耗规则高耗大类、高耗小类、年份必填；
4. 家具规则家具类型必填；人工最大序号必须为正整数且不得回退覆盖已使用流水；
5. 备件规则备件类型必填，但不同备件类型仍共用同一 CurrentValue；
6. 打印标签数量为1～500整数；
7. 部件数量为1～99整数；
8. 单批标签明细总数不超过5000；
9. 本次生成主流水区间不得超过规则最大值；
10. 标签号必须在统一标签空间全局唯一；
11. 批次号必须唯一；
12. 批次标签数量必须与实际标签明细数量一致；
13. 任一校验失败，本次生成整体失败；
14. 失败不得推进 CurrentValue；
15. 预打印与资产接收必须使用同一流水服务。

### 8.2 打印

1. 打印所选至少选择一条；UI层未选择时按钮直接禁用；
2. 打印份数1～99整数；
3. 打印确认展示标签数量、本次份数和总打印张数；
4. 普通标签打印校验公司英文名和标签中文名来源；
5. 同一 `printTaskId` 的成功结果只累计一次；
6. 打印失败不增加累计次数；
7. 打印成功后日志打印份数与累计次数一致；
8. 批次“已打印”只表示至少存在一次成功打印，不表示所有标签全部打印；
9. 打印失败必须保留失败状态及失败原因。

### 8.3 查询

1. 创建时间结束日期不得早于开始日期；
2. 打印时间结束日期不得早于开始日期；
3. 选择弹窗字段支持清空；
4. 查询、打印、导出均应用公司 + 板块数据权限。

### 8.4 导出

1. 有勾选导出所选；
2. 无勾选导出当前查询结果全部数据；
3. 不受当前分页限制；
4. 公式触发字符按纯文本安全写出；
5. 导出接口必须再次校验数据权限。

## 9. 后续操作或补充说明

1. 当前原型流水池只用于模拟页面交互；正式系统必须使用服务端 `MMP_ASSETS_TAG_SEQ_RULE` 等现有流水规则数据，不得照搬前端状态方案。
2. 当前原型批次号使用高精度时间与随机片段仅用于降低 Mock 冲突；正式批次号由后台统一生成并受唯一约束保护。
3. 当前原型统一模拟 Brother 打印成功；真实硬件失败、超时和回执不可信必须在联调环境补测；该说明仅存在于文档，不展示在业务原型页面。
4. 正式打印接口至少区分“创建打印任务”和“确认打印结果”，并以 `printTaskId` 保证结果确认幂等。
5. 接收入库打印虽然不在当前标签打印 PC 原型中完整实现，但必须使用同一套批次、标签清单、日志字段和打印任务状态。
6. 历史累计打印次数上线时按基线迁移，不伪造历史打印时间、IP和打印人。
7. 预打印、资产接收必须共享同一标签生成服务和 CurrentValue；不得由两个模块各自维护自己的“当前最大序号”。
8. 本轮明确不调整部件标签识别规则，继续沿用 4.5 节现状口径。
9. 第二轮对抗性测试用例及发现记录见 `docs/TEST-标签打印-对抗性测试.md`。
