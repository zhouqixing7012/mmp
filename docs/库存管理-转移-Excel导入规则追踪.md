# 库存管理 - 转移 Excel 导入规则追踪

## 1. 来源

本规则依据用户提供的《转移数据导入模板.xls》及当前转移业务口径整理。模板为旧式 Excel 工作簿，包含：

- 第一张表“资产转移导入模板”：15 列，第一列用于回写错误；
- 第二张表“Sheet3”：用途、楼层等填写辅助字典；
- 模板不包含公司列，公司取当前转移单已选择的公司。上传上下文仍携带转移单 ID、单据类型、单据状态、公司和业务类型，历史上传类型为 `uploadType=transfer`。

## 2. 模板列

| 列 | 表头 |
|---:|---|
| 1 | 错误提示 |
| 2 | 资产标签号* |
| 3 | SN号 |
| 4 | 转入人(员工编号)* |
| 5 | 成本中心 |
| 6 | City* |
| 7 | Building* |
| 8 | Floor* |
| 9 | Room |
| 10 | 转移日期(YYYY-MM-DD) |
| 11 | 转移原因 |
| 12 | 用途* |
| 13 | 业务线 |
| 14 | 项目 |
| 15 | 转移说明 |

Excel 下拉选项只是填写辅助；服务端必须重新按系统基础资料校验，不能依赖下拉值。

## 3. 导入校验

1. 标签号有值时优先按标签号找资产；标签号为空时按 SN 号找资产；两者同时填写时标签号优先。
2. 资产所属公司必须等于转移单公司；资产被其他业务占用时不能上传。
3. 转入人填写时检查员工存在且有效；模板标注必填，但上传阶段可能不强制，留空的行在后续确认时仍可能失败。
4. City、Building、Floor 均必填；City 必须有效，Building 必须属于所选 City，Floor 必须有效。
5. 转移日期填写时必须为 `yyyy-MM-dd`；留空使用上传当天日期。
6. 用途填写时必须是系统已有用途；留空沿用资产原用途。
7. 业务线、项目填写时检查是否存在；留空允许通过。
8. 成本中心列不直接覆盖资产成本中心：普通资产主要使用转入人资料中的成本中心，SERVER 资产保留原成本中心。
9. Room、转移原因、转移说明直接保存，当前未发现额外长度或格式校验。

## 4. 批量处理

1. 只要一行错误，整批不保存，不产生部分成功。
2. 系统把每行错误写回 Excel 第一列，用户下载错误结果文件，修改后重新上传。
3. 全部通过后生成转移单明细，并暂时锁定资产。
4. 上传成功不是资产转移完成；用户点击【确认转移】后，系统再次检查资产当前状态。
5. 资产不再处于“在用—使用中”时，确认失败；确认成功后才更新资产信息并解除锁定。

## 5. 当前原型实现

`src/pages/inventoryManagement/TransferPage.js` 已提供：

- 使用 `xlsx` 读取用户提供的 `.xls/.xlsx` 文件；
- 按 15 列表头匹配并逐行预览；
- 按上述规则执行资产、人员、位置、日期、用途、业务线和项目校验；
- 任意错误时禁止整批导入，并下载错误结果文件；
- 全部通过后生成明细、保存草稿并暂时形成资产占用；
- 模板下载与错误结果下载。

## 6. 仍需正式环境确认

以下不由当前模板或前端 Mock 单独确定：

- 并发上传同一资产时的成功顺序；
- 批量锁定失败是否完整回滚；
- 正式环境字典及人员有效状态；
- 转移原因在打印、查询等页面的最终展示位置；
- 旧系统与当前仓库在接口字段、状态码上的完整一致性。
