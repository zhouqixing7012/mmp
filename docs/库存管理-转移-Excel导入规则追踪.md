# 库存管理 - 转移 Excel 导入规则追踪

## 1. 目的

用于记录“库存管理 → 转移”Excel 批量导入在三方比对中的已确认规则、当前原型状态和仍缺失的旧系统来源。

本文件只记录有来源支持的内容，不根据其他模块 Excel 规则类推转移规则。

## 2. 已确认来源规则

根据原版《库存管理—转移》可确认：

1. 转移单编辑页提供【Excel导入】。
2. 同时提供【下载模板】。
3. Excel 导入用于批量新增转移单物资明细。
4. 导入前必须先选择公司；公司未选择时不允许进入导入。
5. 上传上下文至少携带：
   - 转移单 ID；
   - 单据类型；
   - 单据状态；
   - 公司；
   - 业务类型。
6. 历史上传类型为 `uploadType=transfer`。
7. 上传窗口关闭后，重新读取当前转移单详情并刷新转移明细。
8. 原版明确指出：逐列校验、失败行回传、批量锁定细节尚未完整追到上传处理链路。

## 3. 当前原型状态

当前 `TransferPage.js` 已保留：

- 【模板下载】入口；
- 【Excel导入】入口。

当前原型不伪造：

- xlsx 文件解析；
- 服务端上传；
- 错误行文件下载；
- 批量锁定；
- 真实资产台账写入。

## 4. 本轮仓库追查结果

已检索当前仓库代码与可检索提交历史中的：

- `uploadType=transfer`
- `uploadType transfer`
- `转移模板`
- `transfer Excel import`
- `转移 导入`

结果：

- 当前仓库没有旧系统 `transfer` 上传处理器；
- 没有真实转移 Excel 模板文件；
- 没有逐列校验实现；
- 没有失败行回传实现；
- 没有批量锁定 / 回滚实现；
- 可检索历史提交中也未找到上述旧实现。

因此当前资料不足以还原完整上传规则。

## 5. 当前明确的来源缺口

以下项目必须等待旧系统上传处理源码、真实模板或接口文档，不能由产品侧猜测：

1. 模板精确列名、列顺序、示例值。
2. 每列是否必填。
3. 每列格式、长度、字典校验。
4. 资产标签号 / SN 的匹配优先级。
5. 文件内重复资产处理。
6. 与当前转移单已有明细重复时的处理。
7. 与其他业务锁冲突时的处理。
8. 转出人 / 转入人一致性在批量文件中的校验时点。
9. 公司、板块、权限校验在文件解析阶段还是保存阶段执行。
10. 转移日期默认值和空值填充策略。
11. SERVER 成本中心特殊规则如何作用于导入行。
12. 特殊 NO 资产字段是否进入模板。
13. 整批失败还是允许部分成功。
14. 失败行回传文件结构和错误信息。
15. 资产批量锁定发生时点。
16. 处理中途失败的解锁 / 回滚方式。
17. 并发状态变化后的二次校验方式。
18. 上传成功后页面刷新返回的数据结构。

## 6. 已确认产品规则对 Excel 的约束

虽然精确 Excel 链路尚缺来源，但本轮已确认的转移业务规则在正式导入时仍必须成立：

- 公司必须存在；
- 同一张手工转移单内多条资产的转出人必须一致；
- 同一张手工转移单内多条资产的转入人必须一致；
- 转入成本中心由转入人带出并只读；
- SERVER 成本中心保持原成本中心；
- 资产状态只读；
- 转移数量自动取资产数量；
- 转移日期必填；
- 公司 / 板块与转入人不一致时保留二次确认语义；
- 特殊 NO 资产规则继续保留；
- 资产业务锁规则继续保留。

这些是“转移业务规则”，不等同于已确认 Excel 模板列和上传实现细节。
