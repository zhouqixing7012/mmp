# 标签打印三方比对：原版 PRD vs 当前原型 vs 新版 PRD

## 1. 比对基线

本次固定使用以下三个基线：

- 原版 PRD：`docs/标签打印、打印历史、标签预打印+原版PRD.md`
- 当前原型：`src/pages/assetManagement/TagPrintingPage.js`
- 新版 PRD：`docs/标签打印、打印历史、标签预打印+PRD.md`

后续规则：

1. 原版 PRD 仅作为历史业务基线保存，不直接覆盖、不重写。
2. 原型用于确认当前页面字段、文案、交互和已实现规则。
3. 新版 PRD 用于承载当前最终业务口径；需要调整时只修改新版 PRD。
4. 三方存在冲突时，先区分“原版规则被遗漏”和“原版规则已被后续改造替代”，不能直接把原版整段覆盖回新版。
5. 当前原型无需模拟的后台正式规则，可以只保留在新版 PRD 中。

## 4. 正式 PRD 保留、原型无需强行模拟的规则

| 主题 | 原版 PRD | 当前原型 | 新版 PRD | 结论 |
| --- | --- | --- | --- | --- |
| 最新卡片联动 | 动态获取资产/耗材卡片最新信息；台账变化后同步展示 | 当前使用页面 Mock，不做跨模块实时联动 | 已保留正式规则 | 原型可以不做 |
| 打印次数跨入口一致性 | 原版分别维护次数，口径不完全统一 | Mock 初始数据可能存在不一致 | 新版要求同一标签累计次数一致 | 原型可以不为此做复杂改造，正式系统必须保证 |

## 5. 已确认的三方差异口径

### 5.1 常规/高耗跨年查找历史年度范围

原版写“尝试找前一年的规则”；当前原型会按年份倒序找到最近一个存在规则的历史年度。

最终口径以当前原型为准：

- 当年规则存在时，使用当年 CurrentValue。
- 当年规则不存在时，按年份倒序查找最近一个存在规则的历史年度，不要求必须是紧邻上一年度。
- 常规最近历史年度 CurrentValue 未达到 99999 时继续编号，达到 99999 时新年度从 00001 开始。
- 高耗按 `QT-`、`P-`、`N-` 三类前缀分别处理；最近历史年度 CurrentValue 未达到 9999 时继续编号，达到 9999 时新年度从 0001 开始。
- 不存在任何历史年度规则时，从对应规则最小值开始。

新版 PRD 按该规则描述；原版 PRD 保持原样作为历史基线。

### 5.2 家具、手机、备件跨年规则

原版前半段“规则不存在时直接从最小值创建”与后半段“所有家具/手机/备件确定一组流水号，不清零”存在内部冲突。

最终口径以当前原型为准，采用不带年份的全局公共流水：

- 家具：`furniture`
- 手机：`mobile`
- 备件：`spare`

家具、手机、备件切换年份时不创建新的年度流水，继续使用当前公共 CurrentValue；备件 CPU / Card / HD / ME / SP 只决定标签前缀，不拆分流水。

新版 PRD 按该规则描述；原版 PRD 保持原样作为历史基线。

## 6. 已落实到新版 PRD 的调整

按三方比对和后续确认，以下内容已经写入新版 PRD：

1. 创建人使用下拉选择，枚举仅取通过标签预打印生成过标签批次的创建人；当前原型同步按该范围取值。
2. UI 字段和文案以当前页面为准，包括“城市 / 操作员 / 当前日期 / 共打印 X 张标签”等。
3. 常规标签补充显示器 `-V` 具体格式。
4. 常规标签补充超过 15 位去掉年份。
5. 高耗补充完整 `P-/N-/QT-` 标签格式和大类/小类映射。
6. 高耗跨年按当前原型处理：最近历史年度未满 9999 续号；达到 9999 后新年份从 0001 开始。
7. 家具补充 6 位流水及 A/D/E/Y/Q 对应关系。
8. 部件数量补充“包含主标签本身”、`X - 1` 张关联标签和总明细计算公式。
9. 部件标签识别规则直接陈述，不再使用“保持不变 / 本轮不调整”等表述。
10. 补充主标签二维码、部件不生成资产卡片且无二维码、部件使用部件标签模板。
11. 标签生成时间定义为点击“生成标签”并成功创建标签批次时的服务端时间。
12. Brother 环境明确 Google Chrome + Brother b-PAC + Brother 驱动；具体打印机型号、标签纸尺寸、模板文件名、模板坐标和驱动版本标记为当前文档未明确。
13. 新版 PRD 中“既有规则 / 现有规则 / 保持不变 / 本轮不调整”等依赖历史背景的规则表述已经展开为实际规则。

## 7. 后续使用方式

以后标签打印及其他模块做 PRD 校准时，固定按以下顺序检查：

1. 原版 PRD：确认历史业务规则和字段来源。
2. 当前原型：确认当前页面字段、文案、入口、交互及已实现业务规则。
3. 新版 PRD：确认最终目标规则是否完整承接了仍有效的原版规则，同时记录后续明确改造。
4. 原版与新版冲突时，不修改原版；在三方比对记录中说明差异及最终口径，只更新新版 PRD。
