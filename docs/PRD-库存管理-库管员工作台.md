# 库存管理 - 库管员工作台 PRD

> 本文以当前 PC 原型 `src/pages/inventoryManagement/WarehouseWorkbenchPage.js` 为现状基线整理。
> 用户提供的原版《库管员工作台》作为历史业务依据，用于后续三方比对；原版存在但当前原型尚未实现的能力，不在本文中描述为“已实现”。

## 1. 背景

库管员工作台位于“库存管理 → 库管员工作台”，用于为库管员提供资产/耗材业务单据查询入口。

当前原型已经完成：

- 页面入口；
- 工作台标题；
- 【员工页面】、【刷新员工页面】两个顶部操作；
- 资产标签号、员工卡号、员工姓名、资产名称、单据编号、单据类型查询字段；
- 资产出入库单据列表字段和空状态。

当前原型仍处于页面骨架阶段，尚未接入真实待办数据、办理页面跳转、员工独立展示页、扫码/刷卡触发查询和业务节点路由。

## 2. 改造总结

当前原型相较历史页面已经形成以下现状：

1. 页面不再展示单独的“资产出入库”页签，直接展示查询区和“资产出入库单据”列表 Card。
2. 页面右上角不提供独立【扫码】【刷卡】按钮。
3. 页面右上角保留【员工页面】【刷新员工页面】。
4. 查询区保留扫码/刷卡对应输入字段，但当前仅支持录入，尚未实现回车查询。
5. 当前查询按钮为独立居中按钮，尚未绑定实际查询逻辑。
6. 单据类型下拉当前没有候选数据。
7. 待办列表当前固定为空，不会根据查询条件返回数据。
8. 列表“操作”列当前仅展示占位符 `-`，尚未进入业务办理页。
9. 【员工页面】当前仅提示“员工页面字段待确认”，未真正打开员工独立窗口。
10. 【刷新员工页面】当前仅提示“员工页面已刷新”，未维护或清除员工展示状态。

## 3. 通用规则

### 3.1 页面入口

- 一级模块：库存管理；
- 二级菜单：库管员工作台；
- 当前页面无内部业务 Tab；
- 页面标题固定为“库管员工作台”。

### 3.2 页面初始状态

当前原型进入页面后：

- 查询条件全部为空；
- 单据列表为空；
- 列表显示“暂无数据”；
- 不会自动加载待办。

### 3.3 当前查询状态

当前原型仅维护查询输入值，不区分“查询草稿条件”和“已生效查询条件”。

页面尚未实现：

- 点击【查询】后过滤数据；
- 查询结果数量变化；
- 扫描资产标签号后回车查询；
- 输入员工卡号后回车查询；
- 只有一条结果时自动进入办理页面；
- 多条结果时展示真实待办；
- 查询无结果时的业务提示。

### 3.4 当前待办数据

当前 `dataSource` 固定为空数组。

因此目前不存在：

- Mock 待办单据；
- 当前登录人待办权限过滤；
- 单据类型过滤；
- 流程节点过滤；
- 办理状态过滤；
- 申请时间排序；
- 真实“处理”操作。

## 4. 页面字段及交互

### 4.1 顶部操作

当前页面右上角提供：

| 操作 | 当前原型行为 |
|---|---|
| 员工页面 | 点击后提示“员工页面字段待确认” |
| 刷新员工页面 | 点击后提示“员工页面已刷新” |

当前原型不提供：

- 【扫码】；
- 【刷卡】。

### 4.2 查询条件

| 字段 | 组件 | 当前占位文案 | 当前行为 |
|---|---|---|---|
| 资产标签号 | Input | 扫描/输入资产标签号 | 仅维护输入值 |
| 员工卡号 | Input | 刷卡/输入员工编号 | 仅维护输入值 |
| 员工姓名 | Input | 请输入员工姓名 | 仅维护输入值 |
| 资产名称 | Input | 请输入资产名称 | 仅维护输入值 |
| 单据编号 | Input | 请输入单据编号 | 仅维护输入值 |
| 单据类型 | Select | 请选择 | 当前无候选项 |

查询区使用项目统一 QueryBar 布局，但公共 QueryBar 的默认按钮被关闭。

页面在查询区下方单独居中展示【查询】按钮。

当前【查询】按钮没有绑定业务逻辑。

当前页面没有【重置】按钮。

### 4.3 资产出入库单据列表

Card 标题：**资产出入库单据**。

右上角固定展示：

`共 0 条`

列表字段：

| 字段 | 当前展示 |
|---|---|
| 行号 | 数据中的 index |
| 申请单编号 | 普通文本 |
| 单据类型 | 普通文本 |
| 审批环节 | 普通文本 |
| 申请人 | 普通文本 |
| 申请时间 | 普通文本 |
| 操作 | 固定展示 `-` |

当前列表：

- 支持分页 UI；
- 默认每页 10 条；
- 支持切换每页条数；
- 超宽时支持横向滚动；
- 当前没有真实数据。

当前未实现：

- 申请单编号点击进入办理；
- 【处理】按钮；
- 申请单编号排序；
- 申请时间排序；
- 默认申请时间倒序；
- 单条结果自动打开；
- 分页后的连续行号。

### 4.4 员工页面

当前原型尚未实现员工独立页面。

不存在：

- 独立窗口；
- 员工信息；
- 当前单据信息；
- 资产/耗材明细；
- 保管职责；
- 刷卡/扫码进度；
- 自动刷新；
- 办理完成/等待等状态页面。

## 5. 校验

当前原型没有业务校验逻辑。

以下场景当前都不会触发校验：

- 资产标签号为空后回车；
- 员工卡号为空后回车；
- 单据类型无权限；
- 员工卡号无法识别员工；
- 查询结果为空；
- 当前单据不属于当前库管员待办；
- 待办已经被其他人处理。

- 当前登录人待办过滤；

- 员工卡号回车查询；
- 查询排序；
- 单条结果自动进入办理；
- 申请单编号入口；
- 【处理】入口；

- 员工独立页面；
- 员工页面自动刷新；

### 6.2 与现有补充 PRD 的关系

仓库现有 `docs/PRD-库存管理-库管员工作台及员工领用退库打印补充.md` 继续保留。

其中关于：

- 删除“资产出入库”页签；
- 删除独立【扫码】【刷卡】按钮；
- 保留【员工页面】【刷新员工页面】；

与当前原型一致。

该补充 PRD 中关于员工领用/退库库存单据打印的规则属于库存单据打印能力，不并入本文工作台现状描述。

### 6.3 后续三方比对原则

后续固定对比：

1. 用户提供的原版《库管员工作台》；
2. 当前 `WarehouseWorkbenchPage.js` 原型；
3. 本现状 PRD。

差异按以下结论收口：

- **原型应补**：原版业务规则仍有效，当前原型缺失；
- **PRD应跟原型**：当前新交互已被现有补充规则或原型明确覆盖；
- **仅后端/流程规则**：原型无需模拟技术实现，但正式系统必须满足；
- **待确认**：历史规则与当前原型/补充口径存在真实冲突，不能自行裁决。
