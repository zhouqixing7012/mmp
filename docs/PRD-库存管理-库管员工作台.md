# 库存管理 - 库管员工作台 PRD

## 1. 背景

库管员需要处理员工退库、新员工领用、员工借用、资产申请、耗材申请、领用申请单和资产更换等不同业务。各业务来源、当前办理节点和目标办理页面不同。

库管员工作台提供统一待办入口，用于：

- 查询当前登录库管员需要处理的待办单据；
- 按资产、员工和单据信息快速定位待办；
- 展示待办的申请单编号、业务类型、当前审批环节、申请人和申请时间；
- 通过申请单编号进入对应业务办理页面；
- 将当前办理的员工、单据、物资及确认提示同步展示到员工页面；
- 通过【刷新员工页面】刷新员工页面展示状态。

库管员在工作台定位待办后进入对应业务办理页，业务节点推进、资产状态变化、库存数量变化及库存事务在对应业务操作成功后产生。

## 2. 权限

### 2.1 工作台访问权限

库管员工作台固定开放给以下两名员工：

| 工号 | 姓名 |
|---|---|
| 114111 | 杨芊 |
| 213852 | 孙志强 |

系统根据当前登录员工身份校验工作台访问权限。

非以上两名员工进入工作台时返回 403 页面，提示：

当前工作台仅开放给杨芊、孙志强。

### 2.2 待办数据权限

通过工作台权限校验后，待办结果进一步按当前登录库管员过滤。

单据只有在当前办理节点的处理人为当前登录库管员时，才进入该库管员的待办结果。

进入业务办理页面前再次校验：

- 当前节点仍处于待办理状态；
- 当前节点处理人仍为当前登录库管员；
- 当前用户仍具备目标业务页面要求的办理权限。

## 3. 通用规则

### 3.1 工作台业务范围

工作台固定处理以下 7 类业务：

| 工作台业务类型 | 目标办理页面 |
|---|---|
| 员工退库 | 资产退库办理 |
| 新员工领用 | 新员工领用单 |
| 员工借用 | 借用发放 |
| 资产申请 | ES前台领用 |
| 耗材申请 | 耗材领用 |
| 领用申请单 | ES前台领用 |
| 资产更换 | 资产更换办理 |

业务类型同时作为查询条件“单据类型”的候选值。

### 3.2 待办准入规则

单据进入工作台待办结果必须同时满足：

1. 业务类型属于 3.1 节定义的 7 类业务；
2. 当前业务节点处于待办理状态；
3. 当前节点处理人 = 当前登录库管员；
4. 当前登录库管员具备对应业务的办理权限。

工作台查询使用实时待办结果，不以历史列表结果作为办理权限依据。

### 3.3 首次进入与查询结果

首次进入工作台时：

1. 查询条件全部为空；
2. 自动展示当前登录库管员全部实时待办；
3. 默认按申请时间倒序；
4. 当前页为第 1 页；
5. “资产出入库单据”Card 展示结果总数。

主动点击【查询】、扫描资产标签号后回车、刷员工卡号后回车时，按当前查询条件重新筛选。

查询结果处理统一为：

| 结果数量 | 页面行为 |
|---:|---|
| 0 条 | 停留在工作台，列表展示“暂无待处理单据” |
| 1 条 | 停留在工作台，展示该 1 条结果 |
| 多条 | 停留在工作台，展示全部匹配结果 |

查询结果数量不会触发自动进入业务办理页面。

### 3.4 查询匹配规则

查询条件之间使用 AND 关系。

同一待办中存在多条物资时，资产标签号或资产名称任意一条物资命中即可满足该条件。

| 查询项 | 匹配规则 |
|---|---|
| 资产标签号 | 与待办物资资产标签号精确匹配 |
| 员工卡号 | 与待办申请人员工卡号精确匹配 |
| 员工姓名 | 对申请人姓名做包含匹配 |
| 资产名称 | 对待办物资说明做包含匹配 |
| 单据编号 | 对申请单编号做包含匹配 |
| 单据类型 | 与工作台业务类型完全匹配 |

### 3.5 办理入口

申请单编号是工作台待办列表的唯一办理入口。

点击申请单编号时：

1. 重新校验待办仍属于当前登录库管员；
2. 重新校验当前办理节点；
3. 生成当前办理信息；
4. 将当前办理信息同步给员工页面；
5. 进入 3.1 节对应的目标办理页面。

待办列表不设置【处理】操作列。

### 3.6 当前办理信息

当前办理信息用于员工页面展示当前现场办理内容。

包含：

| 数据组 | 字段 |
|---|---|
| 员工信息 | 员工编号、员工姓名、组织 |
| 单据信息 | 单据编号、业务类型、当前审批 / 办理环节、当前办理状态 |
| 物资明细 | 行号、物资小类、资产标签号或物料编码、数量、单位、物资说明 |
| 员工确认内容 | 当前办理场景需要展示的保管职责或退回确认说明 |

进入新的待办办理页时，当前办理信息更新为新单据内容。

业务办理页中的办理阶段、员工确认场景或物资结果发生变化时，员工页面使用最新办理信息展示。

### 3.7 员工确认内容

员工页面的确认内容根据“业务类型 + 当前办理场景”确定，不只按单据类型判断。

| 业务 / 场景 | 员工页面确认内容 |
|---|---|
| 员工退库 | 展示当前退库业务需要员工核对的退回确认说明；不展示领用保管职责 |
| 新员工领用 | 展示领用保管职责 |
| 员工借用 | 展示借用保管职责 |
| 资产申请 | 展示领用保管职责 |
| 耗材申请 | 展示对应耗材领用保管职责 |
| 领用申请单 | 展示领用保管职责 |
| 资产更换 - 退库确认 | 展示旧资产退回确认说明 |
| 资产更换 - 领用确认 | 展示新资产领用保管职责 |

员工页面展示对应办理业务返回的确认内容，不根据工作台自身字段重新拼接业务文案。

### 3.8 并发与实时校验

待办查询结果仅表示查询时点的可办理状态。

以下时点重新校验当前节点及处理人：

- 点击申请单编号进入办理页；
- 目标业务页执行正式办理动作。

如果单据已被其他人处理、当前节点已经变化或处理人已经变化：

- 本次旧节点操作不继续；
- 页面提示待办状态已变化；
- 用户返回或刷新工作台后重新获取实时待办。

工作台不使用历史待办结果强制推进业务节点。

## 4. 页面字段及交互

### 4.1 页面标题与顶部操作

页面标题：

库管员工作台

页面右上角固定展示：

- 【员工页面】
- 【刷新员工页面】

不设置独立【扫码】或【刷卡】快捷按钮。

扫码枪和刷卡设备直接向对应查询输入框录入数据。

### 4.2 查询条件

查询区字段：

| 查询项 | 控件 | 输入 / 查询规则 |
|---|---|---|
| 资产标签号 | 输入框 | 支持扫码枪输入；精确匹配 |
| 员工卡号 | 输入框 | 支持刷卡设备输入；精确匹配 |
| 员工姓名 | 输入框 | 包含匹配 |
| 资产名称 | 输入框 | 包含匹配 |
| 单据编号 | 输入框 | 包含匹配 |
| 单据类型 | 下拉单选 | 7 类工作台业务 |

查询区提供：

- 【查询】
- 【重置】

【查询】：

- 按全部当前查询条件执行；
- 查询结果回到第 1 页。

【重置】：

- 清空全部查询条件；
- 恢复当前登录库管员全部实时待办；
- 回到第 1 页。

### 4.3 扫描和刷卡回车

#### 4.3.1 资产标签号

资产标签号输入框非空时按回车：

- 按当前全部查询条件执行一次查询；
- 资产标签号使用去除首尾空格后的值。

资产标签号输入框为空时按回车：

- 不执行查询；
- 提示：请扫描/输入资产标签号！

#### 4.3.2 员工卡号

员工卡号输入框非空时按回车：

- 按当前全部查询条件执行一次查询；
- 员工卡号使用去除首尾空格后的值。

员工卡号输入框为空时按回车：

- 不执行查询；
- 提示：请扫描/输入员工卡号！

### 4.4 资产出入库单据

Card 标题固定为：

资产出入库单据

Card 右上角展示：

共 X 条

列表字段：

| 字段 | 展示 / 交互规则 |
|---|---|
| 行号 | 按当前分页连续编号 |
| 申请单编号 | 蓝色链接；工作台唯一办理入口 |
| 单据类型 | 展示 7 类业务之一 |
| 审批环节 | 展示当前审批 / 办理节点 |
| 申请人 | 展示员工编号-姓名 |
| 申请时间 | 展示 yyyy-MM-dd |

列表不设置选择列。

列表不设置操作列。

排序规则：

- 默认按申请时间倒序；
- 申请单编号支持排序；
- 申请时间支持排序；
- 其他字段不提供表头排序。

分页规则：

- 默认每页 10 条；
- 支持切换每页条数；
- 查询、重置后回到第 1 页；
- 行号按当前页码连续计算；
- 0 条时展示“暂无待处理单据”。

### 4.5 申请单编号入口

点击申请单编号后，根据业务类型进入：

| 单据类型 | 页面 |
|---|---|
| 员工退库 | 资产退库办理 |
| 新员工领用 | 新员工领用单 |
| 员工借用 | 借用发放 |
| 资产申请 | ES前台领用 |
| 耗材申请 | 耗材领用 |
| 领用申请单 | ES前台领用 |
| 资产更换 | 资产更换办理 |

进入目标页面前同步更新当前办理信息。

目标页面收到：

- 真实申请单编号；
- 业务类型；
- 当前审批 / 办理环节。

### 4.6 员工页面

#### 4.6.1 打开员工页面

点击【员工页面】：

1. 打开独立浏览器窗口；
2. 窗口标题为“员工页面”；
3. 读取当前办理信息并展示；
4. 当前无办理信息时展示“无办理信息”。

浏览器阻止新窗口时提示：

员工页面被浏览器拦截，请允许弹出窗口后重试

打开或关闭员工页面不改变待办状态和业务单据状态。

#### 4.6.2 页面状态

员工页面顶部展示当前办理状态。

无当前办理信息时：

- 状态展示“无办理信息”；
- 页面提示员工等待库管员开始办理业务。

有当前办理信息时：

- 状态展示当前业务返回的办理状态；
- 工作台首次进入某张待办办理页时，可以展示“信息核对”作为当前办理阶段；
- 后续状态随对应业务办理阶段更新。

#### 4.6.3 员工信息与单据信息

员工页面展示：

| 区域 | 字段 |
|---|---|
| 员工信息 | 员工编号、员工姓名、组织 |
| 单据信息 | 单据编号、业务类型、当前环节 |

字段无值时显示“-”。

不根据当前员工档案、资产台账或其他实时数据重新补算历史办理信息。

#### 4.6.4 物资明细

物资明细字段：

| 字段 | 规则 |
|---|---|
| 行号 | 从 1 开始顺排 |
| 物资小类 | 展示当前办理信息中的物资小类 |
| 标签号 / 物料编码 | 资产、低值耐用品优先展示标签号；无标签号的物资展示物料编码 |
| 数量 | 展示当前办理数量 |
| 单位 | 展示当前办理单位 |
| 说明 | 展示物资说明 |

无物资明细时展示：

暂无物资明细

#### 4.6.5 员工确认内容

员工确认区域按 3.7 节规则展示。

当前办理场景不需要员工确认说明时，不展示该区域。

资产更换业务根据当前是“退库确认”还是“领用确认”展示不同确认内容。

#### 4.6.6 自动刷新

员工页面每 3 秒自动刷新一次当前办理信息。

工作台或对应业务办理页面更新当前办理信息后，员工页面在刷新时展示最新内容。

### 4.7 刷新员工页面

点击【刷新员工页面】：

1. 刷新员工页面当前展示；
2. 清除上一笔当前办理信息；
3. 工作台提示：已刷新；
4. 已打开的员工页面刷新后展示“无办理信息”。

刷新员工页面不删除待办，不推进或回退业务节点，不修改资产状态和库存结果。

## 5. 校验

### 5.1 工作台访问

当前登录用户不属于以下任一员工时：

- 114111-杨芊；
- 213852-孙志强。

返回 403 页面。

### 5.2 查询

资产标签号、员工卡号通过回车触发查询时：

- 输入值不得为空；
- 空值分别使用固定提示；
- 多个查询条件同时存在时按 AND 关系过滤。

查询无结果不作为异常，正常展示空列表。

### 5.3 办理入口

点击申请单编号时重新校验：

- 单据业务类型仍属于工作台范围；
- 当前节点仍处于待办理状态；
- 当前节点处理人仍为当前登录库管员；
- 当前用户仍具备目标页面办理权限。

校验失败时不进入旧办理节点，并提示用户刷新待办。

### 5.4 并发状态变化

目标办理页正式提交前再次校验当前节点和处理人。

如果单据已被其他人完成、处理人变化或节点变化：

- 拒绝旧节点操作；
- 返回最新业务状态；
- 页面提示待办状态已变化。

### 5.5 员工页面

打开员工页面时浏览器阻止新窗口：

员工页面被浏览器拦截，请允许弹出窗口后重试

员工页面无当前办理信息时正常展示：

无办理信息

当前办理信息字段为空时：

- 对应字段展示“-”；
- 不通过其他实时档案补算。

物资明细为空时：

暂无物资明细

## 6. 后续操作 / 业务结果 / 补充说明

### 6.1 进入业务办理页面

点击申请单编号并校验通过后：

- 将该单据设为当前办理对象；
- 更新员工页面当前办理信息；
- 进入对应业务办理页面；
- 目标业务页面按自身业务规则继续办理。

工作台本身不因为“进入办理页面”改变业务单据状态。

### 6.2 办理过程中的员工页面更新

对应业务办理过程中，如发生以下变化，可更新当前办理信息：

- 办理状态变化；
- 当前办理环节变化；
- 物资明细变化；
- 从信息核对进入员工确认；
- 资产更换在退库确认与领用确认之间切换；
- 员工确认完成。

员工页面按最新当前办理信息刷新展示。

### 6.3 业务办理结果

正式办理结果由对应业务提交成功后产生，包括：

- 流程节点变化；
- 资产状态变化；
- 库存数量变化；
- 入库 / 出库事务；
- 资产锁定或释放；
- 业务单据完成状态。

业务办理完成后，该单据不再满足当前库管员待办准入条件时，下一次工作台查询不再返回该单据。

### 6.4 刷新员工页面结果

点击【刷新员工页面】后：

- 上一笔当前办理信息被清除；
- 员工页面恢复“无办理信息”；
- 待办列表保持业务实时结果；
- 不修改业务单据；
- 不修改审批 / 办理节点；
- 不修改库存和资产台账。

### 6.5 空值与历史信息

员工页面展示当前办理信息中已经保存的员工、单据和物资数据。

字段无值时统一显示“-”。

不使用当前员工档案、当前资产台账等实时数据覆盖或补算已经形成的历史办理信息。
