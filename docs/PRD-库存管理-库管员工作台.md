# 库存管理 - 库管员工作台 PRD

## 1. 背景

库管员需要处理员工退库、员工领用、员工借用、资产申请、耗材申请和资产更换等不同业务。各业务的办理页面不同，待处理单据也来自不同流程。

库管员工作台提供一个统一入口，用于：

- 查询当前库管员需要处理的待办单据；
- 查看待办的申请人、业务类型、审批环节和申请时间；
- 进入对应业务办理页面；
- 将当前办理信息展示给员工；
- 清空员工展示页面中的当前办理信息。

工作台完成待办查询、待办展示和办理入口，具体办理及库存落账在对应业务页面完成。

## 2. 改造目标

1. 待办结果只包含当前登录库管员仍需处理的单据。
2. 资产标签号和员工卡号支持扫描设备直接输入，并可按回车查询。
3. 查询结果只有 1 条时直接进入对应办理页面；有多条时保留列表供库管员选择。
4. 申请单编号和【处理】进入同一张业务办理页面。
5. 员工页面独立打开，并持续展示当前办理单据和物资信息。

## 3. 页面职责与范围

工作台完成待办查询、待办展示、办理入口和员工办理信息展示。具体业务办理、流程推进及库存落账在各业务页面和对应服务中完成。

| 功能 | 具体规则 |
|---|---|
| 待办查询 | 查询当前库管员、待处理状态、工作台业务范围内的单据 |
| 待办展示 | 展示查询结果数量和待办列表 |
| 办理入口 | 申请单编号、【处理】和单条结果自动进入对应办理页 |
| 员工页面 | 打开独立窗口，展示当前办理上下文 |
| 员工页面刷新 | 清空共享的当前办理上下文，并提示“已刷新” |

## 4. 使用人、权限与待办范围

### 4.1 使用人

工作台允许以下人员使用：

| 工号-姓名 | 原型状态 |
|---|---|
| 114111-杨芊 | 演示操作人 |
| 213852-孙志强 | 可使用人员 |

正式系统必须从当前登录身份获取工号，并在服务端校验工作台权限。页面参数、前端状态或浏览器存储不能绕过该校验。

演示环境固定使用 114111-杨芊 作为操作人。

### 4.2 待办准入条件

一条单据只有同时满足以下条件，才能进入工作台结果：

1. 当前处理人等于当前登录库管员；
2. 单据状态为“待处理”；
3. 单据类型属于本文件第 4.3 节列出的 7 类业务；

单据在查询后被其他人员处理、节点发生变化或权限失效时，正式服务端必须重新校验，页面不能仅依据查询时的结果继续办理。

### 4.3 当前业务类型

工作台展示以下 7 类业务：

- 员工退库
- 新员工领用
- 员工借用
- 资产申请
- 耗材申请
- 领用申请单
- 资产更换


## 5. 页面字段及交互

### 5.1 页面标题与顶部操作

页面标题为“库管员工作台”。

右上角只展示：

- 【员工页面】
- 【刷新员工页面】

扫码枪和刷卡设备直接向资产标签号、员工卡号输入框录入，查询统一由查询按钮或输入框回车触发。

### 5.2 查询条件

查询区包含以下字段：

| 查询项 | 控件 | 有值时的匹配规则 |
|---|---|---|
| 资产标签号 | 输入框 | 与待办物资的资产标签号精确匹配；同一单据任一物资命中即可 |
| 员工卡号 | 输入框 | 与待办记录的员工卡号精确匹配 |
| 员工姓名 | 输入框 | 对申请人姓名做包含匹配 |
| 资产名称 | 输入框 | 对待办物资说明做包含匹配；同一单据任一物资命中即可 |
| 单据编号 | 输入框 | 对申请单号做包含匹配 |
| 单据类型 | 下拉框 | 与业务类型完全匹配；候选值为本文件第 4.3 节的 7 类业务 |

多个条件同时填写时，所有条件必须同时满足。查询不创建、修改或删除业务单据。

页面提供【查询】按钮，不提供独立【重置】按钮。清空输入框后再次点击【查询】，按清空后的条件重新查询。

### 5.3 扫描和刷卡回车

#### 资产标签号

- 输入非空值后按回车，执行一次查询；
- 输入为空后按回车，阻断查询并提示：请扫描/输入资产标签号！。

#### 员工卡号

- 输入非空值后按回车，执行一次查询；
- 输入为空后按回车，阻断查询并提示：请扫描/输入员工卡号！。

扫描设备将结果写入对应输入框，输入框非空时按回车执行查询。

### 5.4 首次进入

正式系统首次进入时：

1. 查询条件全部为空；
2. 结果来源为当前登录库管员的实时待办集合；
3. 结果数量展示当前结果总数。

演示环境首次进入时：

1. 操作人为 114111-杨芊；
2. 查询条件全部为空；
3. 展示 7 条待处理演示待办，分别覆盖本文件第 4.3 节的 7 类业务；
4. 结果数量展示当前结果总数。

点击【查询】、扫描资产标签号或刷员工卡号后，按输入条件重新筛选。

### 5.5 查询结果

| 结果数量 | 页面行为 |
|---:|---|
| 0 条 | 保留当前页面，展示空列表和“暂无待处理单据”，不自动创建或修改单据 |
| 1 条 | 写入该单据的员工页面上下文，并自动进入对应业务办理页面 |
| 多条 | 保留列表，由库管员点击申请单编号或【处理】进入 |

单条结果自动进入时，页面使用与点击入口相同的业务路由。

### 5.6 待办列表

列表右上角展示：

共 X 条

列表字段：

| 字段 | 展示规则 |
|---|---|
| 行号 | 按当前分页连续编号，从 1 开始 |
| 申请单编号 | 蓝色链接；点击进入对应办理页；支持排序 |
| 单据类型 | 展示 7 类业务名称 |
| 审批环节 | 展示当前库管员需要处理的节点名称 |
| 申请人 | 展示工号-姓名 |
| 申请时间 | 展示 yyyy-MM-dd；支持排序 |
| 操作 | 仅展示【处理】；进入对应办理页 |

排序规则：

1. 默认按申请时间倒序；
2. 申请单编号支持表头排序；
3. 申请时间支持表头排序；
4. 分页切换后，行号按当前页连续计算；
5. 默认每页 10 条，允许切换每页条数。

列表不展示已经过滤掉的“已处理”“非当前处理人”和“员工离职”单据。

## 6. 业务办理入口

申请单编号、【处理】和单条结果自动进入以下页面：

| 工作台业务类型 | 目标办理页面 |
|---|---|
| 员工退库 | 资产退库办理 |
| 新员工领用 | 新员工领用单 |
| 员工借用 | 借用发放 |
| 资产申请 | ES前台领用 |
| 耗材申请 | 耗材领用 |
| 领用申请单 | ES前台领用 |
| 资产更换 | 资产更换办理 |

进入办理页前，工作台需要把当前单据的办理信息交给员工页面，包括真实单据编号和当前办理环节。正式系统不能只传业务类型名称。

## 7. 员工页面

### 7.1 打开与关闭

点击【员工页面】：

1. 打开独立浏览器窗口；
2. 窗口标题为“员工页面”；
3. 能够读取当前工作台共享的办理上下文；
4. 没有上下文时展示“无办理信息”。

浏览器阻止新窗口时，工作台提示：

员工页面被浏览器拦截，请允许弹出窗口后重试

关闭员工页面不改变待办状态，也不改变任何业务单据。

### 7.2 办理上下文

库管员进入业务办理页前，保存以下信息：

| 数据组 | 字段 |
|---|---|
| 员工信息 | 员工编号、员工姓名、组织 |
| 单据信息 | 单据编号、业务类型、当前审批/办理环节 |
| 物资明细 | 行号、物资小类、资产标签号或物料编码、数量、单位、物资说明 |
| 领用提示 | 领用类业务需要员工确认的保管职责 |


### 7.3 员工页面展示

员工页面展示以下区域：

| 区域 | 字段或内容 |
|---|---|
| 页面状态 | 有上下文时展示当前办理状态 |
| 员工信息 | 员工编号、员工姓名、组织 |
| 单据信息 | 单据编号、业务类型、当前审批/办理环节 |
| 物资明细 | 行号、物资小类、标签号/物料编码、数量、单位、说明 |
| 保管职责 | 仅“新员工领用、资产申请、耗材申请、领用申请单”展示 |

无物资明细时，明细区域展示“暂无物资明细”。

### 7.4 自动刷新

员工页面：

- 每 3 秒读取一次最新办理信息；
- 工作台更新或清空办理信息后，员工页面刷新展示内容；
- 没有办理信息时，展示“无办理信息”。

员工页面展示的办理状态以对应业务流程返回结果为准。

### 7.5 刷新员工页面

点击【刷新员工页面】：

1. 清空当前员工页面共享上下文；
2. 工作台提示“已刷新”；
3. 员工页面下一次读取时展示“无办理信息”；
4. 不删除待办，不改变业务办理状态，不回滚库存事务。

## 8. 校验与异常

| 场景 | 处理规则 |
|---|---|
| 无工作台权限 | 不展示待办列表，展示 403 结果，并提示“当前工作台仅开放给杨芊、孙志强。” |
| 资产标签号为空后回车 | 不查询，提示“请扫描/输入资产标签号！” |
| 员工卡号为空后回车 | 不查询，提示“请扫描/输入员工卡号！” |
| 新窗口被拦截 | 提示允许弹窗后重试 |
| 员工页面无上下文 | 展示“无办理信息” |
| 单据已被其他人处理 | 正式业务拒绝继续办理并返回最新状态，页面提示用户刷新待办 |
| 当前节点已变化 | 正式业务拒绝旧节点操作，页面不自行推进节点 |
| 共享上下文字段为空 | 对应字段展示 -，不根据当前员工档案或资产台账补算历史值 |

## 9. 业务结果约束

1. 工作台根据当前登录身份展示对应的待办；权限和待办归属以正式业务结果为准。
2. 库管员进入办理页或提交办理动作时，系统重新校验单据仍处于当前节点且仍由当前库管员处理。
3. 业务办理完成后的流程状态、资产状态、库存数量和库存事务，按对应业务办理规则更新。
4. 员工页面展示当前办理上下文中的员工、单据和物资信息；缺少历史快照时显示 `-`，不根据其他档案临时补算。

## 10. 验收标准

1. 非杨芊、孙志强进入页面时看到无权限结果。
2. 演示环境进入页面时，查询条件为空，直接看到覆盖 7 类业务的 7 条待处理演示待办。
3. 页面只展示【员工页面】【刷新员工页面】两个顶部操作。
4. 资产标签号和员工卡号可以由输入框接收扫描/刷卡值并按回车查询。
5. 两个输入框为空时按回车，分别出现指定提示。
6. 6 个查询条件按 AND 关系筛选结果。
7. 查询结果为 0 条时留在当前页面，不创建单据。
8. 查询结果为 1 条时自动进入对应办理页面。
9. 查询结果超过 1 条时留在列表。
10. 申请单编号和【处理】进入同一目标页面。
11. 列表默认按申请时间倒序，申请单编号和申请时间可以排序。
12. 列表分页行号连续，右上角显示结果数量。
13. 员工页面能展示员工、单据和物资信息，并每 3 秒刷新。
14. 点击【刷新员工页面】后，员工页面显示“无办理信息”，待办和单据不被删除。
15. 业务类型下拉和待办列表只展示本文件规定的 7 类业务。
16. 工作台不自行改变审批状态、库存数量、资产状态或库存事务。

## 11. 后续操作与补充说明

以下内容由对应业务 PRD 维护：

- 员工领用/退库打印附页；
- 借用和借用归还的员工操作留痕页；
- 各业务办理页内部字段和校验；
- 工作台之外的库存单据查询、打印和导出。
