# 库存管理 - 库管员工作台 PRD

> 本文以当前 PC 原型 `src/pages/inventoryManagement/WarehouseWorkbenchPage.js` 为实现基线，并结合原版《库管员工作台》及后续确认口径收口。

## 1. 背景

库管员工作台用于集中查找当前库管员需要处理的资产/耗材业务单据，并进入对应业务办理页面。

工作台自身负责：

- 找单；
- 扫描/刷卡查询；
- 展示待办列表；
- 进入对应办理页面；
- 打开员工现场展示页面；
- 刷新员工展示上下文。

工作台不直接代表库存事务已完成。资产出库、退库、借用、领用、更换等业务结果，继续以对应业务流程最终处理结果为准。

## 2. 改造总结

当前实现已按最新口径收口：

1. 页面入口为“库存管理 → 库管员工作台”。
2. 页面不再保留单独“资产出入库”页签，直接展示查询区和待办列表。
3. 删除右上角独立【扫码】【刷卡】按钮；扫码枪/刷卡设备直接向对应查询框写值。
4. 保留【员工页面】【刷新员工页面】。
5. 首次进入不自动加载待办，列表保持空白，只有主动查询/扫码/刷卡后才查询。
6. 资产标签号回车、员工卡号回车可直接查询。
7. 单条查询结果自动进入办理页面；多条结果停留在列表。
8. 申请单编号及【处理】均可进入对应业务办理页面。
9. 员工页面以独立窗口打开，并每 3 秒刷新当前办理上下文。
10. 刷新员工页面会清空当前员工展示信息，并提示“已刷新”。
11. 工作台仅允许杨芊、孙志强使用。
12. 员工离职不进入库管员工作台，由离职流程自己的待办入口处理。

## 3. 通用规则

### 3.1 使用人

当前工作台仅开放：

- `114111-杨芊`
- `213852-孙志强`

当前原型为了演示将当前库管员 Mock 为 `114111-杨芊`。

正式实现必须使用真实当前登录人判断权限，不允许通过页面参数绕过。

### 3.2 待办范围

只展示同时满足以下条件的单据：

1. 当前库管员为该单据当前处理人；
2. 单据当前仍处于待处理状态；
3. 单据类型属于工作台业务范围；
4. 不包含员工离职。

### 3.3 单据类型

当前工作台业务类型固定为：

- 员工退库
- 新员工领用
- 员工借用
- 资产申请
- 耗材申请
- 领用申请单
- 资产更换

**员工离职不在当前工作台展示。**

### 3.4 页面初始状态

首次进入：

- 不自动查询；
- 查询条件为空；
- 列表为空；
- 结果数量显示 0；
- 空状态提示“请查询待处理单据”。

### 3.5 工作台与办理页边界

工作台只做查询和入口。

点击申请单编号、点击【处理】、或单条查询结果自动进入时，统一进入现有对应办理页面，不在工作台内复制另一套办理流程。

当前原型路由映射：

| 单据类型 | 办理页面 |
|---|---|
| 员工退库 | 资产退库办理 |
| 新员工领用 | 新员工领用单 |
| 员工借用 | 借用发放 |
| 资产申请 | ES前台领用 |
| 耗材申请 | 耗材领用 |
| 领用申请单 | ES前台领用 |
| 资产更换 | 资产更换办理 |

## 4. 页面字段及交互

### 4.1 顶部操作

页面右上角仅保留：

- 【员工页面】
- 【刷新员工页面】

不展示：

- 【扫码】
- 【刷卡】

### 4.2 查询条件

| 查询项 | 交互 | 查询规则 |
|---|---|---|
| 资产标签号 | 扫描/输入；回车查询 | 按资产标签号精确匹配关联待办 |
| 员工卡号 | 刷卡/输入；回车查询 | 先按员工卡号识别申请人，再查询该员工待办 |
| 员工姓名 | 文本 | 模糊查询 |
| 资产名称 | 文本 | 模糊查询物资说明 |
| 单据编号 | 文本 | 模糊查询 |
| 单据类型 | Select | 只展示当前工作台 7 类业务 |

查询按钮点击后开始查询。

当前页面继续不提供独立【重置】按钮。

### 4.3 扫描/刷卡回车

#### 4.3.1 资产标签号

资产标签号输入框按回车：

- 有值：直接按当前查询条件执行查询；
- 空值：提示 `请扫描/输入资产标签号！`。

#### 4.3.2 员工卡号

员工卡号输入框按回车：

- 有值：直接按当前查询条件执行查询；
- 空值：提示 `请扫描/输入员工卡号！`。

### 4.4 查询结果

查询后：

- 0 条：保留空列表，不创建、不修改任何业务单据；
- 1 条：自动进入该单据对应办理页面；
- 多条：停留在待办列表，由库管员选择处理。

结果默认按申请时间从新到旧排列。

### 4.5 待办列表

| 字段 | 规则 |
|---|---|
| 行号 | 按当前分页连续编号 |
| 申请单编号 | 蓝色入口；点击进入办理；支持排序 |
| 单据类型 | 业务类型名称 |
| 审批环节 | 当前库管员需处理的节点名称 |
| 申请人 | 工号-姓名 |
| 申请时间 | 展示 yyyy-MM-dd；支持排序 |
| 操作 | 【处理】，进入办理页面 |

列表右上角动态展示当前查询结果：

`共 X 条`

默认排序：申请时间倒序。

### 4.6 当前原型待办 Mock

当前原型 Mock 仅用于验证工作台交互，覆盖：

- 员工退库；
- 新员工领用；
- 员工借用；
- 资产申请；
- 耗材申请；
- 领用申请单；
- 资产更换。

其中物资信息复用现有库存公共资产 Mock，不为工作台另造一套资产属性。

Mock 中不生成员工离职待办。

正式实现必须以真实工作流当前节点、处理人和权限为准。

## 5. 员工页面

### 5.1 打开方式

点击【员工页面】：

- 打开独立浏览器窗口；
- 若没有当前办理信息，展示“无办理信息”；
- 若浏览器拦截弹窗，提示用户允许弹窗后重试。

### 5.2 当前办理上下文

库管员从工作台进入某张单据办理前，工作台将当前办理上下文写入员工页面共享数据。

包括：

- 员工编号；
- 员工姓名；
- 组织；
- 单据编号；
- 业务类型；
- 当前审批/办理环节；
- 资产/耗材明细；
- 领用类业务保管职责。

### 5.3 自动刷新

员工页面每 **3 秒**重新读取一次当前办理上下文。

同时监听浏览器 storage 变化，以便跨窗口及时刷新。

### 5.4 展示内容

| 区域 | 展示内容 |
|---|---|
| 办理状态 | 当前原型进入业务时展示“信息核对”；无数据时展示“无办理信息” |
| 员工信息 | 员工编号、姓名、组织 |
| 单据信息 | 单据编号、业务类型、当前环节 |
| 明细 | 物资小类、标签号/物料编码、数量、单位、说明 |
| 保管职责 | 新员工领用、资产申请、耗材申请、领用申请单展示 |

当前工作台只负责提供展示上下文，具体刷卡/扫码完成状态仍应由对应业务办理流程驱动。

### 5.5 刷新员工页面

点击【刷新员工页面】：

1. 清空当前员工页面共享上下文；
2. 独立员工页面下次轮询后回到“无办理信息”；
3. 工作台提示 `已刷新`。

## 6. 校验

### 6.1 权限

当前使用人不属于杨芊、孙志强时：

- 不展示正常工作台；
- 展示 403 无权限结果；
- 提示“当前工作台仅开放给杨芊、孙志强”。

### 6.2 查询

- 空资产标签号按回车：阻断并提示；
- 空员工卡号按回车：阻断并提示；
- 查询结果为空：只展示空列表；
- 不允许通过查询生成新业务单据；
- 员工离职永远不进入结果集。

### 6.3 待办有效性

正式实现查询时必须重新校验：

- 当前登录人是否仍为处理人；
- 当前节点是否仍待处理；
- 当前单据是否已被其他人处理；
- 当前处理人是否仍具备业务权限。

前端 Mock 只模拟结果，不替代服务端工作流校验。
