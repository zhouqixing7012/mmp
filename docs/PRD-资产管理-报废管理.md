# 资产管理 - 报废管理 PRD

> 当前跨公司转移（调账）的正式目标口径以 `docs/PRD-资产管理-跨公司转移.md` 为准；本文件其余报废模块需待新版流程图补齐后再收口。

## 1. 背景

报废管理用于承接资产从“提出报废或跨公司调账需求”到“账面报废完成”，以及需要实物处置时的后续处置闭环。

本模块统一覆盖以下业务：

1. 跨公司转移（调账）；
2. 资产报废；
3. 待报废池；
4. 账面报废；
5. 待处置池；
6. 资产实物处置；
7. 机房资产报废特殊流程。

本轮将“调账”从资产报废申请中拆出，统一由“跨公司转移”流程发起。跨公司转移审批完成后，资产进入待报废池，再由 ES 账务人员发起账面报废。调账完成后不进入资产处置流程。

## 3. 通用规则

### 3.1 单据与状态

报废业务单据至少支持以下通用状态：

- 草稿；
- 审批中；
- 已驳回；
- 已审批；
- 已完成。

草稿允许编辑和删除；进入审批后原申请数据只读，审批节点只开放当前节点明确允许编辑的字段。

单据提交时必须防重复提交。接口处理中按钮进入 Loading，不允许重复点击产生重复单据或重复事务。

### 3.2 附件

业务支持上传附件。

不同模块现状资料对附件大小限制存在差异，正式统一限制见 8.1 待确认项。在规则确认前，新版原型只展示真实文件选择、上传、预览/下载和删除能力，不伪造上传结果。

### 3.3 资产选择

资产选择必须来自正式资产台账。

除明确允许的特殊场景外：

- 已正式报废资产不可再次选择进入新的报废或调账申请；
- 同一资产不能同时处于两个未结束的互斥业务流程；
- 选择资产后，资产标签号、序列号、分类、公司、板块、责任人、位置、金额等台账字段按资产卡片自动带出；
- 资产数据必须保持同一资产卡片整行关联，不允许跨资产拼接字段。

### 3.4 报废方式与报废类型

报废方式：

- 全部报废；
- 部分报废；
- 调账。

其中“调账”不再从“资产报废”菜单直接发起，只能由“跨公司转移”流程产生。

报废类型：

- 已到报废期；
- 未到报废期；
- 丢失。

### 3.5 金额规则

金额统一保留 2 位小数。

部分报废金额按以下公式计算：

> 报废金额 = 资产总金额 ÷ 资产总数量 × 报废数量

剩余数量 = 原资产数量 - 报废数量。

剩余金额 = 原资产金额 - 报废金额。

### 3.6 报废池与处置池

#### 待报废池

进入待报废池的数据由系统业务流程产生，不开放手工新增、修改或删除。

待报废池至少记录来源业务类型，用于区分：

- 跨公司转移（调账）；
- 部分报废；
- 全部报废；
- 丢失赔偿；
- 机房资产盘亏；
- 装修；
- 软件；
- 其他正式确认的直达账面报废类型。

待报废池支持条件查询、分页和导出。

#### 待处置池

待处置池数据来源于账面报废执行结果。

以下资产不进入待处置池：

- 调账资产；
- 丢失赔偿资产；
- 物料配置为无需处置的资产；
- 业务已明确完成实物处置的资产。

待处置池支持条件查询、分页和导出。

## 4. 页面字段及交互

## 4.1 跨公司转移（调账）

### 4.1.1 入口

入口：资产管理 → 跨公司转移。

“调账”统一通过跨公司转移发起，不再在资产报废申请中提供“调账”发起入口。

### 4.1.2 适用范围及流程

#### A. 机房资产 + 非机房资产中的软件

流程：

> 跨公司转移申请开始 → 资产责任人提交跨公司转移申请 → 责任人 5 级及以上直属领导审批 → 责任人 7 级及以上直属领导审批 → 进入待报废池 → 跨公司转移申请流程结束 → 发送服务号通知所有参与人 → 进入账面报废流程

任一审批节点驳回后，单据退回发起人。

#### B. 非机房资产中的办公设备

流程：

> 跨公司转移申请开始 → ES 管理员提交跨公司转移申请 → ES 主管确认 → 进入待报废池 → 跨公司转移申请流程结束 → 发送服务号通知所有参与人 → 进入账面报废流程

ES 主管驳回后，单据退回发起人。

### 4.1.5 资产选择范围

资产选择范围为当前发起人有权限操作且未正式报废的资产。

资产类型必须符合当前流程分支：

- 机房资产；
- 非机房软件；
- 非机房办公设备。

同一张跨公司转移单只允许包含同一审批路径的数据。不同审批路径的资产必须拆单。

### 4.1.6 审批后业务结果

跨公司转移审批完成后：

1. 资产进入待报废池；
2. 待报废池来源类型标记为“调账”；
3. 跨公司转移单结束；
4. 向发起人和所有审批参与人发送服务号通知；
5. 资产等待后续账面报废；
6. 此阶段不直接把资产台账公司、板块、成本中心、位置等字段改成目标值；
7. 正式资产台账字段在账面报废“执行账面报废操作”时一次性更新。

调账资产完成账面报废后不进入待处置池。

## 4.2 资产报废

### 4.2.1 非机房资产

资产报废只承接“部分报废”和“全部报废”，不再承接“调账”。

#### 部分报废

支持：

- 手工选择资产；
- Excel 导入；
- 手工维护报废数量；
- 自动计算报废金额、剩余数量、剩余金额；
- 填写报废原因；
- 维护是否处置；
- 上传附件。

报废数量不得大于资产卡片数量。

流程全部办结后，资产进入待报废池，来源类型标记为“部分报废”。

#### 全部报废

支持：

- 手工选择资产；
- Excel 导入；
- 填写报废原因；
- 上传附件。

流程全部办结后，资产进入待报废池，来源类型标记为“全部报废”。

列表支持：

#### 机房资产审批

基础审批链：

> 发起人 → 专家评估 → 责任人 7 级及以上领导 → NO 部 7 级及以上领导 → 采购专员 → 后续采购/内审及 ES 节点 → 结束

专家评估：

- 服务器：杨威（220894）、王帅（200636），会签；
- 网络设备：林家展（201938）。

责任人 7 级及以上领导按发起人组织关系匹配。

NO 部 7 级及以上领导当前为章宇东（111681）。若与上一节点为同一审批人，可自动跳过重复节点。

采购报价及内审：

- 数量大于 500 台或报废金额大于 100 万元时进入内审评估；
- 未达到以上任一条件时，不进入内审评估；
- 采购专员节点可选择报价信息由采购部或内审部填写；
- 采购部填写时，报价金额、回收供应商、报价附件必填；
- 内审节点支持多家报价，至少保留一行，每行报价金额、回收供应商、报价附件必填；
- 内审完成后，采购专员从内审报价供应商中选择最终回收供应商，报价金额和附件自动带出；
- 后续回收商确认需要上传实物照片和盖章报价单；
- 收款确认需要上传交接签字表、收款凭证附件，其他附件可选。

审批节点支持同意、驳回、加签；退回节点按当前审批环节规则执行。

#### 地区差异

- 北京机房资产：报废申请流程完成后进入待报废池；
- 非北京机房资产：报废申请后继续完成实物处置相关环节，实物处置完成后进入待报废池；
- 进入待报废池后再由 ES 账务人员执行账面报废。

流程结束后向所有参与人发送服务号通知。

## 4.4 账面报废

### 4.4.1 入口

入口：资产管理 → 账面报废。

以下数据进入账面报废：

- 待报废池中的调账资产；
- 待报废池中的部分报废资产；
- 待报废池中的全部报废资产；
- 丢失赔偿；
- 机房资产盘亏；
- 装修；
- 软件；
- 其他明确允许直达账面报废的业务。

### 4.4.2 调账账面报废

ES 账务人员点击【新建调账报废申请】后，系统按其负责的“财务公司 + 板块”检索待报废池内来源为“调账”的资产。

同一“财务公司 + 板块”生成一张草稿调账报废单。

草稿允许：

- 手工新增待报废池中的调账资产；
- 删除明细；
- Excel 导入；
- 导出明细；
- 修改报废原因；
- 修改允许调整的调账结果字段。

导入必须校验：

1. 资产存在于待报废池；
2. 来源类型为调账；
3. 资产未处于其他账面报废审批或已完成账面报废。

#### 调账审批

流程：

> ES 账务提交 → 财务初审 → ES 二级审批 → ES 一级审批 → 财务一级复审 → 财务二级复审 → 财务经理审批 → 提单人确认 → 结束

审批人按“财务公司 + 板块”映射。

所有审批节点支持同意、驳回；是否支持加签按统一审批能力执行。

财务经理审批完成后，单据回到发起 ES 账务人员。

#### 执行账面报废

ES 账务人员确认单据与审批结果无误后点击【执行账面报废操作】。

系统按资产标签号更新：

| 调账字段 | 资产台账结果字段 |
|---|---|
| 新公司 | 公司 |
| 新板块 | 板块 |
| 成本中心 | 成本中心 |
| City | City |
| Building | Building |
| Floor | Floor |
| 调账后仓库 | 仓库 |
| 调账后责任人 | 责任人 |

执行成功后：

- 生成资产事务记录；
- 生成报废单记录及套打数据；
- 发送服务号通知所有参与人；
- 调账资产不进入待处置池。

### 4.4.3 非调账账面报废

系统按当前 ES 账务人员负责的“财务公司 + 板块”，从待报废池中生成部分报废和全部报废草稿。

若涉及多个“财务公司 + 板块”，拆分生成多张草稿单。

编辑页基本信息：

| 字段 | 读写 | 规则 |
|---|---|---|
| 账面报废申请单号 | 只读 | 系统生成 |
| 公司 | 只读 | 财务公司 |
| 单据状态 | 只读 | 当前状态 |
| 制单人 | 只读 | 当前登录人 |
| 制单时间 | 只读 | 系统时间 |
| 备注 | 可编辑 | 非必填 |
| 附件 | 可编辑 | 非必填 |

资产明细至少包括：

- 资产类别；
- 资产标签号；
- 资产编号；
- 资产说明；
- 资产关键字；
- 数量；
- 原值；
- 净值；
- 购买日期；
- 资产寿命（月）；
- 累计折旧；
- 责任人姓名；
- 责任人工号；
- City；
- Building；
- Floor；
- 报废方式；
- 报废类型；
- 报废原因。

草稿支持添加物资、删除物资、下载模板、Excel 导入、导出明细。

### 4.4.4 非调账审批

审批链根据资产构成动态增加 NO / MIS 节点。

包含机房资产时必须经过 NO 部 7 级及以上领导审批。

包含非丢失赔偿的电脑类资产（主机、显示器、笔记本）时必须经过 MIS 领导审批。

同一单据同时满足两个条件时，NO、MIS 节点均进入审批；若两个节点审批人为同一人，是否自动合并见 8.1 待确认项。

财务和 ES 主链：

> ES 提交 → 财务初审 → 条件审批（NO / MIS） → ES 二级审批 → ES 一级审批 → 财务一级复审 → 财务二级复审 → 财务经理审批 → 提单人确认

审批页面支持导出报废明细，并展示审批历史。

### 4.4.5 执行账面报废

财务经理审批完成后，单据回到 ES 账务发起人。

ES 账务确认无误后点击【执行账面报废操作】。

#### 部分报废

部分报废后：

1. 原资产按报废数量和报废金额执行拆分；
2. 剩余部分生成新资产卡片；
3. 新标签号按“原资产标签号-序号”生成，例如 aaa-1、aaa-2；
4. 入库日期保持原值；
5. 数量、金额按报废比例拆分；
6. 新资产继承原员工信息；
7. 系统根据资产信息匹配虚拟库管员完成入库；
8. 如原资产在员工名下，系统生成资产领用单，将剩余资产重新挂到原员工名下。

#### 全部报废

全部报废执行后，资产台账至少更新：

- 资产状态；
- 报废日期；
- 报废原因；
- 报废类型。

需要处置的资产状态更新为“已报废-待处置”。

无需处置的资产状态更新为“已报废-已处置”。

主资产存在升级耗材时，升级耗材随主资产同步报废。

执行成功后生成：

- 资产事务报表；
- 资产明细报表；
- 资产报废报表；
- 报废单及套打数据；
- 资产操作历史。

需要同步责任人、NO、MIS、EBS 的正式业务结果按系统集成规则执行。

## 4.5 待处置池

数据来源为完成账面报废且仍需实物处置的资产。

列表支持至少以下查询维度：

- 资产标签号；
- 处置状态；
- 录入时间；
- 资产大类；
- 资产小类；
- 区域；
- 财务公司；
- 报废申请单号；
- 账面报废单号。

支持导出。

库管员可执行：

1. 无实物报废：标记无实物报废并填写原因，资产状态更新为“已报废-已处置”；
2. 先处置再报废：标记已处置并填写原因，资产状态更新为“已报废-已处置”；
3. 有实物报废：发起实物处置申请。

## 4.6 资产实物处置

### 4.6.1 新建

ES 点击【新建实物处置申请】后，从处置池选择状态为“已报废-待处置”的资产生成草稿单。

资产支持：

- 条件筛选；
- 按报废申请单号查询；
- 按账面报废单号查询；
- Excel 导入；
- 草稿手工新增、删除；
- 非资产卡片字段编辑。

### 4.6.2 回收商报价

同一处置单最多添加 5 家回收商。

支持：

- 单个维护报价；
- 批量导入报价；
- 按资产标签号匹配报价；
- 数量合计；
- 金额合计。

### 4.6.3 审批流程

流程：

> ES 提交处置申请 → ES 二级审批 → ES 一级审批 → 财务领导审批（抄送相关业务人员） → ES 上传凭证 → 完成

ES 上传凭证至少包括：

- 财务提供的回收商打款入账凭证；
- 待处置实物照片；
- ES 与回收商的实物交接签字表。

ES 确认单据信息完整后点击【完成】。

完成后：

- 资产状态更新为“已报废-已处置”；
- 生成处置业务记录和操作历史；
- 向相关参与人发送通知。

## 5. 校验

### 5.1 跨公司转移

提交前校验：

- 至少存在 1 条资产明细；
- 所有资产符合当前审批路径类型；
- 资产未正式报废；
- 资产未被其他互斥流程占用；
- 新公司、新板块、成本中心、City、Building、Floor、调账后责任人完整；
- 调账后责任人与新公司关系有效；
- 导入资产全部通过正式数据校验。

任一资产失败时，不允许部分提交。

### 5.2 资产报废

- 报废数量必须大于 0；
- 报废数量不得超过资产卡片数量；
- 报废原因按页面规则必填；
- 机房资产报废说明必填；
- 主备件联动必须保持真实关联；
- 已正式报废资产不可再次提交。

### 5.3 账面报废

提交前校验：

- 资产仍存在于对应待报废池；
- 资产来源业务类型与当前账面报废类型一致；
- 资产未处于其他账面报废审批中；
- 资产未完成账面报废；
- 报废类型合法；
- 部分报废数量、金额计算结果合法；
- 同一资产不能在同一单据重复出现。

执行账面报废必须保证资产台账、事务、报废记录在同一次业务提交中保持一致，禁止产生部分成功结果。

### 5.4 资产处置

发起处置前：

- 资产必须存在于待处置池；
- 资产状态必须为“已报废-待处置”；
- 调账和丢失赔偿资产不得进入处置申请；
- 已完成处置的资产不得重复发起。

## 6. 后续操作与业务结果

### 6.1 通知

以下节点完成后发送服务号通知：

- 跨公司转移审批结束；
- 机房资产报废申请结束；
- 账面报废执行完成；
- 实物处置完成。

跨公司转移通知对象为发起人及所有审批参与人。

其他流程通知对象按各自审批链全部参与人执行。

通知可跳转至对应单据详情或审批详情。

### 6.2 操作历史

正式业务操作需记录：

- 单据类型；
- 单据编号；
- 资产标签号；
- 操作人；
- 操作时间；
- 操作节点；
- 修改前值；
- 修改后值；
- 审批结果；
- 审批意见。

资产卡片需要保留报废、调账、处置对应操作历史。

### 6.3 套打与导出

账面报废支持汇总和资产明细套打。

汇总数据按“财务公司 + 板块”维度组织，并可按：

> 资产类别 → 已到报废期 → 未到报废期 → 丢失

进行汇总。

资产详情模板展示各报废类型资产明细。

审批记录在套打模板对应区域展示。

## 7. 补充说明

### 7.1 新旧流程关系

本版正式规则：

- “调账”入口从资产报废迁移到跨公司转移；
- 跨公司转移只完成业务申请和审批，不直接更新目标公司等资产台账字段；
- 审批通过后进入待报废池；
- ES 账务人员继续通过账面报废完成正式账务调整；
- 调账完成后不进入资产处置；
- 资产报废菜单继续承接部分报废、全部报废以及机房资产实物报废申请。

### 7.2 原型实施顺序

原型按以下顺序落地：

1. 跨公司转移列表与申请页；
2. 跨公司转移两套审批路径；
3. 待报废池；
4. 账面报废列表、编辑、审批和执行；
5. 资产报废非机房流程；
6. 机房资产报废流程；
7. 待处置池与资产实物处置。

原型评审过程中用户确认的字段、按钮、状态、文案和流程变化需要同步更新本 PRD。

## 8. 待确认事项

以下内容在现有两份 PRD 与新流程资料中没有形成唯一口径，暂不自行补充：

1. “机房资产 + 非机房软件”跨公司转移中，如果 5 级及以上直属领导与 7 级及以上直属领导为同一人，第二审批节点是否自动跳过。
2. “非机房办公设备”和“非机房软件”的正式资产大类/小类映射范围。
3. 跨公司转移是否仅覆盖集团台账与上海/广州分公司之间，还是允许全部合法财务公司之间跨公司调整。
4. 跨公司转移历史规则中“原资产号增加后缀后推送财务系统、目标分公司按原资产号手工新增”的特殊财务同步规则是否继续保留。
5. 机房资产报废申请完成后的中间资产状态，在“进入待报废池”和“非北京先实物处置”两条路径下需统一确认。
6. 账面报废附件限制：现状资料分别存在“不限制大小”和“单文件不超过 20MB”两种口径，需要统一。
7. 非调账账面报废同时命中 NO 和 MIS 且审批人为同一人时，是否自动合并审批节点。
8. 家具类资产的实物处置流程仍未形成正式规则。
