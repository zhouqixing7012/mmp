# 标签打印对抗性测试

## 1. 测试范围

本测试针对以下范围进行静态代码、规则边界和状态一致性检查：

- 标签打印；
- 标签预打印；
- 标签清单；
- 打印历史；
- 标签流水生成；
- 导出；
- 数据权限与打印状态口径。

测试基线：`main` 当前标签打印原型和《标签打印、打印历史、标签预打印 PRD》。

## 2. 本轮规则调整

本轮按最新确认调整部件标签识别规则：

> **标签类型在生成标签明细时保存，打印时直接按标签类型选择模板。**

新生成标签不能只按字符串判断类型。存量显示器主标签的实际兼容判断是“标签号包含 `-V`”，不是“以 `-V` 结尾”；`P-/N-/QT-` 仍是主标签，`-H1/-H2` 按历史主从关系读取。当前 React 原型仍需同步标签类型字段和模板选择。

除该项外，第一轮发现的问题均按测试结论保留为正式实现约束。

| A15 | 部门/使用人/资产类别选择后无法清空 | 查询条件残留 | 已修复：选择型查询增加清空逻辑 |

## 5. 第二轮新增发现及UI走查处理

### C01 标签清单查询文案不一致

已修复：标签清单查询项统一为“是否已打印”。

### C02 标签清单弹窗标题不一致

已修复：弹窗标题统一为“标签清单”。

### C03 跨年继承规则需固定查找范围

当前原型在当年规则不存在时，会查找“最近的任意历史年份”。PRD当前表述为“最近上一年度规则”，存在研发理解分歧。

风险：如果中间年份没有规则，例如2026无规则、2025无规则、2024有规则，是否允许2026直接继承2024不够明确。

处理建议：正式PRD需明确以下二选一口径并固定：

- 仅查紧邻上一年度；或
- 查最近一个存在规则的历史年度。

当前原型采用“最近一个存在规则的历史年度”。

### C04 打印任务需要支持部分成功

当前原型统一模拟整次打印成功，因此同一 `printTaskId` 下所有标签均写“打印成功”。正式Brother链路可能出现同一次批量任务中部分标签成功、部分标签失败。

风险：如果只维护任务级成功/失败，无法准确累计单标签打印次数和失败重试范围。

正式实现要求：

1. 保留任务级 `printTaskId`；
2. 同一任务下每个标签记录独立打印结果；
3. 任务状态至少支持：待打印 / 已提交打印 / 打印成功 / 部分成功 / 打印失败；
4. 仅成功标签累计打印次数；
5. 失败标签保留失败原因，可针对失败标签重新发起新的打印尝试；
6. 重试不得覆盖原失败日志。

当前原型不模拟真实“部分成功”，该项留正式联调验证。

### UI01 标签打印操作层级

已调整：主列表“打印所选”作为主要操作；未选择时禁用并展示选择数量；“预打印”降为普通入口按钮。

### UI02 标签预打印页面层级

已调整：页面标题统一为“标签预打印”；返回按钮移至页面底部；标签批次列表的“标签清单 / 打印历史”合并为固定右侧操作列。

### UI03 生成标签信息密度

已调整：五类标签规则改为先选择规则，再只展示当前规则对应配置项；移除额外蓝色标题装饰，底部操作栏弱化边框和阴影。

### UI04 标签清单与打印历史

已调整：标签清单仅保留右上角关闭入口；打印所选展示已选数量；打印历史弹窗改为响应式宽度，并使用状态标签展示打印状态。

### UI05 打印确认

已调整：打印确认弹窗直接展示“标签数量 × 打印份数 = 总打印张数”，不在业务界面展示原型模拟、正式环境、后端回执等研发说明文案。

## 6. 正式实现必须补做的非原型测试

以下场景无法在当前纯前端原型中真实验证，不能以原型通过替代正式联调：

1. 两个用户同时对同一流水规则生成标签；
2. 数据库唯一约束和事务回滚；
3. 接口重复请求、浏览器重试、网络超时后的幂等；
4. Brother b-PAC未安装；
5. 浏览器不是Chrome；
6. 打印机离线、缺纸、驱动错误；
7. Brother组件返回失败；
8. Brother组件无法提供可信成功回执；
9. 创建打印任务成功但客户端未执行打印；
10. 同一批量打印任务部分标签成功、部分标签失败；
11. 公司+板块权限被前端参数篡改后的接口拦截；
12. 接收入库打印与统一批次/日志模型的真实系统集成。

## 7. 第二轮结论

第二轮对 B01～B25 进行静态代码和规则回归：

- B11～B13、B25 与最新确认的三条链路不一致，当前 React 原型未通过；
- B10 的正式后端幂等仍需接口联调，当前只验证前端防重复；
- B16 的Brother失败回执无法由当前原型真实验证；
- 数据库事务、并发唯一性、权限篡改等继续属于正式实现测试范围。

第二轮新增4项发现中：

- C01、C02 已在本次UI走查后修复；
- C03 仍需确认跨年流水继承范围；
- C04 仍属于正式打印联调边界。

本次UI走查同步完成操作层级、页面标题、固定操作列、标签清单、打印历史、打印确认等界面收口。

部件标签识别已按最新口径改为读取保存的标签类型；当前原型代码同步属于后续实现工作。
