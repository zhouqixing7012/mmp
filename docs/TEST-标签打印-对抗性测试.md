# 标签打印对抗性测试

## 1. 测试范围

本测试针对以下范围进行静态代码、规则边界和状态一致性检查：

- 标签打印；
- 标签批次 / 预打印；
- 标签清单；
- 打印历史；
- 标签流水生成；
- 导出；
- 数据权限与打印状态口径。

测试基线：`main` 当前标签打印原型和《标签打印、打印历史、标签预打印 PRD》。

## 2. 用户确认的例外

本轮对抗性测试发现现有“部件标签识别规则”存在可讨论空间，但用户明确确认：

> **本轮不调整部件标签识别规则。**

因此以下原有口径继续保留，不作为本轮缺陷：

> 标签号包含 `-`，同时不是 `-V` 特殊形式时识别为部件标签。

除该项外，第一轮发现的问题均按测试结论修复或补充正式实现约束。

## 3. 第一轮发现及处理结果

| 编号 | 攻击场景 | 风险 | 处理结果 |
| --- | --- | --- | --- |
| A01 | 生成标签后退出生成页，再次进入同规则生成 | 页面内流水重置，可能重复标签号 | 已修复：流水池提升至标签打印页面级状态，离开生成页后不重置；正式后端仍必须持久化 |
| A02 | 常规规则切换账套/资产类型 | 所有常规标签共用一个 CurrentValue | 已修复：原型按规则键维护流水；PRD明确正式服务端按规则维度锁定和更新 |
| A03 | 高耗规则在 QT / P / N 间切换 | 不同前缀错误共用流水 | 已修复：QT/P/N分别维护流水 |
| A04 | 家具生成后人工把当前最大序号调回已使用区间 | 可重复生成家具标签 | 已修复：必须为整数且不得小于当前已使用最大值 |
| A05 | 同时/快速重复生成 | 批次号或流水竞争 | 已缓解：原型生成按钮防重复、高精度批次号；PRD要求后端幂等键、事务锁、唯一约束 |
| A06 | 一次打印多份 | 日志无法还原累计打印次数 | 已修复：日志记录本次打印份数 |
| A07 | 后台先记成功，随后本地打印失败 | 系统显示已打印但实物未打印 | PRD已修复正式口径：创建待打印任务，收到可信成功回执后再累计次数；原型只模拟成功回执 |
| A08 | 普通标签补打后从历史标签清单再次重打 | 主列表打印次数与标签清单分叉 | 已修复：普通补打批次标签保留主列表关联，历史重打同步主列表累计次数 |
| A09 | 常规/高耗规则年份清空 | 原型偷偷回退当前年份 | 已修复：年份必填，清空后禁止生成 |
| A10 | 家具最大序号输入小数 | 可能生成非法标签号 | 已修复：正整数校验 |
| A11 | 一次生成超大数量或超过号段最大值 | 页面冻结、流水越界 | 已修复：主标签1～500、部件1～99、单批明细≤5000，同时校验规则剩余号段 |
| A12 | 打印历史无法区分打印来源 | 审计不清 | 已修复：批次和打印日志增加来源 |
| A13 | 批次历史混合多来源但页面仍叫“预打印列表” | 页面语义错误 | 已修复：改为“标签批次 / 预打印”“标签批次列表” |
| A14 | CSV字段以 `= + - @` 开头 | Excel公式注入 | 已修复：导出前按纯文本转义 |
| A15 | 部门/使用人/资产类别选择后无法清空 | 查询条件残留 | 已修复：选择型查询增加清空逻辑 |
| A16 | 开始日期晚于结束日期 | 只返回空数据，不提示错误 | 已修复：创建时间、打印时间均显式提示非法范围 |
| A17 | 缺少查询/打印/导出权限约束 | 前端可见范围与接口范围可能不一致 | PRD已补充公司+板块数据权限及接口二次校验 |

## 4. 第二轮回归用例

### 4.1 流水与标签唯一性

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| B01 | 常规规则生成一批 → 返回 → 再次进入同规则 | 当前最大序号继续上次结果，不回到初始值 |
| B02 | 101+11+年份生成后切换 123+14+同年份 | 两组规则分别读取各自 CurrentValue |
| B03 | 高耗依次选择普通高耗、合约手机、合约电话卡 | QT / P / N 分别维护 CurrentValue |
| B04 | 家具生成后输入小于当前已使用最大值 | 阻止生成并提示流水已使用 |
| B05 | 家具当前最大序号输入小数 | 阻止生成 |
| B06 | 常规/高耗清空年份 | 阻止生成并提示请选择年份 |
| B07 | 本次主标签数量使流水超过规则最大值 | 阻止生成 |
| B08 | 本次总明细超过5000 | 阻止生成 |
| B09 | 待生成标签号已存在于标签清单 | 阻止整批生成，不产生部分成功记录 |
| B10 | 快速重复点击生成 | 前端处理中不重复提交；正式实现还需后端幂等 |

### 4.2 打印状态与日志

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| B11 | 普通标签打印1份 | 主列表次数+1；生成批次、标签明细、详细日志 |
| B12 | 普通标签打印5份 | 主列表次数+5；日志仅一条打印动作记录但 `打印份数=5` |
| B13 | 从普通补打批次标签清单再次打印3份 | 标签清单次数+3；普通主列表对应标签次数同步+3 |
| B14 | 预打印标签打印2份 | 标签明细次数+2；批次变为已打印；写入来源=预打印日志 |
| B15 | 查看打印历史 | 展示来源、打印份数、打印状态、时间、IP、打印人 |

### 4.3 查询、导出与批次

| 用例 | 操作 | 预期 |

## 5. 正式实现必须补做的非原型测试

以下场景无法在当前纯前端原型中真实验证，不能以原型通过替代正式联调：

1. 两个用户同时对同一流水规则生成标签；
2. 数据库唯一约束和事务回滚；
3. 接口重复请求、浏览器重试、网络超时后的幂等；
4. Brother b-PAC未安装；
5. 浏览器不是Chrome；
6. 打印机离线、缺纸、驱动错误；
7. Brother组件返回失败；
8. Brother组件无法提供可信成功回执；
9. 创建打印任务成功但客户端未执行打印；
10. 公司+板块权限被前端参数篡改后的接口拦截；
11. 接收入库打印与统一批次/日志模型的真实系统集成。

## 6. 当前结论

本轮修复后，第一轮除“部件标签识别规则”外的已确认问题均已在原型或PRD中收口。

其中：

- **原型可验证项**：流水不随生成页重置、规则维度隔离、家具回退/小数、年份必填、数量/号段、日志份数/来源/状态、普通补打次数联动、批次页面语义、非法日期、导出安全、选择查询清空。
- **正式后端约束项**：事务锁、流水预占、唯一约束、接口幂等、打印任务状态机、成功回执后累计次数、数据权限接口校验。
- **明确暂不调整项**：部件标签识别规则。
