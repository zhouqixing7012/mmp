# 库存管理 - 资产接收 PRD

## 1. 背景

资产接收用于处理采购资产实际到货后的接收业务。

用户根据采购 PO 查看待接收物资，维护本次实际接收数量，并根据实际到货资产维护资产标签号、SN、部件等信息。接收完成后，系统生成后续采购接收入库草稿单，用户再进入入库模块执行正式入库。

“资产接收”仅处理以下两类资产：

| 资产类型 | 接收方式 |
|---|---|
| 普通资产 | PO → 创建接收单 → 维护资产标签号、SN → 接收确认 → 接收完成 → 自动生成采购接收入库草稿单 |
| 服务器、服务器备件、网络设备、网络设备备件 | PO → 获取 NO/MIS 数据 → 接收确认 → 直接完成接收 → 按 NO 位置自动生成采购接收入库草稿单 |

低值耐用品、普通耗材不在本模块处理，由“耗材接收”独立处理。

本次改造主要对资产接收的业务边界、流程状态、页面交互、数据修改范围、异常处理和后续入库衔接进行统一，避免 PO 状态、接收单状态、接收与入库动作混用，同时保留现有业务中已经明确有效的字段、提示和特殊分支规则。

## 2. 改造总结

| 改造项 | 改造后规则 |
|---|---|
| 业务范围 | 资产接收仅处理普通资产以及服务器、服务器备件、网络设备、网络设备备件；耗材由“耗材接收”独立处理 |
| 接收单状态 | 统一为“草稿 / 已完成”两个状态，不再使用“接收待维护 / 接收完成”等旧状态 |
| 普通资产流程 | 创建接收单后进入草稿；先维护资产标签号和 SN；全部维护完成后点击【接收确认】，接收单直接变为已完成，并自动生成采购接收入库草稿单 |
| 物料、配置修改 | PO 接收页面修改物料或配置后，作为该 PO 行后续未完成接收的默认值使用；不追溯修改此前已完成接收的数据，也不反写采购系统原始 PO 数据 |
| 板块、申请批次 | 修改后立即作为当前 PO 后续未完成接收数据的默认值；已完成接收数据不追溯修改 |
| 分批接收 | 保留分批接收；草稿接收单中的接收数量立即计入草稿占用，避免重复接收 |
| 删除接收行 | 草稿状态允许删除已有接收数量的接收行；删除后同步删除对应接收明细并释放草稿占用数量 |
| 删除草稿接收单 | 接收单列表保留【删除接收单】；详情页保留【取消接收】，两者均删除当前草稿业务数据并释放草稿数量 |
| 部件数量 | 仅允许 2～100，包含主资产本身；子部件数量 = 部件数量 - 1 |
| 部件说明 | 按“部件数量 - 1”生成子部件维护行，默认名称为“部件1、部件2……”；用户可修改 |
| SN“缺省” | “缺省”视为合法 SN，可以完成接收，不参与真实 SN 唯一性校验 |
| 标签 / SN 操作入口 | 【生成标签号】【维护SN号】均根据当前数据状态展示；处理完成后自动隐藏，后续再次出现空值时对应按钮重新展示 |
| 标签打印 | 草稿和已完成状态均允许打印标签；入口统一放在“维护接收明细”页面，打印前必须保证待打印资产已有标签号 |
| 机房资产接收数量 | 由 NO/MIS 数据决定，不允许人工修改 |
| 机房资产操作 | 服务器、服务器备件、网络设备、网络设备备件统一使用【接收确认】，不再使用“执行入库” |
| 机房资产接收结果 | 校验通过后一次性生成已完成接收单，并按 NO 位置拆分生成采购接收入库草稿单 |
| 机房资产异常 | 所有前置校验全部通过后才写入业务数据；任一校验失败，本次不产生接收单或入库草稿 |
| 重复接收 | 已存在有效接收记录的 NO/MIS 数据不得再次生成接收单 |
| 权限 | 按公司 + 板块控制，具体权限规则暂留待补充 |

## 3. 业务流程

### 3.1 普通资产

1. 用户进入 PO 接收页面，系统默认按照剩余可接收数量计算“本次接收数量”。
2. 用户可编辑后续接收使用的物料、配置、接收数量、部件信息。
3. 用户勾选一个或多个 PO 行，点击【创建接收单】。
4. 系统生成草稿接收单，并立即占用对应 PO 草稿数量。
5. 用户进入接收单详情，点击【维护接收明细】逐件维护资产标签号、SN、部件等信息。
6. 所有资产标签号和 SN 维护完成后，用户点击【接收确认】。
7. 系统将接收单更新为已完成，将草稿数量转为已接收数量，并自动生成一张“采购接收”类型的草稿入库单。
8. 用户后续进入“库存管理 → 入库”检查并执行正式入库。

### 3.2 机房资产

适用采购类型：服务器、服务器备件、网络设备、网络设备备件。

1. 用户进入 PO 接收页面，系统根据 NO/MIS 推送数据取得当前可接收数量。
2. 用户勾选需要接收的 PO 行，点击【接收确认】。
3. 系统完成板块、PO 行、NO/MIS 数据、NO 位置、地址映射、City、Building、Floor、重复接收等前置校验。
4. 校验全部通过后，系统直接生成已完成接收单和资产接收明细。
5. 系统按 NO 位置拆分采购接收入库草稿单：相同目标 NO 位置进入同一张入库草稿单，不同 NO 位置拆成不同入库草稿单。
6. 用户后续进入“库存管理 → 入库”检查并执行正式入库。

## 4. 通用规则

### 4.1 状态规则

资产接收存在 PO 状态、PO 行状态和接收单状态，三类状态独立判断，不得混用。

#### PO 状态

| 状态 | 说明 |
|---|---|
| 待接收 | 当前 PO 任一采购行仍存在未完成接收数量 |
| 已接收 | PO 所有采购行均已完成接收，等待后续正式入库 |
| 已入库 | PO 对应资产已经全部完成正式入库 |

PO 状态按整张 PO 的累计数量判断：

- 任一 PO 行仍存在未接收数量时，整张 PO 保持“待接收”。
- 所有 PO 行累计已接收数量达到采购数量后，整张 PO 更新为“已接收”。
- 所有已接收资产后续全部完成正式入库后，整张 PO 更新为“已入库”。
- 部分接收不能提前将整张 PO 更新为“已接收”。

#### PO 行状态

| 状态 | 判断规则 |
|---|---|
| 待接收 | 当前 PO 行仍存在剩余未接收数量 |
| 已接收 | 当前 PO 行采购数量已全部完成接收，但尚未全部正式入库 |
| 已入库 | 当前 PO 行对应资产已全部完成正式入库 |

#### 接收单状态

| 状态 | 说明 | 是否可修改 |
|---|---|---|
| 草稿 | 已创建接收单，资产标签号、SN 等接收数据仍可维护 | Y |
| 已完成 | 已执行接收确认，接收流程结束 | N |

普通资产接收单固定按照 `草稿 → 已完成` 流转。

### 4.2 可接收数量

普通资产支持分批接收。

单条 PO 行的当前可接收数量按照以下公式计算：

`可接收数量 = 采购数量 - 已接收数量 - 草稿数量`

其中：

- 已接收数量：已经完成接收确认的数量。
- 草稿数量：已经被有效草稿接收单占用、但尚未完成接收确认的数量。

创建接收单后，本次接收数量立即计入草稿数量，其他接收单不可重复占用该部分数量。

以下操作需要同步释放对应草稿数量：

| 操作 | 数量处理 |
|---|---|
| 删除接收行 | 释放该接收行对应的草稿数量 |
| 删除接收资产明细 | 对应接收行本次接收数量同步减少，并释放相同草稿数量 |
| 取消接收 | 释放整个接收单占用的草稿数量 |
| 删除草稿接收单 | 释放整个接收单占用的草稿数量 |

接收确认成功后，本次数量从“草稿数量”转入“已接收数量”。

机房资产的可接收数量由 NO/MIS 推送数据决定，不允许人工修改。

### 4.3 接收数据快照

接收单保存本次实际接收时的数据快照。

接收单完成后，历史接收数据不得因为 PO 后续发生修改而变化。

PO 接收页面允许修改的物料、配置、板块、申请批次等信息，只按照本 PRD 约定影响后续未完成接收数据，不追溯修改已经完成的接收单和资产接收明细。

### 4.4 物料和配置修改规则

用户在 PO 接收页面编辑接收信息时，可以重新选择物料、修改配置。

修改后的物料和配置作为该 PO 行**后续未完成接收数据的默认值**使用：

| 数据范围 | 修改后的处理规则 |
|---|---|
| 后续新创建的接收行 | 使用修改后的物料、配置 |
| 尚未完成的后续接收数据 | 使用修改后的默认值 |
| 已完成接收行 | 保留接收完成时的物料、配置快照，不修改 |
| 已完成资产接收明细 | 保留原数据，不修改 |
| 采购系统原始 PO | 不反写原始物料编码、物料名称或配置 |

因此，修改动作只改变资产接收侧后续接收使用的默认数据，不追溯历史已完成接收结果。

### 4.5 板块和申请批次

板块、申请批次用于后续接收业务。

用户修改后立即作为当前 PO 后续未完成接收数据的默认值使用，不需要等到创建接收单时才生效。

| 数据范围 | 修改后的处理规则 |
|---|---|
| 后续新创建的接收行 | 使用修改后的值 |
| 尚未完成的后续接收数据 | 使用修改后的默认值 |
| 已完成接收行 | 保留原接收数据，不修改 |
| 已完成资产接收明细 | 保留原接收数据，不修改 |

申请批次为非必填字段；有值时随接收单继续传递到后续采购接收入库单及入库物资明细。

板块同样随接收单和后续入库单传递。

### 4.6 部件规则

普通资产支持按套件方式维护部件。

| 规则 | 说明 |
|---|---|
| 是否部件 | 未勾选时，不使用部件数量和部件说明 |
| 部件数量 | 勾选“是否部件”后必填 |
| 数量范围 | 2～100，包含 2 和 100 |
| 数量含义 | 部件数量包含主资产本身 |
| 子部件数量 | 部件数量 - 1 |
| 子部件默认名称 | 自动生成“部件1、部件2……”作为默认值，允许用户修改 |
| 取消“是否部件” | 将是否部件改为 N，同时清空部件数量和部件说明，并禁用部件数量输入和部件说明维护入口 |

例如部件数量为 5，则最终表示 1 个主资产 + 4 个子部件，系统自动生成 4 条子部件说明维护行。

### 4.7 SN 规则

资产 SN 支持实际 SN 和“缺省”两种值。

| 类型 | 规则 |
|---|---|
| 实际 SN | 用户人工录入或扫码录入真实 SN，需要进行唯一性校验 |
| 缺省 SN | 系统写入“缺省”，视为已完成维护，不参与真实 SN 唯一性校验 |

相同真实 SN 已被其他资产使用时，不允许保存。

多个资产允许同时使用“缺省”，并可以通过接收确认。

### 4.8 制单人与接收人

接收单区分创建草稿和完成接收两个时间点。

| 字段 | 记录时机 |
|---|---|
| 制单人 | 创建草稿接收单时记录当前操作人 |
| 制单时间 | 创建草稿接收单时记录当前时间 |
| 接收人 | 接收确认成功时记录当前操作人 |
| 接收时间 | 接收确认成功时记录当前时间 |

草稿状态下接收人、接收时间为空。

### 4.9 权限

资产接收权限按照“公司 + 板块”控制。

具体页面可见范围、操作权限和无权限时页面表现暂留待补充。

### 5.3 编辑接收信息

点击 PO 行【编辑】，打开“编辑接收信息”弹窗。

物料选择弹窗至少展示：物料编码、物料名称、配置；支持按物料编码、物料名称查询。选择后同步带出当前所选物料对应的物资总类、资产大类、配置等接收侧数据。

- 子部件维护行数固定等于 `部件数量 - 1`。
- 每一行展示“子部件 N”及一个部件名称输入框。
- 初次生成时默认名称为“部件1、部件2……”。
- 用户可修改默认名称。
- 点击【确定】后回填父弹窗“部件说明”汇总展示。

如果普通资产接收数量大于当前可接收数量：

- 不保存本次编辑。
- 弹窗保持打开。
- 提示：

> 接收数量不能超过可接收数量！

如果部件数量不符合规则，提示：

> 请输入 2～100 之间的整数！

点击维护部件说明时，如果尚未填写合法部件数量，提示：

> 请填写部件数量！

取消“是否部件”后，系统同时：

- 将是否部件改为 N。
- 清空部件数量。
- 清空部件说明。
- 禁用部件数量输入和部件说明维护入口。

保存成功后关闭弹窗，并提示：

> 接收信息已保存，修改将用于该PO后续未完成接收数据

### 5.9 维护接收明细

普通资产点击【维护接收明细】进入资产逐件维护页面。

该操作针对当前接收单的全部接收物资，不依赖某一条接收物资行勾选。

进入页面前先校验：

- 接收单必须至少存在一条接收行。
- 各接收行本次接收数量必须大于 0。

存在某一行接收数量未维护时，提示：

> 第 X 行，未维护接收数量！

当前接收单没有有效接收信息时，提示：

> 请先维护接收信息！

如果当前接收行尚未生成资产明细，系统按照“每接收 1 个数量生成 1 条资产明细”进行拆分。

例如本次接收数量为 5，则生成 5 条资产接收明细，每条初始资产数量为 1。

最后一次完成整条 PO 行接收时，如逐件拆分金额因保留两位小数产生尾差，差额补到最后一条资产明细，保证拆分后的累计金额与采购金额一致。

| 打印标签号 | 当前接收单存在资产明细且所有资产均已有标签号时展示 | 草稿、已完成均允许执行 |
| 编辑 / 查看 | 每条资产明细固定提供 | 草稿为编辑；已完成为只读查看 |

【生成标签号】【维护 SN 号】的显示条件根据**当前实际数据状态**判断，不以“是否曾经点击过按钮”作为唯一判断条件。

例如用户执行【维护 SN 号】后按钮消失；如果后续又将某条资产 SN 清空，则页面再次出现【维护 SN 号】。

删除行、生成标签号、维护 SN、扫描写入 SN、明细编辑保存后均实时保存并立即生效，无需再次点击页面级保存。

### 5.10 删除资产明细

草稿状态允许删除资产明细。

未选择时提示：

> 请先选择需要删除的标签行！

二次确认标题：

> 确认删除选中的标签行吗？

确认弹窗展示本次选择条数，并说明删除后会同步减少接收数量并释放对应 PO 草稿占用数量。

删除一条资产明细后：

1. 删除当前资产明细。
2. 对应接收行“本次接收数量”同步减少 1。
3. 对应 PO 行草稿数量同步减少 1。
4. PO 可接收数量同步增加 1。
5. 资产明细行号重新连续编号。

成功提示：

> 已删除 X 条明细，本次接收数量已同步减少并释放PO占用数量

如果某接收行的本次接收数量减少到 0，则该接收行从当前草稿接收单中移除。

### 5.11 生成资产标签号

【生成标签号】仅在草稿状态且当前至少存在 1 条资产标签号为空时展示。

点击后只处理资产标签号为空的资产明细，已有资产标签号不得重新生成或覆盖。

标签号按照现有资产标签生成规则，根据物料、公司 / 账套、板块、日期等业务信息生成。

存在子部件时，在主资产标签号生成后同步生成子部件标签号：

`子部件标签号 = 主资产标签号-N`

例如主资产标签号为 `112132600468`，则子部件标签号依次为：

- `112132600468-1`
- `112132600468-2`
- ……

生成完成后立即保存。

当所有资产明细均已有资产标签号后，【生成标签号】自动隐藏，同时扫描输入框可用、【打印标签号】可展示。

成功提示：

> 生成成功！

失败提示：

> 生成失败：具体错误信息

### 5.12 SN 维护与扫描

用户可以通过以下方式维护 SN：

| 方式 | 规则 |
|---|---|
| 单条编辑 | 在资产明细中录入真实 SN，也允许将当前 SN 清空后重新维护 |
| 扫描 | 先扫描资产标签号，再扫描对应真实 SN |
| 批量维护缺省 | 将当前 SN 为空的资产明细写入“缺省” |

已有真实 SN 不因批量维护“缺省”而被覆盖。

【维护 SN 号】仅在草稿状态且至少存在 1 条 SN 为空的资产明细时展示。

点击【维护 SN 号】后：

- 仅对当前 SN 为空的资产写入“缺省”。
- 处理完成后立即保存。
- 如果所有资产 SN 均已维护，按钮自动隐藏。
- 如果后续再次出现 SN 为空的资产，按钮重新展示。

批量维护成功提示：

> 已为 X 条空白SN号维护“缺省”并实时保存

如果当前所有 SN 均已维护，则不重复处理，并提示：

> 当前所有SN号均已维护

扫描维护仅在全部资产标签号已生成后可使用：

1. 第一次扫描内容视为资产标签号，系统在当前接收单内查找对应资产。
2. 未找到时提示：

> 未找到匹配的标签号：扫描值

3. 找到后，列表临时定位并只展示该资产，同时勾选该资产，等待录入 SN。
4. 扫描框提示：`已定位 XXX，请扫描SN号`。
5. 第二次扫描内容视为该资产的 SN。
6. 系统校验真实 SN 不重复后写入当前资产并立即保存。
7. 保存完成后恢复完整资产列表，扫描框重新等待下一条资产标签号。

真实 SN 已存在时提示：

> SN 号：XXX 已存在！

扫描写入成功提示：

> 已为 XXX 写入SN号并实时保存

### 5.13 单条资产明细编辑

草稿状态点击【编辑】打开“明细信息维护”弹窗；接收完成后同一入口改为【查看】，全部字段只读。

#### 5.13.1 明细信息

| 字段名称 | 交互方式 | 草稿是否可修改 | 规则 |
|---|---|---|---|
| 资产标签号 | 只读 | N | 系统生成标签 |
| 资产说明 | 只读 | N | 当前物料说明 |
| SN 号 | 输入框 | Y | 保存时校验真实 SN 唯一；“缺省”例外；允许清空后重新维护 |
| 资产标记 | 输入框 | Y | 文本 |
| 备注 | 多行文本框 | Y | 文本 |

#### 5.13.2 部件信息

当主资产存在子部件时，弹窗以表格展示全部子部件；不存在子部件时展示“暂无部件信息”。

| 字段名称 | 交互方式 | 草稿是否可修改 | 规则 |
|---|---|---|---|
| 部件名称 | 输入框 | Y | 每个子部件一行；初始值来自 PO 接收阶段维护的部件说明 |
| 部件标签号 | 只读 | N | 主资产标签生成后自动按“主资产标签号-N”生成 |
| 部件 SN | 输入框 | Y | 支持真实 SN 或“缺省” |

同一主资产内部的多个部件真实 SN 不允许重复；“缺省”不参与重复校验。

重复时提示：

> 存在重复的部件序列号！

部件信息按现有组合规则保存：

`部件名称#部件标签号#部件SN@部件名称#部件标签号#部件SN……`

组合内容总长度不得超过 500 字符，超过时提示：

> 描述字符超长，总长度不能超过 500 字符！

点击【保存】后，SN、资产标记、备注、部件名称、部件 SN 等修改立即保存，并提示：

> 明细信息已保存

已完成接收单进入该弹窗时仅允许查看，不展示保存操作。

### 5.14 标签打印

草稿、已完成状态均允许标签打印，入口统一位于“维护 / 查看接收明细”页面。

只有当前接收单存在资产明细且全部资产均已生成资产标签号时展示【打印标签号】。

如果因异常入口触发打印但仍存在未生成标签号的资产，则不进入打印流程，并提示：

> 有未维护的标签号，请先维护接收明细。

校验通过后，按照当前接收单生成或取得标签打印批次。

存在子部件时，同时打印对应子部件标签；子标签数量 = 部件数量 - 1。

### 5.15 普通资产接收确认

草稿状态点击【接收确认】后，系统校验当前接收单全部资产接收明细。

只有全部资产同时满足以下条件时才允许确认：

- 资产标签号不为空。
- SN 不为空。
- 所有非“缺省”的真实 SN 均通过唯一性校验。

“缺省”视为已完成 SN 维护。

存在资产标签号或 SN 未维护时，提示：

> 有未维护的标签号或 SN 号，请先维护接收明细。

接收确认成功后：

| 数据对象 | 处理结果 |
|---|---|
| 接收单 | 状态由“草稿”更新为“已完成” |
| 接收人 / 接收时间 | 记录当前操作人和当前时间 |
| 接收行 | 固化为本次接收业务快照 |
| 资产接收明细 | 固化，不再允许修改 |
| PO 草稿数量 | 扣减本次草稿占用数量 |
| PO 已接收数量 | 增加本次接收数量 |
| PO 行状态 | 根据当前行累计接收、入库数量重新判断 |
| PO 状态 | 根据整张 PO 累计接收数量重新判断“待接收 / 已接收” |
| 入库单 | 自动生成一张“采购接收”类型的草稿入库单 |
| 后续数据 | 板块、申请批次、资产标签号、SN、部件等接收结果传递到入库单及入库物资明细 |

成功提示：

> 接收确认成功，已生成草稿入库单 XXX

接收确认只表示资产接收完成，不代表资产已经正式入库。

### 5.16 机房资产接收

适用采购类型：服务器、服务器备件、网络设备、网络设备备件。

以上资产不走普通资产“创建接收单 → 手工维护标签号 / SN”的流程，接收数据主要来自 NO/MIS。

#### 5.16.1 页面操作

用户在 PO 物资明细中勾选需要接收的行后点击【接收确认】。

该按钮表示完成资产接收并创建后续入库草稿，不代表正式资产已经完成入库。

PO 物资行仍可进入【编辑】查看 / 调整允许修改的接收侧信息，但“接收数量”只读，由 NO/MIS 数据决定。

#### 5.16.2 接收前校验

系统必须在写入任何接收业务数据前完成全部校验。

| 校验项 | 规则 | 错误提示 |
|---|---|---|
| 板块 | 必须已选择 | 请选择板块！ |
| PO 行 | 至少选择 1 行 | 请选择要接收的物料！ |
| NO/MIS 数据 | 所选资产必须存在可用接收数据 | 接收失败：具体错误信息 |
| NO 位置 | 必须存在 | NO 入库数据缺失 NO 位置信息 |
| 地址映射 | NO 位置必须能够匹配有效位置配置 | XXX 映射不存在或城市建筑楼层存在数据缺失! |
| City | 必须存在 | 同地址映射校验提示 |
| Building | 必须存在 | 同地址映射校验提示 |
| Floor | 必须存在 | 同地址映射校验提示 |
| 重复接收 | 当前 NO/MIS 数据不得已经存在有效接收记录 | 所选资产已完成接收，请刷新后重试。 |

任意一项失败时：

- 不创建接收单。
- 不创建资产接收明细。
- 不创建入库草稿单。
- 不修改 NO/MIS 接收状态。

用户修正问题后可以重新执行接收确认。

#### 5.16.3 接收成功

全部校验通过后，系统一次性完成以下处理：

| 数据对象 | 处理结果 |
|---|---|
| 接收单 | 创建并直接设置为“已完成” |
| 制单人 / 制单时间 | 记录当前操作人和当前时间 |
| 接收人 / 接收时间 | 同本次接收确认操作人和时间 |
| 接收行 | 根据本次勾选 PO 行和 NO/MIS 数据创建 |
| 资产接收明细 | 根据 NO/MIS 数据创建 |
| 资产标签号 | 按 NO/MIS 数据及现有标签规则取得 |
| SN | 来源 NO/MIS |
| 责任人 | 来源 NO/MIS 及相关人员映射 |
| City / Building / Floor | 根据 NO 位置映射取得 |
| 成本中心 | 来源 NO/MIS |
| 购买日期 | 接收阶段生成初始值并传递到后续入库；具体取值沿用现有上游数据规则 |
| 启用日期 | 接收阶段按本 PRD规则生成并传递到后续入库 |
| NO/MIS 数据 | 标记为已完成接收 |
| PO 已接收数量 | 增加本次实际接收数量 |
| PO 行状态 | 根据当前行累计接收数量重新计算 |
| PO 状态 | 部分接收保持“待接收”；全部接收后更新为“已接收” |
| 入库单 | 按 NO 位置拆分并自动创建“采购接收”类型的草稿入库单 |

启用日期规则：

- 当前日期小于每月 26 日：使用当前日期。
- 当前日期大于等于每月 26 日：使用下个月 1 日。

按 NO 位置拆单规则：

- 相同目标 NO 位置的资产进入同一张采购接收入库草稿单。
- 不同 NO 位置的资产拆分为不同采购接收入库草稿单。

上述处理属于一个完整业务动作，只允许全部成功或全部失败。

不得出现接收单已经完成但对应入库草稿单未生成的半完成状态。

成功提示：

> 接收成功，入库单已创建！

失败提示：

> 接收失败：具体错误信息

#### 5.16.4 防重复处理

同一条 NO/MIS 资产数据一旦已经生成有效接收记录，不允许再次执行接收。

重复操作时不产生新业务数据，并提示：

> 所选资产已完成接收，请刷新后重试。

## 6. 校验与异常处理

本章节汇总会阻断用户操作的关键校验。字段本身的普通必填、展示、默认值和只读规则以对应页面字段表为准。

| 操作 | 校验规则 | 校验失败处理 |
|---|---|---|
| 编辑普通资产接收数量 | 必须为正整数 | 不保存本次编辑，保留弹窗 |
| 编辑普通资产接收数量 | 不得大于当前可接收数量 | 不保存，弹窗保持打开，提示“接收数量不能超过可接收数量！” |
| 机房资产接收数量 | 不允许人工修改 | 字段只读 |
| 维护部件数量 | 是否部件=是时必须填写 | 不允许保存 |
| 维护部件数量 | 仅允许 2～100 的整数 | 不允许保存，提示“请输入 2～100 之间的整数！” |
| 维护部件说明 | 必须先填写合法部件数量 | 不进入维护，提示“请填写部件数量！” |
| 创建普通接收单 | 至少选择一条 PO 行 | 不创建接收单，提示“请选择要接收的物料！” |
| 创建普通接收单 | 板块必填 | 不创建接收单，提示“请选择板块！” |
| 创建普通接收单 | 所选行至少存在 1 条有效可接收数量 | 不创建，提示“所选物资当前没有可接收数量” |
| 删除草稿接收单 | 必须选择草稿接收单 | 不执行，提示“请先选择需要删除的接收单！” |
| 删除接收行 | 仅草稿状态允许且必须先选择行 | 已完成不展示入口；未选择提示“请先选择需要删除的接收行！” |
| 进入维护接收明细 | 必须存在接收行 | 不进入，提示“请先维护接收信息！” |
| 进入维护接收明细 | 各接收行本次接收数量必须大于 0 | 不进入，提示“第 X 行，未维护接收数量！” |
| 删除资产明细 | 必须选择资产明细 | 不执行，提示“请先选择需要删除的标签行！” |
| 保存真实 SN | 与其他资产真实 SN 重复 | 不保存当前 SN，提示“SN 号：XXX 已存在！” |
| 扫描资产标签号 | 当前接收单内未找到匹配标签 | 不写入 SN，提示“未找到匹配的标签号：扫描值” |
| 扫描维护 | 资产标签号尚未全部生成 | 扫描框禁用；不允许录入 SN |
| 保存部件 SN | 同一主资产内真实部件 SN 重复 | 不保存，提示“存在重复的部件序列号！” |
| 保存部件组合信息 | 总长度超过 500 字符 | 不保存，提示“描述字符超长，总长度不能超过 500 字符！” |
| 接收确认 | 接收单至少存在一条有效接收行 | 不执行接收确认 |
| 接收确认 | 所有资产均存在资产标签号和 SN | 不执行，保持草稿，提示“有未维护的标签号或 SN 号，请先维护接收明细。” |
| 接收确认 | 所有真实 SN 均不重复 | 不执行，接收单保持草稿 |
| 标签打印 | 所有待打印资产均存在标签号 | 不进入打印流程，提示“有未维护的标签号，请先维护接收明细。” |
| 机房资产接收确认 | 板块、PO 行、NO/MIS 数据、地址映射全部有效 | 本次业务数据全部不写入 |
| 机房资产接收确认 | 不得重复接收 | 不创建重复数据 |

普通资产接收确认失败时：

- 接收单继续保持草稿。
- 已经维护的有效数据保留。
- 用户修正问题后重新点击【接收确认】。

## 7. 后续操作及补充说明

### 7.1 普通资产接收完成后的处理

普通资产完成接收以后，只代表实物接收以及接收数据维护已经完成，此时尚未正式创建资产卡片。

接收确认成功后，系统自动生成一张“采购接收”类型的草稿入库单。

用户后续进入“库存管理 → 入库”检查入库数据并执行正式入库。

正式入库成功后才创建正式资产卡片。

业务边界为：

- 资产接收解决“实际收到了什么”。
- 资产入库解决“资产正式进入哪个仓库，并以什么资产信息建卡”。

### 7.2 机房资产接收完成后的处理

机房资产接收确认成功后，接收单直接完成，同时按 NO 位置自动生成一张或多张“采购接收”类型的草稿入库单。

此时仍然只是“接收已完成、入库待执行”。

用户需要进入入库模块检查入库数据并执行正式入库，正式执行入库成功后才生成资产卡片。

### 7.3 已完成接收单

接收单进入“已完成”后：

| 数据 | 规则 |
|---|---|
| 接收单头 | 只读 |
| 接收行 | 只读 |
| 资产标签号 | 不可修改 |
| SN | 不可修改 |
| 资产标记 | 不可修改 |
| 备注 | 不可修改 |
| 部件数据 | 不可修改 |
| 接收明细 | 允许只读查看 |
| 标签打印 | 允许在“查看接收明细”页面补打 |
| 接收单打印 | 允许 |
| 后续入库 | 作为采购接收入库数据来源 |
