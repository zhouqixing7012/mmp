# 库存管理 - 资产接收 PRD

## 1. 背景

资产接收用于处理采购资产实际到货后的接收业务。

用户根据采购 PO 查看待接收物资，维护本次实际接收数量，并根据实际到货资产维护资产标签号、SN、部件等信息。接收完成后，系统生成后续采购接收入库草稿单，用户再进入入库模块执行正式入库。

资产接收仅处理以下两类资产：

| 资产类型 | 接收方式 |
|---|---|
| 普通资产 | PO → 创建接收单 → 维护资产标签号、SN → 接收确认 → 接收完成 → 按资产大类拆分生成采购接收入库草稿单 |
| 服务器、服务器备件、网络设备、网络设备备件 | PO → 获取 NO/MIS 数据 → 接收确认 → 直接完成接收 → 按 NO 位置自动生成采购接收入库草稿单 |

低值耐用品、普通耗材不在本模块处理，由“耗材接收”独立处理。

资产接收解决“实际收到了什么”；资产入库解决“资产正式进入哪个仓库，并以什么资产信息建卡”。资产接收完成不代表正式入库完成，正式库存及资产卡片结果在后续入库流程产生。

## 2. 权限

权限采用“公司 + 板块数据范围”与“仓库操作权限”两层控制。

### 2.1 数据权限

- 公司、板块决定用户可查看和查询的 PO、采购行及接收单范围。
- 用户无对应公司或板块数据权限时，不返回对应 PO、采购行及接收单。
- PO 列表、接收单列表、详情页均按相同数据权限过滤。

### 2.2 操作权限

业务匹配的目标仓库权限决定用户能否执行以下操作：

- 创建接收单；
- 编辑接收信息；
- 删除草稿接收单；
- 删除接收行；
- 维护接收明细；
- 生成标签号；
- 维护 SN；
- 打印标签；
- 执行接收确认；
- 打印正式接收单。

无仓库操作权限时只允许查看已有数据，不允许提交业务操作。

页面展示、打开详情及提交操作时均重新校验权限，不能仅依赖前端按钮显隐判断权限。

## 3. 通用规则

### 3.1 接收模式

#### 3.1.1 普通资产

普通资产按“先形成草稿接收单，再逐件维护”的方式接收。

业务过程：

1. 进入 PO 接收页面。
2. 系统计算每条 PO 行的剩余可接收数量。
3. 用户可在满足条件时编辑本次接收信息。
4. 勾选一个或多个可接收 PO 行，点击【创建接收单】。
5. 系统生成草稿接收单，并立即形成草稿数量占用。
6. 用户进入接收单详情，通过【维护接收明细】逐件维护资产标签号、SN、部件等信息。
7. 全部逐件明细满足条件后点击【接收确认】。
8. 接收单变为已完成，草稿数量转为已接收数量。
9. 系统按资产大类拆分生成采购接收入库草稿单。
10. 用户进入“库存管理 → 入库”执行正式入库。

#### 3.1.2 机房资产

适用采购类型：

- 服务器；
- 服务器备件；
- 网络设备；
- 网络设备备件。

机房资产不创建草稿接收单，不人工维护接收数量。

业务过程：

1. 用户进入 PO 接收页面。
2. 系统根据 NO/MIS 推送数据取得可接收数量。
3. 用户勾选 PO 行，点击【接收确认】。
4. 系统执行板块、PO 行、NO/MIS 数据、NO 位置、地址映射、City、Building、Floor、重复接收等前置校验。
5. 校验全部通过后直接生成已完成接收单及资产接收明细。
6. 系统按 NO 位置拆分生成采购接收入库草稿单。
7. 用户进入“库存管理 → 入库”执行正式入库。

机房资产统一使用【接收确认】，不使用“执行入库”作为资产接收页面操作。

### 3.2 状态规则

资产接收同时存在 PO 状态、PO 行状态、接收单状态，三类状态独立判断。

#### 3.2.1 PO 状态

| 状态 | 判断规则 |
|---|---|
| 待接收 | 任一采购行仍存在未完成接收数量 |
| 已接收 | 所有采购行均已完成接收，但对应资产尚未全部正式入库 |
| 已入库 | 对应资产全部完成正式入库 |

规则：

- 任一 PO 行仍存在未接收数量时，整张 PO 保持“待接收”。
- 部分接收不能提前将整张 PO 更新为“已接收”。
- 所有 PO 行累计已接收数量达到采购数量后，PO 更新为“已接收”。
- 对应资产全部正式入库后，PO 更新为“已入库”。

#### 3.2.2 PO 行状态

| 状态 | 判断规则 |
|---|---|
| 待接收 | 仍存在剩余未接收数量 |
| 已接收 | 采购数量全部完成接收，但尚未全部正式入库 |
| 已入库 | 对应资产全部正式入库 |

PO 行【编辑】显隐与字段是否可编辑是两个独立判断：

- 【编辑】是否展示：普通资产仅当 PO 行状态为“待接收”且剩余可接收数量大于 0 时展示。
- 字段是否可编辑：只判断当前 PO 行是否被草稿接收单引用。
- 已完成接收单引用不作为 PO 行物料、配置、部件字段锁定条件。

#### 3.2.3 接收单状态

接收单状态仅包含：

| 状态 | 说明 | 数据是否可维护 |
|---|---|---|
| 草稿 | 接收单已创建，标签号、SN 等接收数据仍可维护 | Y |
| 已完成 | 已执行接收确认 | N |

普通资产固定按“草稿 → 已完成”流转。

不新增“已取消”“已作废”等第三种接收单状态。

### 3.3 可接收数量与草稿占用

普通资产支持分批接收。

剩余可接收数量计算规则：

可接收数量 = 采购数量 - 已接收数量 - 草稿数量

其中：

- 已接收数量：已经完成接收确认的数量。
- 草稿数量：被有效草稿接收单占用但尚未完成确认的数量。
- 创建草稿接收单后，本次接收数量立即计入草稿数量。
- 接收确认成功后，本次数量从草稿数量转入已接收数量。

以下操作需要释放对应草稿数量：

| 操作 | 数量处理 |
|---|---|
| 删除接收行 | 释放该接收行对应草稿数量 |
| 删除资产逐件明细 | 来源接收行数量同步减少，并释放相同草稿数量 |
| 取消接收 | 释放整张草稿接收单占用数量 |
| 删除草稿接收单 | 释放整张草稿接收单占用数量 |

PO 行【编辑】是否展示始终按重新计算后的剩余可接收数量判断。

如果某 PO 行已被草稿接收单引用，编辑本次接收数量时允许在该草稿当前占用数量范围内调整。数量上限按：

当前未占用可接收数量 + 当前草稿接收行已占用数量

计算，保存后按新旧数量差额同步调整草稿接收行和 PO 草稿数量。

机房资产可接收数量由 NO/MIS 推送数据决定，不允许人工修改。

### 3.4 PO 级字段固化

PO 级需要固化的字段：

- 板块；
- 申请批次。

规则：

- 板块必填。
- 申请批次选填。
- 当前 PO 尚无任何接收单时允许修改。
- 首次形成有效接收单后，板块和申请批次立即固化为只读。
- 草稿接收单和已完成接收单均属于有效接收单。
- 后续分批接收统一沿用固化后的板块和申请批次。
- 接收单和后续采购接收入库草稿单均使用固化后的值。
- 删除 / 取消全部草稿后，如果当前 PO 已不存在任何接收单，板块和申请批次重新可编辑。
- 已完成接收单不可删除，因此只要 PO 已存在已完成接收单，PO 级板块和申请批次保持固化。

PO 级字段固化与 PO 行基础字段锁定相互独立。已完成接收单会继续固化 PO 级板块、申请批次，但不会继续锁定仍有后续可接收数量的 PO 行物料、配置和部件信息。

### 3.5 PO 行编辑与草稿引用锁定

普通资产 PO 行仅在以下条件同时满足时展示【编辑】：

- PO 行状态 = 待接收；
- 剩余可接收数量 > 0。

草稿接收单引用本身不会让“剩余可接收数量 = 0”的 PO 行额外显示【编辑】。

#### 3.5.1 未被草稿接收单引用

允许维护：

- 物料；
- 配置；
- 普通资产本次接收数量；
- 是否部件；
- 部件数量；
- 部件说明。

#### 3.5.2 已被草稿接收单引用

以下字段只读：

- 物料；
- 配置；
- 是否部件；
- 部件数量；
- 部件说明。

普通资产本次接收数量仍允许调整，并按草稿占用规则重新计算。

保存时只允许持久化本次接收数量变化，不能使用编辑弹窗中的旧值覆盖已经固化的物料、配置和部件信息。

#### 3.5.3 草稿引用解除

删除接收行、取消接收或删除草稿接收单后，重新判断当前 PO 行是否仍被其他草稿接收单引用：

- 无草稿引用：物料、配置和部件信息恢复可编辑；
- 仍有草稿引用：上述字段继续只读。

【编辑】是否展示仍单独根据剩余可接收数量重新判断。

已完成接收记录不作为 PO 行基础字段锁定条件。

#### 3.5.4 机房资产

机房资产接收数量由 NO/MIS 决定，始终不允许人工修改。

机房资产后续仍有可接收数量时，已完成接收记录本身不额外锁定该 PO 行的接收侧基础字段。

保存 PO 行接收侧修改仅更新资产接收侧数据，不反写采购系统原始 PO。

### 3.6 部件规则

普通资产支持按套件维护部件。

| 规则 | 说明 |
|---|---|
| 是否部件 | 是 / 否 |
| 部件数量 | 是否部件=是时必填 |
| 数量范围 | 2～100 |
| 数量含义 | 包含主资产本身 |
| 子部件数量 | 部件数量 - 1 |
| 子部件默认名称 | 部件1、部件2……，允许修改 |
| 取消是否部件 | 清空部件数量、部件说明并禁用部件维护入口 |

子部件标签号规则：

主资产标签号-N

例如主资产标签号为 A001，子部件依次生成 A001-1、A001-2。

部件组合保存格式：

部件名称#部件标签号#部件SN@部件名称#部件标签号#部件SN……

部件组合总长度不得超过 500 字符。

### 3.7 标签号与 SN

#### 3.7.1 标签号

- 标签号为空时允许生成。
- 已有标签号不得被批量生成操作覆盖。
- 子部件标签号按“主资产标签号-N”生成。
- 标签号全部生成后允许打印标签。

#### 3.7.2 SN

| 类型 | 规则 |
|---|---|
| 真实 SN | 需要唯一性校验 |
| 缺省 | 合法；视为已维护；不参与真实 SN 唯一性校验 |

规则：

- 同一接收单内部真实 SN 不得重复。
- 与其他资产已存在的真实 SN 不得重复。
- 多条资产允许同时使用“缺省”。
- 已有真实 SN 不因批量维护“缺省”而覆盖。
- 支持单条编辑、扫码录入、批量维护“缺省”。

### 3.8 制单人与接收人

系统仍记录制单和接收审计信息，但记录字段与页面是否展示分开处理。

| 字段 | 取值时点 |
|---|---|
| 制单人 | 创建草稿接收单时当前操作人 |
| 制单时间 | 草稿创建成功时间 |
| 接收人 | 接收确认成功时当前操作人 |
| 接收时间 | 接收确认成功时间 |

草稿状态下接收人、接收时间为空。

资产接收维护接收明细页、资产接收接收单详情页不展示制单人、制单时间；接收单列表仍可保留制单人、制单时间用于查询和追溯。

### 4.3 编辑接收信息

进入条件：

- PO 行状态 = 待接收；
- 剩余可接收数量 > 0。

| 字段 | 未被草稿接收单引用 | 已被草稿接收单引用 | 规则 |
|---|---|---|---|
| 物料 | 可改 | 只读 | 弹窗选择可用物料 |
| 配置 | 可改 | 只读 | 文本输入 |
| 接收数量 | 普通资产可改 / 机房资产只读 | 普通资产可改 / 机房资产只读 | 普通资产必须为正整数；机房资产由 NO/MIS 决定 |
| 是否部件 | 可改 | 只读 | 是 / 否 |
| 部件数量 | 条件可改 | 只读 | 是否部件=是时 2～100 |
| 部件说明 | 条件可改 | 只读 | 子部件行数 = 部件数量 - 1 |

未被草稿引用时，普通资产接收数量不得超过当前剩余可接收数量。

被草稿引用时，接收数量上限 = 当前未占用可接收数量 + 当前草稿接收行已占用数量。

保存时再次判断当前 PO 行是否存在草稿接收引用：

- 无草稿引用：保存当前允许修改的接收侧字段。
- 有草稿引用：仅保存普通资产本次接收数量，并按新旧数量差额同步调整草稿接收行和 PO 草稿占用；物料、配置、部件信息保持草稿形成时的值。

部件数量不合法时提示：

请输入 2～100 之间的整数！

保存成功提示：

接收信息已保存

## 5. 校验

### 5.1 创建普通资产接收单

| 场景 | 校验 / 提示 |
|---|---|
| 未选择采购行 | 请选择要接收的物料！ |
| 板块为空 | 请选择板块！ |
| 所选行无可接收数量 | 所选物资当前没有可接收数量 |
| PO 行不可接收 | 不允许生成接收数据 |

创建失败时不生成接收单、不增加草稿数量。

### 5.2 编辑 PO 行

普通资产接收数量校验：

- 必须为大于 0 的整数。
- 未被草稿接收单引用时，不得超过当前剩余可接收数量。
- 被草稿接收单引用时，上限 = 当前未占用可接收数量 + 当前草稿接收行已占用数量。
- 机房资产接收数量不允许人工修改。

字段权限校验：

- 当前行无草稿接收引用时，允许修改物料、配置和部件信息。
- 当前行存在草稿接收引用时，物料、配置、部件信息只读，保存时不得覆盖。
- 已完成接收记录不作为 PO 行基础字段锁定条件。

### 5.3 板块与申请批次

- 创建接收单 / 机房资产接收确认前，板块必填。
- 当前 PO 已存在任意草稿或已完成接收单时，禁止修改板块和申请批次。
- 当前 PO 不再存在任何接收单时，板块和申请批次恢复可编辑。

### 5.4 部件

- 是否部件=是时，部件数量必填。
- 部件数量必须为 2～100 的整数。
- 子部件行数 = 部件数量 - 1。
- 部件组合保存总长度不得超过 500 字符。

### 5.5 标签号与 SN

- 进入维护接收明细前必须存在接收行，且各行接收数量大于 0。
- 标签号为空时才允许生成，不覆盖已有标签号。
- 保存真实 SN 时不得与当前接收单其他真实 SN 重复。
- 保存真实 SN 时不得与系统其他资产真实 SN 重复。
- “缺省”允许重复，不参与真实 SN 唯一性校验。
- 批量维护“缺省”不得覆盖已有真实 SN。
- 扫描标签号必须在当前接收单找到匹配资产。
- 扫描标签号命中后仅刷新顶部核对区，不筛选下方明细。

### 5.6 普通资产接收确认

接收确认前必须满足：

- 至少存在一条有效资产逐件明细；
- 所有资产标签号不为空；
- 所有 SN 不为空；
- 所有非“缺省”的真实 SN 唯一；
- 每条电子设备逐件明细必须存在资产大类。

资产大类为空时阻断生成采购接收入库草稿单。

接收确认失败时：

- 接收单继续保持草稿；
- 已维护的有效标签号、SN、部件及其他明细数据保留；
- 不生成重复接收结果；
- 不生成采购接收入库草稿单。

### 5.7 机房资产接收

前置校验至少包括：

- 板块；
- PO 行合法性；
- NO/MIS 数据；
- NO 位置；
- 地址映射；
- City；
- Building；
- Floor；
- 重复接收。

任一校验失败时：

- 不创建接收单；
- 不创建接收明细；
- 不创建采购接收入库草稿单；
- 不修改 NO/MIS 接收状态。

### 5.8 打印

标签打印：

- 待打印资产必须已有标签号。
- 无标签号时按钮不可用。

正式接收单打印：

- 仅已完成接收单允许打印。
- 草稿不打印正式接收单。

### 5.9 重复接收

同一业务来源不得重复产生接收数据。

所有创建、确认操作提交时重新执行重复接收校验，不能只依赖页面加载时状态。

## 6. 后续操作 / 业务结果 / 补充说明

### 6.1 删除接收行

仅草稿接收单允许删除接收行。

删除后：

1. 删除当前接收行。
2. 删除该接收行已生成的资产逐件明细。
3. 释放对应 PO 草稿数量。
4. 重新计算 PO 剩余可接收数量。
5. 重新判断当前 PO 行是否仍被其他草稿接收单引用：
   - 无草稿引用：物料、配置、部件信息恢复可编辑；
   - 仍有草稿引用：上述字段继续只读。
6. 根据新的剩余可接收数量重新计算【编辑】按钮显隐。

如果接收单已经无接收行，则不得执行接收确认，用户可以继续取消该草稿。

### 6.2 删除 / 取消草稿接收单

草稿接收单允许删除或取消。

确认后：

1. 删除接收单头。
2. 删除接收行。
3. 删除已生成的资产逐件明细。
4. 释放整张草稿接收单占用数量。
5. 重新计算 PO 行剩余可接收数量。
6. 重新计算 PO 行草稿引用锁定。
7. 重新计算 PO 级板块、申请批次固化状态。

PO 级处理：

- 如果删除 / 取消后当前 PO 已不存在任何接收单，板块、申请批次恢复可编辑。
- 如果仍存在其他草稿或已完成接收单，板块、申请批次继续只读。

PO 行处理：

- 无其他草稿引用：物料、配置、部件信息恢复可编辑。
- 仍有其他草稿引用：上述字段继续只读。
- 【编辑】按钮始终按新的剩余可接收数量重新判断。

删除 / 取消不新增“已取消”“已作废”状态。

### 6.3 普通资产接收确认结果

接收确认成功后：

- 接收单状态更新为已完成；
- 写入接收人、接收时间；
- 草稿数量转为已接收数量；
- 接收快照固化；
- PO 行、PO 状态按累计接收数量重新计算；
- PO 级板块、申请批次继续保持固化；
- 当前接收单不再作为 PO 行物料、配置、部件字段锁定条件；
- 如果同一 PO 行后续仍有剩余可接收数量且不存在其他草稿引用，则物料、配置、部件信息可在下一批接收前重新维护；
- 系统按资产大类拆分生成采购接收入库草稿单。

### 6.4 普通资产采购接收入库草稿拆单

普通资产接收确认成功后，以接收逐件明细中的“资产大类”为拆单键生成采购接收入库草稿单。

规则：

- 同一接收单内，同一资产大类进入同一张采购接收入库草稿单。
- 不同资产大类分别生成不同采购接收入库草稿单。
- 同一资产大类不得被拆成多张草稿单。
- 不同资产大类不得混入同一张草稿单。
- 资产大类为空时阻断生成。
- 接收完成仅生成入库草稿，不直接完成正式入库。
- 用户后续进入“库存管理 → 入库”执行正式入库。
- 正式入库成功后才创建正式资产卡片。

### 6.5 机房资产接收结果

全部校验通过后：

- 直接创建已完成接收单；
- 写入制单人、制单时间；
- 写入接收人、接收时间；
- 根据 NO/MIS 数据生成资产接收明细；
- 责任人、位置、成本中心按既有映射处理；
- PO / PO 行按累计接收量更新；
- PO 级板块、申请批次固化；
- 已完成接收记录本身不额外锁定后续仍有可接收数量的 PO 行基础字段；
- 按 NO 位置拆分生成采购接收入库草稿单。

正式资产卡片仍在后续入库成功后创建。

### 6.6 接收与入库边界

资产接收完成后仅代表“本次到货资产已确认”。

普通资产：

- 按资产大类生成一张或多张采购接收入库草稿单。

机房资产：

- 按 NO 位置生成一张或多张采购接收入库草稿单。

两类业务均由用户后续进入“库存管理 → 入库”执行正式入库。

正式入库成功后才产生正式库存结果并创建资产卡片。

### 6.7 已完成接收单

已完成后以下数据不可修改：

- 接收单头；
- 接收行；
- 资产标签号；
- SN；
- 资产标记；
- 备注；
- 部件数据。

允许：

- 只读查看；
- 标签补打；
- 接收单打印；
- 作为后续采购接收入库数据来源。

已完成接收单继续参与 PO 级板块、申请批次固化。

已完成接收单不参与 PO 行物料、配置、部件字段锁定判断。

### 6.8 标签打印

标签打印与正式接收单打印互相独立。

规则：

- 草稿和已完成接收单均允许打印标签。
- 打印标签前，对应资产必须已有标签号。
- 标签号未全部生成时，【打印标签号】保持展示但置灰。
- 已完成接收单允许补打标签。
- 打印动作不修改接收数量、PO 状态、接收单状态或入库结果。

### 6.9 物资接收单打印

#### 6.9.1 打印入口

- 仅已完成接收单展示【接收单打印】。
- 草稿不打印正式接收单。
- 打印只读取已保存快照。
- 打印失败允许重试。
- 打印失败不生成新的接收单号。
- 打印失败不重复执行接收确认。

#### 6.9.2 标题与版式

标题固定为：

物资接收单

纸张、联次、签字区域沿用现有打印模板。

明细跨页时：

- 重复表头；
- 显示页码。

#### 6.9.3 表头字段

- 供应商；
- 采购单位；
- 采购订单编号；
- 接收单号；
- 供应商联系人；
- 供应商电话；
- 采购员；
- 采购员电话；
- 接收日期；
- 接收地点；
- PO 说明。

接收地点沿用现有打印数据来源。

无值时留空，不根据仓库或资产位置猜补。

#### 6.9.4 明细字段

- 序号；
- PR 单/行号；
- SA 单/行号；
- 资产说明（品牌、型号、配置）；
- 接收数量；
- 单价；
- 小计；
- 业务线；
- 申请人；
- 备注。

规则：

- 序号从 1 开始。
- 金额保留两位小数。
- 底部展示数量合计和金额合计。

#### 6.9.5 签字区域

保留：

- 供应商（签字）/ 时间；
- 接收方（签字）/ 时间。

打印功能仅预留签字位置，不因打印动作自动写入他人签名。
