# 库存管理 - 资产接收 PRD

## 1. 背景

资产接收用于处理采购资产实际到货后的接收业务。

用户根据采购 PO 查看待接收物资，维护本次实际接收数量，并根据实际到货资产维护资产标签号、SN、部件等信息。接收完成后，资产进入后续采购接收入库流程。

本次改造后，“资产接收”仅包含以下两类资产：

| 资产类型 | 接收方式 |
|---|---|
| 普通资产 | PO → 创建接收单 → 维护资产标签号、SN → 接收确认 → 接收完成 → 后续入库 |
| 服务器、服务器备件、网络设备、网络设备备件 | PO → 获取 NO/MIS 数据 → 接收确认 → 直接完成接收 → 自动生成入库草稿单 |

低值耐用品、普通耗材不在本模块处理，由“耗材接收”独立处理。

本次主要对资产接收的业务边界、流程状态、页面交互、数据修改范围和异常规则进行统一，避免 PO 状态、接收单状态、接收与入库动作混用。

## 2. 改造总结

| 改造项 | 改造后规则 |
|---|---|
| 业务范围 | 资产接收仅处理普通资产以及服务器、服务器备件、网络设备、网络设备备件；耗材由“耗材接收”独立处理 |
| 接收单状态 | 统一为“草稿 / 已完成”两个状态，不再使用“接收待维护” |
| 普通资产流程 | 创建接收单后进入草稿；先维护资产标签号和 SN；全部维护完成后点击【接收确认】，接收单直接变为已完成 |
| 物料、配置修改 | PO 接收页面修改物料或配置，只影响本次接收数据，不修改采购 PO 原始数据 |
| 板块、申请批次 | 修改后只影响后续新创建的接收行，不修改已经完成的历史接收数据 |
| 分批接收 | 保留分批接收；草稿接收单中的接收数量立即计入草稿占用，避免重复接收 |
| 删除接收行 | 草稿状态允许删除已有接收数量的接收行；删除后同步删除对应接收明细并释放草稿占用数量 |
| 部件数量 | 仅允许 2～100，包含主资产本身；子部件数量 = 部件数量 - 1 |
| SN“缺省” | “缺省”视为合法 SN，可以完成接收，不参与真实 SN 唯一性校验 |
| 标签打印 | 草稿和已完成状态均允许打印标签；打印前必须保证待打印资产已有标签号 |
| 机房资产操作 | 服务器、服务器备件、网络设备、网络设备备件统一使用【接收确认】，不再使用“执行入库” |
| 机房资产接收结果 | 校验通过后一次性生成已完成接收单和草稿采购接收入库单 |
| 机房资产异常 | 所有前置校验全部通过后才写入业务数据；任一校验失败，本次不产生接收单或入库草稿 |
| 重复接收 | 已存在有效接收记录的 NO/MIS 数据不得再次生成接收单 |
| 权限 | 按公司 + 板块控制，具体权限规则暂留待补充 |

## 3. 通用规则

### 3.1 状态规则

资产接收存在 PO 状态和接收单状态，两类状态独立维护，不得混用。

#### PO 状态

| 状态 | 说明 |
|---|---|
| 待接收 | 当前 PO 仍存在未完成接收的采购数量 |
| 已接收 | PO 所有采购数量已完成接收，等待后续入库 |
| 已入库 | PO 对应资产已经全部完成后续正式入库 |

PO 状态按整张 PO 的累计数量判断：

- 任一 PO 行仍存在未接收数量时，整张 PO 保持“待接收”。
- 所有 PO 行累计已接收数量达到采购数量后，整张 PO 更新为“已接收”。
- 所有已接收资产后续全部完成正式入库后，整张 PO 更新为“已入库”。
- 部分接收不能提前将整张 PO 更新为“已接收”。

#### 接收单状态

| 状态 | 说明 | 是否可修改 |
|---|---|---|
| 草稿 | 已创建接收单，资产标签号、SN 等接收数据仍可维护 | Y |
| 已完成 | 已执行接收确认，接收流程结束 | N |

普通资产接收单固定按照：

`草稿 → 已完成`

流转。

不再存在“接收待维护”状态。

### 3.2 可接收数量

普通资产支持分批接收。

单条 PO 行的当前可接收数量按照以下公式计算：

`可接收数量 = 采购数量 - 已接收数量 - 草稿数量`

其中：

- 已接收数量：已经完成接收确认的数量。
- 草稿数量：已经被其他有效草稿接收单占用、但尚未完成接收确认的数量。

创建接收单后，本次接收数量立即计入草稿数量，其他接收单不可重复占用该部分数量。

以下操作需要同步释放对应草稿数量：

| 操作 | 数量处理 |
|---|---|
| 删除接收行 | 释放该接收行对应的草稿数量 |
| 删除接收资产明细 | 对应接收行本次接收数量同步减少，并释放相同草稿数量 |
| 取消接收 | 释放整个接收单占用的草稿数量 |
| 删除草稿接收单 | 释放整个接收单占用的草稿数量 |

接收确认成功后，本次数量从“草稿数量”转入“已接收数量”。

### 3.3 接收数据快照

接收单保存本次实际接收时的数据快照。

接收单完成后，历史接收数据不得因为 PO 后续发生修改而变化。

PO 接收页面允许修改的物料、配置、板块、申请批次等信息，只按照本 PRD 约定影响当前或后续接收数据，不追溯修改已经完成的接收单和资产接收明细。

### 3.4 物料和配置修改规则

用户在 PO 接收页面编辑本次接收信息时，可以重新选择物料、修改配置。

修改后的物料和配置只作为本次接收数据使用，创建接收单时保存到对应接收行。

不得因为本次接收修改而反向修改采购 PO 原始物料编码、物料名称或配置。

如果用户修改后未创建接收单即离开当前页面，则不产生新的接收业务数据。

### 3.5 板块和申请批次

板块和申请批次用于后续接收业务。

| 数据范围 | 修改后的处理规则 |
|---|---|
| 后续新创建的接收行 | 使用修改后的值 |
| 已完成接收行 | 保留原接收数据，不修改 |
| 已完成资产接收明细 | 保留原接收数据，不修改 |

申请批次为非必填字段；有值时随接收单继续传递到后续采购接收入库单及入库物资明细。

板块同样随接收单和后续入库单传递。

### 3.6 部件规则

普通资产支持按套件方式维护部件。

| 规则 | 说明 |
|---|---|
| 是否部件 | 未勾选时，不使用部件数量和部件说明 |
| 部件数量 | 勾选“是否部件”后必填 |
| 数量范围 | 2～100，包含 2 和 100 |
| 数量含义 | 部件数量包含主资产本身 |
| 子部件数量 | 部件数量 - 1 |
| 取消“是否部件” | 清空部件数量和部件说明，并禁用相关维护入口 |

例如部件数量为 5，则最终表示 1 个主资产 + 4 个子部件。

### 3.7 SN 规则

资产 SN 支持实际 SN 和“缺省”两种值。

| 类型 | 规则 |
|---|---|
| 实际 SN | 用户人工录入或扫码录入真实 SN，需要进行唯一性校验 |
| 缺省 SN | 系统写入“缺省”，视为已完成维护，不参与真实 SN 唯一性校验 |

相同真实 SN 已被其他资产使用时，不允许保存。

多个资产允许同时使用“缺省”，并可以通过接收确认。

### 3.8 制单人与接收人

接收单区分创建草稿和完成接收两个时间点。

| 字段 | 记录时机 |
|---|---|
| 制单人 | 创建草稿接收单时记录当前操作人 |
| 制单时间 | 创建草稿接收单时记录当前时间 |
| 接收人 | 接收确认成功时记录当前操作人 |
| 接收时间 | 接收确认成功时记录当前时间 |

草稿状态下接收人、接收时间为空。

### 3.9 权限

资产接收权限按照“公司 + 板块”控制。

具体页面可见范围、操作权限和无权限时页面表现暂留待补充。

### 4.3 编辑接收信息

普通资产点击 PO 行【编辑】，打开“接收信息”弹窗。

|---|---|---|---|---|

| 配置 | 多行文本框 | N | Y | 默认带出当前配置；修改后只影响本次接收 |

### 4.4 普通资产创建接收单

普通资产勾选需要接收的 PO 行后点击【创建接收单】。

| 处理 | 规则 |
|---|---|
| 接收单号 | 系统自动生成 REC 接收单号 |
| 接收单状态 | 草稿 |
| 接收行 | 保存当前勾选 PO 行的本次接收数据 |
| 数量占用 | 本次接收数量立即计入对应 PO 行草稿数量 |
| PO 原始数据 | 不修改原 PO 物料、配置等原始数据 |
| 制单信息 | 记录当前操作人为制单人、当前时间为制单时间 |
| 接收信息 | 接收人、接收时间暂为空 |
| 创建成功 | 直接进入新接收单详情 |

| 选择 | 草稿状态展示，用于删除接收行 |
| 行号 | 页面序号 |
| 物料说明 | 本次接收保存的物料 |
| 配置 | 本次接收配置 |
| 部件数量 | 本次部件数量 |
| 部件说明 | 本次部件说明 |
| 本次接收数量 | 当前接收数量 |
| 采购数量 | PO 采购数量 |
| 不含税单价 | 千分位 + 2 位小数 |
| 不含税金额小计 | 本次接收金额 |
| 税额 | 本次税额 |
| 含税单价 | 千分位 + 2 位小数 |
| 含税小计 | 本次含税金额 |
| 税率 | PO 税率 |
| 约定到货日期 | `yyyy-mm-dd` |
| PR 单/行号 | 来源采购 |
| SA 单/行号 | 来源采购 |
| 申请单号 | 来源采购 |
| 部门 | 接收行快照 |
| 业务线 | 接收行快照 |

#### 4.6.3 接收单操作

| 操作 | 草稿 | 已完成 | 规则 |
|---|---|---|---|
| 删除接收行 | Y | N | 草稿状态可删除当前勾选的接收行 |
| 维护接收明细 | Y | 查看 | 草稿可维护；已完成只读查看 |
| 标签打印 | Y | Y | 打印前校验待打印资产已有标签号 |
| 接收单打印 | N | Y | 接收完成后允许打印 |
| 取消接收 | Y | N | 作废当前草稿接收单并释放全部草稿数量 |
| 接收确认 | Y | N | 标签号和 SN 全部维护完成后才能执行 |
| 返回 | Y | Y | 返回上一页 |

“维护接收明细 / 取消接收 / 接收确认 / 返回”为页面级操作，不依赖接收物资行勾选。

“删除接收行”为行级操作，作用于当前勾选的接收行。

### 4.7 删除接收行

草稿状态允许删除已有实际接收数量的接收行。

删除后系统同时执行：

1. 删除当前接收行。
2. 删除该接收行已经生成的资产接收明细。
3. 释放该接收行对应的 PO 草稿数量。
4. 根据释放后的数量重新计算 PO 可接收数量。

删除后如果当前接收单已经不存在任何接收行，则不允许执行接收确认；用户可继续取消该草稿接收单。

### 4.8 取消接收

草稿状态点击【取消接收】后，作废当前草稿接收单。

系统删除：

- 接收单头。
- 接收行。
- 已生成的资产接收明细。

同时释放该接收单占用的全部 PO 草稿数量。

接收单不新增“已取消 / 已作废”状态。

### 4.9 维护接收明细

普通资产点击【维护接收明细】进入资产逐件维护页面。

该操作针对当前接收单的全部接收物资，不依赖某一条接收物资行勾选。

如果当前接收行尚未生成资产明细，系统按照“每接收 1 个数量生成 1 条资产明细”进行拆分。

例如本次接收数量为 5，则生成 5 条资产接收明细，每条初始资产数量为 1。

最后一次完成整条 PO 行接收时，如逐件拆分金额因保留两位小数产生尾差，差额补到最后一条资产明细，保证拆分后的累计金额与采购金额一致。

#### 4.9.1 资产接收明细字段

| 字段名称 | 是否可修改 | 规则 |
|---|---|---|
| 选择 | - | 草稿状态展示 |
| 行号 | N | 页面序号 |
| 资产标签号 | N | 系统生成 |
| SN 号 | Y | 支持录入、扫描或维护为“缺省” |
| 物资总类 | N | 当前物料 |
| 资产大类 | N | 当前物料 |
| 物资说明 | N | 当前接收物料 |
| 配置 | N | 当前接收配置 |
| 部件数量 | N | 当前接收部件数量 |
| 部件说明 | N | 当前接收部件说明 |
| 资产数量 | N | 默认 1 |
| 不含税单价 | N | 当前拆分金额 |
| 税金 | N | 当前拆分税额 |
| PR 单/行号 | N | 来源采购 |
| SA 单/行号 | N | 来源采购 |
| 申请人 | N | 来源采购 |
| 业务线 | N | 来源采购 |
| 资产标记 | Y | 文本 |
| 备注 | Y | 多行文本 |
| 操作 | - | 草稿显示“编辑”；已完成显示“查看” |

#### 4.9.2 草稿状态操作

| 操作 | 规则 |
|---|---|
| 删除行 | 删除当前勾选的资产明细，并同步减少来源接收行数量 |
| 生成标签号 | 对当前所有标签号为空的资产明细生成标签号，已有标签号不覆盖 |
| 维护 SN 号 | 只给当前 SN 为空的资产明细写入“缺省”，已有真实 SN 不覆盖 |
| 打印标签号 | 标签号全部生成后可执行；草稿和已完成状态均允许补打 |
| 扫描维护 | 生成标签号后可使用，按照“标签号 → SN号”两步扫描 |
| 编辑 | 草稿可编辑 SN、资产标记、备注及部件信息；已完成只读查看 |

删除行、生成标签号、维护 SN、扫描写入 SN、明细编辑保存后均实时保存并立即生效。

### 4.10 删除资产明细

草稿状态允许删除资产明细。

删除一条资产明细后：

1. 删除当前资产明细。
2. 对应接收行“本次接收数量”同步减少 1。
3. 对应 PO 行草稿数量同步减少 1。
4. PO 可接收数量同步增加 1。

如果某接收行的本次接收数量减少到 0，则该接收行从当前草稿接收单中移除。

### 4.11 生成资产标签号

点击【生成标签号】后，只处理资产标签号为空的资产明细。

已有资产标签号不得重新生成或覆盖。

标签号按照现有资产标签生成规则，根据物料、公司 / 账套、板块、日期等业务信息生成。

### 4.12 SN 维护

用户可以通过以下方式维护 SN：

| 方式 | 规则 |
|---|---|
| 单条编辑 | 在资产明细中录入真实 SN |
| 扫描 | 先扫描资产标签号，再扫描对应真实 SN |
| 批量维护缺省 | 将当前 SN 为空的资产明细写入“缺省” |

已有真实 SN 不因批量维护“缺省”而被覆盖。

#### 扫描维护

生成标签号之前，扫描光标不可用。

生成标签号后：

1. 第一次扫描内容视为资产标签号，系统在当前接收单内查找对应资产。
2. 找到后定位到该资产，并等待录入 SN。
3. 第二次扫描内容视为该资产的 SN。
4. 系统校验真实 SN 不重复后写入当前资产并立即保存。
5. 保存完成后重新等待扫描下一条资产标签号。

扫描框根据当前阶段展示对应提示，例如“请扫描资产标签号”或“已定位 XXX，请扫描 SN 号”。

### 4.13 部件信息维护

如果当前资产属于套件，在资产明细编辑页面展示部件信息。

| 字段 | 交互方式 | 规则 |
|---|---|---|
| 部件名称 | 输入框 | 每个子部件单独维护 |
| 部件标签号 | 只读 | 根据主资产标签号自动生成 |
| 部件 SN | 输入框 | 可以填写真实 SN 或“缺省” |

子部件标签号按照以下格式生成：

`主资产标签号-1`

`主资产标签号-2`

以此类推。

同一主资产内部，不允许不同子部件使用相同的真实 SN；“缺省”不参与重复校验。

### 4.14 标签打印

草稿、已完成状态均允许标签打印。

点击标签打印前，系统校验当前待打印资产是否全部已有资产标签号。

存在未生成标签号的资产时，不进入打印流程，并提示：

> 有未维护的标签号，请先维护接收明细。

校验通过后，按照当前接收单生成或取得标签打印批次。

存在子部件时，同时生成对应子部件标签。

### 4.15 普通资产接收确认

草稿状态点击【接收确认】后，系统校验当前接收单全部资产接收明细。

只有全部资产同时满足以下条件时才允许确认：

- 资产标签号不为空。
- SN 不为空。
- 所有非“缺省”的真实 SN 均通过唯一性校验。

“缺省”视为已完成 SN 维护。

接收确认成功后：

| 数据对象 | 处理结果 |
|---|---|
| 接收单 | 状态由“草稿”更新为“已完成” |
| 接收人 / 接收时间 | 记录当前操作人和当前时间 |
| 接收行 | 固化为本次接收业务快照 |
| 资产接收明细 | 固化，不再允许修改 |
| PO 草稿数量 | 扣减本次草稿占用数量 |
| PO 已接收数量 | 增加本次接收数量 |
| PO 状态 | 根据整张 PO 累计接收数量重新判断“待接收 / 已接收” |
| 入库单 | 自动生成一张“采购接收”类型的草稿入库单 |
| 后续数据 | 板块、申请批次、资产标签号、SN 等接收结果传递到入库单及入库物资明细 |

接收确认只表示资产接收完成，不代表资产已经正式入库。

### 4.16 机房资产接收

适用采购类型：

- 服务器。
- 服务器备件。
- 网络设备。
- 网络设备备件。

以上资产不走普通资产“创建接收单 → 手工维护标签号 / SN”的流程，接收数据主要来自 NO/MIS。

#### 4.16.1 页面操作

用户在 PO 物资明细中勾选需要接收的行后点击【接收确认】。

不再使用“执行入库”名称。

该按钮表示完成资产接收并创建后续入库草稿，不代表正式资产已经完成入库。

#### 4.16.2 接收前校验

系统必须在写入任何接收业务数据前完成全部校验。

| 校验项 | 规则 |
|---|---|
| 板块 | 必须已选择 |
| PO 行 | 至少选择 1 行 |
| NO/MIS 数据 | 所选资产必须存在可用接收数据 |
| NO 位置 | 必须存在 |
| 地址映射 | NO 位置必须能够匹配有效位置配置 |
| City | 必须存在 |
| Building | 必须存在 |
| Floor | 必须存在 |
| 重复接收 | 当前 NO/MIS 数据不得已经存在有效接收记录 |

任意一项失败时：

- 不创建接收单。
- 不创建资产接收明细。
- 不创建入库草稿单。
- 不修改 NO/MIS 接收状态。

用户修正问题后可以重新执行接收确认。

#### 4.16.3 接收成功

全部校验通过后，系统一次性完成以下处理：

| 数据对象 | 处理结果 |
|---|---|
| 接收单 | 创建并直接设置为“已完成” |
| 接收行 | 根据本次勾选 PO 行和 NO/MIS 数据创建 |
| 资产接收明细 | 根据 NO/MIS 数据创建 |
| 资产标签号 | 按 NO/MIS 数据及现有标签规则取得 |
| SN | 来源 NO/MIS |
| 责任人 | 来源 NO/MIS 及相关人员映射 |
| City / Building / Floor | 根据 NO 位置映射取得 |
| NO/MIS 数据 | 标记为已完成接收 |
| PO 已接收数量 | 增加本次实际接收数量 |
| PO 状态 | 部分接收保持“待接收”；全部接收后更新为“已接收” |
| 入库单 | 自动创建“采购接收”类型的草稿入库单 |

上述处理属于一个完整业务动作，只允许全部成功或全部失败。

不得出现接收单已经完成但入库草稿单未生成的半完成状态。

#### 4.16.4 防重复处理

同一条 NO/MIS 资产数据一旦已经生成有效接收记录，不允许再次执行接收。

重复操作时不产生新业务数据，并提示：

> 所选资产已完成接收，请刷新后重试。

## 5. 校验规则

本章节汇总会阻断用户操作的关键校验。字段本身的普通必填、展示和只读规则以对应页面字段表为准。

| 操作 | 校验规则 | 校验失败处理 |
|---|---|---|
| 编辑接收数量 | 必须为正整数 | 不保存本次编辑，保留弹窗 |
| 编辑接收数量 | 不得大于当前可接收数量 | 不保存，提示“接收数量不能超过可接收数量” |
| 维护部件数量 | 是否部件=是时必须填写 | 不允许保存 |
| 维护部件数量 | 仅允许 2～100 | 不允许保存 |
| 创建普通接收单 | 至少选择一条 PO 行 | 不创建接收单，提示“请选择要接收的物料！” |
| 创建普通接收单 | 板块必填 | 不创建接收单，提示“请选择板块！” |
| 删除接收行 | 仅草稿状态允许 | 已完成状态不展示删除入口 |
| 保存真实 SN | 与其他资产真实 SN 重复 | 不保存当前 SN，提示“SN号：XXX已存在！” |
| 保存部件 SN | 同一主资产内真实部件 SN 重复 | 不保存，提示“存在重复的部件序列号！” |
| 接收确认 | 接收单必须至少存在一条有效接收行 | 不执行接收确认 |
| 接收确认 | 所有资产均存在资产标签号 | 不执行，接收单保持草稿 |
| 接收确认 | 所有资产均存在 SN | 不执行，接收单保持草稿 |
| 接收确认 | 所有真实 SN 均不重复 | 不执行，接收单保持草稿 |
| 标签打印 | 所有待打印资产均存在标签号 | 不进入打印流程 |
| 机房资产接收确认 | 板块、PO 行、NO/MIS 数据、地址映射全部有效 | 本次业务数据全部不写入 |
| 机房资产接收确认 | 不得重复接收 | 不创建重复数据 |

普通资产接收确认失败时：

- 接收单继续保持草稿。
- 已经维护的有效数据保留。
- 用户修正问题后重新点击【接收确认】。

## 6. 后续操作及补充说明

### 6.1 普通资产接收完成后的处理

普通资产完成接收以后，只代表实物接收以及接收数据维护已经完成，此时尚未正式创建资产卡片。

接收确认成功后，系统自动生成一张“采购接收”类型的草稿入库单。

用户后续进入“库存管理 → 入库”检查入库数据并执行正式入库。

正式入库成功后才创建正式资产卡片。

业务边界固定为：

- 资产接收解决“实际收到了什么”。
- 资产入库解决“资产正式进入哪个仓库，并以什么资产信息建卡”。

### 6.2 机房资产接收完成后的处理

机房资产接收确认成功后，接收单直接完成，同时自动生成“采购接收”类型的草稿入库单。

此时仍然只是“接收已完成、入库待执行”。

用户需要进入入库模块检查入库数据并执行正式入库，正式执行入库成功后才生成资产卡片。

### 6.3 已完成接收单

接收单进入“已完成”后：

| 数据 | 规则 |
|---|---|
| 接收单头 | 只读 |
| 接收行 | 只读 |
| 资产标签号 | 不可修改 |
| SN | 不可修改 |
| 资产标记 | 不可修改 |
| 备注 | 不可修改 |
| 部件数据 | 不可修改 |
| 接收明细 | 允许只读查看 |
| 标签打印 | 允许补打 |
| 接收单打印 | 允许 |
| 后续入库 | 作为采购接收入库数据来源 |

### 6.4 本版暂不展开

权限按照“公司 + 板块”控制，但具体权限矩阵暂不在本版定义，由后续补充。
