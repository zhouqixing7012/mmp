# 库存管理 - 资产接收 PRD

## 1. 背景

资产接收用于处理采购资产实际到货后的接收业务。

用户根据采购 PO 查看待接收物资，维护本次实际接收数量，并根据实际到货资产维护资产标签号、SN、部件等信息。接收完成后，系统生成后续采购接收入库草稿单，用户再进入入库模块执行正式入库。

“资产接收”仅处理以下两类资产：

| 资产类型 | 接收方式 |
|---|---|
| 普通资产 | PO → 创建接收单 → 维护资产标签号、SN → 接收确认 → 接收完成 → **按资产大类拆分生成采购接收入库草稿单** |
| 服务器、服务器备件、网络设备、网络设备备件 | PO → 获取 NO/MIS 数据 → 接收确认 → 直接完成接收 → 按 NO 位置自动生成采购接收入库草稿单 |

低值耐用品、普通耗材不在本模块处理，由“耗材接收”独立处理。

本版重点统一 PO、PO 行、接收单之间的数据冻结边界：**首次形成有效接收单即视为接收侧业务数据冻结点，草稿接收单同样参与冻结判断。**

## 2. 改造总结

| 改造项 | 改造后规则 |
|---|---|
| 业务范围 | 仅处理普通资产以及服务器、服务器备件、网络设备、网络设备备件；耗材由“耗材接收”独立处理 |
| 接收单状态 | 草稿 / 已完成 |
| 普通资产流程 | 创建接收单后进入草稿；维护资产标签号和 SN 后点击【接收确认】，接收单变为已完成并**按资产大类拆分生成采购接收入库草稿单** |
| 分批接收 | 支持；草稿接收单中的数量立即计入草稿占用 |
| 数据冻结点 | **只要 PO 已存在任意有效接收单，包括草稿，板块和申请批次立即固化为只读** |
| PO 行冻结 | **某采购行只要已被任意接收单引用，包括草稿，该行【编辑】入口即关闭；即使仍有剩余可接收数量，也只能继续接收，不允许再修改该 PO 行接收基础数据** |
| 冻结释放 | 删除 / 取消草稿接收业务后重新按“是否仍存在接收单引用”判断；PO 不再存在任何接收单时，板块和申请批次重新可编辑；某行不再被任何接收单引用时，该行重新可编辑 |
| 物料、配置修改 | 仅在该 PO 行尚未被任何接收单引用时允许修改；接收单形成后固化 |
| 板块、申请批次 | 无接收单时可维护；首次形成接收单后固化，并作为该 PO 后续接收统一值 |
| 删除接收行 | 草稿状态允许删除；删除后释放对应草稿数量，并重新计算该行冻结状态 |
| 删除 / 取消草稿接收单 | 删除当前草稿业务数据并释放草稿数量；完成后重新计算 PO 级和 PO 行级冻结状态 |
| 部件数量 | 2～100，包含主资产本身；子部件数量 = 部件数量 - 1 |
| SN“缺省” | 合法 SN；视为已维护，不参与真实 SN 唯一性校验 |
| 标签打印 | 草稿和已完成均允许打印标签；正式接收单打印仅已完成允许 |
| 机房资产数量 | 由 NO/MIS 数据决定，不允许人工修改 |
| 机房资产操作 | 统一使用【接收确认】，不使用“执行入库” |
| 电子设备入库草稿拆单 | 接收确认成功后按资产大类拆单；同一接收单内同一资产大类进入同一张采购接收入库草稿单，不同资产大类分别生成不同草稿单；资产大类为空时阻断生成 |
| 机房资产接收结果 | 校验通过后直接生成已完成接收单，并按 NO 位置拆分生成采购接收入库草稿单 |
| 权限 | 公司/板块控制数据范围，仓库权限控制业务操作 |

## 3. 业务流程

### 3.1 普通资产

1. 用户进入 PO 接收页面，系统根据剩余可接收数量计算“本次接收数量”。
2. 对尚未被任何接收单引用的 PO 行，用户可编辑物料、配置、接收数量和部件信息；已被任意接收单引用的 PO 行不再提供编辑能力。
3. 当整张 PO 尚无任何接收单时，用户可维护板块、申请批次。
4. 用户勾选一个或多个可接收 PO 行，点击【创建接收单】。
5. 系统生成草稿接收单并立即占用对应 PO 草稿数量。
6. 草稿创建成功后：
   - 当前 PO 的板块、申请批次立即固化为只读；
   - 本次接收单引用的 PO 行立即冻结编辑能力；
   - 仍有剩余可接收数量的冻结行仍可继续被后续接收单选择，但不可再修改物料、配置、接收侧基础信息。
7. 用户进入接收单详情，通过【维护接收明细】逐件维护资产标签号、SN、部件信息。
8. 全部标签号和 SN 满足规则后点击【接收确认】。
9. 系统将接收单更新为已完成，将草稿数量转为已接收数量，并按资产大类拆分生成“采购接收”草稿入库单：同一资产大类合并进入同一张草稿单，不同资产大类分别生成不同草稿单。
10. 用户后续进入“库存管理 → 入库”执行正式入库。

### 3.2 机房资产

适用采购类型：服务器、服务器备件、网络设备、网络设备备件。

1. 用户进入 PO 接收页面，系统根据 NO/MIS 推送数据取得可接收数量。
2. 对尚未形成接收记录的 PO 行，可维护允许修改的接收侧基础信息；接收数量始终只读。
3. 用户勾选 PO 行，点击【接收确认】。
4. 系统完成板块、PO 行、NO/MIS 数据、NO 位置、地址映射、City、Building、Floor、重复接收等前置校验。
5. 校验全部通过后，系统直接生成已完成接收单和资产接收明细。
6. 接收单生成后立即触发与普通资产相同的 PO / PO 行冻结规则。
7. 系统按 NO 位置拆分采购接收入库草稿单。
8. 用户后续进入“库存管理 → 入库”执行正式入库。

## 4. 通用规则

### 4.1 状态规则

资产接收同时存在 PO 状态、PO 行状态、接收单状态，三类状态独立判断。

#### 4.1.1 PO 状态

| 状态 | 说明 |
|---|---|
| 待接收 | 任一采购行仍存在未完成接收数量 |
| 已接收 | 所有采购行均已完成接收，等待正式入库 |
| 已入库 | 对应资产全部完成正式入库 |

- 任一 PO 行仍存在未接收数量时，整张 PO 保持“待接收”。
- 所有 PO 行累计已接收数量达到采购数量后，更新为“已接收”。
- 全部正式入库后更新为“已入库”。
- 部分接收不能提前将整张 PO 更新为“已接收”。

#### 4.1.2 PO 行状态

| 状态 | 判断规则 |
|---|---|
| 待接收 | 仍存在剩余未接收数量 |
| 已接收 | 采购数量全部完成接收但尚未全部入库 |
| 已入库 | 对应资产全部正式入库 |

**PO 行状态与是否可编辑是两个维度。** 一条 PO 行可以仍为“待接收”，但只要已经被任意接收单引用，就必须冻结编辑。

#### 4.1.3 接收单状态

| 状态 | 说明 | 接收单内数据是否可维护 |
|---|---|---|
| 草稿 | 接收单已创建，标签号、SN 等接收数据仍可维护 | Y |
| 已完成 | 已执行接收确认 | N |

普通资产固定按 `草稿 → 已完成` 流转。

### 4.2 可接收数量

普通资产支持分批接收：

`可接收数量 = 采购数量 - 已接收数量 - 草稿数量`

- 已接收数量：已经完成接收确认的数量。
- 草稿数量：被有效草稿接收单占用但尚未完成确认的数量。
- 创建草稿接收单后，本次接收数量立即计入草稿数量。
- 接收确认成功后，本次数量从草稿数量转入已接收数量。

以下操作需要释放对应草稿数量：

| 操作 | 数量处理 |
|---|---|
| 删除接收行 | 释放该行对应草稿数量 |
| 删除资产逐件明细 | 来源接收行数量同步减少，并释放相同草稿数量 |
| 取消接收 | 释放整张草稿接收单占用数量 |
| 删除草稿接收单 | 释放整张草稿接收单占用数量 |

数量释放和“是否允许编辑”分别计算。释放数量后，只有在该 PO 行已经不再被任何接收单引用时，才恢复编辑。

机房资产可接收数量由 NO/MIS 推送数据决定，不允许人工修改。

### 4.3 接收快照与冻结规则

接收单保存本次实际接收时的数据快照。

首次形成有效接收单是接收侧数据冻结点，**草稿接收单即视为有效接收单**。

#### PO 级冻结

只要当前 PO 存在至少一张草稿或已完成接收单：

- 板块只读；
- 申请批次只读；
- 新建后续接收单继续沿用已固化的板块、申请批次；
- 不允许通过重新进入页面、切换列表或其他入口绕过冻结。

仅当删除 / 取消草稿后，当前 PO 已不存在任何接收单时，板块和申请批次才重新可编辑。

已完成接收单不可删除，因此只要 PO 已存在已完成接收单，板块和申请批次保持永久冻结。

#### PO 行级冻结

某 PO 行只要被至少一张草稿或已完成接收单引用：

- 该行不展示【编辑】；
- 禁止修改物料、配置、本次接收数量、是否部件、部件数量、部件说明等接收侧基础数据；
- 即使当前行仍有剩余可接收数量，后续只允许继续接收，不允许修改该行接收基础数据。

删除草稿接收行、草稿接收单或取消接收后，如果该 PO 行已经不再被其他接收单引用，则该行恢复编辑；如果仍有其他接收单引用，则继续冻结。

### 4.4 物料、配置及接收信息修改规则

只有“尚未被任何接收单引用”的 PO 行允许打开【编辑接收信息】。

可维护字段：

- 物料；
- 配置；
- 本次接收数量；
- 是否部件；
- 部件数量；
- 部件说明。

保存修改只更新资产接收侧数据，不反写采购系统原始 PO。

一旦该行进入任意接收单，即立即固化，不再存在“修改后影响后续未完成接收数据”的逻辑。

### 4.5 板块和申请批次

- 板块：必填。
- 申请批次：选填。
- 当前 PO 尚无接收单时允许修改。
- 修改结果作为该 PO 首次创建接收单时的业务值。
- 首次形成接收单后立即固化为只读，后续分批接收统一沿用。
- 接收单和后续入库单均使用固化后的值。
- 删除 / 取消全部草稿且当前 PO 不存在任何接收单后，字段重新可编辑。

### 4.6 部件规则

普通资产支持按套件维护部件：

| 规则 | 说明 |
|---|---|
| 是否部件 | 是 / 否 |
| 部件数量 | 是否部件=是时必填 |
| 数量范围 | 2～100 |
| 数量含义 | 包含主资产本身 |
| 子部件数量 | 部件数量 - 1 |
| 子部件默认名称 | 部件1、部件2……，允许修改 |
| 取消是否部件 | 清空部件数量、部件说明并禁用维护入口 |

### 4.7 SN 规则

| 类型 | 规则 |
|---|---|
| 真实 SN | 需要唯一性校验 |
| 缺省 | 合法；视为已维护；不参与真实 SN 唯一性校验 |

- 同一接收单内部真实 SN 不得重复。
- 与其他资产已存在的真实 SN 不得重复。
- 多条资产允许同时使用“缺省”。

### 4.8 制单人与接收人

| 字段 | 取值时点 |
|---|---|
| 制单人 | 创建草稿接收单时当前操作人 |
| 制单时间 | 草稿创建成功时间 |
| 接收人 | 接收确认成功时当前操作人 |
| 接收时间 | 接收确认成功时间 |

草稿状态接收人、接收时间为空。

### 4.9 权限

权限采用“公司/板块数据范围 + 仓库操作权限”两层控制：

1. 公司、板块决定用户可查看和查询的 PO、采购行及接收单范围；
2. 业务匹配的目标仓库权限决定用户能否创建接收单、编辑接收信息、删除草稿、维护明细、执行接收确认和打印；
3. 页面展示数据、打开详情和提交操作时均重新校验权限；
4. 用户无数据范围时不返回对应记录，无仓库操作权限时只允许查看已有数据。

### 5.3 编辑接收信息

只有尚未被任何接收单引用的 PO 行允许进入。

| 字段 | 交互 | 规则 |

| 物料 | 弹窗选择 | 可重新选择可用物料 |
| 配置 | 输入框 | 可修改 |
| 接收数量 | 普通资产数字输入 / 机房资产只读 | 普通资产正整数且不超过当前可接收数量 |
| 是否部件 | 下拉 | 是 / 否 |
| 部件数量 | 数字输入 | 是否部件=是时 2～100 |
| 部件说明 | 汇总 + 维护 | 子部件行数 = 部件数量 - 1 |

保存前再次校验当前行是否已经被接收单引用。若用户打开弹窗后其他操作已形成接收单，则本次保存必须被阻断，提示：

> 该采购行已存在接收单，不可再编辑

普通资产接收数量超出可接收数量时不保存并提示；部件数量不合法时提示 `请输入 2～100 之间的整数！`。

保存成功提示：`接收信息已保存`。

### 5.4 普通资产创建接收单

前置校验：

| 场景 | 提示 |
|---|---|
| 未选择采购行 | 请选择要接收的物料！ |
| 板块为空 | 请选择板块！ |
| 所选行无可接收数量 | 所选物资当前没有可接收数量 |

创建成功后：

- 生成 REC 接收单号；
- 状态为草稿；
- 保存当前接收行快照；
- 本次接收数量立即计入草稿数量；
- 当前 PO 板块、申请批次立即冻结；
- 当前接收单引用的 PO 行立即冻结编辑；
- 制单人、制单时间写入；
- 接收人、接收时间为空；
- 进入接收单详情。

### 5.5 接收单列表

查询条件：接收单号、PO 单号、单据状态、制单人、制单时间范围、供应商。

列表字段：选择、行号、接收单号、单据状态、PO 单号、供应商、制单人、制单时间。

- 草稿接收单允许勾选删除；已完成复选框禁用。
- 接收单号作为详情入口，不再保留重复操作列。
- 默认按制单时间倒序。
- 行号按当前排序及分页连续顺排。
- 默认每页 10 条，支持切换每页条数；查询 / 重置后回到第 1 页。

从 PO 进入接收单列表时自动带入 PO 单号并查询；【重置】清空全部查询条件。

#### 删除草稿接收单

删除后同时：

1. 删除接收单头、接收行及已生成的资产接收明细；
2. 释放对应 PO 草稿占用数量；
3. 重新计算 PO 可接收数量；
4. 重新计算 PO 级冻结：若当前 PO 已无任何接收单，板块、申请批次恢复可编辑；
5. 重新计算被删除接收单引用的 PO 行冻结：若某行已无其他接收单引用，则恢复编辑，否则继续冻结。

已完成接收单不可删除。

### 5.6 接收单详情

基础信息只读展示：接收单号、PO 单号、PO 单说明、供应商、联系人、供应商联系电话、采购单位、采购员、采购员联系电话、合同主体、板块、接收人、接收时间、接收单状态、申请批次。接收单详情不展示制单人、制单时间。

接收物资明细展示：行号、资产说明、配置、部件数量、部件说明、本次接收数量、采购数量、金额税额、约定到货日期、PR 单/行号、SA 单/行号、申请单号、部门、业务线。
接收单详情中的行号按当前接收单明细从 1 开始顺排，不使用 PO 物资行 ID 作为展示行号。

草稿状态支持删除接收行、维护接收明细、取消接收、接收确认；已完成状态只读查看并支持接收单打印。

### 5.7 删除接收行

草稿状态允许删除接收行。

删除后：

1. 删除当前接收行；
2. 删除该接收行已生成的资产逐件明细；
3. 释放对应 PO 草稿数量；
4. 重新计算 PO 可接收数量；
5. 重新判断当前 PO 行是否仍被其他接收单引用；若无引用则恢复编辑。

如果接收单已经无接收行，则不得接收确认，用户可继续取消该草稿。

### 5.8 取消接收

仅草稿允许取消。

确认后删除接收单头、接收行和已生成明细，并释放整单草稿数量。完成后重新计算 PO 级和 PO 行级冻结状态。

如果取消后该 PO 已不存在任何接收单，板块和申请批次恢复可编辑；如果仍有其他接收单则继续只读。

接收单不新增“已取消 / 已作废”状态。

### 5.9 维护 / 查看接收明细

普通资产按照“每接收 1 个数量生成 1 条资产逐件明细”。

页面只读展示接收单信息：接收单号、接收人、接收时间、PO 单号、供应商、供应商联系电话、PO 单说明、采购单位、采购员联系电话、板块、部门、采购员、合同主体、订单日期、接收单状态、申请批次。维护 / 查看接收明细页不展示制单人、制单时间。

草稿下接收人、接收时间为空。

逐件明细字段：选择、行号、资产标签号、SN、物资总类、资产大类、资产说明、配置、部件数量、部件说明、资产数量、不含税单价、税金、PR 单/行号、SA 单/行号、申请人、业务线、资产标记、备注、操作。

操作：删除行、生成标签号、维护 SN 号、打印标签号、编辑 / 查看。

- 生成标签号仅处理空白标签号。
- 维护 SN 号仅对空白 SN 写入“缺省”。
- 标签、SN 状态变化后按钮实时按当前数据重新判断。
- 草稿允许编辑；已完成只读查看。
- 扫描采用“先标签号、后 SN”两步方式。
- 扫描光标与扫描核对信息放在同一个 Card；核对区固定展示“资产标签号、SN号、资产说明、配置”。
- 未扫描标签号时核对字段保持空白；标签号命中后，系统将该资产对应字段值带入核对区，并将扫描光标切换为等待 SN。
- **扫描只影响顶部核对区，不改变下方接收资产明细的数据集；标签号命中后下方明细仍保持全量展示，不再临时筛选成单行。**
- SN 扫描成功后继续执行真实 SN 唯一性校验并实时保存；扫描流程恢复等待下一条资产标签号。
- 【重置】清空扫描输入、当前定位 / 核对信息及勾选状态，下方明细保持全量展示。
- 扫描 Card 仅在草稿接收单的【维护接收明细】页面展示；已完成接收单进入【查看接收明细】时不展示扫描 Card，仅保留只读接收明细。
- 删除逐件明细同步减少来源接收行数量并释放 PO 草稿数量；如整条来源接收行被删除，再按行级引用关系判断是否解锁该 PO 行。

### 5.10 标签与 SN

#### 标签号

- 标签号为空时允许生成；已有标签不得覆盖。
- 子部件标签号规则：`主资产标签号-N`。
- 所有标签生成后允许打印标签。

#### SN

- 支持单条编辑、扫码录入、批量维护“缺省”。
- 已有真实 SN 不因批量维护缺省而覆盖。
- 真实 SN 重复时阻断保存 / 确认。

### 5.11 单条资产明细编辑

草稿允许修改 SN、资产标记、备注、部件名称、部件 SN；资产标签号、资产说明等只读。

部件组合保存格式：

`部件名称#部件标签号#部件SN@部件名称#部件标签号#部件SN……`

总长度不得超过 500 字符。

已完成接收单只读查看。

### 5.12 普通资产接收确认

接收确认前要求：

- 至少存在一条有效资产逐件明细；
- 所有资产标签号不为空；
- 所有 SN 不为空；
- 所有非“缺省”的真实 SN 唯一。

成功后：

- 接收单变为已完成；
- 写入接收人、接收时间；
- 草稿数量转已接收数量；
- 接收快照固化；
- 按资产大类拆分生成采购接收入库草稿单；同一资产大类进入同一张草稿单，不同资产大类分别生成不同草稿单；
- PO 行、PO 状态按累计数量重新计算；
- **PO / PO 行冻结继续保持，因为已完成接收单仍属于有效引用。**

### 5.13 机房资产接收

适用服务器、服务器备件、网络设备、网络设备备件。

接收数量由 NO/MIS 决定，不允许人工修改。

前置校验至少包括：板块、PO 行、NO/MIS 数据、NO 位置、地址映射、City、Building、Floor、重复接收。

任一校验失败时，不创建接收单、不创建接收明细、不创建入库草稿、不修改 NO/MIS 接收状态。

全部通过后：

- 直接创建已完成接收单；
- 写入制单人 / 时间、接收人 / 时间；
- 根据 NO/MIS 生成资产接收明细；
- 责任人、位置、成本中心按既有映射处理；
- 按 NO 位置拆分采购接收入库草稿单；
- PO / PO 行按累计接收量更新；
- 固化 PO 板块、申请批次以及本次引用的 PO 行编辑能力。

启用日期：当前日期小于每月 26 日取当前日期；大于等于 26 日取下月 1 日。

## 6. 校验与异常处理

| 场景 | 校验 / 处理 |
|---|---|
| 创建接收单 | 至少选择一条可接收 PO 行 |
| 创建 / 确认 | 板块必填 |
| 编辑 PO 行 | 若该行已被任意接收单引用，阻断并提示“该采购行已存在接收单，不可再编辑” |
| 编辑板块 / 申请批次 | 若当前 PO 已存在任意接收单，禁止修改 |
| 接收数量 | 普通资产必须为正整数且不超过可接收数量 |
| 部件数量 | 是否部件=是时为 2～100 整数 |
| 进入维护接收明细 | 必须存在接收行且各行接收数量大于 0 |
| 保存真实 SN | 不得与其他真实 SN 重复 |
| 扫描标签号 | 必须在当前接收单找到匹配标签；命中后仅刷新顶部核对区，不筛选下方明细 |
| 保存部件组合 | 总长度 ≤ 500 |
| 接收确认 | 标签号、SN 全部维护完成且真实 SN 唯一；电子设备逐件明细必须存在资产大类，否则阻断生成采购接收入库草稿单 |
| 标签打印 | 待打印资产必须已有标签号 |
| 机房资产接收 | NO/MIS、NO 位置、地址映射等全部有效 |
| 重复接收 | 不允许重复产生接收数据 |

普通资产接收确认失败时接收单继续保持草稿，已维护有效数据保留。

## 7. 后续操作及补充说明

### 7.1 接收与入库边界

资产接收解决“实际收到了什么”；资产入库解决“资产正式进入哪个仓库，并以什么资产信息建卡”。

电子设备普通资产接收完成后，系统以接收逐件明细中的资产大类为拆单键生成一张或多张采购接收入库草稿单；同一资产大类不得被拆成多张，不同资产大类不得混入同一张。正式入库成功后才创建资产卡片。

机房资产接收完成后按 NO 位置生成一张或多张采购接收入库草稿单；正式入库后创建资产卡片。

### 7.2 已完成接收单

已完成后接收单头、接收行、资产标签号、SN、资产标记、备注、部件数据均不可修改；允许只读查看、标签补打、接收单打印，并作为后续采购接收入库数据来源。

已完成接收单继续参与 PO 级和 PO 行级冻结，不因“接收已完成”而解除冻结。

### 7.3 冻结释放边界

冻结只能通过删除 / 取消尚未完成的草稿业务数据释放：

- PO 级：当前 PO 已无任何接收单 → 板块、申请批次恢复可编辑；
- PO 行级：当前 PO 行已无任何接收单引用 → 该行恢复编辑；
- 只释放数量但仍保留接收单引用时，不解除冻结；
- 已完成接收记录不可删除，因此其对应冻结持续有效。

## 8. 物资接收单打印

### 8.1 打印入口

- 仅“已完成”接收单展示【接收单打印】；草稿不打印正式接收单。
- 标签打印与接收单打印互相独立。
- 打印只读取已保存快照，不修改接收数量、PO 状态、入库草稿或库存结果。
- 打印失败允许重试，不生成新的接收单号，不重复执行接收确认。

### 8.2 标题与版式

标题固定为“物资接收单”。纸张、联次、签字区域沿用现有打印模板；明细跨页重复表头并显示页码。

### 8.3 表头字段

供应商、采购单位、采购订单编号、接收单号、供应商联系人、供应商电话、采购员、采购员电话、接收日期、接收地点、PO 说明。

接收地点沿用现有打印数据来源；无值留空，不根据仓库或资产位置猜补。

### 8.4 明细字段

序号、PR 单/行号、SA 单/行号、资产说明（品牌、型号、配置）、接收数量、单价、小计、业务线、申请人、备注。

序号从 1 开始；金额保留两位小数；底部展示数量及金额合计。

### 8.5 签字区域

保留：

- 供应商（签字）/ 时间；
- 接收方（签字）/ 时间。

打印功能仅预留签字位置，不因打印动作自动写入他人签名。
