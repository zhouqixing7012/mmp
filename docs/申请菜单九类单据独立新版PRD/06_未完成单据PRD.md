# 未完成单据 PRD

编写日期：2026年10月14日。版本：申请菜单可达页面的现状规则；范围修订于2026年10月15日。

## 1 背景

当前处理中且具有有效待办节点的单据查询和导出。列表展示每张单据选出的一条待办记录。

本篇用于确认现有页面的字段取值、查询条件和交互结果，供产品与研发核对。未确认事项集中放在第6章，不作为正式规则。

## 2 权限

具有菜单权限的用户可查询；当前查询未再附加申请人为当前用户的条件。查询结果只保留处理中单据及符合待办规则的一个节点。

菜单授权来自当前社区及角色配置；管理员菜单查询绕过角色菜单授权，业务办理权限仍以对应页面和节点校验为准。源码未包含运行中的菜单授权数据，不能据页面文件列出实际获权人员名单。

## 3 通用规则

3.1 只返回单据状态为处理中3的记录。待办先排除非待办以及审批人账号以-1结尾的记录，按单据分组、流程序号长度及序号倒序选第一条，再排除等待节点。

3.2 一个单据有多名待办人时只展示选出的一人；同流程序号相同的记录没有第三排序键，不能承诺固定展示哪一人。若选出的第一条为等待节点，单据被排除，并不继续找第二条。

3.3 默认固定按申请头创建时间倒序；当前调用未使用页面提交的列头排序字段。用户记录缺失或用户状态为空按离职展示；这不代表有独立HR离职时间判断。

3.4 查询选填条件为空时不增加过滤；多项条件组合为同时满足。编码、账号和日期用于匹配，显示名称用于阅读。日期从／至在本篇合为一个范围条件。页面存在重置或清空查询条件入口时，统一按“重置”描述；不据此新增原页面未提供的业务动作。

## 4 页面字段及交互

### 4.1 查询条件

进入方式：申请→未完成单据。

| 字段 | 展示及交互 | 来源和取值逻辑 |
| --- | --- | --- |
| 单据类型 | 下拉框，选填 | 选项来自当前处理中单据已有的类型，并读取单据类型字典名称；选中后精确匹配申请头类型。 |
| 单据编号 | 文本框，选填 | 去除首尾空格后，申请单号包含匹配。 |
| 申请人 | 人员单选，选填 | 精确匹配申请头申请人账号。 |
| 公司 | 公司单选，选填 | 精确匹配申请头财务公司编码。 |
| 板块 | 板块单选，选填 | 精确匹配申请头财务板块编码。 |
| 部门 | 部门单选，选填 | 精确匹配申请头部门编码。 |
| 申请时间 | 日期范围，选填 | 将申请头创建时间转为日期后比较，包含开始及结束日期；只选择一端时执行单边过滤。 |
| 是否离职 | 下拉框，选填 | 是对应用户状态N，否对应Y；用户资料缺失或用户状态为空时按N处理，显示为已离职。 |

| 字段 | 展示及交互 | 来源和取值逻辑 |

| 单据编号 | 只读展示。 | 取申请头编号。 |
| 单据类型 | 只读展示。 | 取申请头类型编码对应的单据类型字典名称。 |
| 业务类型 | 只读展示。 | 按申请头单据类型与业务类型组合，查询业务类型字典名称。 |
| 单据状态 | 只读展示。 | 取申请头状态对应名称，数据范围固定为处理中3。 |
| 审批环节 | 只读展示。 | 取选出的最新待办记录节点名称。 |
| 审批人 | 只读展示。 | 选出的待办审批人账号-当前用户姓名。 |
| 申请人 | 只读展示。 | 申请头申请人账号-当前用户姓名。 |
| 申请时间 | 只读展示；日期格式yyyy-MM-dd。 | 申请头创建时间，显示yyyy-MM-dd。 |
| 公司 | 只读展示。 | 申请头财务公司编码关联当前公司描述。 |
| 板块 | 只读展示。 | 申请头财务板块编码关联当前板块描述。 |

### 4.3 查看进度弹窗字段及交互

进入方式：申请→未完成单据→列表“查看流程”。单据类型为REC、ED时不显示入口；领用或采购记录按统一申领领用流程类型查看，其他记录使用本行保存的流程类型。

弹窗标题为“审批信息”，宽800、高550。内容按流程图、审批记录和适用的外部系统记录纵向展示，不使用页签；没有查询条件。弹窗只读，通过外层关闭控件退出，原列表及业务状态不变。

| 字段 | 展示及交互 | 来源和取值逻辑 |
| --- | --- | --- |
| 审批环节 | 只读 | 当前审批记录保存的节点名称。 |
| 审批人 | 只读 | 当前记录保存的审批人工号，拼接“-”及人员基础资料中的当前姓名；不是列表中选出的那一位审批人。工号为空则不拼接；有工号但查不到姓名时，当前代码可能显示工号-null。 |
| 审批状态 | 只读 | 直接显示当前记录保存的审批状态描述，不由页面重新按编码翻译，也不统一改成“审批中”。 |
| 审批时间 | 只读，yyyy-MM-dd | 当前记录保存的审批时间，精确到日；为空时留空。 |
| 审批意见 | 只读，文字自动折行 | 当前记录保存的审批意见；没有意见时留空，不自动填充同意等文案。 |

每张单据的基础审批记录先按流程序号长度、流程序号、审批时间依次升序排列，再对非空流程序号去重，每个序号只保留排序后的第一条；空序号记录不展示。相同排序值没有额外的唯一排序条件。

不同流程序号的多节点、多名审批人逐行显示；相同序号即使有多人也只保留一条，不能按“展示全部并行审批人”理解。此弹窗没有额外剔除跳过、等待节点；是否显示待审批记录取决于已取得的数据，不补齐尚未生成的未来节点。

流程结束后仍显示已取得的记录及其原状态，不清空历史审批人，不统一替换为“流程已结束”。本表没有代理人列，也没有单独的当前节点字段、审批意见输入框、同意或驳回按钮；不提供分页、导出和保存入口。

传入业务号为统一申领子单时，先反查原申请编号及申请行。

统一申领的记录按“原申请→关联领用或采购子单→汇总单”依次拼接。关联子单、汇总单按申请行查找，取各自创建时间最新的匹配单据；一般汇总单只取处理中，原申请行为删除或追加标识时不限此状态。子单记录先去掉第一条再追加；各段分别排序、去重后拼接，不再按审批时间全局重排。

已有汇总记录且其第二条属于指定ES汇总审批节点时，第一条显示为“ES采购汇总／已汇总”，沿用该条审批人和时间，审批意见为空。没有关联汇总单号、关联子单处于等待节点且查到子单明细时，按申请人组织及物资类别取得有效汇总人员，为每人追加一行“ES采购汇总／待汇总”，审批时间与意见为空；资产和耗材分别取对应汇总角色。
当传入的流程类型允许显示流程图时，图在审批记录上方展示；统一申领原申请、资产采购、资产领用、耗材采购不展示图，耗材领用仍展示图。采购扩展记录是否出现按本次传入的流程类型判断；本列表对领用、采购统一传领用类型，不能据业务类型为采购便认定这里一定展示外部采购审批表。
流程图读取本类型对应的流程配置，在审批记录上方显示；图内节点及连线来自配置。转移流程会移除未被标记的四条预设支线。代码以审批时间为空标记对应节点，按记录顺序标记经过的连线；遇到关闭状态时把结束节点纳入连线处理，不另增加一条“结束”审批表记录。未取得流程配置时不保证能显示图，不能把图中全部节点当作都已产生的审批记录。

### 4.4 页面操作

| 操作 | 触发条件及结果 |
| --- | --- |
| 查询／重置 | 按条件及固定待办筛选查询，默认创建时间倒序。 |
| 查看流程 | 领用、采购子流程使用统一申领流程类型；其他记录使用该单据保存的流程类型。 |

## 5 校验

5.1 查询条件均选填，日期选择器约束开始日期不晚于结束日期。

5.2 只选单据类型不表示能查到全部该类型单据；单据还须满足待办、非等待和处理中条件。

5.3 用户基础资料缺失时是否离职显示是；多人同序号时显示结果无稳定第三排序依据。

## 6 后续操作 业务结果 补充说明

6.1 状态完成、没有符合条件的待办或选出等待节点后，该单据不再出现在本查询。

6.2 通用导出列为单据编号、单据类型、业务类型、状态、审批环节、审批人、申请人、申请时间、公司、板块、部门、是否离职。

6.3 另有导出入口复用当前分页参数，仅取得当前页数据；不能把所有导出入口都表述为全量。

6.4 本页提供查询、流程查看和导出，不直接提交审批、终止或补发流程。

6.5 基础资料异常时，姓名或名称未匹配到的直接字符串拼接可能保留编码并带空值文本；字典组件按组件实际结果展示，未发现统一显示横线的规则。当前字典数据、实际角色授权及运行环境的菜单链接未随页面源码提供。涉及固定字典名称的取值须以运行环境配置核对；不会自行补写完整枚举。以上说明对应所提供源码，未连接运行系统验证部署版本。

6.6 统一申领汇总审批历史只有一条时，当前代码仍读取第二条记录，存在弹窗加载失败风险；尚未连接运行环境验证。
