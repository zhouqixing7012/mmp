# 资产申请单 PRD

修订日期：2026年10月16日。以《后台报表&申请》现状PRD的申请查询要求为准，保留已确认的日期区间及预计金额口径。

## 1 背景

员工资产申请的查询、子流程详情和流程进度查看。每条列表以原申请明细及其关联子流程为基础。

查询覆盖原申请、配给、汇总及领用全流程，保留申请单据内容和完整审批信息。人员、组织及状态名称由正式基础资料配置提供。

## 2 权限

按人员、部门、公司分配申请数据范围。用户进入菜单后，仅查询授权范围内的原申请及其关联子单、汇总、出库和审批记录；详情、进度及Excel导出执行相同范围，不能通过单号扩大查看权限。授权名单及组织关系由权限配置提供。

## 3 通用规则

3.1 固定范围为员工资产申请CAA及员工申请EMPLOYEE。列表基于原申请明细连接子流程、汇总单和出库单，不能按一张申请仅一行理解；多个关联子流程或出库单可能增加行数。

3.2 子流程号：一级子单处理中、关联汇总单已驳回时取一级子单号；其他情况优先取关联汇总单号，没有汇总单取一级子单号。

3.3 列表显示关联流程当前已产生的最新环节；同环节有多名有效审批人时共同展示。等待环节显示待汇总，审批人为空。进度中逐条保留实际节点、各审批人及重复办理记录，以记录唯一标识识别同一记录，不能按流程序号或人员删去不同记录。

3.4 单据状态取原员工申请头状态；子流程类型取一级子单类型；两者不一定属于同一张单据。预计采购金额仅在非领用且类型非空时，取原申请明细采购单价×原申请明细数量；领用行金额为空。

3.5 是否超标取原申请明细保存值；正式员工取申请人当前用户资料标记，人员、部门名称由查询时的当前基础资料转换。默认按原申请创建时间倒序。

3.6 查询选填条件为空时不增加过滤；多项条件组合为同时满足。编码、账号和日期用于匹配，显示名称用于阅读。日期从／至在本篇合为一个范围条件。页面存在重置或清空查询条件入口时，统一按“重置”描述；不据此新增原页面未提供的业务动作。

### 4.5 查看进度弹窗字段及交互

点击列表“进度查看”打开只读审批信息。按所点原申请明细关联原申请、配给／领用或采购子单、汇总单；没有子流程时仍显示原申请记录。按业务链依次展示各来源，每个来源内按节点顺序及办理时间展示，不跨来源重排。

| 字段 | 展示及交互 | 来源和取值逻辑 |
| --- | --- | --- |
| 审批环节 | 只读 | 对应系统实际保存的环节名称。 |
| 审批人 | 只读 | 对应记录审批人工号及姓名；同一环节多人逐条显示，保留再次办理记录。 |
| 审批状态 | 只读 | 对应记录保存的办理或审批结果；当前记录可为待审批、待办理或待汇总。 |
| 审批时间 | 日期，只读 | 对应记录保存的时间；尚未办理时为空。 |
| 审批意见 | 文字，只读 | 对应记录保存的意见；为空时留空。 |

记录保留至当前已产生的节点；完成后保留历史，不补造未来审批人或办理结果。重复获取同一唯一标识的记录只展示一次，不按流程序号去重。资产来源分区标题在资产采购及领用分支显示“资产申请详情（此信息来源于资产系统）”。

采购分支继续展示以下三个分区，每个实际节点完整保留，不因已有PR单而删除采购记录中的PR节点，也不替换或删减询报价办理记录。

## 5 校验

5.1 日期选择器约束起止顺序。人员、部门选择后分别保存编码和显示名称，查询用编码。

5.2 查询状态、是否超标、子流程类型和正式员工采用精确匹配；其余文本及未指定精确方式的编码采用包含匹配。

5.3 领用详情按已匹配资产显示标签号；采购行不能凭空生成标签号或出库号。

5.4 详情中的使用说明文本框可输入，但该查询详情未发现提交保存入口，不能认定编辑即写入业务记录。

## 6 后续操作 业务结果 补充说明

6.1 查询、详情、进度及导出读取同一原申请及关联结果；返回列表保持最近一次查询条件及页码。

6.2 查询页面用于查看。输入控件中的临时修改不自动保存；业务办理仍通过对应工作台完成。

6.3 状态编码与名称、正式组织关系、授权人员及外部系统接口由实际配置提供，原型交易演示不作为正式配置。缺少实际记录时留空或明确说明，不伪造采购金额、审批人员和结果。

6.4 本篇依据现状申请要求整改。日期从／至使用一个日期范围；预计采购金额继续使用用户已确认的原申请明细数量，不使用配给或出库执行数量。
