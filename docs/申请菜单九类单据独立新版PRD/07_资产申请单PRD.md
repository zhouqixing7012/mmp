# 资产申请单 PRD

编写日期：2026年10月14日。版本：申请菜单可达页面的现状规则；范围修订于2026年10月15日。

## 1 背景

员工资产申请的查询、子流程详情和流程进度查看。每条列表以原申请明细及其关联子流程为基础。

本篇用于确认现有页面的字段取值、查询条件和交互结果，供产品与研发核对。未确认事项集中放在第6章，不作为正式规则。

## 2 权限

具有菜单权限的用户可查询员工资产申请。当前查询SQL限定资产申请及员工申请类型，未按当前账号额外限制。详情页的仓库组件仍按当前用户仓库操作配置取候选项，不能据此认定列表按仓库权限过滤。

菜单授权来自当前社区及角色配置；管理员菜单查询绕过角色菜单授权，业务办理权限仍以对应页面和节点校验为准。源码未包含运行中的菜单授权数据，不能据页面文件列出实际获权人员名单。

## 3 通用规则

3.1 固定范围为员工资产申请CAA及员工申请EMPLOYEE。列表基于原申请明细连接子流程、汇总单和出库单，不能按一张申请仅一行理解；多个关联子流程或出库单可能增加行数。

3.2 子流程号：一级子单处理中、关联汇总单已驳回时取一级子单号；其他情况优先取关联汇总单号，没有汇总单取一级子单号。

3.3 审批记录对计算后的子流程号取最新一条；没有子流程号时取原申请号。按流程序号长度及序号倒序取一条，不限定待办。等待节点名称转为待汇总，审批人转为空。

3.4 单据状态取原员工申请头状态；子流程类型取一级子单类型；两者不一定属于同一张单据。预计采购金额仅在非领用且类型非空时，取原申请明细采购单价×原申请明细数量；领用行金额为空。

3.5 是否超标取原申请明细保存值；正式员工取申请人当前用户资料标记，人员、部门名称由查询时的当前基础资料转换。默认按原申请创建时间倒序。

3.6 查询选填条件为空时不增加过滤；多项条件组合为同时满足。编码、账号和日期用于匹配，显示名称用于阅读。日期从／至在本篇合为一个范围条件。页面存在重置或清空查询条件入口时，统一按“重置”描述；不据此新增原页面未提供的业务动作。

### 4.5 查看进度弹窗字段及交互

进入方式：申请→资产申请单→列表“进度查看”列的“查看”。没有子流程号时查看原申请；有子流程号时，按本行申请明细标识及采购／领用类型定位关联流程。

弹窗标题为“审批信息”，宽800、高550。内容按流程图、审批记录和适用的外部系统记录纵向展示，不使用页签；没有查询条件。弹窗只读，通过外层关闭控件退出，原列表及业务状态不变。

| 字段 | 展示及交互 | 来源和取值逻辑 |
| --- | --- | --- |
| 审批环节 | 只读 | 当前审批记录保存的节点名称。 |
| 审批人 | 只读 | 当前记录保存的审批人工号，拼接“-”及人员基础资料中的当前姓名；不是列表中选出的那一位审批人。工号为空则不拼接；有工号但查不到姓名时，当前代码可能显示工号-null。 |
| 审批状态 | 只读 | 直接显示当前记录保存的审批状态描述，不由页面重新按编码翻译，也不统一改成“审批中”。 |
| 审批时间 | 只读，yyyy-MM-dd | 当前记录保存的审批时间，精确到日；为空时留空。 |
| 审批意见 | 只读，文字自动折行 | 当前记录保存的审批意见；没有意见时留空，不自动填充同意等文案。 |

每张单据的基础审批记录先按流程序号长度、流程序号、审批时间依次升序排列，再对非空流程序号去重，每个序号只保留排序后的第一条；空序号记录不展示。相同排序值没有额外的唯一排序条件。

不同流程序号的多节点、多名审批人逐行显示；相同序号即使有多人也只保留一条，不能按“展示全部并行审批人”理解。此弹窗没有额外剔除跳过、等待节点；是否显示待审批记录取决于已取得的数据，不补齐尚未生成的未来节点。

流程结束后仍显示已取得的记录及其原状态，不清空历史审批人，不统一替换为“流程已结束”。本表没有代理人列，也没有单独的当前节点字段、审批意见输入框、同意或驳回按钮；不提供分页、导出和保存入口。

原申请、资产采购和资产领用均不显示流程图。资产采购、资产领用分支的审批表上方显示“资产申请详情（此信息来源于资产系统）”。
统一申领的记录按“原申请→关联领用或采购子单→汇总单”依次拼接。关联子单、汇总单按申请行查找，取各自创建时间最新的匹配单据；一般汇总单只取处理中，原申请行为删除或追加标识时不限此状态。子单记录先去掉第一条再追加；各段分别排序、去重后拼接，不再按审批时间全局重排。

已有汇总记录且其第二条属于指定ES汇总审批节点时，第一条显示为“ES采购汇总／已汇总”，沿用该条审批人和时间，审批意见为空。没有关联汇总单号、关联子单处于等待节点且查到子单明细时，按申请人组织及物资类别取得有效汇总人员，为每人追加一行“ES采购汇总／待汇总”，审批时间与意见为空；资产和耗材分别取对应汇总角色。
采购子流程另依次展示“采购申请详情（此信息来源于采购系统）”“PR单审批详情（此信息来源于PR系统）”“采购订单详情（此信息来源于采购系统）”。按所点申请行定位最新汇总行，再查对应的采购申请、PR、询报价及订单流程编号，调用各系统审批历史；存在多条外部关联记录时取查询返回的第一条，未设固定排序。

三个外部记录表均使用下列字段：

| 字段 | 展示及交互 | 来源和取值逻辑 |
| --- | --- | --- |
| 审批环节 | 只读 | 外部审批历史返回的节点名称。 |
| 审批人 | 只读 | 外部审批人工号“-”姓名；姓名截去第一个左括号及后缀；工号含“系统管理员”时清空工号，连接符仍保留。 |
| 审批状态 | 只读 | 外部审批历史返回的审批结果描述，直接显示。 |
| 审批时间 | 只读，yyyy-MM-dd | 后台将外部审批时间按年月日解析并输出，页面直接展示返回字符串。 |
| 审批意见 | 只读 | 外部审批历史返回的意见。页面直接拼接外部字段，缺失值未统一替换为空白。 |

各外部表按接口返回顺序展示，不另按时间排序或按人员合并。采购申请记录会将询报价节点替换为询报价流程的记录；询报价流程至少两条时，先把首条名称改成第二条名称，再删除第二条。采购申请中的“开始”节点会删除；已有PR单号时，还删除其中的“PR单审批”节点；PR和采购订单不执行这套替换。

业务返回失败或没有记录时，移除对应分区标题及表格；网络异常没有专门处理，不能认定也会自动隐藏。若某分区仅一条“询报价／待审批”，隐藏该表并显示“资产申请审批已完成，等待采购发起询价！”。PR表最后一行状态为“已批准”且订单表未隐藏时，显示“采购申请，PR审批已完成，请等待采购员采购！”。该条件按当前代码记录，不按注释改写为无订单流程。

## 5 校验

5.1 日期选择器约束起止顺序。人员、部门选择后分别保存编码和显示名称，查询用编码。

5.2 查询状态、是否超标、子流程类型和正式员工采用精确匹配；其余文本及未指定精确方式的编码采用包含匹配。

5.3 领用详情按已匹配资产显示标签号；采购行不能凭空生成标签号或出库号。

5.4 详情中的使用说明文本框可输入，但该查询详情未发现提交保存入口，不能认定编辑即写入业务记录。

## 6 后续操作 业务结果 补充说明

6.1 列表导出读取最近一次查询保存的完整查询及排序结果，重新按同一查询获取全部行。列为子流程号、子流程类型、申请时间、申请人、申请人部门、申请号、出库号、审批节点、状态、当前审批人、是否超标、预计采购金额、汇总提交人。正式员工列在页面存在但未配置到此导出。

6.2 点击子流程号打开明细详情；汇总提交人链接打开汇总相关单据；流程查看有子流程时拼接原申请与对应子单记录，没有子流程时取原申请记录。

6.3 详情申请人部门、办公区由申请人当前资料覆盖，并非头中保存的历史值；资产行的公司、板块、序列号、启用日期、配置、备注和用途说明按匹配资产的当前信息补充。

6.4 详情城市、建筑、楼层取该申请人名下查询返回的第一项资产地点，未固定排序；不应描述为所领资产自身地点。

6.5 查询每次直接读取业务表，不是前一批统一申领报表的定时结果表。

金额异常说明：预计采购金额直接按单价乘数量，未发现空金额统一补0的处理；单价或数量缺失时可能产生查询转换异常，应与运行数据核对，不写成0.00。

6.6 基础资料异常时，姓名或名称未匹配到的直接字符串拼接可能保留编码并带空值文本；字典组件按组件实际结果展示，未发现统一显示横线的规则。当前字典数据、实际角色授权及运行环境的菜单链接未随页面源码提供。涉及固定字典名称的取值须以运行环境配置核对；不会自行补写完整枚举。以上说明对应所提供源码，未连接运行系统验证部署版本。

6.7 查看进度的外部审批记录存在源码类型不一致：后台把记录集写成文本，页面却按数组逐行读取，未进行第二次解析，不能据字段模板认定三段外部记录已能正确展示。汇总历史只有一条时，另有读取第二条记录的越界风险。以上为源码现状，尚未连接运行环境验证。
