# 新员工领用单 PRD

编写日期：2026年10月14日。版本：申请菜单可达页面的现状规则；范围修订于2026年10月15日。

## 1 背景

新员工领用申请查询和领用详情。仅查询新员工领用单类型NEWEN，区别于MIS预装统计和新员工领用报表。

本篇用于确认现有页面的字段取值、查询条件和交互结果，供产品与研发核对。未确认事项集中放在第6章，不作为正式规则。

## 2 权限

具有菜单权限的用户可查询。查询限定NEWEN类型，未增加申请人为当前用户的条件。详情为查看页；办理和领用确认从对应待办入口进入。

菜单授权来自当前社区及角色配置；管理员菜单查询绕过角色菜单授权，业务办理权限仍以对应页面和节点校验为准。源码未包含运行中的菜单授权数据，不能据页面文件列出实际获权人员名单。

## 3 通用规则

3.1 固定查询NEWEN。默认按申请头创建时间倒序。单据状态、大类、配置等分别按对应字典或基础资料翻译，不能共用一套选项。

3.2 申请人取申请头领用人，显示账号-姓名；公司、板块按头中保存的编码查当前名称并显示编码.名称；部门按保存的部门编码查当前完整部门名。

3.3 审批人取剔除跳过和等待节点后的审批历史最后一条，流程完成后仍可保留最后一位处理人。详情中领用单号按来源申请号查询关联出库单；通过单据ID进入时未回填该查询变量，可能显示为空。

3.4 查询选填条件为空时不增加过滤；多项条件组合为同时满足。编码、账号和日期用于匹配，显示名称用于阅读。日期从／至在本篇合为一个范围条件。页面存在重置或清空查询条件入口时，统一按“重置”描述；不据此新增原页面未提供的业务动作。

## 4 页面字段及交互

### 4.1 查询条件

进入方式：申请→新员工领用单。

| 字段 | 展示及交互 | 来源和取值逻辑 |
| --- | --- | --- |
| 申请单号 | 文本框，选填 | 新员工领用申请编号包含匹配。 |
| 申请人 | 人员单选，选填 | 匹配领用人账号，包含匹配；显示账号及姓名。 |
| 单据状态 | 下拉框，选填 | 读取申请状态字典，按编码精确匹配。 |
| 公司 | 公司选择，选填 | 精确匹配任一所选公司编码；后台支持多编码，公司选择器实际选择方式按组件配置。 |
| 板块 | 板块选择，选填 | 页面提交名称未使用后台接收的板块名称，按当前页面提交无法保证条件生效；列为补充说明待核对项。 |
| 部门 | 部门单选，选填 | 精确匹配单据头部门编码。 |
| 办公区 | 办公区单选，选填 | 按办公区编码包含匹配。 |
| 大类 | 下拉框，选填 | 选项按物资大类编码排序；精确匹配单据头物资大类字段，不是逐条资产明细大类。 |
| 仓库 | 仓库选择，选填 | 按申请头仓库编码包含匹配。 |
| 资产配置 | 下拉框，选填 | 选项来自资产配置字典，但与单据状态使用同一个提交字段，当前实际生成状态过滤条件；不按资产配置字段过滤。 |
| 申请日期 | 日期范围，选填 | 按申请头创建时间过滤，含起日00:00:00和止日23:59:59。 |

## 5 校验

5.1 日期范围约束开始不晚于结束。公司条件后台接受多个编码。

5.2 资产配置和单据状态提交字段重复，可能同时产生互相冲突的状态条件；板块条件提交名称与后台接收不一致。

5.3 列表大类取申请头大类字段，资产明细的大类并不自动参与这一筛选。

5.4 查看详情时按申请号取相关出库单；通过ID直接进入的关联号缺失问题需单独验证。

## 6 后续操作 业务结果 补充说明

6.1 查询详情读取申请头、申请明细及关联出库单；地点、公司、板块、成本中心、业务线和仓库名称分别按对应编码翻译。

6.2 详情申请数量取明细申请数量，领用数量取明细执行数量，两者不强制相同；PR单号取明细关联PR。

6.3 本查询页未配置独立导出，不能拿新员工领用报表或MIS预装统计导出替代。

6.4 菜单查询不新建入职申请，相关申请由新员工流程生成；该生成链路不作为本查询按钮的结果。

6.5 基础资料异常时，姓名或名称未匹配到的直接字符串拼接可能保留编码并带空值文本；字典组件按组件实际结果展示，未发现统一显示横线的规则。当前字典数据、实际角色授权及运行环境的菜单链接未随页面源码提供。涉及固定字典名称的取值须以运行环境配置核对；不会自行补写完整枚举。以上说明对应所提供源码，未连接运行系统验证部署版本。
