# 耗材申请单 PRD

修订日期：2026年10月16日。以《后台报表&申请》现状PRD的申请查询要求为准，保留已确认的日期区间及预计金额口径。

## 1 背景

员工耗材申请的查询、子流程详情和流程进度查看。每条列表以原申请明细及其关联子流程为基础。

查询覆盖原申请、配给、汇总及领用全流程，保留申请单据内容和完整审批信息。人员、组织及状态名称由正式基础资料配置提供。

## 2 权限

按人员、部门、公司分配申请数据范围。用户进入菜单后，仅查询授权范围内的原申请及其关联子单、汇总、出库和审批记录；详情、进度及Excel导出执行相同范围，不能通过单号扩大查看权限。授权名单及组织关系由权限配置提供。

## 3 通用规则

3.1 查询以原申请明细为基础，按物料拆行；同一申请包含多项物料时分别显示。每项物料分别关联配给、采购汇总、领用及出库结果；同一明细存在多个子单或多次出库时，按实际关联分别展示，保留同一原申请单号。

3.2 子流程号规则与资产申请一致：一级子单处理中且汇总单已驳回时取一级子单，否则优先取汇总单，缺失时取一级子单。

3.3 列表显示关联流程当前已产生的最新环节；同环节有多名有效审批人时共同展示。等待环节显示待汇总，审批人为空。进度中逐条保留实际节点、各审批人及重复办理记录，以记录唯一标识识别同一记录，不能按流程序号或人员删去不同记录。

3.4 状态取原申请头。预计采购金额为采购单价×原申请明细数量；领用行金额为空。汇总提交人仅当选定的子流程是耗材汇总单时有值。默认按原申请创建时间倒序。

3.5 查询选填条件为空时不增加过滤；多项条件组合为同时满足。编码、账号和日期用于匹配，显示名称用于阅读。日期从／至在本篇合为一个范围条件。页面存在重置或清空查询条件入口时，统一按“重置”描述；不据此新增原页面未提供的业务动作。

### 4.5 查看进度弹窗字段及交互

点击列表“进度查看”打开只读审批信息。按所点原申请明细关联原申请、配给／领用或采购子单、汇总单；没有子流程时仍显示原申请记录。按业务链依次展示各来源，每个来源内按节点顺序及办理时间展示，不跨来源重排。

| 字段 | 展示及交互 | 来源和取值逻辑 |
| --- | --- | --- |
| 审批环节 | 只读 | 对应系统实际保存的环节名称。 |
| 审批人 | 只读 | 对应记录审批人工号及姓名；同一环节多人逐条显示，保留再次办理记录。 |
| 审批状态 | 只读 | 对应记录保存的办理或审批结果；当前记录可为待审批、待办理或待汇总。 |
| 审批时间 | 日期，只读 | 对应记录保存的时间；尚未办理时为空。 |
| 审批意见 | 文字，只读 | 对应记录保存的意见；为空时留空。 |

记录保留至当前已产生的节点；完成后保留历史，不补造未来审批人或办理结果。重复获取同一唯一标识的记录只展示一次，不按流程序号去重。资产来源分区标题在耗材采购分支显示“资产申请详情（此信息来源于资产系统）”。

采购分支继续展示以下三个分区，每个实际节点完整保留，不因已有PR单而删除采购记录中的PR节点，也不替换或删减询报价办理记录。

| 分区 | 关联及展示规则 |
| --- | --- |
| 采购申请详情（此信息来源于采购系统） | 从当前申请明细关联的汇总结果取得采购申请及询报价流程，展示其全部实际记录。 |
| PR单审批详情（此信息来源于PR系统） | 按该采购结果关联的PR单展示全部审批记录。 |
| 采购订单详情（此信息来源于采购系统） | 按实际关联订单展示创建、审批、下达等已经产生的节点；一对多关联按对应流程区分。 |

外部分区字段与上表一致。没有关联流程时说明该环节尚未产生；读取失败须显示失败状态，不能把失败等同于没有流程。原型使用清楚标识的本地交易演示，真实采购、PR和订单接口接入后另行验证。关闭弹窗回到原查询结果，条件及分页保持。

### 4.7 Excel导出

按最近一次查询条件导出全部授权结果，按原申请物料明细及关联结果展开，与现状模板保持以下20列顺序。没有发生采购或领用的字段留空，不推算实际采购金额。

| 顺序 | 字段 | 取值 |
| --- | --- | --- |
| 1 | 子流程单号 | 与当前查询行同名字段保持相同来源。 |
