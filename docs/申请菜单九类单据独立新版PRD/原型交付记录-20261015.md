# 申请菜单原型交付记录

目标分支 main；依据本目录 01—09 新版 PRD，以 2026 年 10 月 15 日的可达页面范围为准。入口为后台“申请”，紧接“资产报表”，未创建分支或 worktree。

| 菜单 | 实现范围 |
| --- | --- |
| 移库单 | 查询、可排序列表、分页、全量/当前页导出、只读单头与明细、资产/耗材信息、当前单打印。 |
| 退库单 | 查询、只读详情、首条主资产、附属耗材和配件、附件/维修记录、进度、草稿删除及数量反馈、导出。 |
| 转移单 | 查询、创建、草稿编辑、完成查看、资产/物资明细增改删、保存锁定、执行资产更新与事务生成。 |
| 借用单 | 查询、借用/续借差异详情、配件查看和只读审批记录；不增加发起或导出。 |
| 更换单 | PRD只有入口说明，保留菜单并显示字段待定义，不借用工作台更换办理页。 |
| 未完成单据 | 处理中及有效待办筛选、每单选一条、等待首条整单排除、离职标记、进度、全量/当前页导出；REC/ED无流程入口。 |
| 资产申请单 | 原申请与领用/采购子流程查询、详情、汇总、超标/非超标、部门分组、参考用量、PO组合去重、附件与明细导出。 |
| 耗材申请单 | 对应耗材原申请、子流程及汇总详情，普通耗材与资产明细区别、进度及导出。 |
| 新员工领用单 | NEWEN查询及只读领用详情，申请数量/领用数量分开；无办理或独立导出。 |

## 本次确认

两份申请 PRD 的通用规则写“原申请数量”，列表表格写“执行数量”。用户明确选择原申请数量，统一为原申请明细采购单价×原申请明细数量；领用行金额为空。对应两份列表描述各增加3个有效字符，其他正文不重写。

## 数据与未定义边界

- 单据、标签、数量、日期及审批记录均为明确的交易演示。物料和仓库固定属性取已有参考目录的完整行，未连接原系统数据库或外部采购、PR系统。
- 查询是申请业务数据源，不使用资产统一申领报表的预生成结果表，也不扩展为个人工作台办理入口。
- 原版运行字典和菜单角色配置未提供，未知状态保留编码/样例，不把样例称为正式完整枚举；未新增真实身份授权。
- 未提供实际流程图配置时只显示已取得的审批表和配置缺口说明，不按历史记录编造完整图。外部审批分区明确为演示，不声称真实系统已经接通。
- 新员工板块和资产配置两项在 PRD 中已记录提交字段错误，原型暂禁用并说明，其他查询可用；未擅自定义修复后的业务字段。
- 转移明细的旧状态控件误绑用途，原型只读显示关联卡片状态，避免把错误状态写入资产；不是复制旧代码缺陷，也未据此重写 PRD 的现状说明。
- 移库库区/货位按明确启用配置条件展示，参考目录未提供对应开关时不猜测启用值。未知办公区、财务及地点映射不由近似字段补造。
- 转移费用账户仅使用明确的演示映射，未知组合停止，不将缺失的财务规则写成通用拼接算法。转移保存、锁定、删除、执行使用同一交易源，执行先校验整单再更新，当前标签页会话中刷新保留；退库草稿删除结果也在当前标签页会话中刷新保留。只读查询详情里的可输入控件不保存回源单。
