# 申请菜单查询选择器复用核查

本轮检查实际菜单映射的九个查询入口，以98891224为基线。只调整查询控件复用、候选显示结构及业务标签；单据关联、筛选匹配、导出和数据授权保留。

| 菜单 | 人员查询复用入口 | 其他选择入口 |
|---|---|---|
| 移库单 | 制单人 | 原状态字典、单边日期范围保留 |
| 退库单 | 申请人 | 子公司下拉；部门与仓库选择弹窗 |
| 转移单 | 转出人、接收人 | 转出人子公司下拉；转出人部门弹窗 |
| 借用单 | 申请人 | 子公司下拉；部门弹窗 |
| 更换单 | 申请人 | 子公司下拉；部门弹窗 |
| 未完成单据 | 申请人 | 公司单选弹窗、板块下拉、部门弹窗 |
| 资产申请单 | 申请人、当前审批人、汇总提交人 | 部门弹窗；业务节点及状态字典保留 |
| 耗材申请单 | 申请人、当前审批人、汇总提交人 | 部门弹窗；业务节点及状态字典保留 |
| 新员工领用单 | 申请人 | 公司多选弹窗、板块下拉、部门/办公区/仓库弹窗，大类与配置下拉保留 |

人员统一复用AssetPersonSelect及现有PERSON_LOOKUP_FIELDS/COLUMNS，弹窗提供员工编号、员工姓名、部门的查询及显示，按原账号回填，不用显示姓名代替筛选值。角色通过字段身份映射，不凭可见标签猜控件。其他选择继续共用LookupInput/SelectModal、Select、AssetTreeSelect及日期范围，未另建人员、公司或部门选择器。部门、公司、办公区、仓库查询列使用对应业务名称，仓库保留所属公司列。

人员显示优先沿用原申请记录明确的账号/姓名，缺失姓名时仅按相同账号补充现有共享人员资料；部门只使用明确的人员资料，不把申请单部门补给当前审批人。所有候选值仍经过原申请访问校验及可见记录过滤，未扩大候选权限、单多选或单据查看范围。

正式人员及组织主数据接入和候选授权的独立配置仍未完成；本轮没有声称实现PRD的完整正式基础资料候选，也没有把现有演示记录推导候选提升为正式业务规则。公共PRD同步人员弹窗共用查询列及角色复用口径，保留各单据的单多选与匹配定义。

验证包含九类查询入口、十四个人员字段的真实弹窗结构、新员工弹窗内编号/姓名组合查询、选择回填及主查询结果、公司多选、子公司下拉、部门弹窗和服务权限过滤。8套77项测试与严格CI生产构建通过；未浏览器视觉验收、未验证正式基础资料服务、未追踪Actions。
