## 确定的UI问题

### UI-01 查询按钮越出卡片边界

- 位置：九类列表共用查询区；01～08、10可见。
- 观察：查询条件已占满三列，右侧【查询】【重置】仍横向追加，【重置】超出查询白卡右边界。
- 建议：复用 QueryBar 的条件区与独立按钮区；宽屏右侧纵排，空间不足时放下一行右对齐，保持卡片内边距。
- 规范：UI规范13.4、21。
- 证据：[01-list.png](assets/20261022-application-ui/01-list.png)、[07-list.png](assets/20261022-application-ui/07-list.png)、[10-newemployee-list.png](assets/20261022-application-ui/10-newemployee-list.png)。

### UI-02 汇总值没有对齐数量、金额列

- 位置：资产、耗材申请单 → 汇总提交人 → 统一申请汇总详情。
- 观察：部门汇总的“3 17,400.00”挤在物资类别附近；超标/非超标表的数量、金额合计也合并成一段文本，无法沿列核对。
- 建议：合计行保留与表头对应的数量、金额单元格，数值右对齐；合计标签跨非数字列，不合并数值列。业务计算口径不变。
- 规范：UI规范20、20.1、17A。
- 证据：[20-summary.png](assets/20261022-application-ui/20-summary.png)、[21-summary-bottom.png](assets/20261022-application-ui/21-summary-bottom.png)、[30-consumable-summary.png](assets/20261022-application-ui/30-consumable-summary.png)。

### UI-03 查看进度时丢失单据标识

- 位置：资产申请单列表；其他宽表需逐表同类检查。
- 观察：实际向右滚动后，“进度查看”可见，但左侧子流程单号、申请单号和申请人已移出视野。操作前需要来回横移确认行。
- 建议：固定辨认单据所需的主键列及右侧操作列，减少默认列宽；保留必要的横向滚动，不删业务字段。
- 规范：UI规范20、20.2。
- 证据：[07-list.png](assets/20261022-application-ui/07-list.png)、[26-table-right.png](assets/20261022-application-ui/26-table-right.png)。

### UI-04 长文本字段仍塞在三列单格

- 位置：移库、新员工、退库、转移、续借、更换详情。
- 观察：备注、退库/转出/续借/更换原因，以及退库配置、使用说明被压在普通单格；真实长文本会抬高整行并挤占相邻字段。
- 建议：按实际字段将原因、备注、配置、详细说明等独立整行，自动换行；保持其他短字段三列对齐。
- 规范：UI规范15.3。
- 证据：[11-newemployee-detail.png](assets/20261022-application-ui/11-newemployee-detail.png)、[12-storage-detail.png](assets/20261022-application-ui/12-storage-detail.png)、[13-detail.png](assets/20261022-application-ui/13-detail.png)、[14-detail.png](assets/20261022-application-ui/14-detail.png)、[15-detail.png](assets/20261022-application-ui/15-detail.png)、[16-detail.png](assets/20261022-application-ui/16-detail.png)、[28-borrow-detail.png](assets/20261022-application-ui/28-borrow-detail.png)、[29-use-detail.png](assets/20261022-application-ui/29-use-detail.png)。

### UI-05 空值留白，无法区分未填写与漏加载

- 位置：多类列表与详情。
- 观察：邮箱、成本中心、办公区、板块等空值直接显示空白；同一页面其他区域又使用“-”。
- 建议：非适用或无记录的普通只读值统一“-”；真正加载失败单独说明，不用“-”掩盖错误；真实0保留其业务含义。
- 规范：UI规范15.6。
- 证据：[11-newemployee-detail.png](assets/20261022-application-ui/11-newemployee-detail.png)、[14-detail.png](assets/20261022-application-ui/14-detail.png)、[17-detail.png](assets/20261022-application-ui/17-detail.png)、[18-detail.png](assets/20261022-application-ui/18-detail.png)。

### UI-06 审批及配件弹窗有多层滚动

- 位置：资产申请进度、未完成流程、退库配件。
- 观察：审批信息内每段表格各有纵向滚动条，外层长弹窗还要继续向下滚；配件仅一行数据也同时出现横、纵滚动条并截住末列。
- 建议：优先让弹窗内容区统一纵向滚动；短表按内容自然撑高，仅宽表保留横滚；长流程可按来源分区或页签组织，保留所有记录。
- 规范：UI规范13、27.1。
- 证据：[19-asset-original.png](assets/20261022-application-ui/19-asset-original.png)、[22-pending-flow.png](assets/20261022-application-ui/22-pending-flow.png)、[27-accessory-modal.png](assets/20261022-application-ui/27-accessory-modal.png)。

### UI-07 空结果文案不统一且缺少业务对象

- 位置：移库查询空结果、汇总非超标空区、更换待发放区。
- 观察：同时出现“暂无数据”“无展示数据！”；无法直接知道是条件无匹配、本批没有该类申请，还是尚未产生后续数据。
- 建议：分别写“暂无符合条件的移库单”“本批暂无非超标申请”等；阶段性无记录的文案须依据实际流程，不自行推断失败或完成。
- 规范：UI规范26、28.1。
- 证据：[24-empty-query.png](assets/20261022-application-ui/24-empty-query.png)、[21-summary-bottom.png](assets/20261022-application-ui/21-summary-bottom.png)、[16-detail.png](assets/20261022-application-ui/16-detail.png)。

## 需要资料或业务明确的观察项

### OBS-01 时间字段只有日期（需核对数据精度）

- 位置：移库、新员工、退库及部分查询列表。
- 观察：“制单时间”“申请时间”等只显示yyyy-MM-dd，而转移详情显示完整时分秒。
- 建议及边界：核对各正式PRD及时间来源：若业务只需自然日，统一日期命名；若需要精确时点，显示真实时间，不能拼造00:00:00。
- 依据：UI规范17；业务字段定义优先。
- 证据：[11-newemployee-detail.png](assets/20261022-application-ui/11-newemployee-detail.png)、[12-storage-detail.png](assets/20261022-application-ui/12-storage-detail.png)、[13-detail.png](assets/20261022-application-ui/13-detail.png)。

### OBS-02 可输入字段没有保存结果（既有演示限制/需业务明确）

- 位置：资产/耗材申请详情、统一申请汇总。
- 观察：单据备注、建筑、使用说明或项目用途说明使用输入框；页面只有返回/导出。源码核对发现这些输入仅更新本页状态，未提供持久化动作。此前交付记录也已明确只读查询中的输入不保存。
- 建议及边界：先明确查询详情是否允许维护及其保存时点。纯展示字段用文本；确需修改则定义保存/取消和结果反馈。本轮不擅自增加保存按钮，也不擅自取消PRD保留的输入。
- 依据：UI规范28；现状PRD及交付边界。
- 证据：[17-detail.png](assets/20261022-application-ui/17-detail.png)、[18-detail.png](assets/20261022-application-ui/18-detail.png)、[20-summary.png](assets/20261022-application-ui/20-summary.png)、[21-summary-bottom.png](assets/20261022-application-ui/21-summary-bottom.png)。

### OBS-03 状态编码和配置缺口占据业务界面（已有资料依赖）

- 位置：移库、资产/耗材申请、新员工领用、未完成单据。
- 观察：状态展示“状态1/状态2/3”；蓝色说明条写运行配置、字段冲突、未接通知等。新员工板块/资产配置禁用有明确未定义来源。
- 建议及边界：真实字典/配置补齐后再展示业务名称；演示限制应继续真实说明，可统一收纳到明确的原型说明入口，字段本身保留不可用原因。不得猜测编码含义、隐藏未接入事实或伪造候选。
- 依据：UI规范1、28.1；task_plan已记载资料依赖。
- 证据：[01-list.png](assets/20261022-application-ui/01-list.png)、[07-list.png](assets/20261022-application-ui/07-list.png)、[08-list.png](assets/20261022-application-ui/08-list.png)、[10-newemployee-list.png](assets/20261022-application-ui/10-newemployee-list.png)、[06-list.png](assets/20261022-application-ui/06-list.png)。

## 可访问性风险与验证边界

1. 部件入口的可访问名称目前只有“1”“0”，读屏很难辨别对应哪个资产、点击后看什么；建议补充“查看某资产配件（1件）”等可访问名称，不改变视觉列名和业务能力。证据为本轮页面DOM与配件入口截图。
2. 审批长弹窗的多层滚动增加键盘浏览风险；本轮未做完整Tab顺序、焦点圈定/返回、读屏与对比度测量，不能据截图声称符合或不符合全部WCAG标准。
3. 未执行提交、保存、删除、审批、真实通知、打印及文件导入导出；未修改业务数据。未进行手机、小屏、缩放和跨浏览器验证。示例之外的全部角色、全部状态及极长/大批量数据未穷举。
4. 输入字段的本页状态限制另外以当前源码及原交付记录核对，属于观察项，不据此宣称原型已实现保存。未擅自删除“代理人”等PRD字段，也未把空数据自动改成隐藏条件。
5. 不把页面截图中的顶部标签栏暂时未出现视作“嵌套页面壳”缺陷：滚动位置不同会影响截入范围，证据不足，已排除该猜测。
6. 独立只读截图复核覆盖01～08、10～18；根代理复核全部30张证据。报告不包含独立复核未实际查看的额外验证承诺。未运行Jest、构建或生产接口验证。
