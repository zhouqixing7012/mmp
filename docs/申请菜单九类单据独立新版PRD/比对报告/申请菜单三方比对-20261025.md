# 申请菜单原型、新版PRD、现状PRD三方比对

核查日期：2026-10-25。分支：`feat/application-asset-report`；远端核查基线：`8f9e1f51c08e3f49855b1dd97e0ef8e1e1562025`。

本次覆盖九类查询页面的筛选、列表、详情、进度、导出、数据来源与权限实现。原型依据为当前源码及mock；未运行浏览器、未实拍截图、未验证线上交互或正式系统数据，因此这是一份业务与实现的静态比对，不是浏览器验收。本轮只新增比对报告，不修改业务代码或正式PRD。

## 一、结论与依据

不能认定“所有页面已无疑问或全部一致”。主要问题并非业务规则不存在，而是原业务PRD已有规定，查询原型和新版PRD没有完整沿用。

三方资料：

- 现状PRD：[后台报表&申请](../../后台报表&申请现状PRD/后台报表&申请.md)，申请章节从729行开始。
- 新版PRD：本目录上级的01—09九篇。
- 原型：`src/pages/applicationQueries/`、`src/services/applicationQueryService.js`及其关联业务存储与mock。
- 业务依据：库存管理移库PRD；员工自助退库、借用、转移、更换、新员工领用、资产申请及耗材申请PRD。

现状PRD对资产申请、耗材申请的详细字段仍待补充；新员工领用没有独立的申请查询章节。因此这些部分以现状明确范围、新版字段、源业务规则交叉核查，不能宣称全部字段都已得到三方现状验证。

以下规则已经确认，不再重复征求决定：申请菜单查询员工或ES已发起的业务源单；借用结束状态用“已完成”；周报每周一北京时间10:00通过服务号发给ES-何文；具体接口不写主PRD。

### 展示与格式差异

- 新版资产申请详情数量规定千分位／小数格式，原型部分详情直接显示原值，整数小样本未暴露问题。见新版07:96—97，`ClaimApplicationDetail.jsx:14—16,30`。
- 新员工新版09:127保留旧源码空值拼接行为，原型统一显示横线。建议新版描述目标空值展示，不把旧空值拼接缺陷当目标规则；无流程／读取失败不能只用横线代替。
- 未完成列表日期为yyyy-MM-dd，Excel及周报仍导出完整时间。见`unfinishedDefinition.js:12,17—19`。需在修订时明确展示精度，当前仅构成格式差异。
- 退库类型“离职归还”与源业务“离职退还”用词不同。建议查询沿用源业务名称，真实历史值按业务码兼容，不猜两个不同字符串一定是两个业务类型。
