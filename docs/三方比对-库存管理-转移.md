# 库存管理 - 转移 三方比对

> 比对对象
>
> 1. 原版 PRD：用户提供《库存管理—转移》22页版本；
> 2. 当前原型：`src/pages/inventoryManagement/TransferPage.js`；
> 3. 新 PRD：`docs/PRD-库存管理-转移.md`，按当前原型重新整理。
>
> 本文用于识别差异，不在未确认前直接把历史规则强行恢复到原型。

## 1. 结论分类

| 分类 | 含义 |
|---|---|
| 原型应补 | 原版规则仍具有明显业务必要性，当前原型缺失，建议后续补原型 |
| PRD应跟原型 | 当前原型已经形成新的明确交互，原版描述应退出 |
| 仅后端规则 | 正式研发需要，但不要求 PC 原型模拟完整技术过程 |
| 待确认 | 原版与当前原型存在业务冲突，不能仅凭现状自行决定 |

## 7. 第一批冲突确认结果

以下规则已经确认并完成收口：

1. 新建转移单首次点击【添加物资】时，先自动保存单头并生成 AT 单号，再进入添加资产。
2. 转入成本中心根据转入人自动带出并只读。
3. 资产状态只读。
4. 转移数量自动取资产数量，不提供用户输入。
5. 混合选择删除时，仅删除草稿；已完成单据保留。
6. 存在物资明细后，单头备注只读。
7. 后台手工创建制单人取当前登录人。
8. SERVER 成本中心特殊规则、特殊 NO 资产规则继续保留。

本批规则已同步至当前原型和新 PRD。

仍未确认的差异继续保留原表结论，不因本批确认自动推断。
