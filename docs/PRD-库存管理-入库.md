# 库存管理 - 入库 PRD

## 1. 背景

入库用于承接资产、低值耐用品、普通耗材等物资进入仓库后的正式库存处理。

入库单既可以由用户在入库模块手工创建，也可以由资产接收、耗材接收等上游业务生成来源入库任务。

当前入库类型固定为：

| 入库类型 | 说明 |
|---|---|
| 新增入库 | 非采购接收场景，由用户手工新增物资并执行入库 |
| 采购接收 | 承接资产接收、耗材接收完成后的采购物资 |
| 退库入库 | 正常使用中的资产退回仓库 |
| 借用归还 | 借用中的资产归还仓库 |

入库负责完成正式库存事务，并根据不同物资类型新增或更新资产 / 耗材台账、更新 PO 入库结果、生成业务事务记录。

普通耗材在耗材接收确认时已经同步完成入库，入库模块仅保留对应已完成入库单用于查询、查看、打印和业务追溯。

## 2. 权限

权限采用“公司 + 板块数据范围”与“仓库操作权限”两层控制。

### 2.1 数据权限

公司、板块决定用户可查看和查询的数据范围，包括：

- 入库单；
- 采购接收待入库物资；
- 退库待入库资产；
- 借用待归还资产；
- 采购来源数据。

用户无对应公司或板块数据权限时，不返回对应记录。

### 2.2 操作权限

仓库权限决定用户能否执行：

- 创建入库单；
- 编辑草稿；
- 选择当前仓库；
- 添加、编辑、删除入库物资；
- 下载模板；
- Excel 导入；
- 执行入库；
- 删除草稿入库单；
- 单条打印、批量打印；
- 重试采购系统回传。

操作权限至少区分：

- 入库单查看权限；
- 创建权限；
- 草稿编辑权限；
- 执行入库权限；
- 删除草稿权限；
- 打印权限；
- 仓库可操作范围。

打开草稿、选择仓库、选择物资、执行入库、删除草稿及重试采购回传时均重新校验当前权限，不能只依赖按钮显隐。

## 3. 通用规则

### 3.1 入库类型与来源

| 来源 | 入库类型 | 初始状态 | 当前仓库 | 是否需要执行入库 |
|---|---|---|---|---:|
| 入库模块手工创建 | 新增入库 | 草稿 | 用户选择 | Y |
| 入库模块手工创建 | 采购接收 | 草稿 | 用户选择 | Y |
| 资产接收完成 | 采购接收 | 草稿 | 用户选择 | Y |
| 低值耐用品接收完成 | 采购接收 | 草稿 | 用户选择 | Y |
| 普通耗材接收完成 | 采购接收 | 已完成 | 来源业务已确定 | N |
| 入库模块手工创建 | 退库入库 | 草稿 | 用户选择 | Y |
| 入库模块手工创建 | 借用归还 | 草稿 | 用户选择 | Y |

系统生成采购接收草稿时：

- 入库类型固定为“采购接收”，不可修改；
- 保留上游接收单、PO、接收物资及拆单关系；
- 当前仓库由用户选择，不再自动匹配为只读；
- 选择仓库后，根据仓库所属公司限定当前草稿可处理的来源物资；
- 来源物资与当前仓库公司不一致时不得加入或执行入库。

普通耗材接收确认后直接生成“已完成”的采购接收入库单，不进入草稿维护和执行入库流程。

### 3.2 入库单状态

| 状态 | 说明 |
|---|---|
| 草稿 | 尚未正式入库，可按规则维护 |
| 已完成 | 已正式完成入库，只读 |

状态流转：

草稿 → 已完成

已完成单据不允许恢复草稿。

普通耗材接收产生的采购接收入库单创建时即为“已完成”。

### 3.3 当前仓库规则

#### 3.3.1 草稿入库单

新增入库、采购接收、退库入库、借用归还的草稿单均由用户选择当前仓库。

当前仓库统一放在【入库单信息】Card 右上角，不占用 DetailGrid 字段位。

选择当前仓库后：

- 系统取得仓库所属公司；
- 当前入库单可选择 / 可处理的物资按该公司过滤；
- 不属于当前仓库公司的物资不展示，也不允许加入；
- 执行入库时再次校验所有入库物资公司与当前仓库公司一致。

各类型具体规则：

| 入库类型 | 仓库选择后的物资范围 |
|---|---|
| 新增入库 | 物资及相关基础数据按当前仓库公司范围使用；公司字段由当前仓库带出 |
| 采购接收 | 待入库物资按当前仓库公司过滤 |
| 退库入库 | 待退库资产按当前仓库公司过滤 |
| 借用归还 | 待归还资产按当前仓库公司过滤 |
| 系统生成采购草稿 | 当前来源组内，仅处理与当前仓库公司一致的来源物资 |

系统生成采购草稿的当前仓库同样可选择，不再采用“系统自动匹配后只读”的旧规则。

#### 3.3.2 切换仓库

手工创建的新增入库、采购接收、退库入库、借用归还草稿已经存在入库物资时修改仓库：

1. 进行二次确认；
2. 确认后清空当前草稿内与旧仓库公司相关的入库物资及临时维护数据；
3. 用户按新仓库公司重新选择 / 新增物资。

系统生成采购草稿切换仓库后，重新按新仓库公司过滤当前来源组物资；与新仓库公司不一致的来源物资不得进入有效入库明细。

已完成入库单当前仓库只读。

### 3.4 入库类型切换

手工创建草稿时允许选择入库类型。

- 当前草稿尚无入库物资时，可直接切换入库类型。
- 当前草稿已有入库物资时，切换前进行二次确认。
- 确认后清空当前入库物资及对应临时维护数据，再按新入库类型展示页面字段。
- 系统生成采购接收草稿不允许修改入库类型。

确认文案：

不同入库类型的字段和物资来源不同，切换后当前入库物资将被清空，是否继续？

### 3.5 草稿维护与行编辑

草稿状态下，新增入库、采购接收、退库入库、借用归还四类“入库物资”表格最后统一增加固定在右侧的【操作】列。

操作列展示【编辑】。

点击【编辑】时：

- 复用该入库类型原有的添加 / 选择入库物资弹窗；
- 字段、选择规则、校验与新增时保持一致；
- 将当前行已保存信息回显；
- 不另做字段缩水版编辑弹窗。

数量编辑规则：

| 入库类型 | 行编辑中的数量 |
|---|---|
| 新增入库 | 可编辑 |
| 采购接收 | 继承接收结果，只读 |
| 退库入库 | 继承待退库数量，只读 |
| 借用归还 | 继承待归还数量，只读 |

已完成入库单不展示行编辑操作。

### 3.6 采购接收来源快照

采购接收入库物资以来源接收结果作为业务快照。

入库阶段不得无依据重新计算、重新归类或猜补来源数据。

除明确允许维护的字段外，采购接收来源字段只读。

字段取值规则：

| 字段 | 取值规则 |
|---|---|
| 物资说明 | 继承接收完成快照 |
| 物资总类 / 物资大类 / 物资小类 | 继承来源物料分类 |
| 配置 | 继承接收阶段最终配置 |
| 计量单位 | 继承来源物料单位 |
| 申请批次 | 资产接收来源按上游快照继承；耗材 / 低值耐用品来源为空 |
| 入库数量 | 继承已完成接收数量 |
| 原值 | 继承采购 / 接收价格数据 |
| 税金 | 继承采购 / 接收税金数据 |
| 金额小计 | 按当前入库明细保存金额展示，保留两位小数 |
| 资产标签号 / 耗材标签号 | 继承接收确认结果 |
| SN号 | 继承接收确认结果 |
| 资产状态 | 按当前入库业务目标状态展示 |
| City / Building / Floor | 继承来源及当前仓库位置规则 |
| NO位置 | 机房资产继承来源数据，仅作为业务字段保留，不再作为采购接收入库拆单键 |
| 原资产标签号 | 有来源关系时继承 |
| 所在部门 | 继承采购 / 接收链路中的使用部门 |
| 责任人 | 按采购接收入库现有责任规则带出 |
| 新增类型 | 按现有采购接收入库规则带出 |
| 用途 | 按来源快照带出，无值保持为空 |
| 公司 | 继承来源接收结果，并参与当前仓库公司校验 |
| 成本中心 | 继承采购 / 接收链路现有值 |
| 业务线 | 继承采购 / 接收链路现有值 |
| 项目 | 继承来源，无值为空 |
| 板块 | 继承来源接收结果 |
| 费用账户 | 按既有规则生成或继承；生成失败不得伪造成功值 |
| 服务 | 机房资产继承来源数据，普通物资为空 |
| 购买日期 | 继承来源购买日期 |
| 启用日期 | 继承来源启用日期 |
| PR单号 / 申请单号 / PO单号 | 继承来源采购及接收关系 |
| 申请人 | 继承采购 / 申请来源人员 |
| 主资产标签号 | 有主资产关系时继承 |
| 供应商 | 继承来源供应商 |
| 使用说明 | 采购接收资产按采购订单行使用部门生成部门层级说明 |
| 备注 | 继承已有备注 |

资产接收来源可以继承资产部件信息。

低值耐用品、普通耗材接收链路不传递部件数据，因此采购接收入库中不展示低值耐用品 / 普通耗材的部件数量、部件说明。

采购接收入库明细中的“使用说明”不写入正式资产卡片的“使用说明”字段，资产卡片继续使用既有建卡规则。

### 3.7 待入库物资池与占用

采购接收待入库物资必须同时满足：

1. 已完成接收；
2. 尚未完成正式入库；
3. 未被其他有效入库草稿占用；
4. 公司与当前仓库公司一致。

以下数据不进入当前待入库物资池：

- 接收尚未完成；
- 已正式入库；
- 已被其他有效采购接收入库草稿占用；
- 普通耗材已自动完成入库的数据；
- 公司与当前仓库公司不一致的数据。

物资加入有效采购接收入库草稿后立即进入入库占用状态，不得再次进入其他有效采购接收入库草稿。

以下操作释放占用：

| 操作 | 结果 |
|---|---|
| 删除采购草稿中的物资 | 释放该物资占用 |
| 删除整张采购草稿 | 释放整单物资占用 |

执行入库成功后，占用转为正式入库结果，不再释放。

### 3.8 采购接收拆单

采购接收来源生成规则按物资类型区分。

#### 3.8.1 资产

资产类采购接收按照：

位置 + 资产大类

两个维度共同拆单。

规则：

- 同一来源范围内，位置相同且资产大类相同的资产进入同一采购接收入库草稿组；
- 位置不同必须拆分；
- 资产大类不同必须拆分；
- 位置和资产大类均相同不得无依据重复拆分；
- 位置、资产大类直接继承接收完成快照，不在入库阶段重新猜补；
- 任一拆单关键字段缺失时阻断对应草稿组生成。

“位置”使用接收完成时已经确认的业务位置，不以 NO 位置替代。

服务器、服务器备件、网络设备、网络设备备件与普通资产统一遵循“位置 + 资产大类”拆单，不再单独按 NO 位置拆单。

NO 位置仍作为机房资产业务字段保留。

#### 3.8.2 低值耐用品和普通耗材

耗材类不按位置、耗材大类或其他物资属性继续拆单。

按接收单维度生成：

- 同一接收单内的低值耐用品进入同一采购接收入库草稿来源组；
- 普通耗材接收确认后按接收单维度生成一张已完成采购接收入库单；
- 不因耗材大类、标签号、位置不同继续拆分。

### 3.9 各类型候选物资资格

#### 3.9.1 采购接收

候选物资必须：

- 已完成接收；
- 尚未正式入库；
- 未被其他有效入库草稿占用；
- 公司与当前仓库公司一致。

#### 3.9.2 退库入库

候选资产状态固定为：

在用-使用中

其他状态不得通过退库入库加入。

#### 3.9.3 借用归还

候选资产状态固定为：

在用-借用中

不得使用“借出”等非正式状态值。

用途固定使用资产台账枚举：

- 部门公用；
- 员工用机；
- 其他用途；
- 专业用途。

资产标记固定使用资产维护枚举：

- 硬件老化；
- 组件缺失；
- 设备故障；
- 物理损伤；
- 空。

### 3.10 Excel 批量导入通用规则

新增入库、退库入库、借用归还共用入库物资区域的【下载模板】【Excel导入】入口。

采购接收入库不提供 Excel 导入。

三个入库类型分别使用独立模板：

| 入库类型 | 模板文件 |
|---|---|
| 新增入库 | 新增入库数据导入模板.xls |
| 退库入库 | 退库入库数据导入模板.xls |
| 借用归还 | 借用归还数据导入模板.xls |

通用流程：

选择入库类型 → 选择当前仓库 → 下载对应模板 → 上传 Excel → 按当前类型逐行校验 → 全部通过后加入草稿明细 → 用户执行入库 → 更新资产 / 物料库存

通用规则：

1. 支持 .xls / .xlsx 上传，下载模板统一为 .xls。
2. 上传前必须先选择当前仓库。
3. 上传时按当前入库类型校验模板表头，不允许混用其他类型模板。
4. 资产匹配优先按资产标签号；标签号为空时按 SN。
5. 同一文件内不允许重复资产。
6. 当前入库单已存在的资产不得重复导入。
7. 任意一行校验失败，整批导入失败，正确行也不保存。
8. 错误原因写入模板第一列【错误提示】，生成错误结果文件供修改后重新上传。
9. 全部校验通过后，只加入当前草稿明细，不立即更新正式资产或库存。
10. 正式结果仅在【执行入库】整单成功后产生。
11. 上传阶段不新增独立资产锁定动作，但仍执行资产存在性、公司、状态和重复校验。
12. 日期统一按 YYYY-MM-DD 校验。
13. Excel 模板不设置“Excel 专有业务字段”；模板字段以当前业务页面和正式入库规则为准，历史模板中的废弃字段不再保留。

### 3.11 执行入库事务

【执行入库】作为完整本地业务事务。

只有所有本地校验和业务写入全部成功后，才允许：

- 入库单由草稿变为已完成；
- 增加正式库存；
- 新增或更新资产 / 耗材台账；
- 更新相关 PO；
- 生成业务事务记录。

任一本地步骤失败：

- 入库单保持草稿；
- 页面已维护数据保留；
- 不增加正式库存；
- 不生成半完成台账；
- 不更新 PO 正式入库数量；
- 用户修正问题后可重新执行。

采购系统回传发生在本地正式入库成功之后。

采购回传失败不回滚本地正式入库结果。

### 3.12 PO 状态

PO 状态按累计接收和累计正式入库结果判断：

| 条件 | PO 状态 |
|---|---|
| 仍存在未完成接收数量 | 待接收 |
| 全部数量已接收，但仍存在未正式入库数量 | 已接收 |
| 全部数量均已正式入库 | 已入库 |

一张入库单完成不能直接决定整张 PO 状态，必须重新计算整张 PO 全部采购行累计结果。

普通耗材接收确认时同步完成入库，其对应数量同时计入已接收数量和已入库数量。

## 4. 页面字段及交互

### 4.1 入库单列表

#### 4.1.1 查询条件

| 字段 | 交互方式 | 查询规则 |
|---|---|---|
| 入库单号 | 输入框 | 模糊查询 |
| 入库类型 | 下拉单选 | 新增入库 / 采购接收 / 退库入库 / 借用归还 |
| 单据状态 | 下拉单选 | 草稿 / 已完成 |
| PO 单号 | 输入框 | 模糊查询 |
| PR 单号 | 输入框 | 模糊查询 |
| 标签号 | 输入框 | 同时支持资产标签号、耗材标签号 |
| 制单人 | 输入框 | 模糊查询 |

## 5. 校验

### 5.1 通用校验

| 场景 | 校验 / 处理 |
|---|---|
| 执行入库 | 至少存在 1 条有效入库物资 |
| 执行入库 | 当前仓库已选择且有效 |
| 执行入库 | 所有物资公司与当前仓库公司一致 |
| 执行入库 | 必填字段已维护 |
| 删除入库单 | 所选单据必须全部为草稿 |
| 删除物资 | 仅草稿状态允许 |
| 已完成入库单 | 不允许编辑 |
| 入库数量 | 必须为大于 0 的有效数量 |
| 批量打印 | 所选单据必须全部为已完成 |

### 5.2 新增入库

- 物资说明必填。
- 入库数量必须为大于 0 的整数。
- 原值必须有效。
- 资产标签号、SN 按对应唯一性规则校验。
- 责任人必填。
- 所在部门由责任人带出并固定为 SOHU0001.虚拟组织。
- 板块必填。
- 费用账户组成字段不完整时不得生成完整费用账户。
- 购买日期、启用日期按通用日期规则校验。
- 报废新增必须按规则维护原资产标签号。
- 部件数量大于 0 时必须先有资产标签号，并完整维护对应部件。
- 主资产标签号、供应商等选择数据必须有效。

### 5.3 采购接收

- 待入库物资必须已完成接收。
- 尚未正式入库。
- 未被其他有效草稿占用。
- 公司与当前仓库公司一致。
- 系统采购草稿当前仓库必须由用户选择。
- 手工采购草稿当前仓库必须由用户选择。
- 同一接收物资不得同时进入多张有效草稿。
- 采购接收数量继承来源，只读。
- 机房资产维保结束日期不得早于维保开始日期。
- 资产拆单关键字段“位置、资产大类”不得为空。
- 耗材按接收单维度生成，不额外拆单。

### 5.4 退库入库

- 当前仓库必选。
- 候选资产状态必须为“在用-使用中”。
- 资产公司必须与当前仓库公司一致。
- 同一资产不得在当前入库单重复。
- 责任人必填且有效。
- 退库数量按物资类型规则取得。
- 退库日期必填。
- 鉴定日期填写时不得晚于退库日期。
- 退库原因必填。

### 5.5 借用归还

- 当前仓库必选。
- 候选资产状态必须为“在用-借用中”。
- 资产公司必须与当前仓库公司一致。
- 同一资产不得在当前入库单重复。
- 责任人必填且有效。
- 归还数量取当前待归还数量，不允许人工修改。
- 归还日期必填。
- 鉴定日期填写时不得晚于归还日期。
- 资产标记、用途必须使用正式枚举。

### 5.6 Excel 导入

三类导入统一校验：

- 模板表头必须与当前入库类型一致；
- 当前仓库必须已选择；
- 任意一行错误时整批不保存；
- 文件内重复不允许；
- 当前入库单重复不允许；
- 公司必须与当前仓库公司一致；
- 错误原因写入第一列；
- 全部通过后才加入草稿；
- 上传成功不等于正式入库。

各类型字段、状态、责任人、日期等具体校验按 4.7 执行。

### 5.7 执行入库

本地执行任一步骤失败：

- 入库单保持草稿；
- 不写正式库存；
- 不生成半完成台账；
- 不更新 PO 正式入库数量；
- 保留用户草稿信息；
- 用户修正后可重新执行。

执行成功后才能将单据更新为已完成。

## 6. 后续操作 / 业务结果 / 补充说明

### 6.1 删除草稿 / 删除物资

入库列表仅允许删除草稿单。

删除草稿：

- 二次确认；
- 删除采购接收草稿时不删除上游接收单；
- 不回退上游接收状态和已接收数量；
- 释放采购待入库物资占用；
- 对应物资重新进入待入库池。

删除采购接收入库物资：

- 仅释放当前入库单占用；
- 不删除接收结果；
- 不回退接收单状态；
- 可重新加入其他有效采购草稿。

已完成入库单禁止删除。

### 6.2 普通资产入库结果

执行成功后：

1. 入库单更新为已完成。
2. 创建正式资产台账卡片。
3. 资产状态更新为目标状态。
4. 写入当前仓库。
5. 保存标签号、SN、金额、配置、责任及业务属性。
6. 采购接收入库明细“使用说明”不覆盖资产卡片“使用说明”。
7. 更新 PO 已入库数量。
8. 重新计算 PO 状态。
9. 生成资产入库事务及相关报表数据。
10. 触发采购系统回传。

### 6.3 机房资产入库结果

除普通资产结果外：

- 保存 NO位置；
- 保存服务；
- 保存维保开始日期、维保结束日期；
- 维保信息传入资产台账及相关财务数据；
- 向对应采购人员发送入库完成通知。

机房资产采购接收拆单同样使用“位置 + 资产大类”，NO位置不再作为拆单键。

### 6.4 低值耐用品入库结果

执行采购接收入库成功后：

1. 入库单更新为已完成。
2. 增加目标耗材仓库存。
3. 生成低值耐用品耗材台账卡片。
4. 保存耗材标签号、SN等接收结果。
5. 不生成、不保存耗材部件数据。
6. 更新 PO 已入库数量。
7. 重新计算 PO 状态。
8. 生成库存事务记录。
9. 触发采购系统回传。

### 6.5 普通耗材自动入库

普通耗材在耗材接收确认时已经完成：

- 按接收单维度生成已完成采购接收入库单；
- 增加对应耗材仓库存；
- 更新 PO 已入库数量；
- 触发采购系统回传。

入库模块不执行第二次入库，仅查询、查看和打印。

### 6.6 退库入库结果

执行成功后：

- 入库单更新为已完成；
- 资产进入当前仓库；
- 更新责任人相关成本中心和费用账户；
- 更新资产标记；
- 写入退库日期、退库原因及本次退库信息；
- 资产状态更新为“在库-待处理”；
- 更新资产台账；
- 生成退库入库事务。

### 6.7 借用归还结果

执行成功后：

- 入库单更新为已完成；
- 资产进入当前仓库；
- 写入归还日期和归还信息；
- 更新责任人；
- 清理借用相关信息；
- 资产状态更新为“在库-待处理”；
- 更新资产台账；
- 生成借用归还入库事务。

### 6.8 PO 更新

正式入库成功后只更新本次实际成功入库数量。

更新后根据整张 PO 全部采购行累计结果重新计算状态。

不得直接使用当前入库单状态覆盖整张 PO 状态。

### 6.9 采购系统回传

采购相关入库本地成功后向采购系统回传。

回传数据至少包括：

- 入库单号；
- 入库日期；
- PO单号及 PO 行；
- 物料；
- 本次入库数量；
- 金额等采购闭环数据。

成功：

采购回传状态 = 成功。

失败：

采购回传状态 = 失败。

本地正式入库与采购回传是两个独立结果：

- 本地入库成功后，不因回传失败回滚库存、台账或 PO 本地结果；
- 入库单保持已完成；
- 页面展示【重试采购回传】；
- 重试成功后状态更新为成功；
- 重试失败继续保持失败，可再次重试。

### 6.10 上下游衔接

普通资产：

资产接收 → 已完成接收 → 按位置 + 资产大类形成采购接收入库来源组 → 选择当前仓库 → 执行入库 → 资产台账 → PO 更新 → 采购回传

机房资产：

资产接收 → 已完成接收 → 按位置 + 资产大类形成采购接收入库来源组 → 选择当前仓库 → 执行入库 → 资产台账 → PO 更新 → 采购回传

低值耐用品：

耗材接收 → 已完成接收 → 按接收单维度形成采购接收入库来源组 → 选择当前仓库 → 执行入库 → 耗材台账 + 库存 → PO 更新 → 采购回传

普通耗材：

耗材接收 → 接收确认 → 按接收单维度自动完成入库 → 已完成入库单 + 库存 → PO 更新 → 采购回传

#### 6.11.5 借用退库单打印

表头：

退库单号、退库时间、仓库名称、使用部门、员工信息。

明细：

序号、资产大类、品名、资产标签号、SN号、数量、退库原因、鉴定结果、备注。

页脚：

退库人（签字）/ 时间、库管员（签字）/ 时间。

借用归还不追加员工操作确认信息页。

#### 6.11.6 打印版式与异常

- 纸张和联次沿用现有打印模板。
- 单条打印、批量打印字段口径一致。
- 明细跨页时重复表头并展示页码。
- 空值打印为空白，不打印 null、undefined。
- 金额保留两位小数。
- 整数数量不展示无意义小数。
- 明细为空禁止生成正式打印单。
- 打印失败允许重试，不重复执行库存事务或生成新业务单号。
