# 库存管理 - 入库 PRD

## 1. 背景

入库用于承接资产、低值耐用品、耗材等物资进入仓库后的正式库存处理。

入库单既可以由用户在入库模块手工创建，也可以由资产接收、耗材接收等上游业务自动生成。

当前入库类型固定为：

| 入库类型 | 说明 |
|---|---|
| 新增入库 | 非采购接收场景，由用户手工新增物资并执行入库 |
| 采购接收 | 承接资产接收、耗材接收完成后的采购物资 |
| 退库入库 | 资产退库后重新进入仓库 |
| 借用归还 | 借用资产归还仓库 |

本需求需明确采购接收入库的完整来源、草稿占用、仓库匹配、机房资产拆单、正式入库后的台账与库存变化、采购系统回传，并完善新增入库、采购接收、退库入库、借用归还的页面字段及交互。

## 2. 入库单来源

### 2.1 来源矩阵

| 来源 | 入库类型 | 初始状态 | 仓库 | 是否需要执行入库 |
|---|---|---|---|---:|
| 入库模块手工创建新增入库 | 新增入库 | 草稿 | 用户选择 | Y |
| 入库模块手工创建采购接收 | 采购接收 | 草稿 | 按来源物资公司匹配 | Y |
| 普通资产接收完成 | 采购接收 | 草稿 | 按公司匹配 | Y |
| 服务器接收完成 | 采购接收 | 草稿 | 按公司匹配 | Y |
| 服务器备件接收完成 | 采购接收 | 草稿 | 按公司匹配 | Y |
| 网络设备接收完成 | 采购接收 | 草稿 | 按公司匹配 | Y |
| 网络设备备件接收完成 | 采购接收 | 草稿 | 按公司匹配 | Y |
| 低值耐用品接收完成 | 采购接收 | 草稿 | 按公司匹配耗材仓 | Y |
| 普通耗材接收完成 | 采购接收 | 已完成 | 按公司匹配耗材仓 | N |

| 用户手工创建借用归还 | 借用归还 | 草稿 | 用户选择有权限仓库 | Y |

### 2.2 机房资产拆单

服务器、服务器备件、网络设备、网络设备备件完成接收后：

1. 系统根据资产所属公司匹配目标仓库。
2. 在目标仓库确定后，再根据 NO 位置进行入库单拆分。
3. 同一公司、同一 NO 位置的资产可进入同一张采购接收入库草稿单。
4. 同一公司但 NO 位置不同的资产分别生成不同的采购接收入库草稿单。
5. NO 位置仅用于拆分入库单，不参与目标仓库匹配。

示例：

| 公司 | NO 位置 | 处理结果 |
|---|---|---|
| A公司 | NO-A | 入库草稿单1 |
| A公司 | NO-A | 入库草稿单1 |
| A公司 | NO-B | 入库草稿单2 |

草稿单1、草稿单2的目标仓库均为 A 公司匹配到的仓库。

## 3. 业务流程

### 3.1 系统自动生成采购接收入库草稿

适用于：

- 普通资产；
- 服务器；
- 服务器备件；
- 网络设备；
- 网络设备备件；
- 低值耐用品。

流程：

`完成接收 → 确定公司 → 按公司匹配目标仓库 → 机房资产按 NO 位置进一步拆单 → 创建采购接收入库草稿 → 进入入库列表 → 用户检查草稿 → 执行入库 → 正式入库 → 更新库存 / 台账 / PO → 回传采购系统`

系统自动生成的采购接收入库草稿：

- 入库类型固定为“采购接收”，不允许修改；
- 当前仓库由系统匹配，只读，不允许修改；
- 保留来源 PO、接收单及接收物资关系；
- 来源接收结果作为入库草稿的基础数据；
- 不提供【待入库物资】入口，不允许继续追加其他物资；
- 草稿状态允许删除当前入库物资，删除后释放该物资的入库占用。

### 3.2 手工创建采购接收入库

用户进入入库列表点击【创建】，选择入库类型“采购接收”。

通过【待入库物资】选择已经完成接收、尚未正式入库、且未被其他有效入库草稿占用的数据。

选择物资后：

- 系统根据来源物资所属公司匹配目标仓库；
- 当前仓库自动带出并只读；
- 同一张入库单仅允许加入目标仓库一致的物资；
- 保存草稿后，所选物资进入入库占用状态。

后续点击【执行入库】完成正式入库。

手工采购接收主要用于已完成接收但当前不存在有效入库草稿的数据，例如系统自动生成的采购接收入库草稿被删除后重新组建入库单。

### 3.3 普通耗材自动入库

普通耗材不进入待执行草稿。

耗材接收点击【接收确认】后：

`完成接收 → 按公司匹配耗材仓 → 增加耗材库存 → 自动生成已完成采购接收入库单 → 回传采购系统`

该入库单进入入库列表，用于查询、查看、打印和业务追溯，不允许再次编辑或执行入库。

### 3.4 新增入库

用户：

`创建入库单 → 选择新增入库 → 选择仓库 → 新增或批量导入物资 → 保存草稿 → 检查数据 → 执行入库 → 生成正式资产数据`

新增入库支持：

- 手工新增物资；
- 模板下载；
- Excel 导入；
- 数据导出。

### 3.5 退库入库 / 借用归还

用户分别选择待退库、待归还资产，维护对应业务信息后执行入库。

执行成功后：

- 入库单状态更新为已完成；
- 更新资产所在仓库及资产状态；
- 更新对应资产台账；
- 生成对应业务事务记录。

## 4. 通用规则

### 4.1 入库单状态

| 状态 | 说明 |
|---|---|
| 草稿 | 尚未正式入库，可按规则维护 |
| 已完成 | 已正式完成入库，只读 |

状态流转：

`草稿 → 已完成`

已完成单据不允许恢复草稿。

普通耗材接收产生的入库单创建时即为“已完成”。

### 4.2 入库类型切换

手工创建草稿时允许选择入库类型。

- 当前草稿尚无入库物资时，可直接切换入库类型。
- 当前草稿已经存在入库物资时，切换前进行二次确认。
- 确认切换后清空当前入库物资及对应临时维护数据，再按新入库类型展示页面字段。
- 系统自动生成的采购接收入库草稿不允许切换入库类型。

确认文案：

> 不同入库类型的字段和物资来源不同，切换后当前入库物资将被清空，是否继续？

### 4.3 仓库规则

#### 4.3.1 采购接收

采购接收目标仓库统一按照公司匹配。

| 匹配结果 | 处理 |
|---|---|
| 唯一匹配 | 正常生成或继续入库 |
| 未匹配 | 阻断 |
| 匹配多个 | 阻断并要求检查仓库配置 |

采购接收入库的目标仓库确定后只读，不允许人工修改，包括：

- 普通资产；
- 服务器；
- 服务器备件；
- 网络设备；
- 网络设备备件；
- 低值耐用品；
- 普通耗材。

手工采购接收入库在选择第一批待入库物资后，根据其公司自动匹配目标仓库，并锁定当前仓库。

#### 4.3.2 其他手工入库类型

新增入库、退库入库、借用归还由用户从有权限仓库中选择当前仓库。

当草稿已经存在入库物资后修改仓库：

- 进行二次确认；
- 确认后清空当前入库物资，避免公司、位置等仓库衍生信息与新仓库不一致；
- 用户需重新添加物资。

### 4.4 待入库物资池

采购接收的待入库物资必须同时满足：

1. 已完成接收；
2. 尚未完成正式入库；
3. 未被其他有效入库草稿占用。

以下数据不进入待入库物资池：

- 接收尚未完成；
- 已正式入库；
- 已被其他有效草稿入库单占用；
- 普通耗材已经自动完成入库的数据。

### 4.5 入库占用

物资加入有效草稿入库单后立即进入入库占用状态，不得再次出现在其他采购接收入库单的待入库物资中。

以下操作释放占用：

| 操作 | 结果 |
|---|---|
| 删除草稿入库单中的物资 | 对应物资重新进入待入库物资池 |
| 删除整张草稿入库单 | 整单物资重新进入待入库物资池 |

执行入库成功后，占用转为正式入库结果，不再释放。

### 4.6 草稿删除

入库列表仅允许删除草稿入库单。

删除前进行二次确认。

删除系统自动生成的采购接收入库草稿后：

- 不删除上游已完成接收单；
- 不回退接收状态；
- 不回退已接收数量；
- 仅释放入库占用；
- 对应物资重新进入待入库物资池，可重新组建采购接收入库草稿。

已完成入库单禁止删除。

### 4.7 PO 状态

PO 状态按累计接收和入库结果判断：

| 条件 | PO 状态 |
|---|---|
| 仍存在未完成接收数量 | 待接收 |
| 全部数量已接收，但仍存在未正式入库数量 | 已接收 |
| 全部数量均已正式入库 | 已入库 |

一张入库单完成不能直接决定整张 PO 状态，必须重新计算整张 PO 全部采购行的累计结果。

普通耗材接收确认时同步完成入库，其对应数量同时计入已接收数量和已入库数量。

### 4.8 执行入库事务

【执行入库】作为完整本地业务事务处理。

只有所有本地校验和业务写入全部成功后，才允许：

- 入库单由草稿变为已完成；
- 增加正式库存；
- 新增或更新资产 / 耗材台账；
- 更新相关 PO；
- 生成业务事务记录。

任一本地步骤失败：

- 入库单保持草稿；
- 页面已维护数据保留；
- 不增加正式库存；
- 不生成半完成台账数据；
- 不更新 PO 为已入库；
- 用户修正问题后可重新执行。

采购系统回传发生在本地正式入库成功之后，回传失败不回滚本地入库结果。

## 5. 入库单列表

### 5.1 查询条件

| 字段 | 交互方式 | 查询规则 |
|---|---|---|
| 入库单号 | 输入框 | 模糊查询 |
| 入库类型 | 下拉单选 | 新增入库 / 采购接收 / 退库入库 / 借用归还 |
| 单据状态 | 下拉单选 | 草稿 / 已完成 |
| PO 单号 | 输入框 | 模糊查询 |
| PR 单号 | 输入框 | 模糊查询 |
| 标签号 | 输入框 | 同时支持资产标签号、耗材标签号模糊查询 |
| 制单人 | 输入框 | 模糊查询 |
| 制单日期 | 日期范围 | 按起止日期查询 |

点击【查询】按照当前条件刷新列表。

点击【重置】清空全部查询条件。

“制单日期”使用单个日期范围控件。

### 5.2 列表字段

| 字段 | 规则 |
|---|---|
| 行号 | 当前分页连续序号 |
| 入库单号 | 蓝色链接；草稿进入编辑页，已完成进入详情页 |
| 申请单号 | 无值显示“-” |
| 单据状态 | 草稿 / 已完成 |
| 入库类型 | 新增入库 / 采购接收 / 退库入库 / 借用归还 |
| 入库仓库 | 仓库编码 + 名称 |
| 制单日期 | `yyyy-mm-dd` |
| 制单人 | 工号-姓名 |
| 物资数量 | 当前入库单总数量 |
| 是否刷卡领用 | 是 / 否 |
| 操作 | 草稿【编辑】；已完成【打印】 |

列表 Card 右上角展示当前查询结果数量：`共 X 条`。

分页默认每页 10 条，支持切换每页展示条数。

### 5.3 页面操作

列表支持：

- 【创建】
- 【删除】
- 【批量打印】

表格复选框允许选择草稿或已完成单据，由具体操作进行状态校验。

【删除】：

- 至少选择 1 张入库单；
- 所选单据必须全部为草稿；
- 包含已完成单据时提示 `仅草稿入库单允许删除`；
- 删除前进行二次确认；
- 删除采购接收草稿时同步释放对应待入库物资占用。

【批量打印】：

- 至少选择 1 张入库单；
- 所选单据必须全部为已完成；
- 包含草稿时提示 `仅已完成入库单允许打印`。

入库物资表中的标签号存在值时展示为蓝色详情入口，可点击打开“入库物资信息”；链接文本需支持光标拖选复制。

只读“入库物资信息”弹窗仅保留右上角关闭图标，不重复展示 footer【关闭】。

## 11. 校验与异常处理

### 11.1 通用校验

| 场景 | 校验 / 处理 |
|---|---|
| 执行入库 | 至少存在 1 条有效入库物资 |
| 执行入库 | 当前仓库有效 |
| 执行入库 | 必填字段已维护 |
| 删除入库单 | 所选单据必须全部为草稿 |
| 删除物资 | 仅草稿状态允许 |
| 已完成入库单 | 不允许编辑 |
| 入库数量 | 必须为大于 0 的有效数量 |
| 批量打印 | 所选单据必须全部为已完成 |

### 11.2 采购接收校验

| 场景 | 校验 / 处理 |
|---|---|
| 待入库物资 | 必须已完成接收 |
| 待入库物资 | 尚未正式入库 |
| 待入库物资 | 未被其他有效草稿占用 |
| 仓库 | 必须根据公司唯一匹配 |
| 自动生成采购草稿 | 入库类型不可修改 |
| 自动生成采购草稿 | 当前仓库不可修改 |
| 自动生成采购草稿 | 不允许继续追加待入库物资 |
| 手工采购草稿 | 同一单据所选物资必须匹配到同一仓库 |
| 重复加入 | 同一接收物资不得同时进入多张有效入库单 |
| 机房资产维保日期 | 维保结束日期不得早于维保开始日期 |

### 11.3 执行失败

本地执行过程中任一步骤失败：

- 入库单保持草稿；
- 不写正式库存；
- 不生成半完成台账；
- 不改变 PO 正式入库数量；
- 保留用户已经维护的草稿信息；
- 用户修正后可重新执行。

## 12. 执行入库后的数据变化

### 12.1 普通资产

正式执行入库成功后：

1. 入库单更新为已完成。
2. 创建正式资产台账卡片。
3. 资产状态更新为入库后的目标状态。
4. 写入目标仓库。
5. 保存标签号、SN、金额、配置、责任及业务属性等信息。
6. 更新 PO 已入库数量。
7. 重新判断 PO 状态。
8. 生成资产入库事务记录及相关报表数据。
9. 触发采购系统入库结果回传。

### 12.2 机房资产

除普通资产正式入库结果外：

- 保存 NO 位置；
- 保存服务信息；
- 保存维保开始日期、维保结束日期；
- 维保信息继续传入资产台账及相关财务数据；
- 向对应采购人员发送入库完成通知。

NO 位置只用于接收后生成入库草稿时拆单，不用于仓库匹配。

### 12.3 低值耐用品

执行采购接收入库成功后：

1. 入库单更新为已完成。
2. 增加目标耗材仓库存。
3. 生成对应低值耐用品耗材台账卡片。
4. 保存耗材标签号、SN、部件等信息。
5. 更新 PO 已入库数量。
6. 重新计算 PO 状态。
7. 生成对应库存事务记录。
8. 触发采购系统入库结果回传。

### 12.4 普通耗材

普通耗材在耗材接收确认时已经完成：

- 入库单生成并直接为已完成；
- 对应耗材仓库存已经增加；
- PO 已入库数量已经更新；
- 触发采购系统入库结果回传。

入库模块不再执行二次入库，仅提供查询、查看和打印。

### 12.5 PO

正式入库成功后只更新本次实际成功入库数量。

更新完成后根据整张 PO 的全部采购行重新计算状态，不允许简单使用当前入库单状态覆盖 PO 状态。

### 12.6 退库入库 / 借用归还

执行成功后：

- 入库单更新为已完成；
- 资产进入目标仓库；
- 资产状态更新为“在库-待处理”；
- 更新资产台账；
- 生成对应退库 / 归还事务记录。

## 13. 采购系统回传

采购相关入库完成后，系统向采购系统回传入库结果。

回传数据至少包含：

- 入库单号；
- 入库日期；
- PO 单号及 PO 行；
- 物料；
- 本次入库数量；
- 金额等采购侧闭环所需数据。

### 13.1 成功

采购回传状态更新为“成功”。

### 13.2 失败

采购回传状态更新为“失败”。

采购系统回传与本地入库是两个独立结果：

- 本地正式入库已经成功时，不因采购回传失败回滚库存、台账、PO 本地数据；
- 已完成入库单保持“已完成”；
- 用户可在入库单详情点击【重试采购回传】；
- 重试成功后，采购回传状态更新为“成功”；
- 重试失败继续保持“失败”，允许后续再次重试。

## 14. 权限

入库权限按照业务仓库及人员权限控制，至少区分：

- 入库单查看权限；
- 创建权限；
- 草稿编辑权限；
- 执行入库权限；
- 删除草稿权限；
- 打印权限；
- 仓库可操作范围。

具体权限矩阵后续根据权限方案补充。

## 15. 后续衔接

### 15.1 普通资产

`资产接收 → 已完成接收单 → 采购接收入库草稿 → 执行入库 → 资产台账卡片 → PO 已入库 → 采购系统回传`

### 15.2 机房资产

`资产接收 → 已完成接收单 → 按 NO 位置拆分采购接收入库草稿 → 执行入库 → 资产台账卡片 → PO 已入库 → 采购系统回传`

目标仓库始终按照公司匹配，NO 位置仅用于拆单。

### 15.3 低值耐用品

`耗材接收 → 已完成接收单 → 采购接收入库草稿 → 执行入库 → 耗材台账 + 库存 → PO 已入库 → 采购系统回传`

### 15.4 普通耗材

`耗材接收 → 接收确认 → 自动完成入库 → 已完成入库单 + 库存 → PO 已入库 → 采购系统回传`
