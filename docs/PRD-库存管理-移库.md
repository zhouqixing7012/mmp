# 库存管理 - 移库 PRD

## 1. 背景

移库用于处理资产及低值耐用品在不同仓库之间的库存转移。

一次完整移库包含两个阶段：

`来源仓调出 → 集团通用在途库 → 目标仓接收`

来源仓执行调出后，物资不直接成为目标仓库存，而是先进入 **V00001-集团在途总库**。目标仓完成接收后，物资才正式进入目标仓。

移库过程中需要完整记录实际移出仓库、实际移入仓库、移库物资明细、资产验证情况、来源仓调出结果、在途状态、目标仓接收或驳回结果、资产卡片变化、调出/调入事务、驳回产生的反向移库关系，以及操作人与操作时间。

当前移库范围暂不包含普通耗材数量型移库。

## 2. 业务范围

### 2.1 支持物资

| 物资类型 | 是否支持移库 | 处理方式 |
|---|---:|---|
| 资产 | Y | 按标签/SN逐件移库 |
| 低值耐用品 | Y | 按耗材标签/SN逐件移库 |
| 普通耗材 | N | 当前不提供移库能力 |

低值耐用品在移库过程中按照具有唯一标签/SN的实物进行逐件管理，不采用普通耗材的数量型库存移库模式。

## 3. 角色与权限

| 角色 | 可执行操作 | 限制 |
|---|---|---|
| 来源仓出库管理员 | 创建、编辑、添加/删除物资、保存草稿、移库提交、删除草稿 | 必须具备来源仓出库权限 |
| 目标仓入库管理员 | 查看待接收单、验证、接收、驳回 | 必须具备目标仓入库权限 |
| 单据查看人员 | 查看单据、明细、打印、导出 | 按数据权限控制 |
| 系统 | 锁定/解锁资产、更新资产卡片、生成事务、生成反向移库单、发送通知、同步数据 | 自动执行 |

### 3.1 发起权限

用户只能查看、创建和操作本人具有出库权限的仓库对应移库单。

创建时，“当前仓库”仅允许选择：

- 当前账号具有出库权限；
- 仓库状态有效；
- 一级仓库。

### 3.2 接收权限

接收列表只展示当前用户具有目标仓入库权限的移库单。

无目标仓权限的用户不展示对应待接收数据，也不允许验证、接收或驳回。

## 4. 核心业务规则

### 4.1 单据粒度

一张移库单固定对应 **一个实际移出仓库 + 一个实际移入仓库**，允许包含多条物资明细。

不得在一张移库单内混用多个来源仓或多个目标仓。

### 4.2 仓库规则

当前仓库为实际移出仓库；对方仓库为实际移入仓库。

二者：

- 必填；
- 不得相同；
- 必须属于同一财务公司。

### 4.3 在途库

来源仓正式调出后，资产统一进入 **V00001-集团在途总库**。

目标仓正式接收以前：

- 不属于来源仓库存；
- 不属于目标仓库存；
- 处于移库在途状态。

## 5. 状态规则

### 5.1 移库单状态

| 状态 | 业务含义 | 可执行操作 |
|---|---|---|
| 草稿 | 尚未执行正式调出 | 编辑、添加/删除明细、保存、删除、提交 |
| 待接收 | 来源仓已经调出，仍存在未完成接收的明细 | 验证、接收、驳回 |
| 已完成 | 原单全部有效明细均已进入终态 | 查看、打印、导出 |

移库单不设置“已驳回”单据状态。驳回是明细处理结果，原单中的驳回物资会生成新的反向移库单。

### 5.2 明细状态

| 状态 | 含义 |
|---|---|
| 草稿 | 尚未调出 |
| 已取消 | 草稿阶段取消，不执行调出 |
| 待接收 | 已调出，目前位于在途库 |
| 已接收 | 已进入目标仓 |
| 已驳回 | 目标仓拒绝接收，已进入反向移库链路 |

### 5.3 单据完成条件

存在任意“待接收”明细时，原移库单继续保持“待接收”。

当全部有效明细均变成已接收、已驳回、已取消等终态时，原移库单变为“已完成”。

例如：5条移库物资中3条接收、2条驳回，则原移库单已完成，同时2条驳回物资进入反向移库单。

## 6. 整体业务流程

### 6.1 正常移库

`创建移库草稿`
→ 选择来源仓、目标仓
→ 添加资产/低值耐用品
→ 系统锁定新增物资
→ 保存草稿
→ 点击【移库提交】
→ 来源仓正式调出
→ 资产进入 V00001 在途库
→ 单据进入待接收
→ 目标仓验证物资
→ 分批执行移库接收
→ 资产进入目标仓
→ 全部明细终态
→ 原移库单已完成

### 6.2 驳回

`待接收资产`
→ 填写驳回原因
→ 当前行变为已驳回
→ 系统自动生成反向移库单
→ 原移库单继续处理其他行
→ 原单全部行终态后变为已完成
→ 原来源仓在反向移库单中执行接收
→ 被驳回资产重新进入原来源仓

## 9. 资产锁

### 9.1 新增明细

将资产/低值耐用品加入移库草稿时：

1. 记录进入本流程前的原锁状态。
2. 原本未锁定的实物，由当前移库流程进行锁定。
3. 原本已经被其他业务锁定的实物禁止加入移库单。

统一提示：`当前资产已被其他业务锁定，无法移库`

不提供“确认后强制移库”等绕过操作。

### 9.2 删除

草稿删除明细或删除整张移库单：

- 如果资产进入流程前未锁定，则解锁；
- 如果资产原本已经处于锁定状态，则不改变原锁状态。

### 9.3 接收完成

正常移库流程完成后，当前流程增加的锁释放，并恢复进入流程前正确的锁定状态。

## 14. 移库提交

### 14.1 提交前校验

点击【移库提交】后重新检查：

1. 移库单存在；
2. 当前仓库有效；
3. 对方仓库有效；
4. 当前仓库不等于对方仓库；
5. 至少存在一条有效明细；
6. 单据不存在重复标签号；
7. 每件资产仍位于当前来源仓；
8. 每件资产仍处于可移库状态；
9. 每件资产仍由本移库流程正常锁定；
10. V00001集团在途总库有效。

任一失败时整单不执行正式调出。

### 14.2 资产快照

正式调出前，按照每条资产/低值耐用品保存本次移库快照。后续单据详情读取移库快照，而不是当前资产实时卡片。

## 15. 来源仓正式调出

正式提交成功后：`来源仓 → V00001集团在途总库`

每条物资明细状态变为待接收，单据状态变为待接收。

资产卡片：

| 字段 | 调出后 |
|---|---|
| 仓库 | V00001-集团在途总库 |
| City | 保持原值 |
| Building | 保持原值 |
| Floor | 保持原值 |

目标仓接收前，不提前写入目标仓位置。

### 15.1 事务

资产化实物来源仓调出：每件生成一条事务，事务类型为 **24**，事务来源为当前移库单号。

## 16. PC - 移库接收列表

移库接收单不能手工创建。

正常来源为移库发起单完成正式调出；反向来源为目标仓驳回待接收明细后系统自动生成。

### 16.1 通知

生成待接收数据后，向对应目标仓库负责人发送通知。

超过7天仍未接收完成时，从超期开始每日向目标仓库负责人发送催办通知，直到接收流程结束。

### 16.2 查询条件

查询条件包括移库单号、单据状态、制单人、制单日期、资产扫描。只展示当前用户具备目标仓入库权限的单据。

## 18. 资产验证

支持扫码枪、手工输入、狐小E。

### 18.1 自动扫描验证

成功定位当前待接收明细后：`未验证 → 已验证`。系统记录验证时间和验证方式。

### 18.2 手工验证

手工执行验证时验证说明必填，成功后记录验证说明。

### 18.3 取消验证

待接收明细允许 `已验证 → 未验证`。已接收、已驳回明细禁止取消验证。

## 19. 移库接收确认

支持多次分批接收。

用户勾选 **已验证 + 待接收** 明细后点击【移库接收确认】，弹出 `是否确定执行移库接收？`。

确认后仅处理当前勾选行：

- 明细变为已接收；
- 更新对应发起单明细；
- 更新资产卡片；
- 生成调入事务；
- 记录接收仓管员；
- 记录接收时间。

取消则关闭确认框，页面数据不变。

不存在“已验证 + 待接收”选中明细时提示 `无已验证待接收的资产`，不执行接收。

| 仓库 | 目标仓 |
| City | 目标仓City |
| Building | 目标仓Building |
| Floor | 目标仓Floor |
| Room | 清空 |
| 责任人 | 目标仓虚拟库管员 |
| 费用账户 | 按目标组织信息重新生成 |
| 资产标记 | 使用接收明细维护值 |
| 锁状态 | 恢复流程前正确状态 |

目标仓 Building 为空时，在目标 City 下查找名称为“缺省”的 Building。目标仓 Floor 为空时使用编码 **299**。

### 20.1 调入事务

正式接收时，每件资产化实物生成一条事务，事务类型为 **25**，事务来源为当前移库单号。

## 21. 移库驳回

### 21.1 操作范围

目标仓可以选择当前待接收明细进行驳回。已接收明细禁止驳回。

### 21.2 驳回原因

驳回原因必填，最多 **200字**。

### 21.3 驳回结果

点击【移库驳回】后：

1. 本次选中待接收行变为已驳回；
2. 不直接将资产退回原来源仓；
3. 系统自动针对本次驳回明细创建一张新的反向移库单；
4. 原单继续处理剩余待接收行；
5. 原单全部行终态后变为已完成。

## 22. 反向移库单

反向移库是目标仓驳回后的系统自动处理结果。

### 22.1 仓库关系

原单 `A仓 → B仓`，B仓驳回后反向单为 `B仓 → A仓`。

| 字段 | 反向单 |
|---|---|
| 移出仓库 | 原单目标仓 |
| 移入仓库 | 原单来源仓 |

被驳回资产实际仍处于集团在途库，反向单用于承接其返回原来源仓的接收链路。

### 22.2 生成内容

反向单继承本次被驳回明细、标签号、SN、物资信息、原移库单号、驳回原因，并记录来源移库单号用于正向/反向业务追溯。

### 22.3 初始状态

反向移库单生成后状态为待接收。

不重新要求原目标仓执行一次来源仓调出，因为被驳回物资尚未离开在途库。

由原来源仓管理员执行移库接收，完成 `V00001集团在途总库 → 原来源仓`。反向接收完成后，资产重新成为原来源仓库存。

## 23. 查看移库物资详情

点击标签号进入只读“移库物资信息”。页面读取本次移库历史快照。

### 23.1 移库单信息

展示移库单号、当前仓库、对方仓库、来源移库单号、出库仓库管理员。

### 23.2 资产信息

展示标签号、SN、原值、净值、资产状态、板块、使用公司、使用部门、成本中心、业务线、费用账户、管理人、City、Building、Floor、Room、启用日期、用途。

### 23.3 移库结果

展示目标仓、数量、调出说明、接收说明、资产验证、接收仓管员、接收时间、移库状态。

## 24. 删除

### 24.1 删除明细

仅草稿允许。至少选择1行。点击【删除物资】后二次确认：

- 删除明细；
- 释放本流程产生的资产锁；
- 重新计算行号。

### 24.2 删除整单

仅草稿允许。

删除前遍历全部明细、释放本流程增加的资产锁，再删除明细及移库单。待接收和已完成单据禁止删除。

## 25. Excel 导入

### 25.1 模板字段

| 字段 | 必填规则 |
|---|---|
| 标签号 | 与SN至少填写一项 |
| SN | 与标签号至少填写一项 |
| 移库出库说明 | 选填 |

不提供物料编码/普通耗材数量相关移库字段。

### 25.2 导入规则

支持 Excel 2003 `.xls` 和 Excel 2007+ `.xlsx`，从第2行读取。

资产通过标签号、SN匹配。

### 25.3 原子导入

只要任意一行校验失败，本次 Excel 导入全部不保存。

错误写入 Excel“导入结果”列，页面提示 `数据校验失败，请下载结果查看！`。

无有效数据提示 `未找到需要导入的数据行`。

文件格式错误提示 `上传文件格式不正确，仅支持 Excel 2003 或 Excel 2007 格式数据文件！`。

## 26. 接收 Excel

目标仓可下载当前移库单接收模板。

模板预填标签号、SN、物资说明、数量、调出说明；接收人员补充接收说明。

上传后只允许更新当前移库单已存在的明细，不得通过接收 Excel 新增物资。

## 27. 导出与打印

### 27.1 列表导出

包含移库单号、单据状态、移出仓、移入仓、制单日期、制单人、物资数量、接收人。

### 27.2 明细导出

包含移库单号、单据状态、当前仓、移出仓、移入仓、标签号、SN、物资总类、物资说明、数量、调出说明、接收说明、验证状态、明细状态、接收人、接收时间。

### 27.3 打印

打印移库单头、移出仓、移入仓及移库明细。

## 28. 移动端

移动端与PC采用同样的单据状态、明细状态、调出、接收、驳回和反向移库规则。

### 28.1 选择仓库

按当前账号仓库权限展示，支持ERP公司分组及`编码.名称`搜索。

### 28.2 页面入口

包括：我发起的、我接收的、创建移库、快捷扫码。

### 28.3 我发起的

展示草稿、待接收、已完成。

### 28.4 我接收的

优先展示待接收。

### 28.5 创建

维护当前仓库、对方仓库、备注。不展示运输方式、预计到达时间。

### 28.6 添加物资

支持扫码、标签查询、SN查询、查看资产、加入单据。普通耗材不允许添加。

### 28.7 验证与接收

支持单行扫码验证、取消验证、单行/多行接收、单行/多行驳回。

PC与移动端的驳回处理结果完全一致：原单明细已驳回 → 原单最终完成 → 自动生成反向移库单。

## 30. 数据更新与审计

### 30.1 资产事务

| 阶段 | 事务类型 | 粒度 | 来源 |
|---|---:|---|---|
| 来源仓 → 在途库 | 24 | 每个资产化实物一条 | 移库单号 |
| 在途库 → 目标仓 | 25 | 每个资产化实物一条 | 移库单号 |
| 驳回物资返回来源仓 | 按反向移库接收逻辑 | 每个实物一条 | 反向移库单号 |

### 30.2 历史快照

来源仓正式调出前保存资产快照。

后续查看历史移库单时，优先展示移库发生时的数据，不得因为资产后来再次移库、更换责任人、修改位置或修改资产属性导致历史移库单内容变化。

### 30.3 单据关联

反向移库单必须保存来源移库单号，原移库单也应能够查询其生成的反向移库单，形成 `原移库单 ↔ 反向移库单` 双向追溯。

### 30.4 外部同步

移库核心业务成功后再进入外部同步队列。

同步失败：

- 不回滚已经成功的本地移库；
- 记录失败状态；
- 支持后续重试。
