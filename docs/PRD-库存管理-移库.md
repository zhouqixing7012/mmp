# 库存管理 - 移库 PRD

## 1. 背景

移库用于处理资产及低值耐用品在不同仓库之间的库存转移。

完整移库分为两个业务阶段：

`移出仓库正式调出 → V00001-集团在途总库 → 移入仓库正式接收`

物资从移出仓库正式调出后，先进入 **V00001-集团在途总库**。移入仓库完成接收后，物资才正式成为移入仓库库存。

移库需要完整记录移出仓库、移入仓库、移库物资、验证结果、调出结果、在途状态、接收或驳回结果、物资卡片变化、移库调出记录、移库调入记录、反向移库关系、操作人及操作时间。

当前范围只包含资产和低值耐用品逐件移库。普通耗材数量型移库不在本功能范围内。

## 2. 权限

### 2.1 权限原则

移库使用两层权限：

1. 公司、板块控制用户可查看的数据范围。
2. 仓库权限控制用户可以对哪些仓库执行创建、编辑、调出、验证、接收、驳回、删除、打印和导出。

打开单据、实时保存、提交调出、验证、接收、驳回、删除、打印和导出时，均重新校验当前用户权限。

### 2.2 发起权限

用户具备移出仓库出库权限后，可以：

- 查看该移出仓库发起的全部移库单，不限制单据创建人；
- 创建移库单；
- 编辑草稿；
- 添加、编辑和删除草稿物资；
- 删除草稿；
- 提交正式调出；
- 查看移库结果；
- 在 PC 端按单据状态执行打印和导出。

PC 和移动端使用相同的数据范围。

移出仓库候选必须同时满足：

1. 当前用户具有该仓库出库权限；
2. 仓库状态有效；

### 2.3 接收权限

用户具备移入仓库入库权限后，可以：

- 查看该移入仓库的全部待接收及历史移库单，不限制单据创建人；
- 验证待接收物资；
- 接收待接收物资；
- 驳回待接收物资；
- 查看接收结果；
- 在 PC 端导出接收列表和接收明细。

PC 和移动端使用相同的数据范围。

### 2.4 查看、打印与导出权限

1. 用户只能查看其公司、板块数据范围及仓库权限范围内的移库单。
2. PC 发起列表和接收列表均支持导出当前查询结果。
3. 已完成移库单允许打印。
4. 草稿、出库待接收和已驳回移库单不显示打印入口。

## 3. 通用规则

### 3.1 支持物资

| 物资类型 | 是否支持 | 处理方式 |
|---|---:|---|
| 资产 | 是 | 按资产标签号或 SN 逐件移库 |
| 低值耐用品 | 是 | 按低值耐用品标签号或 SN 逐件移库 |
| 普通耗材 | 否 | 不进入移库候选范围 |

资产和低值耐用品均按具有唯一标签号或 SN 的实物管理。移库数量取当前实物数量，不允许用户手工修改。

### 3.2 PC 与移动端能力

| 能力 | PC | 移动端 |
|---|---:|---:|
| 发起移库 | 是 | 是 |
| 查看移出仓库发起单据 | 是 | 是 |
| 查看移入仓库接收单据 | 是 | 是 |
| 扫码添加物资 | 否 | 是 |
| 手工选择物资 | 是 | 是 |
| Excel 导入物资 | 是 | 否 |
| 扫码枪验证 | 是 | 否 |
| 手工验证 | 是 | 否 |
| 未验证原因填写后接收 | 否 | 是 |
| 手机扫码验证 | 否 | 是 |
| 分批接收 | 是 | 是 |
| 驳回物资 | 是 | 是 |
| 打印 | 是 | 否 |
| Excel 导出 | 是 | 否 |
| 草稿编辑和删除 | 是 | 是 |

PC 与移动端使用相同的仓库、状态、实时保存、锁、调出、接收、驳回和反向移库规则。移动端未验证直接接收的条件见第 5.10 节。

### 3.3 单据粒度

一张移库单固定对应：

- 一个移出仓库；
- 一个移入仓库；
- 一条或多条逐件物资明细。

一张移库单不能混用多个移出仓库或多个移入仓库。

### 3.4 仓库规则

正式提交移库前，移出仓库和移入仓库：

1. 均为必填；
2. 均必须为状态有效的仓库；
3. 必须属于同一财务公司；
4. 不能为同一仓库。

点击移出仓库或移入仓库字段时打开仓库选择器。

仓库选择器查询条件：

| 查询条件 | 规则 |
|---|---|
| 仓库编码 | 支持包含匹配 |
| 仓库名称 | 支持包含匹配 |
| 财务公司 | 支持按公司筛选 |

仓库选择器结果字段：

| 字段 | 规则 |
|---|---|
| 仓库编码 | 仓库唯一编码 |
| 仓库名称 | 仓库名称 |
| 财务公司 | 仓库所属财务公司 |

仓库选择为单选，选择后回填“仓库编码.仓库名称”。

### 3.5 在途库规则

移出仓库正式调出后，物资统一进入 **V00001-集团在途总库**。

移入仓库正式接收前，物资处于移库在途状态。物资卡片仓库为集团在途总库，位置仍保留调出前的信息，不提前写入移入仓库位置。

### 3.6 移库单状态

| 状态 | 业务含义 | 可执行操作 |
|---|---|---|
| 草稿 | 已形成移库草稿，尚未执行正式调出 | 编辑、添加/删除物资、删除草稿、提交调出 |
| 出库待接收 | 移出仓库已正式调出，仍存在待接收明细 | 查看、验证、接收、驳回、导出 |
| 已完成 | 全部明细已接收，或不存在待接收明细且存在已接收与已驳回混合结果 | 查看、打印、导出 |
| 已驳回 | 全部明细均已驳回 | 查看、导出 |

### 3.7 明细状态

| 状态 | 业务含义 |
|---|---|
| 草稿 | 已实时保存到草稿，尚未正式调出 |
| 待接收 | 已正式调出，目前位于集团在途总库 |
| 已接收 | 已由移入仓库正式接收 |
| 已驳回 | 已被移入仓库驳回，并已进入反向移库链路 |

草稿删除物资时直接移除明细，删除后的明细不再参与单据状态计算。

### 3.8 单据状态计算

移库单状态按全部现存明细计算：

1. 任意明细仍为“待接收”时，单据状态为“出库待接收”。
2. 全部明细均为“已接收”时，单据状态为“已完成”。
3. 全部明细均为“已驳回”时，单据状态为“已驳回”。
4. 不存在待接收明细，且同时存在“已接收”和“已驳回”时，单据状态为“已完成”。

例如：5 条物资中 3 条接收、2 条驳回，原移库单状态为“已完成”，2 条已驳回物资进入反向移库单。

### 3.9 实时保存

新建移库单时：

1. 用户先选择移出仓库，可以继续选择移入仓库并填写备注。
2. 尚未成功添加物资时，不生成空移库单。
3. 首次成功添加物资时，系统自动生成以 `TS` 开头的移库单号，同时保存单头、首条明细和本流程锁。
4. 草稿生成后，移出仓库、移入仓库、备注、移库说明及明细新增、编辑、删除均实时保存。
5. 实时保存失败时，本次修改不生效，页面保留失败前已保存内容，并提示失败原因。

用户离开已有物资的草稿页面时，草稿和本流程锁继续保留。用户可以重新进入草稿继续处理；删除明细、删除草稿或正式完成对应流程时按锁规则释放。

### 3.10 物资锁

#### 3.10.1 添加物资

1. 物资成功加入草稿时，系统立即保存明细并增加本流程锁。
2. 已被其他业务锁定的物资不能加入移库单。
3. 同一标签号在同一张移库单中只能存在一条。

物资被其他业务锁定时提示：

> 当前物资已被其他业务锁定，无法移库

#### 3.10.2 删除及修改移出仓库

1. 删除草稿明细时，释放该明细对应的本流程锁。
2. 删除整张草稿时，释放全部明细对应的本流程锁。
3. 草稿已有物资时修改移出仓库，需要先确认清空全部物资；确认后释放全部明细锁、清空明细，再保存新的移出仓库。

#### 3.10.3 调出、接收和驳回

1. 正式调出后，本流程锁继续保留至物资完成接收或反向接收。
2. 正常接收完成后，释放该物资的本流程锁。
3. 物资被驳回时，本流程锁随物资转入反向移库单，反向接收完成后释放。

### 3.11 历史信息

来源仓正式调出前，按每件资产或低值耐用品固定保存本次移库信息。

历史移库详情按移库历史记录展示当时的物资、组织和位置等信息，不随物资后续再次移库、责任人变化、位置变化或卡片维护而改变。原值和净值按资产标识重新查询价值资料，不使用移库发生时的历史快照。

### 3.12 通知与催办

1. 正式调出并形成待接收物资后，通知移入仓库全部有效负责人。
2. 反向移库单形成后，通知该反向单移入仓库的全部有效负责人。
3. 正常移库从正式调出成功时间起算；反向移库从反向单生成时间起算。
4. 待接收时间超过 7 天后，从第 8 天开始每日向对应仓库全部有效负责人发送催办通知。
5. 当前单据全部明细进入已接收或已驳回状态后停止催办。
6. 通知发送失败时保留失败记录，并在下一次通知任务中继续发送。
7. 通知失败不改变移库单、明细和物资状态。

## 4. PC 页面字段及交互

### 4.1 页面导航

PC 移库页面顶部提供：

- 【发起单据】；
- 【接收单据】。

进入移库单编辑、查看或接收详情后，页面使用独立详情视图。从详情返回列表时，恢复进入详情前的查询条件、分页页码和每页条数。

列表公共规则：

1. 不同查询条件之间使用 AND。
2. 未填写的查询条件不参与过滤。
3. 点击【查询】或【重置】后返回第 1 页并清空当前勾选。
4. 【重置】清空当前列表全部查询条件。
5. 默认按制单日期降序排列；制单日期相同时按移库单号降序排列。

### 4.2 发起列表

#### 4.2.1 数据范围

展示当前用户拥有出库权限的移出仓库所发起的全部移库单，不按制单人过滤数据范围。

#### 4.2.2 查询条件

| 字段 | 控件 | 查询规则 |
|---|---|---|
| 移库单号 | 输入框 | 支持包含匹配和回车查询 |
| 单据状态 | 下拉 | 草稿 / 出库待接收 / 已完成 / 已驳回 |
| 制单人 | 人员选择器 | 精确匹配 |
| 制单日期 | 日期范围 | 包含开始日期和结束日期 |
| 物资扫描 | 输入框 | 支持标签号或 SN；扫码枪或人工输入后回车 |

物资扫描用于筛选发起列表。无论匹配 0 张、1 张或多张单据，均停留在列表展示查询结果。

点击制单人字段打开人员选择器。人员选择器支持按员工编号、员工姓名、部门查询，结果展示员工编号、员工姓名和部门，每次选择一人。

#### 4.2.3 列表字段

| 字段 | 规则 |
|---|---|
| 行号 | 按当前分页连续编号 |
| 移库单号 | 蓝色链接，支持拖选复制；点击进入编辑或查看 |
| 单据状态 | 草稿 / 出库待接收 / 已完成 / 已驳回 |
| 移出仓库 | 编码.名称 |
| 移入仓库 | 编码.名称 |
| 制单日期 | `yyyy-MM-dd` |
| 制单人 | 工号-姓名 |
| 物资数量 | 当前明细数量汇总，右对齐，按业务原值展示 |

列表右上角展示“共 X 条”，支持分页和每页条数切换。

无查询结果时展示“暂无发起单据”。

移库单号进入规则：

- 草稿进入编辑页；
- 出库待接收、已完成、已驳回进入查看页。

#### 4.2.4 列表操作

提供：

- 【创建】；
- 【删除】；
- 【导出】。

删除规则：

1. 至少选择一张移库单。
2. 仅草稿允许删除。
3. 删除前进行二次确认。
4. 删除草稿时释放全部明细的本流程锁。

【导出】导出当前查询结果，不受当前勾选影响，文件格式为 Excel `.xlsx`。

### 4.3 创建及编辑移库单

#### 4.3.1 单据信息

| 字段 | 控件/展示 | 必填 | 规则 |
|---|---|---:|---|
| 移库单号 | 只读文本 | - | 首次成功添加物资后自动生成；生成前显示“添加物资后自动生成” |
| 单据类型 | 只读文本 | - | 固定为“移库单” |
| 单据状态 | 只读状态 | - | 草稿 |
| 移出仓库 | 仓库选择器 | 添加物资前必填 | 当前用户具有出库权限的有效仓库 |
| 移入仓库 | 仓库选择器 | 移库提交前必填 | 有效仓库；与移出仓库属于同一财务公司且不得相同 |
| 制单人 | 只读文本 | - | 首次生成草稿时记录当前操作人，格式为“工号-姓名” |
| 制单日期 | 只读日期 | - | 首次生成草稿时记录当前日期 |
| 来源移库单号 | 条件只读 | 否 | 反向移库单展示原移库单号 |
| 备注 | 多行文本 | 否 | 最多 60 字；草稿生成后实时保存 |

#### 4.3.2 修改移出仓库

草稿无物资时，修改移出仓库后保存当前页面值，并重新选择移入仓库。

草稿已有物资时，提示：

> 修改移出仓库后将清空当前移库明细，是否继续？

确认后：

1. 释放全部明细的本流程锁；
2. 删除全部移库明细；
3. 清空当前勾选；
4. 保存新的移出仓库；
5. 清空移入仓库，等待重新选择。

取消后保持原数据。

#### 4.3.3 添加方式

添加物资前必须先选择移出仓库。

提供：

1. 【添加物资】：打开物资选择弹窗；
2. 【物资扫描】：扫描或输入标签号、SN 后回车，直接定位、校验并添加物资；
3. 【Excel导入】：按模板批量校验并添加物资。

首次成功添加物资时自动生成草稿单号并实时保存。

#### 4.3.4 扫描添加

物资扫描是直接添加动作。每次处理完成后自动清空输入框，继续等待下一次扫描。

| 场景 | 处理结果 |
|---|---|
| 未选择移出仓库 | 提示“请先选择移出仓库” |
| 标签号或 SN 无法精确定位 | 提示“物资不存在或不在移出仓库内！” |
| 物资不属于移出仓库 | 提示“物资不存在或不在移出仓库内！” |
| 当前单据已存在该物资 | 提示“该物资已添加，请扫描其他物资” |
| 物资当前无库存 | 提示“物资不在库” |
| 物资被其他业务锁定 | 提示“当前物资已被其他业务锁定，无法移库” |
| 普通耗材或其他不支持类型 | 提示“当前物资类型暂不支持移库” |
| 校验通过 | 生成或更新草稿，保存明细并加锁 |

扫描成功或失败均不改变明细列表筛选状态；明细区域始终展示当前草稿全部物资。

### 4.4 草稿物资明细

#### 4.4.2 明细操作

提供：

- 【添加物资】；
- 【删除物资】；
- 【模板下载】；
- 【Excel导入】。

删除物资规则：

1. 至少选择一条草稿明细。
2. 删除前进行二次确认。
3. 删除成功后实时保存，释放对应本流程锁，并重新连续编号。

页面底部提供：

- 【移库提交】；
- 【返回】。

### 4.5 添加及编辑物资弹窗

#### 4.5.1 弹窗入口

### 4.9 物资验证

验证支持：

- 扫码枪；
- 手工输入标签号；
- 手工验证；
- 狐小E验证。

#### 4.9.1 扫码枪和手工输入

接收详情的“物资扫描”用于直接验证物资。

1. 仅在单据状态为“出库待接收”时展示。
2. 扫描或输入资产、低值耐用品标签号后回车执行验证。
3. 每次处理完成后自动清空输入框。
4. 扫描不会筛选下方明细，接收明细始终展示当前单据全部物资。

处理顺序：

1. 在当前接收单明细中按标签号精确匹配。
2. 未匹配时提示“该物资不在接收单中，请扫描其他物资”。
3. 已验证时提示“该物资已扫描，请扫描其他物资”。
4. 已接收或已驳回时提示“当前物资已处理，不能重复验证”。
5. 匹配到“未验证 + 待接收”明细时，更新为已验证，记录验证方式和验证时间，并自动勾选该行。

#### 4.9.2 手工验证

只有“未验证 + 待接收”明细提供【手工验证】。

手工验证时验证说明必填。成功后记录：

- 验证状态为已验证；
- 验证方式为手工；
- 验证时间；
- 验证说明。

#### 4.9.3 狐小E验证

狐小E识别物资标签号后，将标签号传入当前接收单验证。

1. 狐小E使用与扫码枪相同的匹配、状态检查和提示规则。
2. 验证成功后记录验证方式为狐小E、验证时间，并自动勾选对应明细。
3. 未匹配、已验证、已处理时使用第 4.9.1 节对应提示。

验证成功后保持“已验证”，PC 和移动端均不能恢复为未验证。

### 4.10 移库接收确认

移库支持多次分批接收。

接收条件：

1. 至少勾选一条明细；
2. 所选明细全部为“已验证 + 待接收”；
3. 当前用户具有移入仓库入库权限；
4. 物资仍位于集团在途总库；
5. 移入仓库仍然有效；
6. 费用账户可以根据移入仓库及目标组织信息生成。

点击【移库接收确认】后提示：

> 是否确定执行移库接收？

确认后仅处理本次勾选明细。

任一所选明细校验失败，或任一所选明细费用账户生成失败时，本次勾选明细整批不接收；未勾选明细不受影响。页面保留勾选结果并提示具体失败原因。

不存在符合条件的勾选明细时提示：

> 无已验证待接收的物资

### 4.11 移库驳回

待接收物资无需先验证即可驳回。已接收、已驳回明细不能再次驳回。

点击【移库驳回】后打开驳回窗口：

| 字段 | 必填 | 规则 |
|---|---:|---|
| 驳回原因 | 是 | 最多 200 字 |

一次可以勾选一条或多条待接收明细。确认驳回后：

1. 本次勾选明细变为已驳回；
2. 针对本次勾选明细生成一张反向移库单；
3. 一次勾选多条时，多条明细进入同一张反向移库单；
4. 多次执行驳回时，每次生成一张新的反向移库单；
5. 原移库单继续处理剩余待接收明细；
6. 重新计算原移库单状态。

### 4.12 反向移库

反向移库用于承接已驳回物资返回原移出仓库的流程。

原单业务方向为 `A 移出仓库 → B 移入仓库` 时，反向单业务方向记录为：

`B 原移入仓库 → A 原移出仓库`

被驳回物资实际仍位于 V00001-集团在途总库，因此反向移库不再执行一次调出。反向单生成后直接进入“出库待接收”，由原移出仓库管理员完成：

`V00001-集团在途总库 → A 原移出仓库`

反向单字段：

| 字段 | 规则 |
|---|---|
| 移出仓库 | 原单的移入仓库 |
| 移入仓库 | 原单的移出仓库 |
| 来源移库单号 | 原移库单号 |
| 单据状态 | 出库待接收 |
| 物资明细 | 本次被驳回明细 |
| 驳回原因 | 原样带入 |

反向移库单的制单人显示“系统生成”，制单日期取反向单生成日期。

反向移库单进入原移出仓库的接收列表，并使用与正常移库单相同的验证、接收和驳回规则。反向单再次发生驳回时，按本次驳回物资继续生成新的反向移库单。

原移库单保存其生成的全部反向移库单号，反向移库单保存来源移库单号，支持双向追溯。

### 4.14 Excel 导入

Excel 导入仅用于发起阶段批量添加移库物资和移库说明。

#### 4.14.1 模板字段

| 字段 | 填写规则 |
|---|---|
| 导入结果 | 用户上传时保持空白；校验失败时由系统写入错误原因 |
| 标签号 | 与 SN 至少填写一项 |
| SN | 与标签号至少填写一项 |
| 移库说明 | 选填 |

#### 4.14.2 文件规则

1. 支持 Excel 2003 `.xls` 和 Excel 2007+ `.xlsx`。
2. 从第 2 行开始读取数据。
3. 导入前必须选择移出仓库。
4. 首次导入成功时自动生成草稿单号，保存单头、明细和锁。

#### 4.14.3 数据匹配与校验

1. 标签号、SN 至少填写一项。
2. 只填写标签号时，标签号必须精确匹配一件物资。
3. 只填写 SN 时，SN 必须精确匹配一件物资。
4. 标签号、SN 同时填写时，必须指向同一件物资。
5. 物资必须位于移出仓库且有库存。
6. 物资类型必须为资产或低值耐用品。
7. 物资不能被其他业务锁定。
8. 同一文件内不能重复导入同一物资。
9. 当前移库草稿中不能已存在同一物资。
10. 保存前再次校验物资位置、库存、状态和锁。

#### 4.14.4 整批处理

任意一行校验失败时，本次导入全部不保存，也不增加任何物资锁。

错误结果至少包含：

- Excel 行号；
- 错误字段；
- 错误原因。

错误原因写入模板“导入结果”列。

页面提示：

- 数据校验失败：`数据校验失败，请下载结果查看！`
- 无有效数据：`未找到需要导入的数据行`
- 文件格式错误：`上传文件格式不正确，仅支持 Excel 2003 或 Excel 2007 格式数据文件！`

全部校验通过后，整批实时保存明细并增加本流程锁。

| 出库/入库签字与时间 | 打印模板留空，供线下填写 |

已有移库明细中包含普通耗材或文具时，照常打印；数量和物资说明取移库明细，没有标签号或 SN 时对应位置留空。模板不单列成本、净值或费用账户。

移库打印按单据明细和打印时的基础资料组装，不完整使用移库发生时的资产历史快照。仓库名称和类别名称按打印时的资料查询，详细配置按标签号读取当前资产卡片。移库历史信息页属于独立的数据路径，不与本打印取值规则混用。

## 5. 移动端页面字段及交互

“我发起的”展示当前用户拥有出库权限的移出仓库对应全部单据，不按创建人过滤。

“我接收的”展示当前用户拥有入库权限的移入仓库对应全部单据，不按创建人过滤，并优先展示出库待接收单据。

### 5.2 仓库选择

移入仓库只展示与移出仓库属于同一财务公司的有效仓库，并排除当前移出仓库。

### 5.3 发起单据列表

列表字段：

- 制单日期；
- 制单人；
- 物资数量。

草稿进入编辑，其他状态进入查看。

无查询结果时展示“暂无发起单据”。

### 5.5 创建及编辑移库单

页面字段：

添加前必须选择移出仓库。候选范围、重复、库存、类型和锁校验与 PC 一致。添加成功后实时保存并增加本流程锁。

### 5.8 接收详情

单据信息：

- 移库单号与单据状态；
- 移出仓库和移入仓库，纵向展示；
- 来源移库单号（仅反向移库单展示）；
- 备注（有值时展示）。

单据详情不重复展示列表中已有的制单人和制单日期。

明细卡片同时展示物资状态、移库状态和验证状态，并提供独立的资产详情页面。资产详情展示资产说明、大类、小类、标签号、SN、数量、板块、公司、仓库、使用状态、责任人和资产地点；“本次移库”展示移库单号、移库状态、验证说明、接收时间、接收仓管员和驳回原因（有值时展示）。

明细信息：

- 标签号；
- SN；
- 物资说明；
- 验证状态；
- 移库状态；
- 资产标记；
- 接收说明；
- 验证说明；
- 接收仓管员；
- 接收时间。

### 5.9 移动端验证

移动端仅通过手机扫描二维码验证，不提供手工输入标签号、手工验证或狐小E验证。

验证成功后记录验证说明并自动勾选对应明细。已验证明细保持勾选，不能取消勾选。

### 5.10 移动端接收与驳回

1. 已验证且待接收的明细进入详情时自动勾选，不能取消勾选。
2. 勾选未验证的待接收明细时，先打开“填写验证原因”窗口；填写原因后点【确定】才勾选并允许接收，点【取消】则保持未勾选。
3. 填写原因不会把物资改为“已验证”；接收时按“已验证”或“未验证但已填写原因”两种条件校验。
4. 未验证且未填写原因的明细不能接收。
5. 待接收明细无需验证即可驳回；每次驳回按本次勾选明细生成一张反向移库单。
6. 支持单条和多条接收、驳回；接收、驳回及费用账户失败规则与 PC 一致。

### 5.11 快捷扫码

快捷扫码用于快速定位当前用户有权接收的待接收物资。

1. 使用手机扫描二维码获取资产标签号。
2. 系统在当前用户拥有入库权限的移入仓库范围内，查询包含该物资的“出库待接收”移库单。
3. 未匹配单据时提示“未找到当前待接收移库单”。
4. 只匹配一张单据时，进入该接收详情并按第 4.9 节执行验证。
5. 匹配多张单据时，先展示移库单号、移出仓库、移入仓库和制单日期，由用户选择一张后执行验证。
6. 验证成功后停留在接收详情，并自动勾选对应明细。

## 7. 业务结果与补充说明

### 7.1 正式调出结果

移库提交成功后：

1. 单据状态变为“出库待接收”。
2. 全部草稿明细变为“待接收”。
3. 物资仓库更新为 V00001-集团在途总库。
4. City、Building、Floor 保持调出前信息。
5. 保存移库发生时的历史信息。
6. 每件物资生成一条移库调出记录，来源为当前移库单号。
7. 通知移入仓库全部有效负责人。

### 7.2 正常接收结果

本次勾选物资接收成功后：

| 物资字段 | 更新规则 |
|---|---|
| 仓库 | 更新为移入仓库 |
| City | 取移入仓库 City |
| Building | 取移入仓库 Building；为空时在目标 City 下使用名称为“缺省”的 Building |
| Floor | 取移入仓库 Floor；为空时使用编码 299 |
| Room | 清空 |
| 责任人 | 更新为移入仓库虚拟库管员 |
| 费用账户 | 按移入仓库及目标组织信息重新生成 |
| 资产标记 | 使用接收明细维护值 |
| 锁 | 释放本流程锁 |

同时：

1. 明细状态变为“已接收”。
2. 记录接收仓管员和接收时间。
3. 每件物资生成一条移库调入记录，来源为当前移库单号。
4. 按全部明细结果重新计算移库单状态。

### 7.3 驳回结果

本次勾选物资驳回成功后：

1. 明细状态变为“已驳回”。
2. 本次勾选明细进入一张新的反向移库单。
3. 物资继续保留在 V00001-集团在途总库。
4. 本流程锁转入反向移库单。
5. 原移库单继续处理其他待接收明细。
6. 按全部明细结果重新计算原移库单状态。

### 7.4 反向接收结果

原移出仓库完成反向接收后：

1. 物资从 V00001-集团在途总库进入原移出仓库。
2. 仓库、位置、虚拟库管员和费用账户按原移出仓库重新生成。
3. 记录反向接收人和接收时间。
4. 生成移库调入记录，来源为反向移库单号。
5. 释放反向移库流程锁。
6. 反向移库单按明细结果更新为已完成。

### 7.5 原单与反向单追溯

原移库单记录其生成的全部反向移库单号；每张反向移库单记录来源移库单号。

用户可以从原移库单查看对应反向移库单，也可以从反向移库单返回来源移库单。

### 7.6 通知与催办结果

1. 正式调出后向移入仓库负责人发送待接收通知。
2. 反向移库单形成后向该反向单移入仓库负责人发送待接收通知。
3. 正常移库从正式调出成功时间起算，反向移库从反向单生成时间起算；第 8 天起每日发送催办通知。
4. 全部明细完成接收或驳回后停止催办。
5. 发送失败的通知保留失败记录并继续重试。

### 7.7 数据记录

移库过程保存以下记录，便于后续按单据、物资和人员追溯：

| 记录类型 | 保存内容 |
|---|---|
| 草稿实时保存 | 单头字段、明细新增、明细删除、移库说明、接收说明、资产标记、操作人、操作时间、失败原因 |
| 物资锁变化 | 加锁单号、加锁物资、释放原因、释放人、释放时间 |
| 正式调出 | 提交人、提交时间、移出仓库、移入仓库、集团在途总库、调出前仓库和位置、调出后仓库 |
| 验证与直接接收 | 验证状态、验证方式、验证人、验证时间、验证说明、未验证直接接收原因 |
| 正常接收 | 接收人、接收时间、移入仓库、接收后位置、资产标记、费用账户、接收说明 |
| 驳回 | 驳回人、驳回时间、驳回原因、被驳回明细、生成的反向移库单号 |
| 反向接收 | 反向接收人、反向接收时间、返回的原移出仓库、反向接收后位置、费用账户 |
| 单据关系 | 原移库单号、反向移库单号、来源移库单号 |
| 通知与催办 | 通知对象、通知时间、催办时间、发送失败原因、下次继续发送记录 |
| 业务结果 | 单据状态变化、明细状态变化、移库调出记录、移库调入记录 |
