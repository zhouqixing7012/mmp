# 库存管理 - 移库 PRD

## 1. 背景

移库用于处理资产及低值耐用品在不同仓库之间的库存转移。

一次完整移库包含两个阶段：

`来源仓调出 → 集团通用在途库 → 目标仓接收`

来源仓执行调出后，物资不直接成为目标仓库存，而是先进入 **V00001-集团在途总库**。目标仓完成接收后，物资才正式进入目标仓。

移库过程中需要完整记录实际移出仓库、实际移入仓库、移库物资明细、资产验证情况、来源仓调出结果、在途状态、目标仓接收或驳回结果、资产卡片变化、调出/调入事务、驳回产生的反向移库关系，以及操作人与操作时间。

当前移库范围暂不包含普通耗材数量型移库。

## 2. 业务范围

### 2.1 支持物资

| 物资类型 | 是否支持移库 | 处理方式 |
|---|---:|---|
| 资产 | Y | 按标签/SN逐件移库 |
| 低值耐用品 | Y | 按耗材标签/SN逐件移库 |
| 普通耗材 | N | 当前不提供移库能力 |

低值耐用品在移库过程中按照具有唯一标签/SN的实物逐件管理，不采用普通耗材数量型库存移库模式。

## 3. 角色与权限

| 角色 | 可执行操作 | 限制 |
|---|---|---|
| 来源仓出库管理员 | 创建、编辑、添加/删除物资、保存草稿、移库提交、删除草稿 | 必须具备来源仓出库权限 |
| 目标仓入库管理员 | 查看待接收单、验证、接收、驳回 | 必须具备目标仓入库权限 |
| 单据查看人员 | 查看单据、明细、打印、导出 | 按数据权限控制 |
| 系统 | 锁定/解锁资产、更新资产卡片、生成事务、生成反向移库单、发送通知、同步数据 | 自动执行 |

### 3.1 发起权限

用户只能查看、创建和操作本人具有出库权限的仓库对应移库单。

创建时，“当前仓库”仅允许选择：

- 当前账号具有出库权限；
- 仓库状态有效；
- 一级仓库。

### 3.2 接收权限

接收列表只展示当前用户具有目标仓入库权限的移库单。无目标仓权限的用户不展示对应待接收数据，也不允许验证、接收或驳回。

## 4. 核心业务规则

### 4.1 单据粒度

一张移库单固定对应 **一个实际移出仓库 + 一个实际移入仓库**，允许包含多条物资明细。

不得在一张移库单内混用多个来源仓或多个目标仓。

### 4.2 仓库规则

当前仓库为实际移出仓库；对方仓库为实际移入仓库。

二者：

- 必填；
- 不得相同；
- 必须属于同一财务公司。

### 4.3 在途库

来源仓正式调出后，资产统一进入 **V00001-集团在途总库**。

目标仓正式接收以前：

- 不属于来源仓库存；
- 不属于目标仓库存；
- 处于移库在途状态。

## 5. 状态规则

### 5.1 移库单状态

| 状态 | 业务含义 | 可执行操作 |
|---|---|---|
| 草稿 | 尚未执行正式调出 | 编辑、添加/删除明细、保存、删除、提交 |
| 出库待接收 | 来源仓已经调出，仍存在未完成接收的明细 | 验证、接收、驳回 |
| 已完成 | 全部明细已接收，或不存在待接收行且存在已接收+已驳回等混合终态 | 查看、打印、导出 |
| 已驳回 | 全部有效明细均已驳回 | 查看、打印、导出 |

“已驳回”仅表示原移库单全部有效明细均被目标仓驳回。被驳回的明细仍按照反向移库规则生成新的反向移库单，不直接退回原来源仓。

### 5.2 明细状态

| 状态 | 含义 |
|---|---|
| 草稿 | 尚未调出 |
| 已取消 | 草稿阶段取消，不执行调出 |
| 待接收 | 已调出，目前位于在途库 |
| 已接收 | 已进入目标仓 |
| 已驳回 | 目标仓拒绝接收，已进入反向移库链路 |

### 5.3 单据状态计算

移库单头状态统一按明细状态计算：

1. 全部有效明细均为“已接收” → 单据状态为 **已完成**；
2. 全部有效明细均为“已驳回” → 单据状态为 **已驳回**；
3. 仍存在任意“待接收”明细 → 单据状态为 **出库待接收**；
4. 已不存在待接收明细，且同时存在“已接收 + 已驳回”或其他终态组合 → 单据状态为 **已完成**。

例如：5条移库物资中3条接收、2条驳回，则原移库单状态为“已完成”，同时2条已驳回物资进入反向移库单。

## 6. 整体业务流程

### 6.1 正常移库

`创建移库草稿`
→ 选择来源仓、目标仓
→ 添加资产/低值耐用品
→ 系统锁定新增物资
→ 保存草稿或直接移库提交
→ 来源仓正式调出
→ 资产进入 V00001 在途库
→ 单据进入出库待接收
→ 目标仓验证物资
→ 分批执行移库接收
→ 资产进入目标仓
→ 全部明细进入终态
→ 按明细结果计算原移库单最终状态

### 6.2 驳回

`待接收资产`
→ 填写驳回原因
→ 当前行变为已驳回
→ 系统自动生成反向移库单
→ 原移库单继续处理其他行
→ 原单全部行进入终态
→ 若全部驳回则原单为已驳回；若部分接收、部分驳回则原单为已完成
→ 原来源仓在反向移库单中执行接收
→ 被驳回资产重新进入原来源仓

## 9. 资产锁

### 9.1 新增明细

将资产/低值耐用品加入移库草稿时：

1. 记录进入本流程前的原锁状态；
2. 原本未锁定的实物，由当前移库流程进行锁定；
3. 原本已经被其他业务锁定的实物禁止加入移库单。

统一提示：`当前资产已被其他业务锁定，无法移库`

不提供“确认后强制移库”等绕过操作。

### 9.2 删除

草稿删除明细或删除整张移库单：

- 如果资产进入流程前未锁定，则解锁；
- 如果资产原本已经处于锁定状态，则不改变原锁状态。

### 9.3 接收完成

正常移库流程完成后，当前流程增加的锁释放，并恢复进入流程前正确的锁定状态。

| 制单日期 | 只读 | - | 当前日期 |
| 备注 | 多行文本 | N | ≤60字 |

### 11.2 修改当前仓库

当前草稿无物资时直接修改。

已经存在物资时弹出：`修改当前仓库后将清空当前移库明细，是否继续？`

确认后：

1. 释放当前移库流程产生的资产锁；
2. 清空所有移库明细；
3. 清空当前已选明细；
4. 修改当前仓库；
5. 对方仓库重新选择。

取消则保持原数据。

### 11.3 新建页添加物资

新建移库单时，不要求先保存单头即可添加物资，但**必须先选择当前仓库**。

- 已选择当前仓库 → 可点击【添加物资】，按当前仓库筛选资产/低值耐用品；
- 未选择当前仓库 → 不允许进入物资选择，提示 `请先选择当前仓库`；
- 新建页尚未生成移库单号时，已添加物资暂存在当前页面草稿中；
- 点击【保存草稿】后统一生成移库单号并保存单头及已添加明细；
- 点击【移库提交】时若仍未生成单号，校验通过后系统先生成单号并保存，再继续正式调出。

## 13. 添加/编辑移库物资

### 13.1 前置条件

打开物资选择前必须已经选择当前仓库。

未选择当前仓库时提示：`请先选择当前仓库`。

添加/编辑移库物资弹窗顶部只提供一个“移库物资”弹窗选择字段，不再分别展示“标签号 / SN号 / 物资说明”三个选择字段。

新增时点击“移库物资”打开标准选择弹窗；已有明细编辑时不允许替换为另一件实物，仅维护当前物资的移库说明。

### 13.2 物资选择查询条件

“选择移库物资”弹窗查询条件固定为：

| 字段 | 规则 |
|---|---|
| 标签号 | 模糊查询 |
| SN号 | 模糊查询 |
| 板块 | 模糊查询 |

不在该弹窗额外提供物资总类、公司等查询条件；可选范围由系统固定过滤规则控制。

### 13.3 系统固定过滤

仅展示：

- 当前仓库的实物；
- 当前有库存的实物；
- 当前用户具有操作权限的数据；
- 未被其他业务锁定的数据；
- 资产或低值耐用品；
- 当前移库单尚未添加的数据。

普通耗材不得出现在移库可选列表。

| 原值 | 会计格式：千分位 + 2 位小数 |

## 14. 移库提交

### 14.1 提交前校验

点击【移库提交】后重新检查：

1. 当前仓库有效；
2. 对方仓库有效；
3. 当前仓库不等于对方仓库；
4. 当前仓库和对方仓库属于同一财务公司；
5. 至少存在一条有效明细；
6. 单据不存在重复标签号；
7. 每件资产仍位于当前来源仓；
8. 每件资产仍处于可移库状态；
9. 每件资产仍由本移库流程正常锁定；
10. 不存在普通耗材；
11. V00001集团在途总库有效。

若当前为新建未保存单据，系统可在提交校验通过后先生成移库单号并保存单头/明细，再继续执行正式调出，不要求用户为了提交先单独执行一次保存草稿。

任一校验失败时整单不执行正式调出。

### 14.2 资产快照

正式调出前，按照每条资产/低值耐用品保存本次移库快照。后续单据详情读取移库快照，而不是当前资产实时卡片。

## 15. 来源仓正式调出

正式提交成功后：`来源仓 → V00001集团在途总库`

每条物资明细状态变为待接收，单据状态变为出库待接收。

资产卡片：

|---|---|
| 仓库 | V00001-集团在途总库 |
| City | 保持原值 |
| Building | 保持原值 |
| Floor | 保持原值 |

目标仓接收前，不提前写入目标仓位置。

### 15.1 事务

资产化实物来源仓调出：每件生成一条事务，事务类型为 **24**，事务来源为当前移库单号。

## 16. PC - 移库接收列表

移库接收单不能手工创建。

正常来源为移库发起单完成正式调出；反向来源为目标仓驳回待接收明细后系统自动生成。

接收列表状态统一使用：**出库待接收 / 已完成 / 已驳回**。

### 16.1 通知

生成待接收数据后，向对应目标仓库负责人发送通知。

超过7天仍未接收完成时，从超期开始每日向目标仓库负责人发送催办通知，直到接收流程结束。

接收详情可展示通知状态、催办状态作为原型/异常追溯信息。

### 16.2 查询条件

- 移库单号；
- 单据状态；
- 制单人；
- 制单日期；

资产扫描仅作为接收列表筛选条件，不自动打开唯一匹配单据。

## 18. 资产验证

支持扫码枪、手工输入、狐小E。

### 18.1 扫码验证

接收详情中的资产扫描用于验证当前单据中的待接收物资。

输入标签号/SN并回车：

- 精确匹配待接收行 → `未验证 → 已验证`，记录验证方式=扫码、验证时间；
- 已验证 → 提示“当前资产已验证”；
- 已处理 → 阻止重复验证；
- 未匹配当前单据 → 提示 `当前移库单中未找到该资产`。

### 18.2 手工验证

未验证待接收行提供【手工验证】。

手工验证时验证说明必填；成功后记录：

- 验证状态=已验证；
- 验证方式=手工；
- 验证时间；
- 验证说明。

### 18.3 取消验证

待接收且已验证行允许【取消验证】：

`已验证 → 未验证`

同时清空验证方式、验证时间、验证说明。已接收、已驳回明细禁止取消验证。

## 19. 移库接收确认

支持多次分批接收。

用户勾选 **已验证 + 待接收** 明细后点击【移库接收确认】，弹出：

`是否确定执行移库接收？`

确认后仅处理当前勾选行：

- 明细变为已接收；
- 更新对应发起单明细；
- 更新资产卡片；
- 生成调入事务25；
- 记录接收仓管员；
- 记录接收时间；
- 按第5.3节规则重新计算单据状态。

取消则关闭确认框，页面数据不变。

所选数据中存在未验证或非待接收行时不执行接收；不存在“已验证 + 待接收”选中明细时提示 `无已验证待接收的资产`。

## 21. 移库驳回

### 21.1 操作范围

目标仓可以选择当前待接收明细进行驳回。已接收、已驳回明细禁止再次驳回。

### 21.2 驳回原因

点击【移库驳回】后弹出驳回窗口。

驳回原因：

- 必填；
- 最多 **200字**。

### 21.3 驳回结果

确认驳回后：

1. 本次选中待接收行变为已驳回；
2. 不直接将资产退回原来源仓；
3. 系统自动针对本次驳回明细创建一张新的反向移库单；
4. 原单继续处理剩余待接收行；
5. 每次驳回后按第5.3节规则重新计算原单状态；
6. 全部有效明细均已驳回时，原单状态为“已驳回”；
7. 已无待接收行且同时存在已接收、已驳回等终态时，原单状态为“已完成”。

## 22. 反向移库单

反向移库是目标仓驳回后的系统自动处理结果。

### 22.1 仓库关系

原单 `A仓 → B仓`，B仓驳回后反向单为 `B仓 → A仓`。

| 字段 | 反向单 |
|---|---|
| 移出仓库 | 原单目标仓 |
| 移入仓库 | 原单来源仓 |

被驳回资产实际仍处于集团在途库，反向单用于承接其返回原来源仓的接收链路。

### 22.2 生成内容

反向单继承：

- 本次被驳回明细；
- 标签号；
- SN；
- 物资信息；
- 原移库单号；
- 驳回原因。

反向单记录来源移库单号；原单同步记录生成的反向移库单号，形成双向追溯。

### 22.3 初始状态

反向移库单生成后状态为 **出库待接收**。

不重新要求原目标仓执行一次来源仓调出，因为被驳回物资尚未离开在途库。

由原来源仓管理员执行移库接收，完成：

`V00001集团在途总库 → 原来源仓`

反向接收完成后，资产重新成为原来源仓库存。

移动端与PC采用同样的单据状态、明细状态、调出、接收、驳回和反向移库规则。

移动端页面待补充后，再与本 PRD 逐页核对交互细节；当前先锁定核心业务规则。

### 28.2 页面入口

### 28.3 我发起的

### 28.4 我接收的

优先展示出库待接收。

### 28.5 创建

维护当前仓库、对方仓库、备注。不展示运输方式、预计到达时间。

### 28.6 添加物资

### 28.7 验证与接收

支持单行扫码验证、取消验证、单行/多行接收、单行/多行驳回。

PC与移动端的状态口径统一：

- 全部已接收 → 原单已完成；
- 全部已驳回 → 原单已驳回，并生成反向移库单；
- 仍存在待接收行 → 原单出库待接收；
- 无待接收行且同时存在已接收、已驳回等终态 → 原单已完成，同时已驳回行进入反向移库单。

| 驳回原因超限 | `驳回原因最多允许填写200个字` |
| 费用账户生成失败 | `生成费用账户出错（TAG_NUMBER=...）` |

## 30. 数据更新与审计

### 30.1 资产事务

| 阶段 | 事务类型 | 粒度 | 来源 |
|---|---:|---|---|
| 来源仓 → 在途库 | 24 | 每个资产化实物一条 | 移库单号 |
| 在途库 → 目标仓 | 25 | 每个资产化实物一条 | 移库单号 |
| 驳回物资返回来源仓 | 按反向移库接收逻辑 | 每个实物一条 | 反向移库单号 |

### 30.2 历史快照

来源仓正式调出前保存资产快照。

后续查看历史移库单时，优先展示移库发生时的数据，不得因为资产后来再次移库、更换责任人、修改位置或修改资产属性导致历史移库单内容变化。

### 30.3 单据关联

反向移库单必须保存来源移库单号，原移库单也应能够查询其生成的反向移库单，形成：

`原移库单 ↔ 反向移库单`

双向追溯。

### 30.4 外部同步

移库核心业务成功后再进入外部同步队列。

同步失败：

- 不回滚已经成功的本地移库；
- 记录失败状态；
- 支持后续重试。
