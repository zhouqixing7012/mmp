# 后台基础配置页面审计清单

## 审计基准

- 基准文件：拆分前完整 `src/pages/yewurules.js`
- 审计对象：`src/pages/yewurules/modules/` 下全部后台业务页面
- 审计维度：查询条件、查询/重置区域、操作栏、按钮可用状态、新增/编辑弹窗、批量弹窗、选择弹窗、表格列、侧边栏可访问性
- 原则：优先恢复拆分前已有结构和交互入口，不自行新增无依据字段或业务动作

## 当前框架状态

- 后台基础配置和个人工作台共用 `AdminSidebar`。
- 侧边栏头部和用户信息区域固定，菜单主体使用独立纵向滚动区域。
- 展开后台基础配置后，可滚动访问组织管理及其下方全部菜单。
- 个人工作台菜单已独立收口，不影响后台基础配置菜单完整性。

## 按钮状态原则

### 启用/停用

拆分前大多数页面的“启用”“停用”按钮没有根据勾选行数设置 `disabled`。因此模块化后不得额外增加 `disabled={selectedRowKeys.length === 0}`。

已修正“费用账户规则”中误加的启用/停用置灰条件。

### 删除

删除属于危险操作。拆分前以下页面在未勾选数据时，删除按钮本身就是置灰状态，保留该行为：

- 公司归属权限
- 仓库信息、仓库用途、仓库权限
- 单据编号规则
- 影像器材配给方案
- 物资申请超标配置
- 资产折旧规则
- 账套内容维护

### 物料基础数据

物料大类、物料小类、品牌、型号、配置页面中，“停用”按钮在未选择数据时置灰属于拆分前原有逻辑；“启用”按钮不置灰。

## 当前已完成的框架修正

1. 后台模块已从大文件拆分到 `src/pages/yewurules/modules/`。
2. 查询区域统一向 `QueryBar`、`QueryItem` 收敛。
3. 状态展示统一向 `StatusTag` 收敛。
4. 选择字段优先复用 `SelectModal` 或已有同类弹窗。
5. 费用账户规则、账套内容维护和物资申请超标配置等重点页面已完成多轮查询区、操作栏和弹窗修正。
6. 侧边栏滚动问题已修复，长菜单不再因页面高度限制而无法访问。

## 尚未纳入本轮的增强

- 多数查询和重置按钮仍是演示入口，尚未全部真正过滤数据。
- 启用、停用、删除、同步、保存等按钮仍有部分缺少 loading、确认、消息反馈和数据更新。
- 页面数据仍有部分直接读取 mock 数组，尚未全部统一封装业务 service。
- 刷新后的持久化和跨页面数据联动尚未全部完成。
- 少数弹窗仍超过 80 行，后续应拆成独立组件。
- 尚未执行全量本地构建和后台页面自动化回归。

## 下一步优化计划

### 第一阶段：交互闭环

1. 为查询、重置、分页实现真实状态过滤。
2. 启用、停用、删除增加选中校验、二次确认和成功提示。
3. 新增、编辑弹窗增加必填校验、提交 loading、关闭重置和防重复提交。
4. 同步、导入、下载模板等按钮补充明确的演示反馈。

### 第二阶段：数据层统一

1. 为后台配置建立统一 mock service。
2. 页面不再直接把 mock 数组作为最终数据源。
3. 新增、编辑、启停、删除写入统一演示存储。
4. 统一提供“重置演示数据”能力。
5. 地点基础数据维护与 ES 前台领用地点选项改为同一 service 数据源。

### 第三阶段：组件与代码质量

1. 将超过 300 行的页面继续拆分。
2. 将超过 80 行的 Modal 拆成独立组件。
3. 抽取后台列表页公共工具栏、状态批量操作和通用选择字段。
4. 将查询字段、表格列和 Select options 迁入配置文件。

### 第四阶段：业务链路与回归

1. 申请、审批、配给、统一汇总和领用读取一致的数据对象。
2. 费用账户相关映射与资产台账演示数据建立可见联动。
3. 补充后台侧边栏、组织管理、费用账户规则和物资申请超标配置的 Playwright 冒烟用例。
4. 执行一次全量构建和页面级验收，更新最终检查清单。
