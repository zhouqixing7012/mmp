# 员工资产信息查询三方比对：原版 PRD vs 当前原型 vs 新版 PRD

## 1. 比对基线

本次固定使用以下三个基线：

- 原版 PRD：`docs/员工资产信息查询+原版PRD.md`
- 当前原型：`src/pages/assetManagement/EmployeeAssetInfoQueryPage.js`
- 新版 PRD：`docs/PRD-资产管理-员工资产信息查询.md`

处理原则：

1. 原版 PRD 只作为历史业务基线保存，不直接覆盖修改。
2. 当前原型用于确认页面字段、控件、页签、查询和演示行为。
3. 新版 PRD 承载当前目标业务规则。
4. 原版与原型冲突时，先判断是原型偏差还是后续明确改造，不用原型反向覆盖原版业务规则。
5. 原版没有定义、原型自行出现的字段或规则，不自动写入新版 PRD。
6. 新版 PRD 对原版未定义的规则明确标记“当前未定义”。

## 2. 当前三方总体状态

本轮已根据三方比对结果完成原型校准，当前原型已与原版及新版 PRD 的已明确规则对齐：

1. 员工信息改为人员单选选择器。
2. 查询条件按资产 / 耗材 / 合约号码 / 单据信息页签动态展示。
3. 资产只按“资产责任人 = 查询员工”查询。
4. 耗材只按“耗材当前责任人 = 查询员工”查询。
5. 合约号码只按“合约号码当前责任人 = 查询员工”且当前有效关系查询。
6. 单据信息支持申请人、责任人、`payPersonId`、入库/出库明细关联人员等多种员工关系。
7. 耗材和合约号码列表字段已按原版 PRD 调整。
8. 原型中无需求依据的“资产担保人 / 担保来源单据”已删除。
9. 资产标签号、耗材标签号、合约号码、申请单号、核心单据已提供详情入口。
10. 单据状态已补齐“已完成 / 处理中 / 已驳回”。
11. 单据信息按创建时间倒序。
12. 四个页签分别使用对应空状态文案。

仍未由原版需求明确的规则继续保持“当前未定义”，不由原型自行推断。

## 4. 资产页签三方比对

### 4.1 员工归属

三方当前统一：

> 资产责任人 = 查询员工

当前原型不再使用“责任人 OR 单据申请人”判断资产归属。

原型中保留一条“申请人为当前员工但责任人为其他员工”的对抗性 Mock，用于确认该资产不会错误出现在当前员工资产列表中。

### 4.2 数据范围

| 规则 | 原版 PRD | 当前原型 | 新版 PRD |
| --- | --- | --- | --- |
| 资产状态 | 状态代码 3、6 | 使用 statusCode 3、6 过滤 | 保留 3、6；名称映射未定义 |
| 物资大类 | 资产 | 使用 materialType=资产过滤 | 物资大类=资产 |

资产状态代码 3、6 对应的正式状态名称仍未由原版 PRD 明确。

### 4.3 列表字段

当前原型字段已调整为：

- 行号
- 资产标签号
- 资产说明
- 资产状态
- 资产责任人
- 单据申请人
- 所在单据编号
- 单据类型
- 单据业务类型
- 单据状态
- 单据审批环节
- 单据审批人
- 公司
- 板块

原型额外的“资产担保人”已删除。

### 4.4 详情入口

当前原型：

1. 资产标签号使用蓝色链接按钮打开资产卡片详情。
2. 所在单据编号存在值时可打开对应业务单据详情。
3. 无关联单据时展示 `-`，不提供空链接。

## 6. 合约号码页签三方比对

三方当前统一：

### 6.2 员工归属

## 7. 单据信息页签三方比对

### 7.1 员工关系

原版 / 新版允许通过以下关系查询员工相关单据：

- `payPersonId`
- 责任人员工字段
- 申请人员工字段
- 入库明细关联人员
- 出库明细关联人员

当前原型已按以上关系建立统一员工归属判断，不再只按申请人查询。

### 7.2 业务类型

原版 / 新版明确可覆盖：

- 更换
- 退库
- 员工转移
- 借用
- 统一申请相关
- 合约号码相关
- 新员工相关
- 出库
- 入库
- 资产转移

当前原型使用多种 Mock 单据验证“申请人 / 责任人 / payPersonId / 明细人员”不同命中路径，正式业务数据仍需由各业务模块提供。

### 7.3 列表字段

当前原型字段与原版 / 新版一致：

- 行号
- 申请单号
- 单据类型
- 业务类型
- 单据状态
- 申请人
- 申请时间
- 核心单据
- 公司
- 板块
- 部门
- 操作

### 7.4 单据状态

三方当前统一：

- 已完成
- 处理中
- 已驳回

### 7.5 详情与流程入口

当前原型：

1. 申请单号可进入业务单据详情。
2. 核心单据存在时可进入对应业务单据详情。

### 7.6 排序

## 9. 权限与历史单据

### 9.1 权限

已明确：

> 只有拥有“资产管理 → 员工资产信息查询”菜单权限的后台用户可以访问。

仍未明确：

- 数据权限具体维度。
- 公司 / 板块 / 部门等数据范围。
- 服务端接口如何校验数据权限。

当前原型不模拟服务端权限绕过场景；正式实现必须补充权限规则。

### 9.2 历史单据旧系统详情

原版要求：

> 切换新系统后，历史单据详情页保留旧系统地址。

当前仍缺少：

1. 历史单据的单据类型或时间范围定义。
2. 旧系统 URL 生成规则。
3. SSO / 权限透传方式。
4. 旧系统不可访问时提示。
5. 新系统详情与旧系统详情入口优先级。

当前原型不自行编造旧系统地址。

## 10. 当前仍需业务确认的规则

三方比对后剩余的业务规则缺口：

1. 资产状态代码 `3`、`6` 对应的状态名称。
2. 资产、耗材、合约号码页签的正式默认排序规则。
3. 合约号码“当前有效”的正式状态集合。
4. 数据权限具体维度与接口校验规则。
5. 历史单据旧系统地址及新旧详情跳转规则。
6. 离职员工是否允许在正式人员选择器中搜索和选择。

以上未定义项不影响当前原型按已明确规则完成校准。
