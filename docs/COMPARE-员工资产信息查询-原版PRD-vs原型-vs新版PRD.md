# 员工资产信息查询三方比对：原版 PRD vs 当前原型 vs 新版 PRD

## 1. 比对基线

本次固定使用以下三个基线：

- 原版 PRD：`docs/员工资产信息查询+原版PRD.md`
- 当前原型：`src/pages/assetManagement/EmployeeAssetInfoQueryPage.js`
- 新版 PRD：`docs/PRD-资产管理-员工资产信息查询.md`

处理原则：

1. 原版 PRD 只作为历史业务基线保存，不直接覆盖修改。
2. 当前原型用于确认当前页面已经展示的字段、控件、页签和 Mock 行为。
3. 新版 PRD 承载当前目标业务规则。
4. 原版与原型冲突时，不因为原型已经实现就自动改写业务规则。
5. 原版没有定义、原型自行出现的规则或字段，不自动写入新版 PRD。
6. 新版 PRD 对原版未定义的规则直接标记“当前未定义”，不使用“沿用现有规则”代替。

## 2. 总体结论

当前原型已经具备：

- “员工资产信息查询”页面入口。
- 资产 / 耗材 / 合约号码 / 单据信息四个页签。
- 查询、重置、页签切换、分页。
- 资产和单据信息的基础 Mock 展示。
- 页签切换时保留当前查询输入状态。

但原型与原版 PRD 在多项核心业务规则上存在差异，其中部分差异会直接改变查询结果，不属于单纯 UI 差异。

新版 PRD 本轮以原版明确业务规则为基线重新整理，同时把未定义规则单独列出；没有为了匹配当前 Mock 原型而修改资产、耗材、合约号码的员工归属判断。

## 4. 资产页签三方比对

### 4.1 员工归属规则

原版明确：

> 资产责任人 = 查询员工

当前原型实际过滤：

> 资产责任人命中查询员工 **或** 单据申请人命中查询员工

这会把“员工只是某张业务单据申请人、但资产并不归其负责”的记录带入资产页签。

新版 PRD 明确：

> 资产必须满足资产责任人 = 当前查询员工。

结论：**以原版和新版 PRD 为准，当前原型属于业务查询偏差，需要调整。**

### 4.2 数据范围

| 规则 | 原版 PRD | 当前原型 | 新版 PRD |
| --- | --- | --- | --- |
| 资产状态 | 代码 3、6 | 未按状态范围过滤 Mock | 保留代码 3、6；状态名称映射标记未定义 |
| 物资大类 | 资产 | 未体现物资大类过滤 | 明确物资大类 = 资产 |

结论：正式查询需要补数据范围限制；当前原型没有体现。

### 4.3 列表字段

原版与新版字段：

- 行号
- 资产标签号
- 资产说明
- 资产状态
- 资产责任人
- 单据申请人
- 所在单据编号
- 单据类型
- 单据业务类型
- 单据状态
- 单据审批环节
- 单据审批人
- 公司
- 板块

当前原型在以上字段之外额外增加：

- 资产担保人

原版和新版 PRD 均没有“资产担保人”规则来源。

结论：**资产担保人属于原型额外字段，当前没有需求依据；如无新的业务来源，应从原型删除。**

### 4.4 详情入口

原版要求资产标签号可点击打开资产卡片详情，存在关联单据时支持查看业务单据或流程。

当前原型：

- 资产标签号仅为普通文本。
- 所在单据编号仅为普通文本。
- 未实现资产卡片详情入口。
- 未实现关联单据/流程入口。

新版 PRD 保留原版详情要求。

结论：原型缺失详情交互。

## 5. 耗材页签三方比对

> 耗材当前责任人 = 查询员工

当前原型使用与资产相同的通用过滤：

> 耗材责任人命中 **或** 单据申请人命中

新版 PRD：

> 耗材必须满足耗材当前责任人 = 当前查询员工。

结论：**当前原型查询逻辑需要调整。**

- 公司

- 责任人

- 成本中心

当前原型使用通用 workflow 列：

- 行号
- 耗材标签号
- 耗材说明
- 耗材状态
- 耗材责任人
- 资产担保人
- 担保来源单据

- 单据状态

结论：耗材页签当前原型与需求字段口径差异较大，后续需要按新版 PRD 重构。

当前原型耗材标签号为普通文本。

结论：原型缺失详情入口。

## 6. 合约号码页签三方比对

### 6.1 查询条件

原版要求：

> 合约号码页签展示“合约号码”查询条件。

当前原型没有合约号码查询条件，仍展示资产标签号、单据编号、单据状态。

新版 PRD恢复“合约号码”专属查询条件。

结论：原型需要调整。

### 6.2 员工归属规则

原版：

> 合约号码当前责任人 = 查询员工，查询当前有效合约号码。

当前原型使用：

> 责任人命中或申请人命中

且没有“当前有效状态”过滤。

新版 PRD：

> 合约号码当前责任人 = 当前查询员工；当前有效状态集合因原版未定义而标记待确认。

结论：当前原型员工归属逻辑不符合原版；有效状态范围还需要业务补充。

### 6.3 列表字段

原版与新版要求：

- 行号
- 合约号码
- 副卡
- 状态
- 责任人编号
- 责任人
- 公司
- 部门
- 领用时间
- 备注

当前原型字段：

- 行号
- 合约号码标签号
- 合约号码说明
- 合约号码状态
- 责任人
- 责任人公司
- 责任人部门
- 所在单据编号
- 单据申请人
- 单据类型
- 单据业务类型
- 单据审批环节
- 单据审批人

主要差异：

1. 原型没有真正的“合约号码”字段。
2. 原型没有副卡、责任人编号、领用时间、备注。
3. 原型增加标签号、说明及整组单据流程字段，原版无对应要求。

结论：合约号码页签需要按新版 PRD 重新校准字段。

## 7. 单据信息页签三方比对

### 7.1 查询范围

原版明确覆盖：

- 普通员工申请单
- CAA/CAC 库存类单据
- CAA/CAC 采购类单据
- 独立入库单
- 独立出库单
- 资产转移单

并可通过：

- `payPersonId`
- 责任人员工字段
- 申请人员工字段
- 入库/出库明细对应人员字段

建立员工关系。

当前原型只对 Mock 单据执行：

> 申请人 = 查询员工

没有实现责任人、`payPersonId`、入库/出库明细人员等多关系查询。

新版 PRD完整保留原版员工关联范围。

结论：当前原型仅覆盖了“申请人”这一条查询分支，正式查询能力不足。

### 7.2 业务类型

原版和新版明确识别：

- 更换
- 退库
- 员工转移
- 借用
- 统一申请相关
- 合约号码相关
- 新员工相关
- 出库
- 入库
- 资产转移

当前原型仅提供一条“新员工领用” Mock，不代表其他业务已实现。

### 7.3 列表字段

单据信息列表字段三方整体一致：

- 行号
- 申请单号
- 单据类型
- 业务类型
- 单据状态
- 申请人
- 申请时间
- 核心单据
- 公司
- 板块
- 部门
- 操作

但当前原型的申请单号、核心单据、操作均为普通文本，没有实现详情跳转或流程查看。

### 7.4 单据状态

原版和新版：已完成 / 处理中 / 已驳回。

当前原型下拉仅提供：

> 已完成

结论：原型需要补处理中、已驳回。

### 7.5 默认排序

原版和新版要求：

> 单据创建时间倒序

当前原型没有明确排序逻辑，仅按 Mock 数组顺序展示。

结论：原型需要补排序规则。

## 9. 权限与历史详情

### 9.1 权限

原版要求：

> 只有拥有“资产管理 → 员工资产信息查询”权限的后台用户可以访问。

同时说明查询数据受到资产管理后台数据权限限制，但没有明确具体维度。

当前原型只展示页面，没有体现服务端权限规则。

新版 PRD：

- 保留菜单权限要求。
- 将数据权限具体维度明确标记为当前未定义，不自行推断公司、板块、部门或其他权限范围。

### 9.2 历史单据详情

原版要求：

> 切换新系统后，历史单据详情页保留旧系统地址。

当前原型未实现。

新版 PRD保留该要求，并明确以下内容尚未定义：

- 历史单据适用范围。
- 旧系统 URL 生成规则。
- SSO / 权限透传。
- 访问失败提示。
- 新旧系统详情入口优先级。

## 10. 新版 PRD 相对原版的整理

新版 PRD没有改变原版已经明确的核心业务规则，主要做了以下结构化整理：

1. 按“背景 → 改造总结 → 通用规则 → 页面字段及交互 → 校验 → 后续操作或补充说明”重组。
2. 将四个页签的查询条件、员工归属、数据范围、字段和详情入口拆开描述。
3. 明确“当前持有关系”和“历史单据关系”不可混用。
4. 将原版未定义的规则单独列出，不用模糊历史表述代替。
5. 增加数据归属校验，防止因为“申请人命中”把非员工当前责任的资产/耗材/合约号码查出。
6. 将历史旧系统详情要求拆成待补规则，避免研发自行推断。
7. 保留原版耗材字段名称，不擅自把“资产大类 / 资产小类 / 资产说明”改为新的耗材字段名称。

## 11. 当前建议优先处理的原型差异

按影响程度，当前原型首先需要处理的业务差异为：

1. **员工选择方式**：普通 Input 改为人员单选选择器。
2. **查询条件按页签动态展示**：资产/耗材显示资产标签号；合约号码显示合约号码；单据信息显示单据编号、单据状态。
3. **资产/耗材/合约号码归属判断**：禁止使用“责任人 OR 申请人”；必须按当前责任人判断。
4. **耗材列表字段**：按新版 PRD 重构。
5. **合约号码列表字段**：按新版 PRD 重构。
6. **资产担保人 / 担保来源单据**：当前没有原版需求依据，需删除或补充业务来源后再保留。
7. **详情入口**：资产标签、耗材标签、申请单号、核心单据按业务对象提供详情入口。
8. **单据状态**：补齐处理中、已驳回。
9. **单据信息员工关系**：补 `payPersonId`、责任人、入库/出库明细关联人员等查询分支。
10. **空状态**：按四个页签使用对应空文案。
11. **单据排序**：按创建时间倒序。
12. **资产状态 3/6、合约号码有效状态、数据权限、历史旧系统地址规则**：其中原版仍有信息缺口，正式实现前需业务确认，不能由原型自行补造。
