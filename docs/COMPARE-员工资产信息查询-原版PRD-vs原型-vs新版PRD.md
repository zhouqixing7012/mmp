# 员工资产信息查询三方比对：原版 PRD vs 当前原型 vs 新版 PRD

## 1. 比对基线

本次固定使用以下三个基线：

- 原版 PRD：`docs/员工资产信息查询+原版PRD.md`
- 当前原型：`src/pages/assetManagement/EmployeeAssetInfoQueryPage.js`
- 新版 PRD：`docs/PRD-资产管理-员工资产信息查询.md`

处理原则：

1. 原版 PRD 只作为历史业务基线保存，不直接覆盖修改。
2. 当前原型用于确认页面字段、控件、页签、查询和演示行为。
3. 新版 PRD 承载当前目标业务规则。
4. 原版与原型冲突时，先判断是原型偏差还是后续明确改造，不用原型反向覆盖原版业务规则。
5. 原版没有定义、原型自行出现的字段或规则，不自动写入新版 PRD。
6. 新版 PRD 对原版未定义的规则明确标记“当前未定义”。

## 2. 当前三方总体状态

本轮已完成新版 PRD 重构。员工选择、页签、数据归属、状态范围、排序、权限和历史单据规则继续保留；耗材、合约号码列表字段按最新业务确认调整。当前原型尚未同步本轮字段变化：

1. 员工信息改为人员单选选择器。
2. 查询条件按资产 / 耗材 / 合约号码 / 单据信息页签动态展示。
3. 资产只按“资产责任人 = 查询员工”查询。
4. 耗材只按“耗材当前责任人 = 查询员工”查询。
5. 合约号码只按“合约号码当前责任人 = 查询员工”且当前有效关系查询。
6. 单据信息已按业务分支拆分员工关系：普通员工业务与 CAA/CAC 使用单据头申请人/领用人员；独立入库使用入库明细退回人员；独立出库使用出库明细责任人；独立资产转移使用转移明细责任人或申请人。
7. 新版 PRD 已按最新确认结果收窄耗材列表，并重新补齐合约号码流程单据信息。
8. 原型中无需求依据的“资产担保人 / 担保来源单据”已删除。
9. 资产标签号、耗材标签号、合约号码、申请单号、核心单据继续保留详情入口；耗材关联主资产标签号明确为普通文本。
10. 单据状态已补齐“已完成 / 处理中 / 已驳回”。
11. 单据信息按申请时间降序。
12. 四个页签分别使用对应空状态文案。

本轮只修改 PRD 及比对记录，不修改 React 原型；字段差异作为后续原型同步任务保留。

## 4. 资产页签三方比对

三方当前统一：

> 资产责任人 = 查询员工

当前原型不再使用“责任人 OR 单据申请人”判断资产归属。

原型中保留一条“申请人为当前员工但责任人为其他员工”的对抗性 Mock，用于确认该资产不会错误出现在当前员工资产列表中。

### 4.2 数据范围

| 规则 | 原版 PRD | 当前原型 | 新版 PRD |
| --- | --- | --- | --- |
| 资产状态 | 状态代码 3、6 | 使用 statusCode 3、6 过滤；3=在用-借用中，6=在用-使用中 | 3=在用-借用中，6=在用-使用中 |
| 物资大类 | 资产 | 使用 materialType=资产过滤 | 物资大类=资产 |

资产状态代码已确认：`3 = 在用-借用中`，`6 = 在用-使用中`。

### 4.3 列表字段

当前原型字段已调整为：

- 行号
- 资产标签号
- 资产说明
- 资产状态
- 资产责任人
- 单据申请人
- 所在单据编号
- 单据类型
- 单据业务类型
- 单据状态
- 单据审批环节
- 单据审批人
- 公司
- 板块

原型额外的“资产担保人”已删除。

### 4.4 详情入口

当前原型：

1. 资产标签号使用蓝色链接按钮打开资产卡片详情。
2. 所在单据编号存在值时可打开对应业务单据详情。
3. 无关联单据时展示 `-`，不提供空链接。

> 耗材当前责任人 = 查询员工

当前原型不再使用单据申请人参与耗材当前归属判断。

### 5.2 列表字段

当前原型仍展示公司、板块、分类、品牌、数量、金额、成本中心、仓库、启用日期等旧字段，与新版 PRD 不一致，后续同步原型时删除。

标签号、责任人、数量、启用日期等属于业务演示交易数据。

不再展示资产标签号、单据编号、单据状态。

三方当前统一：

> 合约号码当前责任人 = 查询员工

当前有效合约号码已确认只取状态为：

> `在用-使用中`

的记录；当前原型已按该状态过滤。

### 6.3 列表字段

新版 PRD 按最新确认结果将合约号码列表固定为：

- 行号
- 合约号码
- 合约号码说明
- 合约号码状态
- 责任人
- 责任人公司
- 所在单据编号

- 单据业务类型

## 7. 单据信息页签三方比对

### 7.1 员工关系

原版 PRD 只定义了可使用 `payPersonId`、责任人、申请人、入库/出库明细关联人员等字段；现代码补充材料进一步明确了不同业务分支实际使用哪类员工关系。

当前新版 PRD / 原型已细化为：

| 业务分支 | 员工关系 |
| --- | --- |
| 普通员工业务单据 | 单据头申请人员优先；申请人员为空时使用领用人员 / `payPersonId` 兜底 |
| CAA/CAC 库存类 | 员工申请单上的申请人员或领用人员，并关联后续库存业务 |
| CAA/CAC 采购类 | 员工申请关系中的申请人员或领用人员，并关联采购、接收或后续执行单据 |
| 独立入库 | 入库明细退回人员 |
| 独立出库 | 出库明细责任人 |
| 独立资产转移 | 转移明细责任人或申请人 |

当前原型不再使用一个“任意员工字段命中即可”的通用 OR 判断，而是按业务分支执行对应关系。

### 7.2 业务类型

原版 / 新版明确可覆盖：

- 更换
- 退库
- 员工转移
- 借用
- 统一申请相关
- 合约号码相关
- 新员工相关
- 出库
- 入库
- 资产转移

当前原型使用多种 Mock 单据分别验证普通员工业务、CAA/CAC、独立入库、独立出库和独立资产转移的员工关联路径，正式业务数据仍需由各业务模块提供。

### 7.3 列表字段

当前原型字段与新版 PRD 一致：

- 行号
- 申请单号
- 单据类型
- 业务类型
- 单据状态
- 申请人
- 申请时间
- 核心单据
- 公司
- 板块
- 部门
- 操作

申请单号规则已进一步明确：

1. 员工单据信息每条结果必须有申请单号/主业务编号，不允许为空。
2. 普通申请类展示正式申请单号。
3. 独立入库、独立出库、独立资产转移等没有上游员工申请流程时，申请单号列展示当前业务主单号。
4. “核心单据”只用于展示由申请继续生成的下游执行单据；没有下游执行单据时展示 `-`。

### 7.4 单据状态

三方当前统一：

- 已完成
- 处理中
- 已驳回

### 7.5 详情与流程入口

当前原型：

1. 申请单号可按单据类型进入对应业务详情。
2. 核心单据存在时可按单据类型进入对应执行单据详情。
3. 历史单据模拟为跳转旧系统对应详情，不在原型中编造旧系统 URL。
4. 当前单据存在但未配置详情页面时，提示“暂无明细展示页面！请联系维护人员添加。”
5. 操作列提供“查看流程”。
6. 无申请单号或核心单据时展示 `-`。

### 7.6 排序

员工单据信息当前统一按：

> 申请时间降序。

## 8. 默认排序规则

资产、耗材、合约号码三个页签当前统一使用以下默认排序：

1. 先按所在单据编号字段 `sp_po_putin_num` 降序。
2. `sp_po_putin_num` 为空的记录排在非空记录之后。
3. 相同 `sp_po_putin_num` 下按标签号字段 `tag_number` 升序。
4. `sp_po_putin_num` / `tag_number` 可以作为排序数据字段使用，不要求因为参与排序就在列表中新增展示列。

员工单据信息按申请时间降序。

当前原型已按以上规则实现。

## 10. 权限与历史单据

### 10.1 权限

最终口径：

> 只有拥有“资产管理 → 员工资产信息查询”菜单权限的后台用户可以访问。

本功能暂不增加公司、板块、部门等额外数据权限限制；拥有菜单权限的用户可以查询全部员工，包括离职员工。

### 10.2 历史单据旧系统详情

原版要求：

> 切换新系统后，历史单据详情页保留旧系统地址。

最终口径已确认：

> 历史单据跳转至旧系统对应单据详情页。

PRD 不维护具体旧系统 URL；当前原型不自行编造旧系统地址。

## 11. 当前仍需业务确认的规则

本轮三方比对涉及的核心查询、状态范围、排序、权限、离职员工查询及历史单据跳转规则继续保留。耗材与合约号码列表字段已同步到新版 PRD，当前原型尚未同步本轮字段变化。


## 12. 现代码补充材料吸收结论

本轮补充材料用于解释旧系统/现代码的实际查询方式，不直接作为新版页面结构的最高优先级来源。

### 12.1 已吸收

1. 资产标签号在资产页签支持包含匹配。
2. 普通员工业务单据按单据头申请人员关联；申请人员为空时使用领用人员兜底。
3. CAA/CAC 库存类、采购类通过员工申请关系关联，并继续关联后续库存、采购、接收或执行单据。
4. 独立入库按入库明细退回人员关联。
5. 独立出库按出库明细责任人关联。
6. 独立资产转移按转移明细责任人或申请人关联。
7. 单据详情根据业务类型进入对应详情；单据存在但未配置详情页面时使用固定兜底提示。
8. 普通员工业务、独立入库、独立出库、独立资产转移之间不得混用员工关联字段。

### 12.2 不吸收

以下内容属于旧页面结构、旧实现缺陷或已被后续确认规则替代，因此不回写新版 PRD：

1. “名下资产 / 担保资产 / 合约机 / 员工单据信息”四页签结构。
2. “担保资产”页签、资产担保人、担保来源单据等旧页面字段。
3. 合约机继续使用资产标签号作为查询条件。
4. 单据状态显示但实际不参与后台查询。
5. 未选择员工直接查询并返回空列表。
6. 单据编号在资产类页签显示但后端实际不生效。
7. 员工单据按创建时间倒序；当前目标规则已明确为按申请时间降序。
8. 页签仅位于结果区内部；当前目标交互已明确为页签位于查询区上方。
9. 旧页面的空状态表现为空表；当前新版 PRD 已有明确空状态文案。

### 12.3 暂不升级为目标规则

现代码材料提到“同一资产转移单可能因为不同明细人员关系被多个员工查询到”。该内容属于现代码行为描述，但没有形成新的业务确认，因此当前不额外写成目标规则，也不据此改变新版原型。

另外，补充材料曾描述部分独立入库、独立出库、资产转移记录可能没有前置申请单，进而出现申请单号为空。该表现不作为目标规则：新版已明确员工单据信息每条记录必须展示申请单号/主业务编号；无上游员工申请流程时展示当前独立业务主单号。
